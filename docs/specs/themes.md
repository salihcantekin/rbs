# Spec: Themes and appearance

- Status: Draft
- Owner crate(s): `rbs-ui` (`tokens`: theme model, resolving, checks, bounds, token metadata), `rbs-user-data` (theme and appearance documents, theme library), `rbs-app` (Settings › Appearance, theme editor, applying themes to windows and native layers)
- Related ADRs: [0015](../adr/0015-ui-design-rules.md), [0049](../adr/0049-main-window-areas-panel-states-and-sizes.md), [0051](../adr/0051-user-data-profiles-and-scene-collections.md), [0057](../adr/0057-user-themes-and-appearance-settings.md)
- Rules: [UI principles](../ui/principles.md) U7, U11, U12, U17

## Purpose

Users change the look of RBS with themes: files that override design tokens on top of a built-in theme, kept in a library, shared as single files, and chosen in Settings › Appearance. This spec defines the theme file, the appearance file, the checks every theme passes and how the app applies a theme.

## Scope

In scope: the theme document (format 1), resolving a theme on its base, checks and bounds, the theme library, the appearance document, the Appearance page's behaviour, applying a theme at run time.

Out of scope, later changes: themes in `.rbspack` packs; font files; a curated accent shortcut; detecting the OS high-contrast setting; theme methods in the control API other than `ui.theme.reload` and `ui.theme.switch {id}` (View › Theme; [control API](control-api.md#client-scoped-ui-commands)); a text size preference. The token names, groups and built-in values are in the [design system spec](ui-design-system.md#tokens).

## Contract

### Themeable tokens (`rbs_ui::tokens`)

| Group | Tokens | Value | Bounds |
| --- | --- | --- | --- |
| Colours | every name in `THEME_COLORS` | `"#rrggbb"` (opaque) | contrast and hue rules of the design system |
| Font | `font.family` | array of family names | 0 to 8 names, each 1 to 64 characters, no control characters or text direction marks |
| Text | `type.caption`, `.body`, `.label`, `.title`, `.heading` | `{ size, line, weight }`, whole style | size 11 to 48, line from size to 2 x size, weight 300 to 900 |
| Spacing | `space.1` ... `space.8` | logical px | 0 to 64 |
| Spacing | `size.panel.pad`, `size.section.gap`, `size.field.gap` | logical px | 8 / 12 / 6 to 64 (floors, ADR-0076) |
| Controls | `size.control.sm` / `.md` / `.lg` | logical px | 24 to 64 (U7) |
| Shapes | `radius.sm` / `.md` / `.lg` | logical px | 0 to 32 |
| | `radius.button` | logical px | 0 to 32 (a button with text; owner decision 2026-11-14) |
| | `size.button.chip` | logical px | 12 to 32 (the chip behind a button's lead icon) |
| Lines | `size.border` | logical px | 1 to 4 |
| | `size.focus-ring` | logical px | 2 to 6 (U7) |
| | `size.toast.border` | logical px | 2 to 4 (the notice outline stays visible) |
| Icons | `size.icon.box` / `size.icon.stroke` | logical px | 12 to 32 / 1 to 3 (U7) |
| Menus | `size.menu.sm` / `.md` | logical px | 160 to 480 |
| RBS menu | `size.app-menu.w` / `.categories` / `.list-h` | logical px | 480 to 960 / 120 to 320 / 240 to 720 |
| Motion | `motion.fast` / `motion.normal` | ms | 120 to 200 (U12; reduce motion turns motion off) |

`THEMEABLE` lists them with metadata for the editor: name, label in words, group, value kind, bounds. Not themeable, refused in a theme: `color.state.live`, `color.text.on-live` (U12), `color.caption.close-hover`, `color.caption.close-text` (the Windows close button as the OS draws it, ADR-0071), `size.caption.w`, `size.color.code`, `size.window.*`, `size.floating.*`, `size.settings.*`, `size.field.compact`, `size.field.drag-step`, `size.toggle.*`, `step.*`, `size.tracking.caps`, `size.meter.peak`, `size.meter.bar`, `size.meter.scale`, `size.meter.scale-line`, `size.meter.readout`, `size.mixer.strip`, `size.mixer.splitter`, `size.mixer.controls`, `size.mixer.min-h`, `size.transition.*`, `size.toast.rail`, `size.toast.max` (the widest a notice may be), `delay.*` (`delay.toast` is how long a notice stays, `delay.toast-tick` how often its seconds step).

The built-in token file gains `[font] "font.family" = []` (empty: the OS UI font); `tokens.toml` becomes format 2 and `Tokens::parse` still reads format 1 files (given the empty family), so `RBS_TOKENS` files keep working.

### Theme rules

Run by `Tokens::resolve` on every resolved theme and by `Tokens::parse` on the built-in file (each theme in it), so built-in tuning is held to the same rules:

- **Contrast**: the rules of the design system plus `color.border.focus` on `color.surface.overlay` and `.sunken` (3:1), `color.text.inverse` on `color.accent.hover` (4.5:1, 7:1 high contrast), `color.accent` on every surface (3:1), `color.text.secondary` on `color.accent.subtle` (4.5:1, 7:1 high contrast), `color.state.live` on `color.surface.sunken` (3:1), and the pairs the desktop UI draws besides: `color.state.error` (error text) on every surface and on `color.accent.subtle` (4.5:1, 7:1 high contrast), `color.border.focus` on `color.accent.subtle`, `color.border.strong` on `color.surface.base`, `.sunken`, `.overlay` and `color.accent.subtle`, `color.brand` on `color.surface.raised` and `.overlay` (3:1; the RBS mark on its chip in the menu button), and `color.accent` on `color.accent.subtle` (3:1; the last three for a Checkbox on a hovered or selected row, ADR-0062), and `color.state.warning` on `color.surface.overlay` and `color.accent.subtle` (3:1; the mark of an unavailable source on a hovered or selected row, ADR-0077), and the notice card: `color.text.primary`, `color.text.secondary` and `color.toast.edge` on `color.toast.surface`, and `color.toast.surface` (the seconds and the hourglass) on `color.toast.edge` (4.5:1, 7:1 high contrast), `color.border.focus`, `color.border.strong` and `color.accent` on `color.toast.surface` (3:1), and `color.toast.edge` on `color.surface.base`, `.raised`, `.overlay` and `.sunken` (3:1, so the outline stays visible on the window and on panels). Test `every_drawn_pair_has_a_contrast_rule` (in `rbs-app`, which owns the `.slint` files) reads them and fails when a text, border or icon colour is drawn on a theme colour no rule covers, or covers only with 3:1 when it is text (4.5:1). It expands components per instance (the instance's properties over the defaults, children at `@children`), takes the nearest ancestor `background` (through `transparent`; a popup or window starts afresh; a colour that is not a theme token ends the search), follows `if` conditions and ternaries with each condition as one atom shared by every expression of that instance (so a button's background and text take the same branch), and checks a `FocusRing` against what is around its control. Exempt: `color.text.disabled` (inactive controls, WCAG 1.4.3) and `color.border.subtle` (dividers and resting outlines that carry no meaning alone). The Tint buttons add `color.text.primary` and `.secondary` on `color.button.fill`, `.hover`, `.pressed` and `.chip`, `color.text.primary` on `color.accent.subtle.hover`, `color.text.inverse` on `color.accent.pressed` and `color.state.error` on `color.action.destructive.subtle` and `.subtle.hover` (4.5:1, 7:1 high contrast), `color.text.secondary` on `color.accent.subtle.hover`, `color.action.destructive.subtle` and `.subtle.hover` (a Button's caption and hint; 4.5:1, 7:1 high contrast), and `color.accent` on `color.button.chip` and `color.accent.subtle.hover`, and `color.border.focus` on `color.button.fill`, `.hover`, `.pressed`, `color.accent.subtle.hover` and both danger fills (3:1; the focus ring is drawn over the button's own fill). Accepted without a rule: `color.state.live` on `color.surface.raised` and `.overlay` (the fixed live colour is not a theme's to fix and live always shows its words, ADR-0057 review item 1), and on `color.accent.subtle` (the small live dot before "REC" on the selected scene row); the test lists them by name, so any other live pair fails. Record's dot and a running output's stop square on a button sit in a `color.surface.sunken` well, covered by the live rule (ADR-0118). Not seen: a sibling drawn under a text and colours set from Rust (native layers).
- **Live red reserved**: every theme colour differs from `color.state.live` by at least ΔE2000 15 (`MIN_DELTA_E_FROM_LIVE`); the 45 degree hue rule for `color.state.error`, `color.action.destructive` and `color.meter.clip` stays.
- **Across tokens**: the `line` of `type.caption`, `type.body` and `type.label` and `size.icon.box` are at most `size.control.sm`; `size.control.sm <= .md <= .lg`; `space.1 <= space.2 <= space.3 <= space.4 <= space.6 <= space.8`; `radius.sm <= .md <= .lg`; text sizes `caption <= body <= title <= heading` and `body <= label <= title`; `size.focus-ring <= space.1`; `size.field.gap <= size.section.gap`; `size.icon.box <= size.button.chip <= size.control.sm` and `radius.button` at most half of `size.control.sm` (ADR-0118). A token below its floor (`MINIMUMS`: `size.focus-ring`, `size.icon.*`, `size.panel.pad` 8, `size.section.gap` 12, `size.field.gap` 6, `size.tab.indicator` 2, `size.toast.border` 2, `size.toast.rail` 4, `size.window.min-*`) makes the file refused with "<token> must be at least <floor> (<rule>)"; panel padding has a ceiling of 64 like the other spacing tokens. `size.tab.indicator` is not themeable.
- **Size**: a theme file over 64 KiB (`MAX_THEME_FILE`) is not read; more than 256 unknown token names (`MAX_UNKNOWN_TOKENS`) fails the theme.

### Effects ([ADR-0120](../adr/0120-theme-effects.md))

A theme chooses how lively its controls look: **Calm** (no key, the default), **Vivid** or **Tactile**. Implemented in `rbs_ui::tokens` (`effects.rs`), `rbs-app-ui/build.rs` and the library `Button`, `IconButton` and `SplitButton`.

- **Token file format 3** adds `[effects.vivid]` and `[effects.tactile]`; calm has no table (all zero). Format 3 still needs `[font]` and needs both tables; a table in a format 1 or 2 file is refused. A format 2 file (an older `RBS_TOKENS`) has no effect tables: every theme resolves to calm, and a theme that asks for more gets the notice "This build's token file has no effects".
- **Effect tokens** (each table holds all of them; inclusive bounds; not themeable one by one): `effects.shadow.blur` 0 to 4 px, `effects.shadow.offset` 0 to 2 px, `effects.shadow.alpha.dark` and `.light` 0 to 0.5, `effects.glow.blur` 0 to 4 px, `effects.glow.alpha` 0 to 0.5, `effects.sheen.alpha` 0 to 0.3, `effects.sheen.band` 0 to 4 px, `effects.key.edge` 0 to 2 px, `effects.key.shade` 0 to 0.4 (a mix of the fill's encoded sRGB channels toward black), `effects.press` 0 to 2 px. A fraction is a TOML number from 0 to 1. Rules: `effects.press <= effects.key.edge`, and `effects.key.edge + max(effects.shadow.blur + effects.shadow.offset, effects.glow.blur) <= EFFECT_EXTENT_MAX` (4 px, a constant).
- **Derived colours**: shadow black at the base's alpha; glow `color.accent` (the primary rest fill) at the glow alpha; sheen white at the sheen alpha; key edge the rest fill of the kind (`color.accent`, `color.button.fill`, `color.action.destructive.subtle`, `color.accent.subtle`) mixed toward black.
- **Extent and clamps** (per slot, on the lengths after density): the extent is `max(0, min(4, space.1, space.2 − size.focus-ring))`, 4 px regular and roomy, 2 px compact; shadow, glow, key edge and press are scaled down together to fit it. The sheen band is clamped to `max(0, (size.control.sm − max(size.button.chip, size.icon.box, type.label line)) / 2)`, 2 px with the built-in sizes.
- **Checks** (decision 9): the key edge colours and the glow differ from `color.state.live` by ΔE2000 15 or more; `color.border.focus` on `color.surface.base` blended with a neighbour's strongest shadow or glow at the outer edge of the extent keeps 3:1. A failure drops the theme's effects to calm with an effects notice naming the check; its colours and colour warnings are unchanged. The built-in file is strict: `Tokens::parse` refuses a file whose Dark or Light theme fails a check in either setting.
- **High contrast** always resolves to calm and keeps the stored key; the editor shows the control disabled with the reason.
- **Effects notice**: a `ThemeProblem` with `Severity::Notice`, `token: Some("effects")` and no rule, kept in `ResolvedTheme::warnings` beside the colour warnings. It never refuses a theme, Fix ignores it, and colour warning counts leave it out (`ThemeProblem::is_warning`, `ResolvedTheme::colour_warnings`). An unknown stored value reads as calm with "This theme uses effects this version does not have; it shows as Calm" and is kept unchanged on save.
- `ResolvedTheme` carries `effects` (resolved) and `effect_values`; `ResolvedTheme::effect_draw()` gives what a slot draws.

### Theme document (`kind = "theme"`, format 1 or 2)

```toml
format = 1
kind = "theme"
name = "Midnight"
base = "dark"
author = "Salih"
description = "Deep blue surfaces with a warm accent"

[colors]
"color.surface.base" = "#0b1020"
"color.accent" = "#ff9f43"

[font]
"font.family" = ["Inter", "Segoe UI", "Helvetica Neue"]

[type]
"type.body" = { size = 14, line = 20, weight = 400 }

[length]
"radius.md" = 8

[duration]
"motion.fast" = 100
```

| Key | Meaning |
| --- | --- |
| `base` | Required: `dark`, `light` or `high-contrast` |
| `author`, `description` | Optional display text: one line, no control characters or text direction marks, at most 64 and 200 characters |
| `effects` | Optional: `"calm"`, `"vivid"` or `"tactile"` (ADR-0120). Missing or `"calm"` is calm and is written as no key. A value that is not a string, or not a valid name, is refused; a valid unknown name is kept and reads as calm with the effects notice |
| `colors`, `font`, `type`, `length`, `duration` | Optional tables of overrides, keyed by token name; a token belongs to its table's group (a colour under `[length]` is refused) |

**Format** (ADR-0120 decision 2): a theme whose stored `effects` is calm or missing is written as format 1, so older builds keep reading it; any other stored value (vivid, tactile, an unknown one, or a high-contrast theme that asks for vivid) is written as format 2. The stored key decides, never the resolved effects. Format 1 reads as format 2 with no change, and a format 1 file with a hand-edited `effects` key is read and honoured. Older builds refuse format 2 and fall back to the theme's base. Writing format 2 over a format 1 file keeps the old file once as `<id>.toml.format1.bak`.

Other top-level keys are refused (ADR-0051 decision 2). Unknown token names inside the tables are the theme exception to ADR-0051's unknown-key rule (ADR-0057 decision 3): Inside the tables, a key that is a valid token name (lowercase words joined by `.` or `-`) but not known to this build is kept, rendered back on save in its table, not applied, and reported (`ResolvedTheme::unknown`); an invalid name is refused. Rendering is deterministic and writes overrides sorted by name.

### Resolving and checking

`Tokens::resolve(&self, theme: &ThemeOverrides) -> Result<ResolvedTheme, ThemeProblems>` on the built-in tokens of the running build:

- starts from `base`'s colour set and the shared lengths, durations, text styles and font family, then applies each override;
- runs every check of the design system and every theme rule above and returns all problems at once, each `ThemeProblem { token: Option<String>, reason, severity, rule }` naming the token it belongs to (the editor shows it beside the token). **Errors** (the theme is refused): a non-themeable token, a value of the wrong kind, a value out of bounds, each failed rule across tokens. **Warnings** (ADR-0072; the theme resolves and is used): each failed contrast rule (naming the foreground token, with the ratio found and needed), each failed hue rule, each colour too close to live; contrast thresholds are the high-contrast ones when `base` is `high-contrast`. `Err` carries errors and warnings together; `Ok(ResolvedTheme)` carries `warnings`. Built-in token files (and `RBS_TOKENS`) treat every rule as an error. `suggest_colour(tokens, theme, token)` returns the nearest-lightness colour that clears the token's warnings;
- `ResolvedTheme` holds `base`, one colour set (plus the fixed colours), lengths, durations, text styles, the font family list and the unknown names.

Property test: for any set of overrides drawn from the themeable tokens with values in and out of bounds, `resolve` either returns a theme whose only problems are colour warnings or returns at least one error, and never panics.

### Theme library (`rbs-user-data`)

`UserData::themes() -> Library<Theme>` on `themes/` with every rule of the [user data spec](user-data.md#libraries-library). Export scrubs nothing. Built-in themes are not in the library; the app lists them first, as Dark, Light and High contrast, with the ids `builtin:dark`, `builtin:light`, `builtin:high-contrast`. Duplicating a built-in theme creates a user theme with that base and no overrides; duplicating a user theme copies its base and overrides.

### Appearance document (`appearance.toml`, `kind = "appearance"`, format 4)

| Key | Type | Default |
| --- | --- | --- |
| `mode` | `"system"` or `"fixed"` | `"system"` |
| `dark` | theme id | `"builtin:dark"` |
| `light` | theme id | `"builtin:light"` |
| `theme` | theme id | `"builtin:dark"` |
| `density` | `"regular"`, `"compact"` or `"roomy"` | `"regular"` |
| `compact_steps` | integer 1, 2 or 3 | 1 |

Format 1 is format 3 without `density` or `compact_steps` (read as `regular`, step 1). Format 2 is format 3 without `compact_steps` (read as step 1). Format 4 adds the value `"roomy"` (ADR-0112); a format 3 file reads unchanged, and an older build refuses a format 4 file and starts with its defaults. A `compact_steps` outside 1, 2 or 3 is refused. The step is kept while `density` is `regular`.

Compact spacing does not write the theme. While `density` is `compact`, each slot's freshly resolved length map is stepped `compact_steps` times (a second step on that same map would go further, so the app resolves again first). `space.*` and `size.control.*` each take the next smaller token's length, repeated; the smallest step is unchanged. `size.panel.pad`, `size.section.gap` and `size.field.gap` take the Nth smaller original `space.*` value that is still at or above that token's floor; when no such value remains, the token sits on its floor. `size.field.gap` is then kept at or below `size.section.gap`. No length is introduced except a token's floor. Text, radii, icons, menus and every non-themeable size stay as resolved. The same step applies to every theme the slots use. Off, the theme's own lengths are used.

Roomy spacing (ADR-0112 decision 9) does not write the theme either. While `density` is `roomy`, `size.control.md` takes the resolved `size.control.lg`, and `size.panel.pad`, `size.section.gap` and `size.field.gap` each take the next larger resolved `space.*` value (unchanged when none is larger). Nothing else changes: `space.*`, `size.control.sm`, `size.control.lg`, text and every non-themeable size stay as resolved, so the sizes built from the smallest steps (the Mixer strip, compact fields, the Transition panel) are the same in every density. Every value only grows or stays, so no "must not be smaller than" rule can fail. With the built-in lengths the default control is 32 px, the panel pad 16, the section gap 24 and the field gap 12.

**Panel outline** (ADR-0112 decision 3). Each slot also says whether docked panels and Settings cards draw their `color.border.subtle` outline (`Theme.panel-outline`): yes when the slot's `color.surface.raised` and `color.surface.base` differ by less than 1.15:1 (`rbs_ui::tokens::PANEL_OUTLINE_BELOW`), so colour alone would not separate a panel from the window ground. The built-in Dark (1.17) and Light (1.18) draw none; High contrast (1.06) and a user theme with close surfaces keep it. It is computed once when the slot is filled.

**Button outline** (ADR-0118). Each slot also says whether secondary, danger and framed buttons draw their `color.border.subtle` outline (`Theme.button-outline`, `ResolvedTheme::button_outline`): yes when a resting fill (`color.button.fill` or `color.action.destructive.subtle`, `BUTTON_FILLS`) differs by less than 1.15:1 from any of `color.surface.base`, `.raised`, `.sunken` or `.overlay` (`BUTTON_SURFACES`). The built-in Dark draws none; Light and High contrast keep it. A user theme that recolours the surfaces but not the button colours keeps the base theme's fills, and the outline follows; a fill that fails a contrast rule is a colour warning (ADR-0072).

`UserData::appearance()` returns the defaults and the reason when the file cannot be read; `set_appearance(&WriterLock, ..)` writes it through the user data writer. A theme id is `builtin:<name>` or a library id. An id that names no usable theme falls back to `builtin:<base>` when the theme's `base` can be read (envelope and `base` key only), else to `builtin:dark` (for `dark` and `theme`) or `builtin:light` (for `light`); the app shows a note and does not rewrite the file. **Deleting:** an id whose theme file is gone (the theme was deleted) is not such a case: deleting a theme in use sets the slots that name it to `builtin:<base>` of the deleted theme and saves the choice, and at start (before the user data writer lock is taken) a slot naming a missing file is set to `builtin:dark` (`dark`, `theme`) or `builtin:light` (`light`) and saved, with no note. `rbs-app --reset-appearance` moves `appearance.toml` to `appearance.toml.reset.bak` (numbered when taken) and starts with the defaults.

### Settings › Appearance (`rbs-app`)

- Theme choice: "Use the system appearance" (on by default) uses the built-in Dark theme while the system is dark and the built-in Light theme while it is light. A saved custom dark or light slot is read as that built-in pair. Choosing a theme in the list (Use) turns the choice to one theme (`fixed`) and does not change the system pair, so turning the switch back on returns to the built-in pair. Turning the switch off without choosing a theme keeps the built-in theme of the scheme the windows are showing. "Compact spacing" (off by default) steps spacing, control height and the panel, section and field gaps for every theme, as above; the theme files stay as saved. While it is on, "Amount" is a slider of stops 1, 2 and 3 (1 is the next smaller step, 3 is as tight as these tokens can go; a double click returns it to 1) and a notice says the tightening applies to every theme and does not change theme files. Off, each theme's own lengths are used and the step is remembered. The themes list shows each theme with a swatch of `color.surface.base`, `color.text.primary` and `color.accent`. A change is applied at once and written to `appearance.toml`.
- Themes list: each row ends with its actions as icon buttons (`IconButton`, accessible names "Use <name>", "Edit <name>" or "Duplicate <name> to edit" for a built-in theme, "Duplicate <name>", and for user themes "Export <name>…" and "Delete <name>…"; a built-in row leaves the places of Export and Delete empty so the icons line up), acting on that row's theme (it is selected first). Delete asks in a callout under the list. Import (a ghost button with the `import` icon) is at the right of the card's description line. A selected user theme has its Name field under the list (Rename). File dialogs as for output profiles. An unusable theme shows its first problem and "Edit" to see all; it cannot be used. A usable theme with colour warnings (ADR-0072) shows "N colour warnings" with an amber mark under its name; importing a theme that has warnings selects it and says so in the page note ("Imported \"X\". It has N colour warnings, M about the Live colour, which can hide whether you are live. Open it to see them."), and the theme is added and usable.
- Theme editor: groups Colours, Text, Font, Spacing and size, Shapes, Motion; per token a label, the control (ColorPicker; NumberField; text styles as size, line and weight fields; font family as an editable list with a note naming the family in use), a reset button that removes the override, and its problems. The font family field suggests the installed families whose names start with, then contain, the name being typed after the last comma (at most 8; shown under the field; Down and Up choose, Tab completes and keeps typing, Return completes and confirms, Escape hides the list, a click completes and confirms the whole name). They are read the first time something is typed (P13), in the same list as Add font. Every edit without an error is applied to every window at once when a slot uses the theme, colour warnings included (ADR-0072); editing a theme no slot uses shows a notice under the title ("This theme is not in use, so the windows do not show its changes. Pick it under Theme in use to see them.") in place of the hint. The page opens with the theme the windows use now selected in the list, and a picker whose theme cannot be used shows the built-in theme used instead. The editor's lists update row by row, so a menu open in a row (Add font) stays open while "Keep this look?" counts down; a colour that breaks a rule shows a warning in plain words on both rows of its pair (live warnings first) with a **Fix** button that moves its lightness to the nearest passing value, and a count under the title; an edit with an error (a value out of bounds) is shown with its problem and not applied; Save is on for any change without an error; a value still being typed (before Return or leaving the field) turns Save on, and Save applies it first, so it never needs leaving the field; Save and Cancel (Close while nothing changed) are at the top of the editor, once. Each token is a row: its label, hint and problem on the left, its fields and Reset on the right (the font family field takes the row's width under the label; empty, it shows "System font" in `text.secondary`; beside it **Add font** opens the searchable picker (`Overlays.picker-*`, ADR-0094 B1, the same overlay as Add source) over the families installed on this computer, sorted by name, without the OS's hidden dot-names, with a filter field (names containing the text, without regard to case); a pick goes first in the list and is applied like a typed list. The families are read the first time the picker opens, never before, P13). Beside the editor the theme list is a narrow column (`size.menu.sm`) at the top, without the "Built in" chips; it is never stretched to the editor's height; Cancel restores the saved theme. Unknown tokens are listed read-only as "Not used by this version". Built-in themes open read-only with "Duplicate to edit". The Shapes group ends with an **Effects** row (ADR-0120 decision 5): a SegmentedControl Calm, Vivid, Tactile with the hint "How lively buttons look…"; an unknown stored value shows as Calm, and a change applies at once with no "Keep this look?". Reset sets Calm. On a high-contrast theme, or with a token file that has no effects, the control is disabled and the hint gives the reason. The effects notice shows on this row, never among the general problems.
- Keep this look: changing `font.family` in the editor of a theme a slot uses, or a colour edit that takes primary text below contrast 1.5 on `surface.base`, `.raised` or `.overlay`, shows "Keep this look?" with Keep and Undo; without an answer within 15 seconds (`KEEP_LOOK_TIMEOUT`, measured on the app's injected clock) the previous look comes back. Escape is Undo. Choosing a theme, or turning "Use the system appearance" on or off, is kept at once and is not undone on that timer. The themes list selects the theme that was just chosen.
- While `RBS_TOKENS` or `RBS_THEME` is set, the page shows a note that a development override is in effect.

### Applying (`rbs-app` `look`)

- **Slots.** The generated `Theme` global has `slots: [ThemeSlot; 2]`: slot 0 is used while the OS scheme is dark, slot 1 while it is light. `ThemeSlot` holds every theme colour, every themeable length, duration and text style, `high-contrast: bool` (base is `high-contrast`), and the effect fields of ADR-0120 (`effects-on`, `effects-shadow-blur`, `-offset`, `effects-shadow`, `effects-glow-blur`, `effects-glow`, `effects-sheen`, `effects-sheen-band`, `effects-key-edge`, `effects-press`, `effects-key-primary`, `-secondary`, `-danger`, `-checked`; `SLOT_EFFECTS`), filled by `slot()` from `ResolvedTheme::effect_draw()` after density. Only library components read `Theme.effects-*` (`cargo xtask check-ui`). `Theme.active` is `Palette.color-scheme == light ? 1 : 0`, unless `Theme.os-scheme` is 0 or 1. On Windows the menus stay the system's and a dark theme asks for the dark menu, a light theme for the light one; that request changes what Palette reports, so the app sets `os-scheme` from the system setting (dark 0, light 1, high contrast 1) and updates it when that setting changes. Every `Theme.*` colour, `Theme.high-contrast` and `Tokens.*` themeable value reads `slots[active]`. The fixed colours and non-themeable tokens stay single values. `Theme.choice` is removed. Built-in defaults: slot 0 Dark, slot 1 Light.
- **Filling the slots.** `system` mode: slot 0 = resolved `dark`, slot 1 = resolved `light`. `fixed` mode: both = resolved `theme`. Compact spacing then steps those freshly resolved lengths (`compact_steps` while `density` is `compact`). `RBS_THEME=<dark|light|high-contrast>`: both = that built-in theme, and the appearance choice, including compact spacing, is not applied. `RBS_TOKENS=<file>`: the themes resolve on that file instead of the built-in one.
- **On a change** of choice or theme, the shell sets the slots of every open window and gives native layers their new colours (preview selection outline, meters); each new window gets the same slots when it opens.
- **Font.** `look` is given a `FontCatalog` (`fn has_family(&self, name: &str, sample: &str) -> bool`): in the app the system font database, in tests a fake. The window's `default-font-family` is the first name in `font.family` for which `has_family` is true with the UI language's sample text (its alphabet and digits); none: the OS UI font (empty string). The choice is made again when the UI language changes.
- **Reading.** Files are read at start (the themes `appearance.toml` names), when the Appearance page opens (envelopes) and on the `ui.theme.reload` command (View › Reload themes): it reads the token file (`RBS_TOKENS` when set), `appearance.toml` and the theme files again, resolves the two slots as at start (with `RBS_THEME`, that built-in theme of the new file), applies them to every open window and refreshes the Appearance page; an open draft in the editor stays open and is checked again against the new file, and what cannot be used is reported as at start. Opening the page also reads the files again. Nothing watches files or polls (P13).
- **View › Theme** (`ui.theme.select`): a picker of at most the first ten themes (built-in Dark, Light and High contrast, then user themes by library name). Picking one runs the same Fixed-mode choice as Settings › Appearance › Use, without opening Settings. While Appearance follows the system, no choice is checked; picking still switches to Fixed.

## Errors and failure behaviour

Nothing panics. A theme that cannot be read or has an error is never applied (colour warnings do not count); the slot uses its built-in fallback and the Appearance page says why. Library errors are `DataError` (user data spec); check failures are `ThemeProblems`. A new error rule (a bound or a rule across tokens) can refuse a saved theme that passed before; a new colour rule only adds a warning: it falls back the same way and the page names the failed rule, so the user can fix the colour in the editor.

## Performance requirements

User-paced; never on a hot path. Resolving and checking a theme takes well under 1 ms; applying sets each window's globals once per change. No cost while the user does nothing.
