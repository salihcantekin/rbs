# Spec: Scene model

- Status: Draft
- Owner crate(s): `rbs-scene`
- Related ADRs: [0013](../adr/0013-zero-cost-when-unused.md), [0015](../adr/0015-ui-design-rules.md), [0021](../adr/0021-scene-collection-model.md), [0039](../adr/0039-scene-source-types.md), [0051](../adr/0051-user-data-profiles-and-scene-collections.md), [0110](../adr/0110-canvas-layout-space.md)

## Purpose

The scene collection is the document the user edits: canvases, sources, scenes and the items that place sources in scenes (glossary: Scene collection). This spec defines its model, the invariants every edit keeps, undo, and how a scene becomes the flat layer list the compositor draws. The UI, the control API, scripts and remote panels all edit it through the same operations (vision, "Declarative scenes").

## Scope

In scope: the in-memory model, validated edits with undo, scene scopes and per-canvas layout (UI rule U15), nested scenes, flattening, which sources must be Active, and binding a collection to a media graph description.

Out of scope, later changes:

- Applying the bound description through `rbs_graph::runtime::Controller` and delivering layer lists to running compositor nodes (engine wiring in `rbs-app`).
- The control API command schema; it maps one-to-one onto the operations here. The on-disk document format and its versioning are in the [user data spec](user-data.md) (ADR-0051); this crate provides the validating loader.
- Audio filters, per-source monitoring and mixer buses, transitions, groups, animation, keep-warm policy. Which node type a built-in source is and how instances are built: [scene sources](scene-sources.md).

`Canvas::new`, `Source::new`, `Filter::new`, `Scene::new` and `SceneItem::new` build model values for documents (edits issue ids themselves).

### Loading (`SceneCollection::from_parts`)

`from_parts(canvases, sources, scenes, IdCounters) -> Result<SceneCollection, SceneError>` is the validating loader for documents. It trims names, refuses duplicate canvas, source, scene or item ids (`DuplicateId`; items are unique across all scenes), raises each counter above the highest id in use (`IdsExhausted` when no id is left), and checks every invariant below on the result. `id_counters()` returns the counters a document stores. A test rebuilds collections from their parts and checks equality and counters.

### Edits (`SceneCollection`)

Canvases: `add_canvas`, `remove_canvas`, `rename_canvas`, `set_canvas_format`, `set_program`, `set_preview`, `set_canvas_master_volume`, `set_canvas_master_muted` (ADR-0081: live controls with a record of their own that expects and replaces only `master`; `ReplaceCanvas` and every other canvas record ignore `master` when they check what they expect and keep the current one, so a fader move never makes an earlier rename conflict or come back; removing a canvas removes its master and undoing the removal restores it), `set_canvas_follow(canvas, follow, fallback)` (ADR-0093: the canvas shows the program scene of `follow`; `InvalidFollow` when it follows itself, an unknown canvas or another follower, when the followed canvas follows, or when a `Fallback::Scene` is not one the canvas may show or the canvas follows nothing; `followed_programs(last)` gives the scene each follower shows now: the followed program scene when the follower may show it (U15), else its `fallback`, `KeepLast` taking `last` then the canvas's own program; `Canvas` also holds `audio_from`, `Main` only for now), `auto_layout(canvas, scene, mode, picture, focus)` (ADR-0093 decision 4: gives each visible source item of the scene a layout for the canvas, in one undo step; `picture` is the source's uncropped size, `None` keeps the item; modes `Fit` letterboxes, `Fill` covers the canvas and cuts the picture (crop) around the item's `focus`, `Stack` puts the visible items in equal bands from top to bottom, the lowest layer first; rotation and flips of the old layout are dropped; the pure arrangement is `rbs_scene::auto_layout`), `set_globals` (ADR-0065; `globals_of(canvas)` and `is_global_scene(scene)` read it; `showable_scenes(canvas)` is `scenes_for(canvas)` without the global scene, for scene lists, switching and program fallbacks). Collection: `set_glide(glide)` (ADR-0100: replaces `CollectionGlide`; one undo step; `InvalidGlide` for `duration_ms` above `MAX_GLIDE_MS`), `set_transition(transition)` (ADR-0128: replaces `CollectionTransition`; one undo step; `InvalidTransition` when a duration is above `MAX_GLIDE_MS`; `UnknownSource` for an unknown stinger source). The stinger source is never placed (ADR-0140 decision 1): an edit after which `placed_stinger()` names it while it did not before (an `add_item`, a paste, a duplicate or making a placed source the stinger) is refused with `StingerPlaced`; a loaded document that already breaks the rule stays editable. `delete_source` of the stinger source clears `stinger.source` in the same undo step. Sources: `add_source`, `delete_source` (removes it from every scene), `rename_source`, `set_source_settings`, `add_filter`, `remove_filter`, `set_filter_enabled`, `move_filter`, `set_filter_settings` (ADR-0062), `set_source_volume`, `set_source_muted` (ADR-0059), `set_source_sync_offset` (ADR-0062), `set_source_mixer_hidden` (ADR-0080), `set_source_monitor` (ADR-0097), `set_source_glide` (ADR-0100: sets or clears `Source.glide`; one undo step; same bounds as the collection), `set_source_record_separately` (ADR-0086: sets `Source.record_separately`; one undo step; both false is the default and the binder does not read it). Scenes: `add_scene`, `duplicate_scene` (new scene and item ids, the same sources and nested scenes, same layouts and the same levels; refused for a canvas's global scene), `set_scene_own_levels(scene, audio)` and `set_scene_shared_levels(scene)` (ADR-0091: one undo step each, with a record that checks only the mode and keeps the entries current when applied, so live level edits never make it conflict; `GlobalScene` for a global scene), `set_scene_level(scene, source, level)` (ADR-0091: sets or, with `None`, removes one entry; `SharedLevels` while the scene is in Shared levels, `InvalidVolume` out of range; its record covers only that entry; the app keeps it for `reset_source` and drops it for live edits), `placed_sources(canvas, scene)` (every source the scene places, nested and global included, hidden items too), `heard_levels(canvas, scene)` (the sources' own levels for those sources: what Own levels start with), `program_levels(canvas)` and `heard_audio(canvas, source)` (the program scene's entry over the source's own volume and mute: what the canvas's mixer gives the source). `delete_source` removes the source's entries in the same record and its undo puts them back into scenes still in Own levels; every other scene record ignores `audio` except the removal of a scene, whose undo restores the scene with it. `remove_scene`, `rename_scene`, `set_scene_scope`, `set_scene_transition(scene, transition)` (ADR-0135: sets or clears `transition_in` as one undo step; an empty override is stored as `None`; `InvalidTransition` for a duration above `MAX_GLIDE_MS`; `duplicate_scene` and scene copies keep it). Items: `add_item` (at an index or on top), `remove_item` (one item, from this scene only; used to move items), `remove_from_scene(item)` (ADR-0065 decision 7, ADR-0142: Remove from scene, one undo record answering `Removed { source_deleted, deleted_sources, removed_items }`: at the source's last placement in any scene, global scenes included, it is `delete_source` with its companions; otherwise the item goes, and when its scene no longer draws the source (no other item of it in the scene or in a scene nested in it, whatever the items' visibility) the companions' items placed directly in that scene go too, a companion left placed nowhere being deleted; other scenes never change; a nested scene's item goes alone; the host labels the history entry from the result), `move_item`, `set_item_visible`, `set_item_locked`, `set_item_layout` (default or for one canvas), `clear_item_layout`, `resize_text(item, settings, layout)` (ADR-0129 decision 12: the item's source settings and its default layout as one undo step, an `Op::Batch` of `ReplaceSource` and `ReplaceItem`; `UnknownItem` when the item places a scene), `set_scene_items(scene, items)` (ADR-0151: replaces every item of the scene, in order, as one undo record that expects the scene's whole item list; an item that stays keeps its content, an item not in the scene now keeps its id only when the collection issued it and no other item uses it, and no id appears twice; otherwise `UndoConflict` and nothing changes; the invariants are checked as for every edit).

Every edit returns an `Undo`. `SceneCollection::undo(record)` applies it and returns the record that redoes it. `generation()` increases by one on each committed edit, a field edit included, and never on a refused one. It is the collection's revision: a reader that kept the value it last saw (the control thread's source rows, audit F-10) can tell that nothing changed without comparing content. It is not stored in the file and it is not part of equality. `level_edits()` counts, among those edits, the field edits whose records only set sources' audio (`source_audio`) and those that only set canvas masters (`master`); a batch of both kinds counts in neither. `LevelEdits::others(generation)` is then a revision of everything else, so a reader can tell that a fader step moved only levels and patch the rows it shows instead of rebuilding them (audit F-10). An item is found through an id-to-scene index kept beside the scenes, and a scene list sorts through an index of that canvas's order. Neither index is stored in the file. Records form a stack: applied in reverse order they restore every earlier state exactly. Every record carries the state it expects to find (for replacements, the whole current canvas, source, scene header or item; for moves, the current index), so a record used out of order is refused with `UndoConflict` instead of reverting later changes, never applied half-way. `Undo` is opaque for now; a serialisable operation type comes with the control API schema.

Names are trimmed of surrounding whitespace on input.

`set_program` and `set_preview` change the document (which scene a canvas shows is saved) and return an `Undo` like any edit, but they are live actions: the control API does not put them on the user's undo stack, so undoing a layout change can never cut the program (ADR-0021).

Volume, mute (ADR-0059) and the sync offset (ADR-0062) are live controls too: `set_source_volume`, `set_source_muted`, `set_source_mixer_hidden`, `set_source_monitor` and `set_source_sync_offset` (`InvalidSyncOffset` out of range) return an `Undo` with a record of their own that expects and replaces only the source's `audio`, and the application keeps them off the user's undo stack. Every other source record (rename, settings, filters, the whole-source replacement) ignores `audio` when it checks the state it expects and keeps the current `audio` when it applies, so a fader move or mute between an edit and its undo neither makes the undo conflict nor brings the old volume back. The binder ignores `audio` (no new source node); the application sends it to the mixer strip of the source (recording spec, `Studio::set_mix`).

Equality of collections compares content and ignores id counters (undo does not wind them back).

### Invariants

Checked after every edit on the would-be result; a refused edit leaves the collection unchanged. Each is covered by a test in `crates/rbs-scene/tests/collection.rs`.

1. Names are non-blank and unique among canvases, among sources and among scenes.
2. Node type ids are reverse-DNS; float settings are finite. A source's volume and a canvas's master volume are finite and in `0..=1` (`InvalidVolume`).
3. Canvases are at least 1x1, at most `MAX_CANVAS_SIDE` (16384) pixels on a side and at most `MAX_FRAME_RATE` (1000) frames per second (`CanvasTooLarge`, `FrameRateTooHigh`).
4. Every item refers to an existing source or scene; every override and canvas scope refers to an existing canvas.
5. Layouts are finite with opacity in 0..=1 and a valid style. Crop and a style other than the default are only set on source items (a nested scene cannot be cropped or shaped by a flat layer list; `CropOnScene`, `StyleOnScene`), and so is a scroll (`ScrollOnScene`, ADR-0150); a scroll is valid (`Scroll::is_valid`) or the layout is refused (`InvalidLayout`), on the default layout and on every per-canvas override. A canvas `layout_size` has the same bounds as its picture size (not empty, at most `MAX_CANVAS_SIDE`). Stored boxes may lie outside the layout space. Per-canvas overrides are in their canvas's layout space; the default layout is read in the space of whichever canvas draws it, and an edit to it is stored in the space of the canvas it was made on (ADR-0110).
6. Nesting is acyclic, at most `MAX_NESTING_DEPTH` (16) scenes deep, and no scene flattens to more than `MAX_LAYERS` (4096) layers, counting hidden items (so showing an item never fails). Diamond-shaped nesting multiplies layers, so the bound is checked on every edit; it also bounds the recursion of `flatten`.
7. Scope (U15): a canvas shows only its own and shared scenes as program or preview. A scene scoped to canvas C may nest shared scenes and scenes of C; a shared scene may nest only shared scenes, because it can be shown anywhere.
8. Per-canvas layouts exist only for canvases that may show the scene (a scene scoped to canvas C has overrides for C only). Filter ids are unique across the collection.
9. Removing a canvas is refused while scenes are scoped to it; its per-canvas layouts are dropped (and restored by undo). Removing a scene removes the items that nest it and clears it from program and preview (restored by undo). Deleting a source removes all its items (restored in their original positions by undo). Removing a global scene clears the canvas's `globals` (restored by undo, refused with `UndoConflict` when the canvas has another global scene by then). Removing a canvas removes its global scene with it (restored by undo); other scenes scoped to it still block the removal.
10. Global scenes (ADR-0065): the global scene of canvas C is scoped `Canvas(C)`, is not the program or preview scene of any canvas, is nested by no item and nests no scene (`GlobalScene`). A scene the canvas may show and the global scene together flatten to at most `MAX_LAYERS` layers (`TooManyLayers`). The global scene's name is left out of the scene-name check (rule 1), since it is never listed.

A property test applies random sequences of every edit kind, checks that refused edits change nothing and every reachable state flattens on every canvas, then undoes everything back to the start and redoes it to the end, comparing every intermediate state. Another test checks that each kind of record is refused when used out of order.

### Flattening

`flatten(canvas, scene) -> Vec<FlatLayer>`, bottom first. A `FlatLayer` has the `source`, the item `path` from the shown scene to the source item, a `transform` (`Affine2`, same convention as `rbs-gpu`: maps the unit square of the cropped source to canvas pixels), the `crop` in source pixels (the compositor turns it into texture coordinates with the real source size), `opacity`, the item's `style` and `box_size` (`|Layout::size|`, the units of the style; the compositor evaluates the shape on the unit square scaled by it, so the shape transforms with the picture, also inside scaled or squashed nested scenes). A scrolling item's layer also has `scroll` (ADR-0150): its `Scroll` with speed, gap and fade in canvas pixels along the direction (the layout value times the length of the transform's axis along the direction over `|size|` along it, so a nested scene's box scales it), and `scroll_key: ScrollKey`, its run: canvas, source, the scaled settings and the box's length across the direction in canvas pixels, floats compared by bits with `-0.0` as `0.0`. A box with no length along or across the direction has neither. `scroll_keys_cued(canvas, scene, cued)` returns the keys `flatten_cued` would give, plus those of items faded to opacity 0, which flattening leaves out (their runs go on); hidden items and hidden nested scenes give none.

- The layout drawn for each item is `layout_on(canvas)` mapped from the canvas `layout_size` into its current `size` (ADR-0110): the layout-space rectangle is fitted, centred, into the canvas with one scale (the smaller side ratio); position, size and style lengths take that scale. Equal sizes use the stored box unchanged. `Layout::placed_in` is that map and `Layout::stored_in` is its inverse, so an edit made in current pixels is stored in the layout space and draws where it was made.
- Hidden items, everything inside a hidden nested scene, and items whose effective opacity is 0 are left out. `flatten_cued(canvas, scene, cued)` is the same list and also draws an item whose id is in `cued` when `visible` is false (ADR-0105). It does not write `visible`. An empty set does not look up ids. Nested content under a hidden nested scene stays omitted unless that nested-scene item is visible or cued. Callers pass cues only for a shown scene (the canvas `program`, or `preview` when set); a cue on an item that is not in that tree is not in the result, so a preview-only item is not on the program list. Global-scene items use the same rule. The merge is a lookup of the active cue map, bounded by running cues, on the control thread when the layer list is rebuilt. It is not a per-frame scan and it does not run from `Node::process`. The implementation PR records `hot-path-review` for that merge (ADR-0105 decision 8). The Sources row Show control and remaining-time label are not in the Slint UI yet (rule 16); `item.show` and `item.set_show_for` are in the command registry.
- A nested scene's canvas-sized coordinate space is scaled into its item's box; transforms compose, opacities multiply.
- `flatten` refuses a scene the canvas may not show (`ScopeViolation`).
- When the canvas has a global scene (ADR-0065), its layers follow the scene's, so global sources are drawn above every scene; their `path` starts with the global item. Flattening the global scene itself draws it once.
- Opacity of a nested scene multiplies into each of its layers; this is not group opacity (overlapping layers inside a half-transparent nested scene show through each other). Nested content outside the nested scene's canvas area is not clipped to the item's box, and crop is not available on nested scenes. Group opacity, clipping and crop of nested scenes need render-to-texture for nested scenes, a later decision.
- A crop that leaves no picture of the source as it is now (a window that shrank under its crop) is not drawn (gpu-compositor spec, ADR-0058). The crop is not re-derived when the picture changes size: the box stays and the picture is rescaled into it.
- A source may store `region: Option<SourceRegion>` (ADR-0103): full-picture edge insets `left`, `top`, `right`, `bottom`. Absent is the whole picture. It is not settings. Flatten replaces the layer crop with the intersection of the region and the item crop (the wider inset on each edge). That one crop is the compositor's existing UV. The stored region is not rewritten when the picture shrinks; an empty intersection is the empty-crop skip. Fit, recrop and the scale-keeping picture size use the region size (`picture_w − left − right` after clamping) when a region is set. Item crop values stay full-picture pixels.
- Display chrome (ADR-0104) is `chrome: Option<DisplayChrome>` on `Source`, only for `org.rbs.source.display`. Insets are capture pixels (`top`, `right`, `bottom`, `left`) plus `fill` (`cover` or `fit`). Applying chrome writes those insets into `region`. `fill` is not part of the rectangle: cover and fit are `Layout` placements of the item box (`place_chrome`), not a second compositor scale. The binder's settings compare ignores region and chrome, so neither edit replaces the capture node.

`visible_sources(canvas, scene)` is the set of sources of visible items (not inside a hidden nested scene), whatever their opacity: a fade from 0, or a source used for its audio, still needs it running; with a global scene on the canvas its visible sources are included (ADR-0065), so they are Active, linked to every compositor of the canvas and, sound-only ones, mixed with the program. `wanted_sources()` is every source placed in any scene that the user has not deactivated. Hiding an item, or switching to a scene that does not draw it, leaves the device open. `source.set_active` false (the source menu and Properties) is what releases it. A source placed nowhere is Standby.

**Source activity (ADR-0152).** `Source.activity` (`rbs_scene::activity::SourceActivity`: `run`, `on_return`, `linger_s`, each optional; all absent is the type's default) is not settings, so changing it never replaces a node; `set_source_activity` is one undo step and refuses a linger over `MAX_LINGER_S` (600) with `InvalidActivity`. A type declares what it allows with `NodeTypes::activity(type_id) -> ActivityTraits` (default `ActivityTraits::PLACED`: `run: placed` only, no `on_return`, linked while warm). `rbs-sources` declares media (`run` `placed`/`shown`/`on_air`, default `shown`; `on_return` `resume`/`restart`/`continue`, default `restart`; `continue` since phase 5) and browser (`run` `placed`/`shown`/`on_air`, default `shown`, `placed` being ADR-0149's background page; `on_return` `continue`/`restart`, default `continue`, `restart` reloading a running page on its on-air edge) and display, window and camera capture (`run` `placed`/`shown`/`on_air`, default `placed`, no `on_return`, linked while warm; phase 4: the capture node opens on its own thread, so `shown` and `on_air` close the session below that level and open it again on return, io-nodes spec); every other built-in type and any unknown type is `PLACED`. `source_levels(cued_items)` gives each placed, not deactivated source its level: `Placed`, `Shown` when a canvas's `preview` scene draws it with `visible` true (or a cue there), `OnAir` when a canvas's `program` scene does (with its global scene and cues). The binder raises a bound hold scene's sources and a running transition's outgoing `drawn`, `heard` and stinger to `OnAir`, and these stay Active whatever their policy. A source is temporal when its effective `run` is not `placed`. `running_sources(types)` / `running_sources_cued(types, cued)` is every source whose level reaches its effective `run` (a cued source is at least `Shown`), so by default capture sources and stills run while placed and media and browser sources run when the union of every canvas's program and preview scenes draws them with `visible` true. Opacity does not matter, including 0. A scene that is not a canvas's program or preview does not count. One visible placement is enough. A follower counts once the host has written the scene it is showing, including a followed program, into `program`. `warm_sources(canvas, types)` lists only sources whose effective `run` is `placed` and whose type is `linked_while_warm`, so a hidden temporal source is not linked, and a `run: placed` media source is Active but unlinked. With `run: on_air`, the preview compositor neither draws nor links a source that only the preview shows. A saved policy the type does not allow is reported as `BindProblem::ActivityUnsupported(source)` on every sync; the type's default is in force and the saved value is kept. `visible_sources_cued` counts a cued hidden item as drawn, including for the program mixer (ADR-0105 decision 6). `cued_drawn_sources(cued_items)` is the source ids a shown scene draws only because of that item set; an empty set returns nothing and does not walk scenes. **Linger (ADR-0152 decisions 3, 4 and 8, phase 3).** A binder built `with_clock(clock)` (the studio passes the engine clock) keeps a source Active for its effective `linger_s` after it leaves the running set: at each sync, a source that was Active by level, policy or a forced cause at the last sync and is not now starts lingering until `now + linger_s`. A linger ends when the source is in the running set again (leaving again starts a full new one), its end is reached at a sync, its `linger_s` becomes 0, or it is deactivated (Off) or deleted; an ended linger never starts again by itself. A lingering source is warm (decision 4): Active, linked to the program compositor only when its type is `linked_while_warm` (`warm_sources_with(canvas, types, lingering)`), and not in the on-air set. `linger_s` 0 and a binder without a clock add nothing. `SceneBinder::linger_end()` is the soonest end (`None` while nothing lingers), `linger_wait(now)` the time left to it and `is_lingering(source)` the state; the host arms one control-side wake for that end and updates the studio when it is due (`Studio::linger_due`, `linger_wait`). Not built yet: the rebase across a studio restart (the new studio starts with no linger). **On-air set (ADR-0107 decision 6).** Every sync reports `BindReport::on_air_sources`: the Active temporal sources at level `OnAir`: drawn with `visible` true by some canvas's program scene (counting `cued_items`) or bound hold scene, or in a running transition's outgoing set or stinger. A temporal source that is Active but not in the set is drawn only by a preview scene; a media source is then cued (ADR-0108 decision 10). **Level changes (ADR-0152 decision 7).** Every sync also reports `BindReport::level_changes`: `(source, level, on_return)` for each source whose level or effective `on_return` changed since the last successful sync, in source id order (`on_return` `None` for a type without one); a source that left every scene or was deactivated is listed once as `Unplaced`, a deleted one not at all, and nothing is listed when nothing changed. `SceneBinder::level_of(source)` is the current pair (`(Unplaced, None)` for a source the binder holds no level for). The host writes a media source's on-air state from its level (so a `run: placed` film plays on air too) and its `on_return` from the changes, and writes both when it adopts a created or replaced node, before the apply that prepares it (`MediaControl::set_on_air` and `set_on_return`, scene sources spec; `rbs_sources::media_return_edge` maps the policy).

### Graph binding (`rbs_scene::binder`)

`SceneBinder::new(types)` takes a `NodeTypes` lookup (`NodeTypeId` to `Arc<NodeDescriptor>`, from the adapter registry or plugin manifests). `sync(collection, graph)` updates a `GraphDescription` to match the collection and returns a `BindReport`.

- **Ownership.** The binder owns the nodes it creates and the links it makes (filter chains, links into each compositor's layers pin), and never touches anything else. The application attaches outputs (stream, recording, preview panels, projectors) to `compositor(canvas, role)` and may link other inputs of a compositor; those links survive every sync. If someone else removes a bound node, the next sync binds that object again from scratch (and removes filter nodes that would be orphaned).
- **Nodes.** One node per source, however many scenes and canvases place it. A source whose settings change gets a new source node of the same type and partition, so the application builds an instance for the new settings; its filter nodes stay and the chain is linked to the new node (ADR-0039). The exception is a type for which `NodeTypes::live_settings(type_id)` is true (a default trait method, false unless a type says so; `rbs-sources` answers true for `org.rbs.source.text`, ADR-0129 decision 5): its node is kept on any settings change, the box included, the stored settings are updated, and the source is listed in `BindReport::changed_sources` (`(source, node)`), never in the created, retired or replaced lists; the application sends the new settings to whatever feeds the node. A type may instead name some keys as live with `NodeTypes::live_keys(type_id)` (a default trait method returning no keys; `rbs-sources` names `loop`, `restart_when_shown`, `start_ms` and `end_ms` for `org.rbs.source.media`, ADR-0108 decision 12): when every key whose value differs (added, changed or removed) is live, the nodes are kept, the stored settings are updated, and the source is listed in `BindReport::live_changed` (`(source, picture node, changed keys)`, the keys sorted), never in the created, retired, replaced or changed lists; any other changed key replaces the source as before. `region` and `chrome` are not settings, so changing them does not replace the node. `BindReport` lists `created_sources`, `retired_sources` (also nodes someone else removed), `replaced_sources` (`(source, old, new)` on a settings change, also listed in the two lists before), `created_filters` and `retired_filters` (also removed by someone else), and `changed_filters` (`(filter, node)` for a kept filter node whose filter's settings changed; the node is never rebuilt for it, the application sends the new values through the node's parameter channel, ADR-0062): the application adopts an instance for each created node into its partition and takes retired instances back after the runtime released them. An exclusive device cannot open the new instance while the old one runs, so for replaced sources the application applies break-before-make (scene sources spec). One node per filter. One compositor node (type `org.rbs.compositor`, kind `Compositor`) per canvas and `Role`: `Program`, and `Preview` while studio mode is on. Node ids stay the same while their object exists (and, for sources, while their settings are unchanged), so the runtime carries running nodes across swaps (ADR-0020). Nodes of removed sources, filters and compositors are moved to Standby and removed with their links, including links the application attached to a removed compositor; `BindReport` lists `retired_compositors`, and a newly created compositor has `created: true`, so the application can re-attach outputs.
- **Wiring.** A source node must be kind `Source` with a video output; a filter node kind `VideoFilter` with video input and output; nodes are wired through their first video pins. The compositor's layers pin is its first many-input video pin (`BoundCompositor::layers_pin`). A source's enabled, bound filters are chained in order; the chain's last node is the source's *producer*. The program compositor's layers pin gets one link per distinct producer of `warm_sources(canvas)` (wanted sources placed on a scene the canvas may show, including hidden and off the current program scene), so `plan()` does not drop them for having no sink and the device stays open; the preview compositor still links only `visible_sources` of its scene. Drawn layers still come only from `flatten` (hidden items are omitted unless `sync_cued` is given their ids). A source faded to opacity 0 stays linked and scheduled; a hide or scene switch does not change whether a warm source is linked. While no shown layer draws it above opacity 0, its video filters are Standby and the compositor links the source node, not the filter tail. An outgoing scene's drawn sources and its stinger keep their filters for the transition. Raising opacity schedules the video filters again and links their tail; the first frames can be the unfiltered picture while those filters start. Temporal sources are omitted from `warm_sources`. The program compositor also links producers of `visible_sources` of its scene, so a temporal source that scene draws stays linked at opacity 0. A hidden temporal source is Standby and is not linked, unless its id is in the cue source set passed to `sync_cued`. Links the compositor no longer needs are removed.
- **States.** Sources in `wanted_sources()` are set Active; other sources are Standby. An enabled, bound filter is Active with its source, except a video filter while no shown layer draws that source above opacity 0 (then Standby). Disabled filters are Standby. Bound compositors are Active, and are scheduled only when an output is attached. These are wanted states; the runtime decides what runs (ADR-0020). Temporal sources use `running_sources_cued` for that Active set instead (`sync` passes an empty set). A hidden temporal source is Standby and is not linked, unless the cue source set names it. `sync_cued(collection, graph, cued_items, cued_sources)` is the same sync: `cued_items` feed flatten and `visible_sources` (mixer included); `cued_sources` is the temporal Active union. Both default to empty. The host holds the cue map (`ItemId` to a studio-clock deadline). While it is empty, nothing is armed and nothing scans items. While it is not, one wake is the soonest deadline. Opening the eye drops the cue. Show on a visible item does nothing. A hidden item with `show_for_ms` starts or restarts the deadline. The map is not saved.
- **Layers.** `BindReport::compositors[(canvas, role)]` is a `BoundCompositor`: its node, `layers_pin`, and `BoundLayer`s bottom first (the flattened layer plus its `producer` node; `scroll` and `scroll_key` as on `FlatLayer`, ADR-0150). `resolve(compositor, plan)` gives each layer the index of its link among the compositor's scheduled links on the layers pin, which is the order `rbs_graph::runtime::Inputs` presents them in. Callers pass the plan the runtime runs, `ApplyReport::plan`, which leaves out nodes whose `prepare` failed. Layers whose producer is not scheduled are left out, so the remaining indices stay correct for that plan. A layer list sent to a running compositor through a parameter channel can meet an older or newer schedule, so the index is only a hint: the node checks it against `layer.producer` with `Inputs::source` and falls back to `Inputs::find` ([ADR-0023](../adr/0023-node-parameter-channels.md)).
- **Audio** (only with `SceneBinder::with_audio(partition)`, ADR-0039; `partition` is an audio partition, never `PartitionId::RENDER`). One mixer node per canvas (type `org.rbs.audio.mixer`, kind `AudioMixer`, first many-input audio pin, an audio output) in that partition, created by the sync that first sees the canvas and kept while the canvas exists (`SceneBinder::mixer(canvas)`; `BindReport::mixers` with `created`; `retired_mixers` when the canvas is removed, with every link the application attached). A canvas without a program scene has a silent mixer. An empty collection keeps that mixer, so the audio worker is not stopped only because no source is heard. A source node with an audio output and no video output (audio-only) goes into that partition; a source with video stays in the render partition. Each mixer gets one link from each source visible in its canvas's **program** scene (`visible_sources`) that has an audio output, so a source only in a preview scene is not on air and one canvas's audio never reaches another canvas's output. An audio-only source is linked from the first audio output of its chain tail. **Picture-and-sound sources (ADR-0106).** `NodeTypes::sound_type(picture)` (default `None`) names the sound node type of a source type. With audio bound, a source of a video type that names one gets two nodes: its picture node (the type's descriptor, video output only) in the render partition and a sound node (the named type, kind `Source`, one audio output) in the audio partition, created, replaced and retired together. A named sound type that is not installed or has no audio output is `UnknownSourceType(source, sound type)`, and the source is not bound (it is never shown without its sound). The sound node takes the picture node's lifecycle state. Every mixer that hears the source (program and hold) is linked from that one sound node, so it is the strip's producer; no link crosses from render into audio and no queue reader is involved. `SceneBinder::sound_node(source)` reads it. `BindReport::picture_sound` lists every bound pair `(source, picture, sound)` in source id order on every sync. The picture node is in `created_sources`; the sound node is not (the application adopts the sound half of the same instance into it), but it is in `retired_sources` and has its own entry in `replaced_sources` (two entries per replaced source). If either node is removed by someone else, both are retired and the source is bound again. Without audio no sound node is made. A video node with an audio output whose type names no sound node is `AudioOnVideoSource` on every sync with audio and is not mixed (a camera microphone stays an ADR-0096 companion). `BoundMixer::inputs` lists the inputs in source id order. For an audio-only source the producer is the tail of its audio filter chain (the source node when no filter is enabled), in the mixer's partition, so it is the strip's producer (ADR-0037, ADR-0082). Strips stay keyed by `SourceId`; the application rebuilds them from `inputs` after every sync, because a settings change gives the source new nodes (`replaced_sources`). No audio-filter chain is bound on a picture-and-sound source (`NoVideoPins`). A quiet sound node is a silent strip; there is no new `BindProblem`. Audio sources are never layers. Audio filters (kind `AudioFilter`, one audio input and output) bind on an audio-only source like video filters on a video source: each filter node takes the source's partition, the chain links use the audio pins, and the mixer link comes from the chain tail and is rebuilt on every chain change (a tail change gives the source a new strip: a 10 to 20 ms dip, ADR-0082 decision 6). **Key links (ADR-0095).** A filter node whose descriptor has an audio input named `key` takes the id of its key source from the `Int` setting `key_source` (absent means none) and gets a link into `key` from the tail of that source's audio chain (the signal before its fader and mute), made after all chains are bound and rebuilt when the key source's tail changes. A key that is deleted, has no bound audio, is the filter's own source, or would close a loop of key links is `KeyUnavailable(filter)` and left unlinked (the node hears silence). Loops are decided before any link is made, over every key setting in filter id order: the link of the filter with the highest id in a loop is the one dropped, whatever the order of the edits. A filter whose node type is not an audio filter on an audio source is `NoAudioPins`; an audio filter type on a source with video is `NoVideoPins`. Mixer states: Active. A missing or unusable mixer type is `BindError::NoMixer`. Without `with_audio`, audio-only sources are `NoVideoOutput`, as before; the settings rebind and the new report fields apply either way.
- **Hold scene** (ADR-0124 phase 2b, [recording](recording.md)). `sync_held(collection, graph, cued_items, cued_sources, hold)` is `sync_cued` plus a map from canvas to `HoldScene { scene, sound }` (at most one per canvas; `sync_cued` passes an empty map). A canvas or scene not in the collection is skipped. For each entry the binder binds a compositor for `(canvas, Role::Hold)` that links the producers of `visible_sources` of that scene, like the preview compositor, and adds those sources to the temporal Active set, so a hold scene's media and browser sources play while it is bound and rest when it is not. With `sound`, and only with `with_audio`, it also binds a hold mixer for the canvas in the audio partition (`SceneBinder::hold_mixer(canvas)`, `BindReport::hold_mixers`), linked exactly as a program mixer is but from the hold scene's visible sources; it has no monitor output and no meters. A picture-and-sound source is heard from its one sound node there too. A sync whose map no longer asks for the compositor or the sound retires them (`retired_compositors`, `retired_mixers`). An empty map costs nothing: no node, link or Active source is added (rule 10).
- **Transition** (ADR-0128 decisions 5 and 6, [recording](recording.md#transitions-adr-0128)). `sync_transition(collection, graph, cued_items, cued_sources, hold, outgoing)` is `sync_held` plus a map from canvas to `OutgoingScene { drawn, heard }` (`#[non_exhaustive]`, built with `OutgoingScene::new`): the sources the program compositor drew and the mixer heard before the program change. For each entry whose canvas has a program scene, the binder binds a compositor for `(canvas, Role::Incoming)` that links the producers of the program scene's `visible_sources`, like the preview compositor, and is a producer of the canvas's program compositor (one more link, so the program compositor runs after it). The `drawn` sources stay linked to the program compositor and in the warm set, the `heard` sources stay linked to the mixer, and both stay Active, so the outgoing scene keeps playing until the transition ends. A canvas without a program scene binds nothing for its entry. A sync without the entry retires the incoming compositor (`retired_compositors`) and unlinks what only the outgoing scene used. `sync_held` passes an empty map, which costs nothing (rule 10). An entry built with `OutgoingScene::towards(scene)` (a T-bar, ADR-0135) makes the incoming compositor draw `scene` instead of the program scene and the mixer also hear `scene`'s `visible_sources_cued`, with `drawn` and `heard` empty, so the program scene stays bound as usual; `with_program(drawn, heard)` turns it back into a plain entry after the take. `with_stinger(source)` (ADR-0140 decision 4) names the stinger's source: while the entry exists it is in `running_sources` and `on_air_sources`, Active, linked to the canvas's program compositor (the warm set) and heard in the program mixer, and a sync without the entry unlinks it; `with_program` keeps it.
- **Problems.** A source or filter whose type is not installed, or has the wrong kind or no usable pins, is left out and reported as a `BindProblem`; the rest is bound.
- **Errors.** `BindError::NoCompositor` if the compositor type is missing or unusable; graph refusals are `BindError::Graph`. On error neither the graph nor the binder changes (sync works on copies).
- `sync` is idempotent: a second call with the same collection changes nothing.

Tests in `crates/rbs-scene/tests/binder.rs` cover a hold scene binding its own compositor and playing its media, a hold scene with sound getting its own mixer fed by the source's sound node, a missing hold scene binding nothing, audio sources feeding the mixer from program scenes only, each canvas mixing only its own program, a picture-and-sound source heard from its sound node in the audio partition (one sound node for every canvas, both nodes replaced together on a settings change, a lost sound node rebinding the source, no sound node without audio, a sound type that is not installed refusing the source, a video node with sound and no sound type not mixed), a hidden temporal source staying Standby and unlinked, the on-air set holding a media source only once a program scene draws it, nodes removed by someone else reported retired, filters on audio sources, a missing mixer type, changed settings giving a new source node and keeping its filters, created and retired reports, a mixer removed by someone else, idempotence with audio, node reuse across canvases, stable ids, hidden sources staying Active and linked (not drawn), a source at opacity 0 staying linked and scheduled, filter chains following enable and removal, links the binder did not make surviving, rebinding after external removal, created and retired compositors, the plan scheduling exactly what the program needs, `resolve` with an unscheduled producer and with a second video input, unknown types, idempotence, and random edit sequences. After each random edit the graph is checked against expectations computed from the collection, not from the binder: source and filter states, exact chain links, compositor links, and no unaccounted nodes; the same run with audio also checks partitions, mixer links and inputs, and that the created and retired reports alone track exactly the bound source nodes, including nodes someone else removes.

### Copies, resets and attribute groups (ADR-0133)

- `SceneCollection::duplicate_source(item, copies, source_fields)` copies the sources in `copies` (`SourceCopy { from, name, standby, muted }`, chosen by the host): the first is the item's source, placed directly above it with the same layout, overrides, visibility, lock and timed show; the rest must be its companions, each placed above its original's item in that scene, else above the first copy. Copies get new source and filter ids; `companion_of` points at the copied picture or is dropped; key links (`source_fields`: the filter setting keys of kind source, from the host's catalogue) that name a copied source are rewritten. A scene in Own levels gives each copy its original's entry. One undo record.
- `SceneCollection::duplicate_scene_with_copies(scene, name, copies, source_fields)` is a scene copy whose items point at the copies; its own levels are re-keyed to them. One undo record; refused for a global scene.
- `AttributeGroup` names the groups of Reset source and Paste attributes. Item groups (`Transform`, `Crop`, `Opacity`, `Style`, `Scroll` (ADR-0150; UI name "Scroll", default none)) write the item's layout on one canvas (its override when it has one). Source groups: `VideoFilters`, `AudioFilters`, `Options` (only `rbs_sources::option_keys`; the other keys are identity), `Region` (region, and Display chrome for a display), `Glide`, `RecordSeparately` (the feeds the target has). `Sound` (volume, mute, monitor) and `SyncOffset` are live: written outside the undo step and never chosen by default. `mixer_hidden`, hints, name, ids, `visible`, `locked`, `show_for_ms` and scene levels are in no group; a unit test destructures the structs so a new field must be classified.
- Reset and paste are compositions made by the application, as looks are: checked per target, applied all or nothing as one undo step, then the live writes.

### Looks (`rbs_scene::look`, ADR-0075)

A `Look` is a preset: an `id` (`builtin:<slug>` for built-in ones), a `name`, a `LookGroup` (`Color`, `Effect`, `Shape`), an optional `ItemStyle` and a list of `LookFilter { type_id, settings }`. `look::built_in()` returns the built-in looks (Warm, Cool, Vivid, Muted, Black and white, Soft contrast, Soft blur, Sharpen, Green screen, Circle, Circle with border, Rounded corners, Rounded with frame, No shape) and `look::find(id)` finds one by id.

Applying a look is a composition of ordinary edits, made by the application, not a new `SceneCollection` method: the style replaces the item's style on the edited canvas; a filter of a named type already on the source has its settings replaced and is enabled, otherwise the filter is appended; filters not named are untouched. Nothing refers to the look afterwards, so the saved collection and the control API do not change. The application validates all values first, rolls back on failure, and records one undo step. `rbs-scene` does not depend on the filter catalogue; a test in `rbs-sources` checks every built-in look against it.

## Errors and failure behaviour

`SceneError` (non-exhaustive): unknown ids, `DuplicateName`, `DuplicateId`, `CanvasTooLarge`, `FrameRateTooHigh`, `EmptyName`, `BadTypeId`, `EmptyCanvas`, `InvalidLayout`, `InvalidSetting`, `CropOnScene`, `StyleOnScene`, `ScrollOnScene` (ADR-0150), `NestingCycle`, `NestingTooDeep`, `TooManyLayers`, `DuplicateFilter`, `ScopeViolation`, `IndexOutOfRange`, `CanvasHasScenes`, `GlobalScene` (ADR-0065), `UndoConflict`, `IdsExhausted`. Edits never panic.

## Performance requirements

Control thread only, user-paced. An edit clones the collection, applies the change and validates the result, which is O(size of the collection); collections hold hundreds of objects. A field edit (the source `audio` and canvas `master` records, alone or in a batch of them, with a new value already in range) is applied in place instead, with no copy and no walk: it cannot break an invariant, a single record is refused before it writes, and a batch refused part-way performs the inverses it already has, so it is still all or nothing (audit F-09; `benches/edit.rs`: a volume edit on 300 sources went from about 105 µs to about 60 ns). Nothing here runs per frame: the graph binder recomputes layer lists only when the collection or the shown scenes change.

## Open questions

- Per-canvas visibility of an item in a shared scene (U15): the override could become `{layout, visible}`.
- How layer lists reach running compositor nodes (a control message at the swap, or node settings), and when compositor `reserve_layers` runs for a larger list.
- Descriptors are looked up once per bound node; replacing an installed node type needs a rebind policy (for example remove and re-add the affected nodes).
- Audio: per-source monitoring, mixer buses, keeping preview audio warm, audio filters.
- Transitions between program scenes and "keep warm" for preview scenes.
