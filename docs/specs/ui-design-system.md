# Spec: UI design system

- Status: Draft
- Owner crate(s): `rbs-ui` (toolkit-neutral model: panels, layout, workspaces, layout undo, tokens, live indicator), `rbs-app` (Slint desktop shell; `ui/tokens.slint` is generated from the token file at build time and its values are set at run time, `ui/components.slint` is the component library)
- Related ADRs: [0008](../adr/0008-ui-as-api-client.md), [0013](../adr/0013-zero-cost-when-unused.md), [0015](../adr/0015-ui-design-rules.md), [0016](../adr/0016-native-desktop-ui.md), [0017](../adr/0017-flexible-panels-and-workspaces.md), [0022](../adr/0022-native-ui-toolkit.md), [0049](../adr/0049-main-window-areas-panel-states-and-sizes.md), [0050](../adr/0050-command-registry-menus-and-toolbar.md)
- Rules: [UI principles](../ui/principles.md)

## Purpose

The single source of visual and interaction decisions for every RBS interface.

Binding now (once ADR-0015 is accepted): token names, the component list and contracts, the main window structure, the core flow interaction limits, and the list of non-undoable actions. Tunable: token values, which are initial and will be adjusted in Phase 2 usability testing.

## Tokens

Tokens are defined once in a data file ([`crates/rbs-ui/tokens.toml`](../../crates/rbs-ui/tokens.toml)) and generated into the native toolkit's format (ADR-0016), and exported as CSS variables only for remote clients outside the desktop app. UI code references tokens by name only (rule U6).

In the desktop shell every token is a run-time value: the build generates the `Theme` and `Tokens` globals with the built-in values as defaults (so the `.slint` files compile and preview on their own) and a function that copies a parsed token file into them (`rbs-app` `look`). Each window gets the token file in use when it opens, so a theme changes without a new build and costs nothing per frame (bindings read the globals; nothing polls). `Theme` holds one colour set per theme in `THEMES` order and `Theme.active` picks one: the OS scheme, or `Theme.choice`. The file in use is the built-in one; `RBS_TOKENS=<file>` names another complete token file as a development aid (a file that fails the checks below is not used, the built-in one is, and the error bar says why). Users pick, make and share themes as overrides of a built-in theme in Settings › Appearance ([themes spec](themes.md), [ADR-0057](../adr/0057-user-themes-and-appearance-settings.md)).

File layout (format 2; format 1 is format 2 without `[font]` and is still read, with the OS UI font): `[fixed]` holds the colours no theme may change (`color.state.live`, `color.text.on-live`, and the Windows close button's `color.caption.close-hover`, `color.caption.close-text`, ADR-0071); `[themes.dark]`, `[themes.light]` and `[themes.high-contrast]` each define exactly the theme colour names below, as opaque `#rrggbb`; `[length]` (logical pixels: the spacing, size, radius, line, menu, window and keyboard step tokens below), `[duration]` (milliseconds: `motion.fast`, `motion.normal`) `[type]` (`{ size, line, weight }` for the five text styles) and `[font]` (`font.family`, a list of family names, empty for the OS UI font) hold the rest. Every theme in the file also passes the theme rules of the [themes spec](themes.md#theme-rules) (bounds, rules across tokens, distance from the live colour). Token names are lowercase words joined by `.` or `-`. A custom theme is a complete token file; its `[fixed]` values must equal the built-in ones (`#c4262e`, `#ffffff`, `#c42b1c`, `#ffffff`), otherwise it is refused. Elevation and easing tokens are added to the file together with the components that use them. `rbs_ui::tokens` parses the file and fails on a missing, unknown or invalid token, a changed fixed colour, and any failed contrast rule:

- text: `color.text.primary` and `.secondary` on every surface, `color.text.inverse` on `color.accent`, and `color.text.primary` on `color.accent.subtle`: at least 4.5:1 (7:1 in `high-contrast`); `color.text.on-live` on `color.state.live` and `color.caption.close-text` on `color.caption.close-hover`: at least 4.5:1 in every theme, because all four are fixed;
- non-text: `color.border.focus` on `surface.base` and `.raised`, `color.border.strong`, `color.state.*` and `color.action.destructive` on `surface.raised`, `color.meter.*` on `surface.sunken`, and `color.state.live` on `surface.base`: at least 3:1;
- the theme rules of the [themes spec](themes.md#theme-rules) add the pairs the UI draws besides (error text at 4.5:1, among others); a test reads the `.slint` files and fails on a drawn pair no rule covers;
- `color.state.error`, `color.action.destructive` and `color.meter.clip` differ in hue from `color.state.live` by at least 45 degrees (rule U12).

## Components

The library is the only way to build UI (rule U6). Each component has: states (default, hover, pressed, focused, disabled, error), keyboard behaviour, accessible name and role, light/dark/high-contrast screenshots, and usage notes.

Initial set: Button (primary, secondary, ghost, danger, live: only to stop a live or recording output, in the fixed live colour), IconButton, Toggle, Checkbox, Radio, Select, Combobox, Slider (with numeric entry), NumberField (drag to change), TextField (editable, disabled, read-only for text the user copies, such as a token shown once: `copy-all()` puts its text on the clipboard, or password for a secret: what is typed is never shown and leaving the field does not confirm it; `placeholder` is shown in `text.secondary` while it is empty, saying what an empty value means, never its name), ColorPicker, Tabs, SegmentedControl, List and TreeList (drag reorder, inline rename), ContextMenu, Popover, Dialog, Toast, Tooltip, PropertyGrid (generated from a settings schema), EmptyState, StatusBadge (live, recording, warning), AudioMeter, AudioStrip (meter, fader, mute, monitor, filters), PreviewCanvas (handles, snapping, guides), SceneCard (thumbnail, name, live badge), TransitionPicker (preview thumbnail), CommandPalette, KeyboardShortcutHint (a chord as a key chip with an optional tag such as "Global"; implemented).

### Icons

One icon set, drawn by the library's `Icon` component as vector paths in a 16 x 16 view box, sized by `size.icon.box` and stroked with `size.icon.stroke`. Icons are never font glyphs: a glyph missing from the OS font shows as an empty box (seen on Windows with U+22EF and U+25BE). Set: `more`, `chevron-down`, `chevron-up`, `chevron-left`, `chevron-right`, `check`, `close`, `dot` (filled, live state; Record), `ring` (outline, not live), `plus`, `pin` (auto-hide and pin), `panel-left`, `panel-right`, `panel-bottom` (area toggles), `bolt` (Go live), `grid` (Stats), `copy` (Outputs), `window` (any other panel), `search`, `monitor`, `camera`, `mic`, `speaker`, `speaker-off`, `eye`, `eye-off`, `expand`, `lock`, `unlock`, and for the Settings sections `sliders` (General), `palette` (Appearance), `keyboard` (Shortcuts), `broadcast` (Stream), `link` (Remote control; also the mark of a source placed in more than one scene), `globe` (Global sources), and `gear` (Settings, `ui.settings.open`), and for menu commands `user` (Output profile), `folder` (Scene collection), `undo`, `redo`, `layout` (Workspace), `panel-all` (Show all areas), `panel-none` (Hide all areas), `reset` (Reset panel sizes, Reset toolbar), `refresh` (Reload theme), `image` (scenes), `arrow-left` and `arrow-right` (Previous and Next scene), `pencil` (Rename), `trash` (Remove scene, Delete source), `transition` and `menu` (the RBS menu button), and `window-minimize`, `window-maximize` and `window-restore` (the Windows window buttons, with `close`; ADR-0071). The paths live in `rbs_ui::icon::ICONS`; the library's `IconName`, `Icon` and `Icons.named` are generated from it (`rbs-app/src/icons.rs`, a test fails when the copy is stale). Registry entries and panels name their icon by these names, and every registry entry has one (a test checks every entry and every menu and context menu layout), so no menu item is blank. **Menu icons.** Menus that take images (the menu bar, context menus) get each icon drawn from its path as an image in a neutral grey (`#8e8e93`) that reads on light and dark menus alike, because native menus follow the OS appearance, not the app theme: 36 px square (macOS shows 18 points), 16 px on Windows (which draws menu bitmaps at 16 x 16). A checked item shows its checkmark in the icon's place and no icon; macOS and Windows native menus show no icon on checkable items at all. Choices in a submenu show checkmarks only. An icon is decorative (no accessible role): the control that shows it carries the name, and state is never shown by the icon alone (U7).

- `Button` takes an optional trailing `icon`; its ink follows the button's text colour, including disabled.
- `NumberField` takes a `label` (its accessible name; role spinbox with the value, increment and decrement actions), a `value`, a `step` and an `edited(float)` callback. Return or leaving the field commits text that differs from what it showed; the field then shows `value` again, so a refused edit never stays in it. Text that is not a number goes back to `value`. Up and Down step from what is typed (Shift: ten steps) and commit at once. A stepper column at the right edge (a divider, then `chevron-up` over `chevron-down`, `text.secondary` on the field, `surface.overlay` under the pointer) shows that the field steps: a press steps once as Up or Down does, holding it keeps stepping after 400 ms (every 80 ms); the buttons never take the focus, so a value being typed stays in the field. `typed(string)` reports each change of the typed text before it is confirmed, for a form whose Save button must see it (the theme editor). States: normal, focused (focus border), disabled (no background, disabled text, no stepping). It shows whole numbers. Drag to change is not there yet.
- `ColorPicker` is a swatch button (`label` is its accessible name, `value` the colour it shows) that opens a popover: a saturation and brightness area at the chosen hue, a hue bar, eight named preset colours (White, Black, Red, Orange, Yellow, Green, Blue, Purple) and the chosen colour as a swatch with its `#rrggbb` text. It reports a choice through `picked(string)` as `#rrggbb`, or `#rrggbbaa` when `value` is not opaque (the transparency is kept), and the choice stands only once the owner sets `value`. A drag on the area or the bar shows the colour in the popover and reports it on release, so one drag is one change; a preset, or an arrow key on the area (saturation left and right, brightness up and down, Shift: ten steps) or on the bar (hue, 1 degree, Shift: 10), reports at once. Return or Space opens it; Escape or a click outside closes it. `open` is true while the popover shows, so the owner can count it as an overlay (the preview layer hides while it is open). The area and the bar are sliders with their values in words; each preset is a button named after its colour. The preset and wheel colours are content colours, not theme tokens.
- `Toggle` is an on/off switch for a setting that applies at once: a track two knobs wide, filled with `color.accent` and the knob at the right when on, `color.surface.sunken` with a `border.strong` outline and the knob at the left when off; the knob's side shows the state as well as the fill (U7). `label` is the accessible name (role switch) when the row shows the name itself; `text` shows a label beside it. Click, Space or Return toggles it and reports `toggled(bool)`; the owner sets `checked`. States: off, on, hover (accent outline, hover fill when on), focused (focus ring), disabled (subtle outline, disabled knob, no input). The knob moves in `motion.fast`.
- `Select` is drawn as a field (mockup E's drop-downs): `color.surface.sunken` with a `border.subtle` outline (`border.strong` on hover and while open), the chosen option left-aligned and elided, and a `chevron-down` at the right; role combobox with "<label>: <option>" as its name and its expanded state. Click, Return, Space or Down opens the list. With no option chosen it shows its `placeholder` (such as "Choose a kind") in `text.secondary`, which is also the accessible value.
- `SegmentedControl` is a sunken track (`color.surface.sunken`, `border.subtle`, `radius.md`) with the options side by side; the chosen one is raised (`color.surface.overlay` with a `border.strong` outline), bold and checked for screen readers, the others in `color.text.secondary`. Each option is a button reached by Tab.
- `IconButton` is the icon-only button (ghost, dense, square). Its `name` must be set and becomes the accessible name (Slint cannot enforce required properties; an accessibility-tree check is a follow-up).

### AudioMeter

The meter of rule U16, used alone and inside AudioStrip. Logic in `rbs_ui::meter` (toolkit-neutral, tested without a window).

- **Scale:** dBFS from -60 (floor; lower levels show an empty bar) to 0, linear in dB. Labelled marks at 0, -6, -12, -18, -24, -36 and -48 dBFS, drawn as static text and ticks.
- **Zones:** the lit bar is `color.meter.low` below -18 dBFS, `color.meter.mid` from -18 to -6 and `color.meter.high` above -6. The zone marks are on the labelled scale, so a zone is never shown by colour alone (U7).
- **Peak hold:** a 2 px line at the highest level of the last 1.5 s, then falling at 20 dB/s; never below the bar. It takes the colour of its zone.
- **Clip indicator:** a box at the end of the bar, outlined while not clipped and filled with `color.meter.clip` once a level reaches 0 dBFS. It stays lit until the operator resets it (click, or the strip's reset command); filled versus outlined is the non-colour cue.
- **Orientation:** vertical (grows upward) or horizontal (grows rightward).
- **Rates:** levels update at 30 Hz while the meter is visible and its audio is active, not at all otherwise (P13, `UpdateRate` of the panel).
- **Accessibility:** one element per meter with role progress indicator, the channel's name as its label and as its value the highest level since the last update in whole dBFS, updated at most once per second (screen readers do not need 30 updates per second). The level is rounded down, so it never reads higher than it was, and capped at +24 dBFS. Text: one Fluent message `meter-value` with variables `$db` (whole dBFS; absent below -60 dBFS) and `$clipped` (`yes` or `no`) and selectors on both, so each language orders the parts itself (English: "-12 dBFS", "silent", "-12 dBFS, clipped"). Messages are never concatenated. `rbs_ui::meter::Meter::take_report` gives the value, `AccessibleLevel::english` the English text until Fluent strings exist.
- **Rendering:** the toolkit draws the static parts (bar background, scale, labels, the clip indicator's outline) and owns the accessible element. The moving parts (lit zones, peak line, filled clip indicator) are drawn by a native compositor layer where one exists (macOS: `rbs_app::native::MeterBridgeLayer`, [ADR-0035](../adr/0035-meters-as-native-layers.md)), so meter updates do not make the toolkit redraw the window; elsewhere the toolkit draws them too. Both paths take their geometry from `rbs_ui::meter::MeterView::frames` and their colours from the theme's tokens. Toolkit content drawn over a meter bridge (menus, popovers, dialogs) hides the layer while it overlaps, as for the preview layer.

## Main window structure

The main window is a frame around a centre and three areas ([ADR-0049](../adr/0049-main-window-areas-panel-states-and-sizes.md)). The picture shows the built-in Edit workspace.

```
+--------------------------------------------------------------------------------+
| Menu bar: File Edit View Scene Source Output Tools Window Help                 | (macOS: system menu bar)
+--------------------------------------------------------------------------------+
| Toolbar (per workspace, customisable): mode | + Scene  Add source | Studio mode |
|   Transition | screenshot marker replay ~ search [L][B][R] Go live Record [live indicator] |
+--+------------+--------------------------------------------+---------------+--+
|e | Left area  |  Centre                                    | Right area    |e |
|d | Scenes     |  Preview (studio mode: Preview | Transition | Inspector     |d |
|g |------------|  rail | Program)                           |---------------|g |
|e | Sources    |                                            | Filters (coll.)|e |
|  |            |                                            |               |  |
|t +------------+--------------------------------------------+---------------+t |
|a | Bottom area: Mixer (collapsed: one-line meter strip)                    |a |
|bs|                                                                         |bs|
+--+-------------------------------------------------------------------------+--+
| Status bar: live/rec state + time, bitrate, dropped frames, CPU, GPU           |
+--------------------------------------------------------------------------------+
```

- **Frame.** Toolbar row, content, status bar. The menu bar exists only on macOS, in the system menu bar; Windows and Linux use the RBS menu (ADR-0069). On Windows the toolbar row is also the title bar (ADR-0071): the OS caption is removed and the row ends with the window buttons; macOS and Linux keep the OS title bar. The live indicator (U4, U21) is at the right end of the toolbar row's end group on every platform, before the window buttons on Windows. The toolbar can be hidden (View › Toolbar): its items go and its row stays as a slim strip that holds the live indicator, so the indicator never moves and never shares a row with the menu bar (a native Windows menu bar and Slint's drawn Linux menu bar cannot hold other elements). The menu bar cannot be hidden.
- **Areas.** `left`, `right` and `bottom` hold panels around the `centre`. Each has a size in logical pixels (width, or height for `bottom`) and can be hidden and shown with its toolbar toggle or the View menu (no shortcut is bound by default, U21); hiding keeps its panels and size. Hide side panels (`ui.area.hide_all`) hides all three and Show side panels (`ui.area.show_all`) shows them again. An area that is visible but empty takes no space. The bottom area spans the full width under the other three. The centre always exists and takes the remaining space; with every area hidden and an empty centre it shows an empty state with Show areas and Reset layout (U10).
- **Edge tabs.** Auto-hidden panels show as tabs on the left, right or bottom window edge (outside the areas, inside the frame); there are no top edge tabs, so nothing sits between the toolbar and the content. An edge with no auto-hidden panel takes no space. Edge tabs stay visible when their area is hidden. Floating windows have no areas: their stacks can collapse but not auto-hide.
- **Look** (implemented, matching the owner's chosen mockup E): the content sits on `surface.base`. Each tab stack is a card: `surface.raised`, `radius.md`, a `border.subtle` line, with gaps of the layout's divider thickness (6 px) between cards and around them; a divider is invisible until hovered, dragged or focused, then drawn in `accent`. A card's header is `size.control.lg` high: its tabs as text, the shown one underlined in `accent` (2 px, no tab background), and on the right Auto-hide (`pin`), Collapse or Expand (`chevron-down` / `chevron-right`, reporting expanded or collapsed) and the panel menu (`more`); a right click on a tab opens that menu too. The centre's last expanded stack shows no Collapse and a centre of one stack no Auto-hide. Edge tabs are cards `size.control.md` wide with the panel's icon and its title turned along the edge; clicking one (or Enter or Space) slides its panel out over the dock area along that edge, `size` wide, as a card with Pin and Hide; Escape, Hide or the tab again slide it back, and pinning, closing or adding an auto-hidden panel slides it back too. The slid-out panel is reported to the preview layer like a toast (ADR-0054). Not yet: hover to open with its delay and grace period, and sliding animation. **Dragging a tab** (ADR-0049 decision 5, inside one window, not while the layout is locked) moves its panel: over a stack, its title row or middle drops the panel in as a tab, and the outer 30 % on each side puts it in a new stack on that side, sharing the stack's place half and half (one layout undo step); within 16 px of the dock area's edge it goes to that edge of the window (in the main window, that area's outer side). `rbs-ui` (`frame::drop_target`) decides the target; the shell shades the part the drop would fill in `accent.subtle` with an `accent` border, reported to the preview layer like a toast. Dropping a panel where nothing would change shows no guide. Tearing off to a new window and dropping into another window stay with the panel menu's Float and Dock for now. The toolbar row is `size.control.md` plus `space.1` above and below on `surface.base`: the Workspace picker as a bordered button reading "Workspace <name>", commands as ghost buttons with their icon before the title, area toggles as their icon alone (tinted `accent.subtle` while on, the title as accessible name), Go live as the one primary button and Record as a secondary button with a `dot` in the live colour. The status bar is `size.control.sm` plus two borders high on `surface.sunken`: live and recording state with duration in words, the stream's connection text, then on the right Output profile and Scene collection (each opens its menu, with New, Duplicate, Rename, Delete, Import and Export) and the canvas size and frame rate. It shows values the app already has and polls nothing (P13); bitrate, dropped frames, CPU and GPU come when a cheap source for them exists. Properties groups its fields under section captions (`type.caption`, uppercase, `text.secondary`): a header row with the source's icon, name and type, then Position and size, Crop and Shape and border; the number fields carry their label inside on the left in `text.secondary` (X, Y, W, H, Left, Right, Top, Bottom) with the value right-aligned. Mixer rows are `size.control.md` high: the kind's icon and the name, then a meter `space.3` thick. Text fields draw the caret 2 px wide in the selection colour (`accent`, selected text in `text.inverse`) so it shows on `surface.sunken` in every theme.
- **Commands.** Every command is in the menu bar; the toolbar only holds a chosen subset (see Commands, menus and the toolbar).

## Studio panels (first version, ADR-0041)

The app runs the studio in its own process on a control thread (`rbs_app::studio_host`, ADR-0041 decision 7). The UI sends commands and receives updates; it never calls the studio. The studio runs one canvas from the scene collection; the Sources panel shows the scene being edited: the program scene, or the preview scene in studio mode (ADR-0061), while the Mixer always plays the program scene's sources.

- **Program and Preview.** Outside studio mode both panels show the scene on air: the picture goes to Program when that panel is open, otherwise to Preview, and the other panel says where the picture is. In studio mode (ADR-0061) Program shows the program scene and Preview the preview scene, each on its own picture (the studio's `scene_preview`); editing on the picture (below) and the selection marks belong to Preview only, so the scene on air is never edited by a stray drag. On Windows a window has a single DirectComposition target, so the preview scene's picture is macOS only for now: on Windows the Preview panel says the platform cannot show it yet (follow-up: one target shared by both pictures). The picture is the studio's preview surfaces (1280 x 720, a ring of 3) shown as a native layer over the panel's content: a Core Animation layer on macOS (ADR-0034) and a DirectComposition visual on Windows (ADR-0036). It is letterboxed, and a new frame changes only the layer. The picture never disappears behind something drawn inside the window (ADR-0054): every open Slint `PopupWindow` (read from Slint with the place Slint gave it, so a new popup needs no code of its own), the bottom toast and the error bar (they report their rectangles in `Shell.bottom-toast` and `Shell.top-toast`) are passed to the layer as covers before every redraw of the main window. A cover beside the picture changes nothing; one over it is cut out: on macOS the picture is shown as tiles around it (rectangular clips sharing the surface), and selection marks are drawn around it on both platforms. On Windows, until the hardware check of ADR-0054 decision 5, the picture hides while a cover overlaps it. The layer is also hidden while the panel is not in the main window. A panel that cannot show the picture says why in words: the studio is starting, the platform has no preview yet (Linux), the session cannot show the layer (for example remote desktop), the picture is in the main window, or the studio stopped. Accessible role: image, named after the panel. **Editing on the picture (ADR-0048):** a press on a source selects the topmost one under the pointer (outside every source clears the selection) and dragging moves it; the selected source shows a 1 px `color.accent` outline and eight 8 px handles (`color.accent` border, `surface.raised` inside; outline only when the box is smaller than three handles on screen). Corner handles resize keeping the aspect ratio, Shift (held at the press) resizes freely; edge handles change one side; a drag never makes a box smaller than 8 canvas pixels or turns it inside out. Moved edges and the box's centre snap to the canvas's edges and centre within 8 logical pixels unless Ctrl (Cmd on macOS) is held at the press. Alt (Option on macOS) held at the press on a handle crops instead of resizing (ADR-0058), once the source has shown a picture: each moved edge cuts or uncuts source pixels at the box's scale, corners move both of their edges, the crop never goes past the picture's edge and leaves at least one pixel, and all crops of one drag are one undo step ("Undo cropping …"); crops go to the studio with the same one-at-a-time numbering as boxes. With the panel focused, arrow keys move the selected source by 1 canvas pixel (Shift: 10) and Escape clears the selection. The marks move with the pointer at once; the studio gets at most one new box at a time (the newest per source waits, each box is numbered and the studio answers every one, even an unchanged or refused box), so the picture follows within a round trip and a refused box puts the marks back where the studio has the source. With a preview layer the layer draws the marks (they show over the live picture); where no layer shows the picture the toolkit draws them over the panel.
- **Sources.** The panel lists the scene's sources, top first, one row each (`size.control.md` high, `space.1` apart): the kind's icon (`monitor`, `window`, `camera`, `mic`, `speaker`), the name, and on the right the Show or Hide button (`eye` / `eye-off`, "Hide <name>" / "Show <name>", reporting checked while hidden). A hidden source stays in the scene but is not drawn; its icon and name use `text.disabled` and the accessible label adds "hidden"; showing or hiding is one undo step ("Undo showing or hiding …"). The type ("Screen capture", "Window capture", "Camera", "Audio input", "System audio", "Application audio") and the state in words ("Running"; "Not shown, closed" for a video source with no picture or recording to feed, which is not opened (P13); or "Not running: <reason>") are in the accessible label; a row whose source is not running shows "<type> · <reason>" in `state.error` under the name. The list order is the drawing order: a source is drawn over every source below it. While the pointer is over a row it shows "Move <name> up" and "Move <name> down" (video sources only, IconButtons with `chevron-up` and `chevron-down`) and "Delete source <name>" (`close`); on a focused row Alt+Up, Alt+Down and Delete (or Backspace) do the same. A move goes over or under the next source with a picture, skipping sound-only sources, which draw nothing; the button is disabled when there is none that way. A row of a video source can also be dragged onto another row of a video source: it takes that row's place (one undo step, "Undo the layer change of …"), and an `accent` line along the row it would go to shows where. Clicking a row, or Return or Space on a focused row, selects it: `accent.subtle` background and a 1 px `accent` border (not colour alone: the accessible selected state too). One selection is shared by every window; the source an Add source adds is selected, and a deleted one is no longer. Add source is the `plus` button in the Sources card's title row (the panel's own action, before Auto-hide); the empty state offers Add source too. Undo and Redo are not in the panel: they are app-wide, in the Edit menu and on the keys.
- **Add source (core flow, 3 interactions).** Add source, then a type (only types this system's adapters provide), then what it captures (the OS's displays, windows, cameras or endpoints, with the default marked). The source is added on top: a screen or window is as large as fits on the canvas with its own aspect ratio, centred (a 21:9 display gets bars above and below on a 16:9 canvas), at the canvas rate; a camera asks for 1280 x 720 at 30 fps and sits 4/15 of the canvas wide in the bottom-right corner; audio is placed in the scene only so that it plays. A name the collection already uses gets " 2", " 3" and so on. The picker has no live preview yet; the new source is selected, with handles on the picture.
- **Properties.** Shows the selected source: its name and, for a video source, X and Y (the box's top-left corner) and Width and Height, as NumberFields in canvas pixels, with a hint saying so. A value applies when confirmed with Return or by leaving the field; Up and Down arrows change it by 1 (Shift: 10) at once. Text that is not a number goes back to the current value; a size of 0 is refused with an error. The fields change the layout the canvas shows: the item's own layout for this canvas if it has one, else its default layout. Rotation stays as it is and gets a field later. A refused change is said in plain words in the error bar. A sound-only source says it has no place on the canvas. Under the box fields, **Shape and border** (ADR-0053): Shape (a SegmentedControl: Rectangle, Circle, Ellipse; Circle is the largest circle centred in the box, Ellipse fills it, each explained in a hint), Corner radius (a NumberField in canvas pixels, Rectangle only; 0 keeps square corners), Border (a Checkbox; on: Width, a NumberField above 0, default 4, and Colour, a ColorPicker swatch beside a TextField taking `#rrggbb` or `#rrggbbaa`; text that is not a colour goes back to the colour that stands, and the field always shows the colour that stands, also after Undo and Redo). The border is drawn inside the shape's edge, so the box, the handles and hit testing stay those of the box (a click in the corner of a circle still selects it). Each confirmed change is one undo step ("Undo the shape or border of …", "Undo cropping …"). The style belongs to the layout the canvas shows, like the box. Between the box fields and Shape and border, **Crop** (ADR-0058): Left, Right, Top and Bottom as NumberFields in source pixels (negative values become 0), and under them **Show** buttons: Canvas size (the centre of the picture as large as the canvas, or the whole picture where it is smaller, fitted to the canvas, so a 1920x1080 part of a 3440x1440 display fills a 1920x1080 canvas 1:1), Whole picture (removes the crop and fits the picture to the canvas, as a new source is placed), Left half and Right half (fitted to the canvas). A change in the crop fields keeps the scale: the box changes so a source pixel keeps its size and the part that stays does not move. A hint gives the picture's size in pixels; until the source has shown a picture once, the fields and buttons are disabled and the hint says so. A crop that leaves no picture is refused in the error bar. Each change is one undo step ("Undo cropping …"). Nothing selected: an empty state that points to the Sources panel. The same box can be moved, resized and cropped with handles on the picture (Program and Preview).
- **Remove from scene and Delete source** (ADR-0065). The Sources panel's delete button (accessible name "Remove <name> from this scene") and the Delete and Backspace keys remove the item from the edited scene only; when it was the source's last placement anywhere (global sources included), the source is deleted in the same undo step. Properties has **Delete source** (a danger ghost Button under the header), which removes the source from every scene and the global sources; with more than one placement it first asks in a callout, "<name> is in N scenes. Delete it from all of them?", with Delete source (danger) and Cancel. A source placed more than once has a `link` mark on its Sources row with "Also in <scene names>" as tooltip and accessible description. When the Sources panel gets a row menu (U3) it repeats Remove from scene, Delete source and Show in every scene; until then the row's remove button, the Delete key and Properties carry them. "is in N scenes" uses the localisation layer's plural forms (U8), and a global placement reads "every scene" ("<name> is in every scene and 2 more."). A toast ("<name> removed from this scene." or "<name> deleted.") with Undo shows for the toast time; Undo puts it back (it undoes the delete only while it is the newest edit; any other edit or undo, also from a control API client, hides the toast). The focus moves to the Sources panel, so Ctrl+Z (Cmd+Z) right after a delete works too; the same after Move up or Move down, since the list is made again.
- **Properties tabs (ADR-0062, mockup E).** Under the header row (the source's icon, name and type), a `SegmentedControl` ("Properties of <name>") with **Transform**, **Filters** and **Audio**. Transform holds Position and size, Crop and Shape and border (the name stays a TextField in the header for every source, ADR-0059); Filters the filter chain; Audio the Sound section and the sync offset. A source without a picture has no Transform or Filters tab and one without sound no Audio tab; when only one tab is left, the control is not shown. The tab picked last is kept per window while the app runs and applies to whichever source is selected (a source without that tab shows its first tab). Filters and the sync offset belong to the source: an edit changes it in every scene that places it, also while studio mode shows a preview scene, so the Filters and Audio tabs show the on-air mark (as the program's edits do, U4) whenever the source can be reached from the program scene. **Filters tab:** one row per filter in chain order: an enable Checkbox with the filter's name as its text ("Turn <filter> on or off"), then Move up, Move down and Remove as `IconButton`s (`chevron-up`, `chevron-down`, `close`; disabled at the ends), the selected row tinted `accent.subtle`; under the list, Add filter (a `Select`-styled menu button listing the catalogue by name; the new filter is selected), and under that the selected filter's fields generated from its schema: a number as a `Slider` with its value and unit beside it, a colour as the `ColorPicker` swatch beside a `TextField` (`#rrggbb` or `#rrggbbaa`), and Reset to defaults. A slider drag shows its effect live on the preview and becomes one undo step when released ("Undo changing <filter> of <source>"); a cancelled drag (Escape, or focus lost before release) puts the model's values back on the picture and makes no step; typed values, Reset to defaults, adding, removing, moving and turning a filter on or off are one step each. Two filters of the same type in one chain are named with a number from the second on ("Blur", "Blur 2") in rows, accessible names and undo labels. Empty chain: an empty state "No filters" with "Add filter to change colours, key out a green screen, blur or sharpen this source." A filter whose type this build lacks is listed with "Not available in this version" in `text.secondary` and can only be removed. **Audio tab:** Sound (volume Slider, value in words, Mute) and **Sync offset**: a NumberField in milliseconds, `-200` to `200`, "Delays this source's sound (positive) or plays it earlier (negative) to match the picture."; a live control like volume, not an undo step (a stated exception to U4, ADR-0062 decision 10), saved with the collection; the hint adds that advancing is limited by the audio latency.
- **Undo and Redo of scene edits (U4).** Adding a source, deleting one, moving it a layer up or down and placing its box (picture panel or Properties) are undoable, in one history shared with control API clients (`edit.undo`, `edit.redo`). One user action is one step: all the boxes of one drag on the picture panel are one step, so Undo puts the source back where the drag started; each arrow-key nudge and each confirmed Properties value is a step of its own. A new edit clears what is left to redo. At least 100 steps are kept; a canvas change clears the history (old boxes would come back at the old size). Undo and Redo are in the Edit menu (disabled when there is nothing to apply, ADR-0050). In the main window and every floating window, Ctrl+Z (Cmd+Z) undoes and Ctrl+Shift+Z (Cmd+Shift+Z) or Ctrl+Y redoes, from any control that does not take the keys itself (text fields keep their own undo); a click where no control takes the focus gives it to the window, so the keys work there too. With nothing to apply a key does nothing. This history is separate from the layout history (U21: "Undo layout change" in the workspace menu).
- **Scenes (ADR-0059).** One row per scene the canvas may show, in creation order (`size.control.md` high, `space.1` apart): its number in `text.secondary` and the name. The scene the canvas shows is marked like a selected row (`accent.subtle` with an `accent` border; the accessible label adds "shown"). Only while something goes out does it take the live colour: a `state.live` border and a badge in `state.live` with `text.on.live` reading "Live" (streaming), "REC" (recording) or "Live · REC" (both), and the accessible label says "on air" or "shown and recording" (U12). The row's Rename and Remove buttons keep their place whether shown or not, so nothing moves under the pointer. A click, Return or Space puts the scene on air at once (a cut); this is a live action, not an undo step. The `+` in the card's title row adds an empty shared scene named "Scene", "Scene 2", ... and puts nothing on air. On hover or focus a row shows Rename (`more`; double click and F2 too: an inline TextField, Return applies) and Remove (`close`; Delete or Backspace too), each one undo step ("Undo adding / removing / renaming the scene …"). Remove is not offered for the last scene. Removing the scene on air first puts the scene before it (else the one after it) on air; Undo brings the scene back but not on air. Undo and Redo never change the scene on air.
- **Lock (ADR-0059).** Each Sources row has a Lock button after Show or Hide (`lock` / `unlock`, "Lock <name>" / "Unlock <name>", reporting checked while locked). A locked item cannot be selected, moved, resized or cropped on the picture: it gets no handles and clicks go to the item under it. Properties, layer order, Undo and the control API still change it. Locking is one undo step ("Undo locking or unlocking …").
- **Existing source.** The Add source menu ends with "Existing source", which lists every source of the collection and places the chosen one in the scene on air again (one source, one volume, on several scenes; one undo step). Global sources are not listed: they are already in every scene (ADR-0065).
- **Name and Sound in Properties (ADR-0059).** The header's name is a TextField: Return or leaving it renames the source (one undo step; an empty or taken name is refused in the error bar and the field goes back). A source with sound gets a **Sound** section: a Slider for the volume (the fader law: linear in dB from −60 dB at its left end, which is silence, to 0 dB at the right; `rbs_ui::fader`), the volume in words beside it ("0 dB", "−6.0 dB", "Silent"), and a Mute Checkbox. While dragging, at most one change per frame reaches the studio, which sends it to the mixer without rebuilding anything (`Studio::set_mix`); the mixer ramps over 10 ms, so it never clicks. Volume and mute are live controls, not undo steps (undoing a layout change never unmutes a microphone), and are saved with the collection.
- **Mixer.** One horizontal AudioMeter per playing audio source, in list order, with the labelled scale under the bars and a clip box that resets on click or activation. Meters update at 30 Hz only while the Mixer is the active tab of a shown stack and has meters; otherwise the timer is stopped (U5, U21). Each row ends with a Mute button (`speaker` / `speaker-off`, "Mute <name>" / "Unmute <name>", reporting checked while muted); a muted row's icon is `speaker-off` in `text.disabled`, so mute is said by icon and state, never by colour alone (U7). The volume is in Properties for now; a fader in the row and monitoring (U16) come with the strip controls. Windows and Linux draw the meters in Slint; the macOS meter bridge is not used by the panel yet.
- **Live controls (Record, Go live).** Two buttons: Record (Stop recording while a recording runs) and Go live (End stream while a stream runs), each in the fixed live colour while its output runs (U12). The text under them says the state in words: starting, "Recording to <file>", stopping, the last outcome ("Saved <path>", with dropped frames if any) or why recording is not possible (no video encoder on this system, the studio stopped); for the stream: "Connecting to <server>…", "Live on <server>", "Not connected to <server>, trying again (attempt n)", "Ending the stream…", the last outcome ("The stream ended after <duration>", with dropped frames, or why it stopped) or why it cannot start (no server or stream key yet, with a "Stream settings" button). Until several outputs run per canvas, one output runs at a time: Go live is disabled with "Stop the recording to go live." while recording, and Record with "End the stream to record." while live. Stopping a recording needs no confirmation while nothing is live (U4: confirmations are for actions while live). End stream always asks first, in place under the button ("End the stream? Viewers see it end." with "Yes, end the stream" in the live colour and Keep streaming; End stream itself is disabled while it asks); it cannot be undone. The confirmation box is a group named "End the stream?" and Keep streaming has the focus. While recording, the live indicator shows "Recording", the duration (1 Hz timer only while recording or live) and the file name as the output; while live, "Live", the time since going live and the server's host name, followed by "not connected" while the connection is down. Closing the app stops the recording and closes the file first. While a stream runs, quitting RBS asks first in the window frame ("End the stream and quit?" with End stream and quit in the live colour, and Keep streaming, which has the focus); the main window is shown and stays open until it is answered. Quitting is Cmd+Q, Dock > Quit or logout on macOS, Quit RBS in the tray menu on Windows, and closing the main window while "When I close the main window" is Quit RBS; with Keep RBS running, closing the main window hides it and asks nothing ([ADR-0056](../adr/0056-keep-running-after-the-main-window-closes.md)). The Outputs line says "live now" only while the stream reaches the server ("connecting" before); the live indicator shows Live from Go live on, with "not connected" until then. A stream started or ended by a control API client (`stream.start`, `stream.stop`) shows here exactly as if these buttons were used; ending it that way does not ask, since the client asked.
- **Outputs.** One line per output saying what it will do: for the recording, the format, encoder, bitrates and folder ("MKV · best encoder · video 12000 kbit/s · audio 160 kbit/s · C:\Users\me\Videos") (the video part names the rate control: "video 12000 kbit/s padded", "video VBR 12000 kbit/s, up to 18000", "video quality 23"); for the stream, the protocol, server, encoder and bitrates ("RTMP · rtmp://live.example.com/app · best encoder · video 6000 kbit/s · audio 160 kbit/s", or "No server yet"), with "live now" in its title while it runs; and a "Recording settings" and a "Stream settings" button that open the Settings window there. Settings are not edited in the panel (U17): a docked panel is often too small for a form.
- **Output profile and Scene collection menus (ADR-0051).** Switching is in the File menu (Output profile and Scene collection pickers; decided 2026-11-06: not in the default toolbar). The status bar shows the ones in use as two pickers, "Output profile <name>" and "Scene collection <name>"; each opens a menu upwards with the entries by name (the one in use checked; picking another switches to it), "Delete <name>…", a name field, and New, Duplicate and Rename, which take the name typed. New makes an entry with defaults (a new scene collection gets one canvas the size of the one in use and one scene); Duplicate copies the one in use as last saved; both then switch to it. Rename renames the one in use. Delete deletes the one in use, after asking in place ("Delete <name>?" with Delete and Keep; it cannot be undone in the app, though the file is kept in `deleted/`): another entry is switched to first, so the only entry cannot be deleted. Switching output profiles loads the profile's Recording and Stream settings and its stream key (each profile has its own; a new or duplicated profile starts without one, and deleting a profile removes its key). Switching scene collections restarts the studio with the collection's first canvas (the picture stops for a moment; the menu's entries are disabled until it runs). Switching either is refused while recording or streaming, with "Stop the recording before …" or "End the stream before …" in the error line; so are actions that would switch (New, Duplicate, Delete of the one in use). A name already used (ignoring case), an empty one or one longer than 64 characters is refused with the reason. In a second RBS that opened the user data read-only, actions that change the libraries are refused and say why. Import… opens the system file dialog for a `.toml` file and adds the entry (a newer format or another kind is refused with the reason; a name in use gets a number, "Default 2"); Export <name>… saves the entry in use, as last saved, to a file the user picks (`<name>.toml`). An exported output profile leaves out what belongs to this computer: the recording folder (the importing computer uses its default) and "a stream key is saved"; the key itself is never in a file. Where RBS has no file dialog yet (Linux today), both say so and point to the `profiles` and `scenes` folders.
- **Settings window layout (U17).** One window, first sized `size.settings.w` x `size.settings.h`. On the left, on `color.surface.raised` with a divider, the title "Settings" with a collapse button (`IconButton`, `chevron-left`; "Collapse the section list") and the flat list of sections in three groups, each under a small upper-case group name: App (General, Appearance, Shortcuts), Output (Video, Global sources, Recording, Stream), Control (Remote control). Each entry has its icon (`sliders`, `palette`, `keyboard`, `monitor`, `globe`, `dot`, `broadcast`, `link`) and name; the section shown has the accent-subtle row with an accent bar at its left edge and the label weight, and is selected for screen readers (never colour alone, U7); Tab focuses entries, Return or Space opens one, a click opens one without a focus ring. Collapsed, the list is a rail of icons (`size.control.lg` plus padding wide): the groups are divider lines, each entry shows only its icon and keeps its name as the accessible name, and the button (`chevron-right`, "Expand the section list") brings the names back; the choice holds while the app runs. On the right, on `color.surface.base`, the page scrolls: a header with the section's name (`type.heading`) and one line on what it is for, then notices and cards. A **notice** (`SettingsNotice`) is a line across the page with an accent bar on `color.accent.subtle` ("Changes apply to the next recording.", "A change restarts the studio…"), or with an error border and error text for a setting that could not be used. A **card** (`SettingsCard`) groups related settings: `color.surface.raised`, `radius.lg`, `border.subtle`, a small upper-case title in `color.text.secondary` (as section titles in mockup E) and an optional one-line description. Inside, **rows** (`SettingRow`) are separated by divider lines: the setting's name (`type.label`) and a one-line explanation (`type.caption`, secondary) on the left, and the control on the right, in a column `size.menu.md` wide for fields and drop-downs (wider for paths and URLs) or at its own width for toggles, segmented controls and buttons. A setting whose content needs the card's width (key pin, token list, a row of buttons, a question asked in place) is a **block** (`SettingBlock`): name and explanation on top, content under them. A **status line** (`SettingsStatus`) says how something runs, with a dot in `color.state.healthy`, `color.state.error` or `color.text.secondary` before the words, which carry the state. Questions asked in place and a token shown once are a **callout** (`SettingsCallout`): `color.surface.overlay` with `border.strong`. - **Settings window, General section (U17, ADR-0056).** The first section. "When I close the main window": a SegmentedControl with "Quit RBS" and "Keep RBS running" (level `simple`), with a hint that says where RBS stays and how to quit, and the platform's default (macOS: Keep RBS running; Windows: Quit RBS). Without a window the live state stays visible: macOS Dock badge "LIVE" (a stream runs) or "REC" (only a recording runs); Windows tray icon variants that differ in shape (plain, recording dot, broadcast glyph) and a tooltip in words ("RBS: live on <host>, 00:12:03"). - **Settings window, Shortcuts section (U17, ADR-0060).** The third section, after Appearance: every command of the registry by menu group with its shortcuts, a search, Add (a recorder: press the keys or pick them, app or global scope, checked at once with Replace for a chord in use), remove, Reset and Reset all. Specified in the [shortcuts spec](shortcuts.md#settings--shortcuts-rbs-app). Screenshots: `/mnt/project-files/shortcuts/` during review.
- **Settings window, Video section (U17).** The canvas the studio runs. - **Settings window, Global sources section (U17, ADR-0065).** In the Output group after Video, icon `globe`, section id `global_sources`. - **Settings window, Recording section (U17).** The search field of U17 comes when there are more sections. Two cards: Files and Encoding (the Stream section shares the Encoding card). Recording: Folder (a full path, confirmed with Return or by leaving the field; default: the user's Videos folder, Movies on macOS), Format (MKV or MP4, a segmented control), Video encoder ("Automatic (best available)" or one of the encoders this system has: only the picked one is tried, and the recording does not start if it cannot open), the video's size setting for the rate control (Video bitrate for CBR, Target bitrate for VBR: presets 2500 to 80000 kbit/s; Quality level for constant quality: 14 to 36, default 23, lower is better) and Audio bitrate (AAC 96, 128, 160 or 192 kbit/s, the rates Media Foundation AAC accepts). An "Advanced settings" row with a "Show" / "Hide" button (accessible names "Show advanced settings" / "Hide advanced settings") opens, in the same place (U2), every other setting that changes the recording's quality, each with its default and a one-line explanation: Rate control (CBR, the default; VBR; Constant quality), Maximum bitrate (VBR only; "Automatic", 1.5 times the target, or a preset), "Pad to the full bitrate" (a Toggle, CBR only, off by default; disabled with a note when the encoder does not declare `cbr_padded`), Keyframe interval (1, 2, 3, 4, 5 or 10 s; default 2 s), Encoder preset (Quality, Balanced, Speed; default Balanced), Profile ("Automatic" or one the encoder declares) and B-frames (0 to the encoder's maximum; disabled with a note when it makes none). The choices come from the picked encoder's capabilities, or from all encoders' for "Automatic"; a saved value the encoder lacks is still shown so it is never changed silently. Changes apply to the next recording and are saved at once; while a recording runs they are disabled and say so. Each recording gets a new file "RBS <local date> <time>.<ext>"; an existing file is never replaced. The settings are kept in the `recording` section of the output profile in use (ADR-0051; a first start takes them from `recording.toml`, which older versions kept) (`format_version = 1`, `folder`, `format` = `"mkv"` or `"mp4"`, optional `encoder` adapter id, `rate_control` = `"cbr"`, `"vbr"` or `"constant_quality"`, `video_kbps`, optional `max_video_kbps`, `quality`, `keyframe_seconds`, optional `profile`, `preset` = `"quality"`, `"balanced"` or `"speed"`, `b_frames`, `cbr_padding`, `audio_kbps`; fields a file from an earlier build lacks take their defaults); a section that cannot be used gives the defaults and a note in the section; one saved by a newer RBS is not changed.
- **Settings window, Stream section (U17).** Where Go live sends the program, and how it is encoded. Server (a TextField with the full URL, `rtmp://host[:port]/app` or `srt://host:port`, confirmed with Return, by leaving the field, by closing Settings or by pressing Go live, so a server typed and not confirmed is never lost; other schemes, `rtmps` included, are refused with a note until a transport has them, and so is anything after `?`, such as `?streamid=` or `?passphrase=`, since a secret would then be in the URL: it goes in the Stream key field; a hint says to copy it from the streaming service). Stream key (a password TextField: what is typed is never shown, confirmed with Return or "Save key"; with SRT it is the optional stream id). The key is never written to a settings file, log or URL: it is kept in the operating system's credential store (the macOS Keychain, the Windows Credential Manager) under the service `RBS` and an account of the output profile in use (`stream-key/<profile id>`; the `default` profile keeps the account `stream key` that RBS used before profiles), and the hint says so; where RBS has no credential store yet (Linux today) it is kept in memory until RBS closes and the hint says that instead. Under the field: "A stream key is saved." or "No stream key yet.", and "Remove key" (asks nothing; it can be typed again). The store is read only when a stream starts and written only when a key is saved or removed, on the studio's control thread (an OS prompt to allow access never blocks the window); nothing reads it at start-up. "Reconnect when the connection drops" (a Toggle, on by default: up to 10 tries, 1 s doubling to 30 s apart, as `rbs-cli stream`; a server that refuses the key is not retried). SRT latency (shown only for an `srt://` server: Default (120 ms), 200, 500, 1000 or 2000 ms). Then a While live card with "Record when the stream starts" (a Toggle, off by default, as asked by the owner on 2026-11-07): when a stream starts (Go live or `stream.start`) and no recording runs, a recording starts with the Recording section's settings, exactly as Record would, and the live controls show it as if Record had been pressed. Ending the stream (End stream, `stream.stop`) stops that recording too, after its tail. A recording that was already running when the stream started is not touched, and no second one starts. A stream that fails (the server refuses, reconnecting gives up) leaves its recording running: it is the copy of what viewers missed, and from then on it is the user's to stop, as is a recording whose stream ended that way; stopping the recording while live never ends the stream. A recording that cannot start (the folder, no encoder) says why under Record and leaves the stream running. While the setting is on, a notice under it says what it costs: with the same encoder picked and the same video settings in Recording and Stream the two share one video encoder (ADR-0047 decision 3) and the extra load is small, otherwise every frame is encoded twice and the notice says so and how to share one; and the disk space the recording takes per hour of streaming at the Recording bitrate (video plus audio; not shown for constant quality, where it says only that the recording needs free space). Kept as `auto_record` in the output profile's `stream` section. Then the same encoder fields as the Recording section, with their own values and the stream's defaults (CBR 6000 kbit/s, keyframe every 2 s, which most services require, balanced preset, audio 160 kbit/s); constant quality is not offered, since services need a bitrate. Changes apply to the next stream and are saved at once; while a stream runs they are disabled and say so. Kept in the `stream` section of the output profile in use (ADR-0051; a first start takes it from `stream.toml`) (`format_version = 1`, `server`, `key_saved`, `reconnect`, `auto_record` (absent: off), optional `srt_latency_ms`, and an `[encoding]` table with the Recording section's encoder fields and names); a section that cannot be used gives the defaults and a note in the section. Starting a stream without a server or saved key does not open anything and says what is missing; the note then follows the settings (it names what is still missing and goes once nothing is). Screenshots: `docs/ui/screenshots/settings-stream-{dark,light,high-contrast}.png`.
- **Settings window, Remote control section (U17, ADR-0044).** Lets other apps on this computer (Stream Deck, panels, scripts) control RBS through the control API. "Allow remote control" (a Toggle, off by default; while off nothing of the API exists). A status line under it: where apps connect (`ws://localhost:<port>`, "Other computers cannot connect"), or in the error colour why it is not running ("another app is using port 4456" with what to do, or that the studio did not start). Port (a TextField, 1024 to 65535, default 4456; confirmed with Return or by leaving the field; a refused value is put back with a note; a change disconnects connected apps, said in the hint). Access tokens: Name (TextField) and Access (SegmentedControl: View only, Control (the default, for panels), Full control, each explained in one line), and "Create access token". A new token is shown once in a bordered group with a read-only TextField, Copy (primary) and Done; it is gone after Done or when the Settings window closes. The list shows each token's name and access with "Revoke"; revoking disconnects the apps using it and shows "<name> was revoked" with Undo, which puts the same token back (until another token is made or the window closes). Name problems (empty, longer than 64 characters, taken) are shown under the button. Kept in `remote-control.toml` in the config directory (`format_version = 1`, `enabled`, `port`, `[[tokens]]` with `name`, `scopes`, `hash`: only SHA-256 hashes); on Unix the file is mode 0600, and a file other users can write is refused. An unreadable, invalid or refused file leaves remote control off, is moved to `remote-control.toml.refused`, and the section says why. Screenshots: `docs/ui/screenshots/settings-remote-control-{dark,light,high-contrast}.png`. **Network access (ADR-0046)**, under the port: "Allow access from other computers" (a Toggle, off by default, disabled while remote control is off), with a hint to turn it on only on trusted networks and that a refused firewall prompt blocks other computers without notice. While on: a status line (where other computers connect, `wss://<name>.local:<port>` or the computer's address, or in the error colour why they cannot, such as a missing key, with "New key" as the fix); "Key pin" (`sha256//...`) and "Certificate fingerprint (SHA-256)", each a read-only TextField with Copy, the fingerprint's hint saying where the certificate came from and when it was just renewed; "Allow remote admin" (a Toggle, off by default; a change restarts the server, said in the hint); "Certificate" (a SegmentedControl: Made by RBS, Your own; the hint says browser panels need the user's own certificate); for Your own, "Certificate file" and "Key file" (TextFields, full paths) and "Use these files", refused with a note when they cannot be read or do not match; for Made by RBS, "New key…", which asks first in a bordered group ("Make new key" primary, "Cancel"), since it cannot be undone. While other computers can connect, the frame bar shows "Reachable from other computers" in every workspace. Screenshots: `docs/ui/screenshots/settings-remote-control-network-{dark,light,high-contrast}.png`.
- **Errors.** The studio not starting or stopping (no usable GPU, a studio node failing for good) shows in the error bar and in the panels. A hardware GPU is preferred; without one the app uses a software adapter.
- **Checks without devices.** A build with the `demo-sources` feature and `RBS_DEMO_SOURCES=1` adds the reference adapters (synthetic display, camera, microphones, loopback) for screenshots and UI checks. `crates/rbs-app/tests/studio_host.rs` covers the host on those adapters: add, unique names, delete and undo, moving a source up and down (past a sound-only source), setting its box (and refusing a zero size), undo and redo of every edit kind with a drag as one step, and shutdown. `crates/rbs-app/tests/studio_record.rs` covers recording through the host with fake encoders: the picked encoder only, automatic fallback, refusals (a running recording, an existing file, an unknown encoder) and a closed file after stop. `crates/rbs-app/tests/studio_stream.rs` covers streaming through the host with a fake RTMP transport: the key read from the store reaches the transport only, a missing key refuses before anything opens (a missing or invalid server is refused by the UI, `stream_profile` unit tests), connection changes reach the UI, one output at a time, and a clean end.

## Panels and workspaces (contract for U21)

Workspaces are client-side UI state. The desktop UI crate owns the panel model and the workspace format; the engine and `rbs-core` know nothing about them (P1).

### Where a feature's settings live

The inspector pattern (as in Figma, Blender, DaVinci Resolve and Visual Studio), so Properties stays short as features grow (owner question, 2026-11-06):

- **Properties is a compact inspector** of the selected item: the settings changed often, per item, at a glance (box, crop, shape and border). It is grouped in sections that collapse and remember their state; a search field comes once it has more than a handful of sections.
- **A feature that grows gets its own panel** (a dockable panel with an id, U21): the mixer, transitions, effects, a theme editor. Properties then shows only a one-line summary of it for the selected item and an Open button that shows that panel with the item selected; editing never happens in two places.
- **Exception: filter chains** (owner's design, mockup E; ADR-0062). They are edited only in the Filters tab of Properties, which stays short because one tab shows at a time; they move to an `rbs.filters` panel only if the tab needs more than one screen. **Mirrored live controls** (volume and mute) show the same single value in the Mixer row and the Audio tab, as on a hardware desk; that is not editing in two places.
- **Rare, complex or one-time work goes to a dialog or a Settings page** (U17): output, encoder and stream settings, import and export, first-time setup.
- Rule of thumb: touched often while live goes in a panel; touched rarely goes in a dialog or Settings. A Properties section that needs more than one screen at the default window size, or needs a large working area (a curve editor, a preview of its own), moves to its own panel.
- New features (crop, filters, themes and later ones) state in their spec where their settings live by these rules.

### Panel model

- A panel id is `<namespace>.<panel>` in lowercase ASCII letters, digits, `.`, `-` and `_`, at most 128 bytes, with optional parameters `?key=value&key=value` in the same characters. Each key appears once and parameters are stored sorted by key, so one panel has exactly one id.
- Every panel has a stable id (`rbs.scenes`, `rbs.sources`, `rbs.preview`, `rbs.program`, `rbs.properties`, `rbs.mixer`, `rbs.live-controls`, `rbs.transition`, `rbs.outputs`, `rbs.stats`, `rbs.status-bar`, plugin panels as `<plugin-id>.<panel>`), a title, an icon, a default dock position and an optional shortcut.
- Panels that can exist more than once take parameters in the id: `rbs.preview?canvas=vertical`, `rbs.program?canvas=horizontal`. Without a parameter they show the canvas being edited.
- A layout is a tree per window: splits (horizontal or vertical, with ratios) whose leaves are tab stacks of panels. Floating windows and projectors have their own tree or content plus their position.
- Each built-in panel declares how often it must redraw while visible: on change only (lists, properties, controls), at most N times per second (`rbs.mixer` 30 Hz, `rbs.stats` and `rbs.status-bar` 1 Hz), or at display rate (`rbs.preview`, `rbs.program`). The shell runs at most one redraw timer, at the fastest rate any visible panel or visible compact view needs, plus 1 Hz for the live indicator while live or recording, and no timer otherwise. Hidden tabs, closed panels, auto-hidden panels that are not out, panels in hidden areas, panels covered by a maximized panel and collapsed panels without a compact view never count.
- `rbs.program`, `rbs.live-controls` and `rbs.mixer` are guarded: closing them while live (directly or by closing their floating window) shows the undo toast of U21. Collapsing or auto-hiding them, hiding their area or covering them with a maximized panel shows no toast: one interaction brings them back.
- **Stack states** (ADR-0049). Panel commands (`ui.panel.collapse(id)` and the others) act on the stack that holds the panel. A tab stack in an area or the centre is:
  - `docked` (default);
  - `collapsed`: only its title row is shown, `size.control.lg` plus border high in a vertical split, a vertical strip as wide in a horizontal split. The strip shows the tabs' icons with their titles as tooltips (no rotated text) and has the accessible name of the stack's panels. The title row or strip has an expand button whose accessible state is collapsed or expanded. It keeps its ratio, used again on expand; the rest of its split takes the space. A split whose stacks are all collapsed shrinks to their title rows; an area whose stacks are all collapsed shrinks to their title rows and keeps its `size` as the size to restore. The centre keeps at least one stack that is not collapsed;
  - auto-hidden: it leaves the tree and becomes edge tabs: those of an area on that area's edge, those of the centre on the left, right or bottom edge nearest to its stack (ties: left, then right, then bottom). Several groups on one edge are drawn in file order. Hovering an edge tab for `motion.hover-open` slides the panel out without taking focus; a click, or Enter or Space on a focused edge tab, slides it out and moves focus into it. It stays out while the pointer is on the tab or the panel and for 300 ms after it leaves both, and slides back on Escape, when focus leaves it or when another edge tab opens; focus returns to the edge tab. A hover-opened panel has no focus: Escape goes to the focused widget first and closes the panel only if that widget does not use it. Edge tabs have the accessible role tab and report expanded or collapsed. Pinning docks the panel next to its anchor if the anchor is docked in the main window (collapsed counts as docked; an anchor in a floating window does not count), else at the outer side of the area of its edge (left, right or bottom), which is shown if it was hidden.
  - **Maximize** (double-click a tab, Shift+Esc while a tab has focus, or the panel menu) shows one panel over the whole content until restored. It is not saved and is not a layout history step; neither is sliding an auto-hidden panel out or back. Covered panels count as hidden (U5).
- **Compact view** (amends U5, ADR-0049). A panel may declare a view drawn in its title row while collapsed, with its own update rate; it follows the same visibility rules as the full panel. `rbs.mixer`: one small meter and a mute button per audio source, meters at 30 Hz while audio is active. Panels without one show only their titles and do no rendering or polling.
- **Size limits.** Each panel declares `min`, `default` and `max` sizes on both axes in logical pixels; `max` may be a share of the window. Dividers move within the limits of the panels on both sides, double-click returns a divider to the default, and View › Reset panel sizes resets them all. Built-in limits (width x height where both matter):

  | Panel or area | Min | Default | Max |
  | --- | --- | --- | --- |
  | Left and right area | 200 px | 260 px | 40 % of the window |
  | Bottom area | 90 px | 200 px | 60 % of the window |
  | `rbs.transition` as the studio rail | 0 | 56 px | 200 px |
  | `rbs.transition` elsewhere | 200 x 120 px | (fills) | (fills) |
  | `rbs.preview`, `rbs.program` | 320 x 180 px | (fills) | (fills) |
  | Auto-hide flyout | the panel's min | 320 px | 60 % of the window |

  - A tree's minimum is computed from its panels: the sum of its children's minimums along a split's axis and the largest across it. An area's minimum is the larger of its own (table) and its tree's; its maximum is the table's. The centre's minimum is its tree's (one preview: 320 x 180 px; a studio split in studio mode: 640 x 180 px).
  - A split child may have a fixed `size` in logical pixels instead of a ratio share: it keeps that size when the window is resized and the other children share the rest by their ratios. Dragging its divider changes its `size`. When the fixed sizes do not fit, they shrink toward their minimums in step 2 of the conflict order below, together with the areas.
  - **Studio mode** is engine state: a canvas is in studio mode while it has a preview scene (scene model, `set_preview`), shared by every client. The registry toggle `canvas.studio_mode.toggle` (parameter `canvas`, default the canvas being edited) pairs `canvas.set_preview {canvas, scene}` (the program scene) and `canvas.set_preview {canvas, scene: null}`, methods of the control API from protocol 1.9 (ADR-0061). It is a live action and on no undo stack (ADR-0021). In studio mode a click on a scene in the Scenes panel previews it (the row is marked in `color.accent`; the scene on air keeps a neutral "Program" badge, and the red Live/REC badge shows only while streaming or recording), and `canvas.transition` (Ctrl/Cmd+Enter, the Scene menu, the rail) puts it on air. While the preview scene is the program scene (entering the mode, or a click on the scene on air), the program is held as it was (ADR-0063): edits to the scene's items show in Preview only, and the transition puts them on air. The held copy is never shown: no extra scene in the Scenes panel, the Sources panel or the saved collection; source settings (filters, volume, mute, sync offset) are shared and reach the program at once.
    - Studio mode never rearranges a workspace. A workspace may hold one **studio split** (`studio = true`, in the centre), saved like any split: Preview, `rbs.transition` as a fixed-size child (the studio rail) and `rbs.program`. It follows the canvas of its Preview panel. In studio mode all three show; otherwise Program is not shown (it counts as hidden, U5) and Preview and the rail fill the split, the rail picking the transition used when the program scene changes. Workspaces without a studio split show Preview and Program wherever they are docked. When a canvas enters studio mode, every client whose workspace has that canvas's Preview (`rbs.preview`, or `rbs.preview?canvas=...` for another canvas) closed opens it where it opens by default (U21; opening is allowed on a locked workspace and is a layout history step like any open), the only layout change studio mode makes.
    - The studio split is one unit. Its three panels cannot be collapsed or auto-hidden (those commands are disabled with the reason), and no tab can be dropped into its stacks (no drop targets are offered there). Closing one of its panels, or moving one out, dissolves it: `studio = true` is dropped, the rail's `size` is dropped (its stack takes a ratio share, the others' shares scaled to make room) and the rest stays as a plain split, in one layout history step. View › Studio layout (`ui.layout.studio_split {canvas}`, default the canvas being edited) builds it again: it opens or moves that canvas's Preview, Transition and Program, puts the split in place of the stack that held Preview if Preview was in the centre and otherwise to the right of the centre's tree, and gives the rail its last size or 56 px; it is one layout history step, refused with `conflict` when a studio split exists, and refused from the pointer on a locked workspace like other rearranging commands.
    - The centre's minimum counts fixed-size children at their minimums (the rail's is 0).
  - The studio rail is drawn as a floating control over the bottom edge of the two views below 40 px, as a rail with Cut, Auto, a T-bar and the duration from 40 to 120 px, and with names and a duration field above 120 px. Outside studio mode it shows only the transition picker and the duration, at any width. First slice (ADR-0061): the only transition is Cut, so the rail shows the transition's name and one primary button, "Transition" ("Go" below 120 px; below 40 px a floating icon button), and outside studio mode a hint at 120 px or wider; Auto, the T-bar, the picker and the duration come with fades. Elsewhere (in an area, a floating window or the Edit workspace) `rbs.transition` is an ordinary panel with the transition list and duration.
  - Dragging the bottom area below 90 px collapses its stacks, and dragging the left or right area below 200 px collapses its stacks to strips; dragging back out expands them.
- **When limits conflict** (small window, 200 % text): the centre's minimum (above) is kept first; then visible areas shrink in proportion down to their minimums; then the bottom area collapses its stacks; then the left and right areas are drawn as their edge tabs (not saved: they return when there is room). Nothing is cut off (U11). A property test covers window sizes from 1280 x 720 upwards and text scales up to 200 %.
- The live indicator is not a panel and cannot be removed (U4, U21). The workspace and Panels menus are in the menu bar (View › Workspace, View › Panels), part of the window frame, not panels.

### Workspace file

Workspaces are stored as versioned TOML in the user's config directory, one file per workspace, so they can be shared and kept in version control. A JSON Schema for the format is published with the UI crate and checked in CI.

Format 2 (ADR-0049; format 1 is read and migrated, see below):

```toml
format = 2
name = "Edit"
locked = false
toolbar = { style = "icons-text", items = [
  "ui.workspace.select", "|", "scene.create", "source.add", "|",
  "canvas.studio_mode.toggle", "transition.pick", "|", "program.screenshot", "marker.add",
  "~", "ui.app_menu.open", "ui.area.toggle?area=left", "ui.area.toggle?area=bottom",
  "ui.area.toggle?area=right", "|", "stream.toggle", "record.toggle",
] }
# rbs.library is a planned panel; until it exists it shows as an unknown-panel placeholder.

[[windows]]
kind = "main"
centre = { tabs = ["rbs.preview"] }
left = { size = 260, visible = true, layout = { split = "vertical", ratios = [0.4, 0.6], children = [
  { tabs = ["rbs.scenes"] },
  { tabs = ["rbs.sources"] },
] } }
right = { size = 290, visible = true, layout = { split = "vertical", ratios = [0.6, 0.25, 0.15], children = [
  { tabs = ["rbs.properties"] },
  { tabs = ["rbs.live-controls"] },
  { tabs = ["rbs.transition"], state = "collapsed" },
] } }
bottom = { size = 200, visible = true, layout = { tabs = ["rbs.mixer"] } }
auto_hide = [
  { edge = "left", tabs = ["rbs.library"], size = 340, anchor = "rbs.scenes" },
  { edge = "right", tabs = ["rbs.stats"], size = 320, anchor = "rbs.properties" },
]

[[windows]]
kind = "floating"
layout = { tabs = ["rbs.outputs"] }
placement = { display = "edid:DEL-41A3-7H2K9", connector = "DP-2", size = [2560, 1440], scale = 1.5, rect = [0, 0, 640, 420] }

[[windows]]
kind = "projector"
content = "program?canvas=vertical"
placement = { display = "edid:SAM-7012-HX55", connector = "HDMI-1", size = [1920, 1080], scale = 1.0, fullscreen = true }
```

Toolbar items are command registry ids ([ADR-0050](../adr/0050-command-registry-menus-and-toolbar.md)): control API method names, or `.toggle` ids that pair two of them (`stream.toggle` = `stream.start` / `stream.stop`). The ids above show the shape; the final list is fixed with the registry.

- **Main window (format 2).** `centre` is a layout tree (required). `left`, `right` and `bottom` are optional tables with `size` (integer logical pixels, 0 to 16384, clamped to the area limits when laid out), `visible` (default true) and `layout` (a tree; an absent area is empty). An area's `layout` has no empty tab stacks (an empty area has no `layout`). A split child may carry `size` (integer logical pixels, 0 to 16384) in place of its ratio share; the split's `ratios` then lists only the children without `size`, in order, and at least one child has no `size`. A split may carry `studio = true` (see Studio mode): at most one, in the centre, horizontal, with exactly three children in order: a stack holding only `rbs.preview` (or `rbs.preview?canvas=...`), a stack holding only `rbs.transition` with a fixed `size`, and a stack holding only the matching `rbs.program`; any other shape is a validation error. Example: `{ split = "horizontal", studio = true, ratios = [0.5, 0.5], children = [ { tabs = ["rbs.preview"] }, { tabs = ["rbs.transition"], size = 56 }, { tabs = ["rbs.program"] } ] }`. `auto_hide` is a list of edge groups: `edge` (`left`, `right`, `bottom`), `tabs` (1 to 32 panel ids), `active` (index into `tabs`, default 0, must be smaller than its length), `size` (integer logical pixels, 0 to 16384, clamped to the flyout limits when shown) and optional `anchor` (a panel id that appears elsewhere in the workspace and not in this group; an anchor that does not resolve, or is not docked in the main window, is ignored and pinning docks at the outer side of the edge's area). At most 16 edge groups. A tab stack may carry `state = "collapsed"`; the centre's tree must keep at least one stack that is not collapsed. Only the main window has `centre`, areas and `auto_hide`; a floating window has `layout`.
- **Implementation status.** `rbs_ui::workspace` reads, validates, migrates and writes everything in this format except fixed-size split children (`size` on a child) and the studio split (`studio = true`), which come with the studio split; until then a file using them is refused as having an unknown field. The shell still draws only the centre.
- **Toolbar** (ADR-0050). `toolbar` is optional (absent: the workspace's built-in default, or the Edit default for user workspaces). `style` is `icons` or `icons-text`; `visible` defaults to true; `items` has at most 64 entries: command ids (the panel id grammar), `"|"` (separator) and at most one `"~"` (flexible space). A command id appears at most once; leading, trailing and repeated separators are removed on load. Unknown command ids are kept and shown as a disabled placeholder whose tooltip names what is missing (Fluent message `toolbar-unknown-command`). Only the id grammar is checked on load: a known id whose parameters its entry does not accept is kept and shown disabled with the reason too, so a registry change never makes a workspace file unreadable.
- **Migration from format 1.** The main window's `layout` becomes `centre`; the three areas start empty and visible; nothing is collapsed or auto-hidden; the toolbar is the default. Floating windows and projectors are unchanged. Migration happens in memory on load; the file is rewritten in format 2 only when the workspace is next saved, after which older builds refuse it (one-way, stated in the release notes). Before that first rewrite the format 1 file is copied to `<file>.format1.bak` next to it (once, never overwritten), so a user can go back to an older build by hand. A format 1 override of a built-in workspace migrates to everything in the centre; the app says so once and offers Restore default.
- `placement.display` is a stable fingerprint derived from the display's EDID (manufacturer, product code, serial). `connector`, `size` (physical pixels) and `scale` help when the fingerprint is ambiguous. `rect` is in logical pixels relative to that display.
- Matching order when a workspace is applied: (1) same fingerprint, (2) same connector with the same size, (3) any display with the same size and scale, (4) no match: the window docks into the main window and a projector is not opened. A rect that would fall outside the matched display is clamped to it.
- Export removes `placement` display details (fingerprint, connector) and keeps only size, scale and relative rect, so exported workspaces are portable and contain no hardware identifiers. Import then matches by step (3) or docks.
- `locked` blocks pointer moves, resizes and close buttons. Commands from the palette, shortcuts and the control API still apply.
- Unknown panel ids (for example from an uninstalled plugin) are kept in the file and shown as a placeholder that offers to install or remove them.
- The format is versioned; RBS reads older versions and migrates them. A file with a newer `format` is refused with a message, never rewritten.
- Validation: unknown keys are errors; there is exactly one `main` window and it is first; a panel id appears at most once in the whole workspace (areas, centre, edge groups and floating windows together); a split has at least two children, one positive ratio per child without a fixed `size`, ratios summing to 1 (within 0.01, then normalised) and at most 16 levels of nesting; a tab stack may carry `active` (index of the visible tab, default 0); only the main window's centre may be an empty stack (`{ tabs = [] }`, every panel closed; format 1: its root); a floating window holds at least one panel; a projector has `content` and no `layout`; names have 1 to 64 characters, no control characters, and are unique ignoring case (Unicode lowercase, not locale-specific).
- Files are named after a slug of the workspace name and written atomically (temporary file, then rename). Files that fail to parse are listed as problems and left untouched. Built-in workspaces need no file; saving a changed built-in writes an override file, and restoring its default removes it.

### Switching

- Client-scoped control API commands `ui.workspace.list` and `ui.workspace.switch(name)` ([control API](control-api.md#client-scoped-ui-commands)), available in the command palette and the workspace menu. Shortcuts are user-assigned; none is bound by default (U21).
- Optional `on_go_live` and `on_stream_end` workspace settings, stored in the UI settings, not in the scene collection or output profile.
- Switching only changes UI state; it never reconfigures sources or outputs.
- Layout changes and switches go into the UI's own layout undo history, not the engine command log. A history step is a whole-workspace snapshot; the moves of one splitter drag form one step; changes that leave the layout as it was record nothing; at least 100 steps are kept.
- Every layout change is a command (open, close, show tab, move to stack, move to edge, float, dock, close window, resize, lock, switch; and with ADR-0049: show or hide an area, collapse or expand a stack, auto-hide or pin a panel, maximize or restore, reset sizes, edit the toolbar, build the studio split). Pointer and keyboard both issue these commands. When `locked` is set, close, move to stack, move to edge, float, dock, close window, resize, auto-hide, pin, toolbar edits and building the studio split are refused if they come from the pointer (collapse, expand, area toggles, maximize and opening an auto-hidden panel stay allowed: they hide or show, they do not rearrange); open, show tab, lock or unlock and switch are always allowed, and every command from the palette, a shortcut or the control API applies.
- The result of every command is validated against the rules above; a command whose result would break one (for example splits nested deeper than 16 levels) is refused, so a workspace can always be saved and loaded again.
- A switch that leaves a guarded panel closed while live shows the same undo toast as closing it. An automatic switch (on go live or stream end) shows one toast naming the previous workspace with a one-click way back; that toast replaces the undo toast for any guarded panel the switch closed, because going back reopens it.
- Deleting a workspace asks for confirmation; deleting a built-in workspace is not possible, only restoring its default.

### Commands, menus and the toolbar

- Decided in [ADR-0050](../adr/0050-command-registry-menus-and-toolbar.md). One command registry in `rbs-ui`: id, title and tooltip (Fluent), icon, default shortcut, menu and group, kind (`action`; `toggle` pairing two control API commands, whose off half keeps its confirmation, so End stream still asks while live; or `picker`), and how to read its enabled state (with the reason when disabled, shown as a tooltip) and checked state. The menu bar, context menus, toolbar, command palette and shortcut map are all built from it (U20).
- Menus: File, Edit, View, Scene, Source, Output, Tools, Window, Help. Every command is in exactly one menu, except the few `NOT_IN_MENU` lists for shortcuts (`scene.position`). `MENU_LAYOUT` lists each menu's ids, `|` separators and `#Heading` section headings (ADR-0069): the RBS menu shows a heading's title, the menu bar draws it as a separator; context menus repeat the commands that apply to their item (U3). Menus show shortcuts and checkmarks.
- The menu bar is Slint's `MenuBar` and context menus are Slint's `ContextMenuArea`. Every RBS window that can take focus (main and floating windows) declares the same menu bar, because the macOS system menu bar shows the focused window's menus; it is shown only on macOS (`Shell.native-menu-bar`). On Windows and Linux the RBS menu takes its place ([ADR-0069](../adr/0069-rbs-menu-and-command-search.md)).
- Kinds (the first bullet's list in full): `action` runs one command; `toggle` pairs two (`stream.toggle` = `stream.start` / `stream.stop`) and reads which applies from state; `picker` opens a list of choices, each of which runs an action with a parameter (`ui.workspace.select` lists workspaces and runs `ui.workspace.switch(name)`; `transition.pick` lists transitions). An id's parameters (`ui.area.toggle?area=left`) are the command's parameters as strings, converted by the types the registry entry declares. In command ids, parameter values are UTF-8 and percent-encoded outside the id characters and ASCII capitals, with capital hex digits (`ui.workspace.switch?name=Live%20show`), and the 128-byte limit counts the encoded form. Escapes are two hex digits; lower case ones are read and written in capitals. The canonical form (parameters sorted by key, values encoded this way) is what files and `ui.command.list` hold. (This settles ADR-0050's "outside the id characters": its own example keeps the capital L.) An entry declares its parameters with a type and whether each is required; an id with an unknown parameter, a value outside its type or a missing required parameter cannot run. A picker's id with its choice parameter (`ui.workspace.select?name=Live%20show`) runs that choice, which is how menus, the toolbar and `ui.command.run` run one; the bare picker id opens the list in the UI, and `ui.command.run` answers it with `invalid_params`.

  - Toolkit: one `CommandMenu` (`rbs-app` `ui/context_menu.slint`, Slint's `ContextMenuArea` with its own right-click handling off) per element that has a menu. Opening calls `ContextMenus.prepare(context, target)` first, which returns the items of the moment, so a menu never shows stale state and nothing is computed while menus are closed (P13). The menu declares 16 generated slots, each a command, separator or submenu by its item's kind (`context_menu.rs`; a test fails when the copy is stale). On macOS and Windows the menu is native (drawn by the OS above the window, so the preview layer needs no cover); elsewhere Slint draws it as an in-window popup, which the preview layer already treats as a cover (ADR-0054).
  - Not yet: menus for panel tabs and card headers (the hand-made panel menu stays until the panel and layout commands are registry entries), the toolbar (Customize toolbar), Mixer rows, edge tabs and the Program picture in studio mode; the reason a disabled item is disabled (ADR-0050 decision 4 wants it as a tooltip; menus have none); Move up and Move down in the Source menu (the layer order has no control API method yet); Duplicate; shortcuts shown in context menus.

Customize toolbar (View menu, or the toolbar's context menu) adds commands from a searchable list, removes and reorders them by drag or keyboard, adds separators, picks the style and resets to the default. Each built-in workspace declares the U1 flows it serves (Edit and Live: all; Minimal: Go live and Record; Audio: Go live, Record and Mute), and a test checks each one with the toolbar hidden, with studio mode on and off, within the Core flows limits; opening an edge tab counts as one interaction.

## Core flows (contract for U1)

Interactions are counted as defined in the UI principles. "Max" is the limit for the whole flow with default choices. The table also holds two U21 flows (switch workspace, hide a panel), marked as such, held to the same counting.

| Flow | Steps | Max |
| --- | --- | --- |
| Add source | "+" on the Sources panel (or drop a file or window onto the preview: 1 drag, done) -> pick a type from large icons with search, recent first -> confirm in the picker, which shows a live preview -> the source is selected on the preview with handles | 3 |

## Actions that cannot be undone

End stream, stop recording, delete a scene collection, delete a recording file, sign out of a service. "Remove from scene" (undoable) and "Delete source" (removes it from every scene; undoable) are distinct commands. Volume, mute and sync offset are live controls, not undo steps (ADR-0059, ADR-0062; no confirmation). Everything else that edits scenes, sources, filters, transitions, audio or settings is undoable.

## Keyboard

Docking by keyboard (U21): Tab moves focus through the frame (menu bar where drawn in the window, toolbar), then each tab stack's tabs and their buttons, then the edge tabs, then the splitters. F10 focuses the menu bar on Windows; on Linux, where Slint's drawn menu bar has no keyboard support yet, F10 opens the same menus as a popup (ADR-0049, decision 8). On a focused tab the panel menu also offers collapse or expand, auto-hide or pin, and maximize or restore; Shift+Esc maximizes or restores the focused panel. Showing or hiding areas has no default shortcut (U21: Ctrl+Alt combinations clash with AltGr); users can assign one. An auto-hidden panel that slides out takes focus and gives it back when it closes. On a focused tab, Enter or Space shows it, the Menu key or Shift+F10 opens its panel menu (move to an edge, move to the next tab stack, float or dock back, close), and Delete closes it. A focused splitter moves by `step.nudge` per arrow key, `step.nudge-large` with Shift. Menus open with the first item focused; Tab and Shift+Tab move between items, Enter or Space chooses one and closes the menu, Escape closes it. Delete or Backspace on a focused tab closes it.

Every menu command is found by the RBS menu's search field (Ctrl/Cmd+K, ADR-0069) with its shortcut; `NOT_IN_MENU` commands are reached by their shortcuts. Defaults include: switch to scene 1-9 (Ctrl/Cmd+1..9), transition preview to program (Ctrl/Cmd+Enter; Space also works while the preview or program has focus), undo/redo, nudge source (arrows, Shift for 10 px), duplicate, delete, toggle studio mode. All shortcuts are rebindable; global hotkeys are opt-in. Shortcuts are decided in [ADR-0060](../adr/0060-shortcuts-in-app-and-global.md) and specified in the [shortcuts spec](shortcuts.md): any command registry id (picker choices included) can be bound to a chord in app scope or globally (macOS and Windows), the user's changes are kept in `shortcuts.toml`, conflicts and unsafe chords are refused before they take effect, and Settings › Shortcuts (after Appearance) views, records, removes and resets them. Implemented today: Undo (Ctrl/Cmd+Z), Redo (Ctrl/Cmd+Shift+Z and Ctrl/Cmd+Y) and the scene position defaults once scene commands exist.

## Requirements on the UI toolkit

The native toolkit chosen under ADR-0016 (Slint, iced or Qt through `cxx-qt`; ADR-0022 proposes Slint) must satisfy:

1. Renders the engine's shared GPU surface for preview and program without CPU copies.
2. Supports the tokens and components above, including custom drawing for meters and the preview canvas at display refresh rate.
3. Accessibility APIs on Windows, macOS and Linux (screen readers, keyboard focus).
4. Fluent-based i18n and right-to-left layout.
5. Idle CPU near zero when nothing changes on screen.
6. A docking system with tabs, splits and floating windows across monitors (U21), or the ability to build one.
7. A licence compatible with ADR-0010.
8. Rich visualisations (meters, equalizer curves, spectrum, histogram, scopes): light graphics with the toolkit's vector primitives; dense or per-pixel graphics drawn on the GPU and shown as textures. Graphics that move at the meter rate or faster are native compositor layers where the platform has a layer backend (ADR-0034 for the preview, ADR-0035 for meters), because the toolkit redraws the whole window for any change.

The comparison prototype and its measurements are in [`prototypes/ui-toolkit`](../../prototypes/ui-toolkit/README.md); the choice is recorded in [ADR-0022](../adr/0022-native-ui-toolkit.md).
