## Purpose

The single source of visual and interaction decisions for every RBS interface.

Binding now (once ADR-0015 is accepted): token names, the component list and contracts, the main window structure, the core flow interaction limits, and the list of non-undoable actions. Tunable: token values, which are initial and will be adjusted in Phase 2 usability testing.

## Tokens

Tokens are defined once in a data file ([`crates/rbs-ui/tokens.toml`](../../crates/rbs-ui/tokens.toml)) and generated into the native toolkit's format (ADR-0016), and exported as CSS variables only for remote clients outside the desktop app. UI code references tokens by name only (rule U6); a value no token covers gets a new token here and in the token file in the same change, never a literal in UI code (steps in the `ui-review` skill).

In the desktop shell every token is a run-time value: the build generates the `Theme` and `Tokens` globals with the built-in values as defaults (so the `.slint` files compile and preview on their own) and a function that copies a parsed token file into them (`rbs-app` `look`). Each window gets the token file in use when it opens, so a theme changes without a new build and costs nothing per frame (bindings read the globals; nothing polls). `Theme` holds one colour set per theme in `THEMES` order and `Theme.active` picks one: the OS scheme, or `Theme.choice`. The file in use is the built-in one; `RBS_TOKENS=<file>` names another complete token file as a development aid (a file that fails the checks below is not used, the built-in one is, and the error bar says why). Users pick, make and share themes as overrides of a built-in theme in Settings › Appearance ([themes spec](themes.md), [ADR-0057](../adr/0057-user-themes-and-appearance-settings.md)).

File layout (format 2; format 1 is format 2 without `[font]` and is still read, with the OS UI font): `[fixed]` holds the colours no theme may change (`color.state.live`, `color.text.on-live`, and the Windows close button's `color.caption.close-hover`, `color.caption.close-text`, ADR-0071); `[themes.dark]`, `[themes.light]` and `[themes.high-contrast]` each define exactly the theme colour names below, as opaque `#rrggbb`; `[length]` (logical pixels: the spacing, size, radius, line, menu, window and keyboard step tokens below), `[duration]` (milliseconds: `motion.fast`, `motion.normal`) `[type]` (`{ size, line, weight }` for the five text styles) and `[font]` (`font.family`, a list of family names, empty for the OS UI font) hold the rest. Every theme in the file also passes the theme rules of the [themes spec](themes.md#theme-rules) (bounds, rules across tokens, distance from the live colour). Token names are lowercase words joined by `.` or `-`. A custom theme is a complete token file; its `[fixed]` values must equal the built-in ones (`#c4262e`, `#ffffff`, `#c42b1c`, `#ffffff`), otherwise it is refused. Elevation and easing tokens are added to the file together with the components that use them. `rbs_ui::tokens` parses the file and fails on a missing, unknown or invalid token, a changed fixed colour, and any failed contrast rule:

- text: `color.text.primary` and `.secondary` on every surface, `color.text.inverse` on `color.accent`, and `color.text.primary` on `color.accent.subtle`: at least 4.5:1 (7:1 in `high-contrast`); `color.text.on-live` on `color.state.live` and `color.caption.close-text` on `color.caption.close-hover`: at least 4.5:1 in every theme, because all four are fixed;
- non-text: `color.border.focus` on `surface.base` and `.raised`, `color.border.strong`, `color.state.*` and `color.action.destructive` on `surface.raised`, `color.meter.*` on `surface.sunken`, and `color.state.live` on `surface.base`: at least 3:1;
- the theme rules of the [themes spec](themes.md#theme-rules) add the pairs the UI draws besides (error text at 4.5:1, among others); a test reads the `.slint` files and fails on a drawn pair no rule covers;
- `color.state.error`, `color.action.destructive` and `color.meter.clip` differ in hue from `color.state.live` by at least 45 degrees (rule U12).

## Components

The library is the only way to build UI (rule U6). Each component has: states (default, hover, pressed, focused, disabled, error), keyboard behaviour, accessible name and role, light/dark/high-contrast screenshots, and usage notes.

Initial set: Button (primary, secondary, ghost, danger, live: only to stop a live or recording output, in the fixed live colour), IconButton, SplitButton, Toggle, Checkbox, Radio, Select, Combobox, Slider and VSlider (the same control drawn upright with 1 at the top: value, keys, scroll wheel, double-click reset and accessibility as Slider; with numeric entry), NumberField (drag to change), TextField (editable, disabled, read-only for text the user copies, such as a token shown once: `copy-all()` puts its text on the clipboard; `end-inset` shortens the text so a control can sit inside the trailing end, or password for a secret: what is typed is never shown and leaving the field does not confirm it; `placeholder` is shown in `text.secondary` while it is empty, saying what an empty value means, never its name), ColorPicker, Tabs, SegmentedControl, List and TreeList (drag reorder, inline rename), ContextMenu, Popover, Dialog, Toast, Tooltip, PropertyGrid (generated from a settings schema), EmptyState, StatusBadge (live, recording, warning), AudioMeter, AudioStrip (meter, fader, mute, monitor, filters), PreviewCanvas (handles, snapping, guides), SceneCard (thumbnail, name, live badge), TransitionPicker (preview thumbnail), CommandPalette, KeyboardShortcutHint (a chord as a key chip with an optional tag such as "Global"; implemented), SizeNest (fixed picture sizes nested in one frame: 720p inside 1080p inside 1440p inside 4K).

### Icons

One icon set ([ADR-0094](../adr/0094-ui-interaction-patterns-and-tabler-icon-set.md): Tabler Icons outline, MIT, converted to 16 x 16 paths by `tools/icons/convert_tabler.py`, licence in `crates/rbs-ui/ICONS-LICENSE.txt`; `dot`, `ring`, `stop`, `clock`, `hourglass`, `rail-between`, `rail-below`, `canvas-vertical`, `circle`, `square`, `rectangle`, `rounded-rectangle`, `ellipse`, `triangle` and the three `window-*` icons are RBS drawings), drawn by the library's `Icon` component as vector paths in a 16 x 16 view box, sized by `size.icon.box` and stroked with `size.icon.stroke`. Icons are never font glyphs: a glyph missing from the OS font shows as an empty box (seen on Windows with U+22EF and U+25BE). Set: `more`, `chevron-down`, `chevron-up`, `chevron-left`, `chevron-right`, `check`, `close`, `dot` (filled, live state; Record), `ring` (outline, not live), `stop` (filled square: a running output's Stop recording and End stream toolbar buttons, in `state.live`), `plus`, `pin` (auto-hide and pin), `collapse`, `auto-hide`, `move`, `float` and `dock` (the panel menu: Collapse, Auto-hide to the edge, Move to, Float in its own window, Dock back), `save` (Save changes, Save as new), `panel-left`, `panel-right`, `panel-bottom` (area toggles), `canvas-vertical` (an upright rounded frame: the Vertical panel and Vertical preview), `bolt` (Go live), `grid` (Stats), `copy` (Outputs), `window` (any other panel), `search`, `monitor`, `camera`, `mic`, `speaker`, `speaker-off`, `headphones` and `headphones-off` (the Mixer's monitor button, the Audio settings section), `eye`, `eye-off`, `expand`, `lock`, `unlock`, and for the Settings sections `sliders` (General), `palette` (Appearance), `keyboard` (Shortcuts), `broadcast` (Stream), `link` (Remote control; also the mark of a source placed in more than one scene), `globe` (Global sources), `warning` (a source that is unavailable, ADR-0077), `info` (an info button that shows or hides a field's help text), `clock`, `hourglass` (filled, the seconds left on a notice), and `gear` (Settings, `ui.settings.open`), and for menu commands `user` (Output profile), `folder` (Scene collection), `undo`, `redo`, `layout` (Workspace), `panel-all` (Show all areas), `panel-none` (Hide all areas), `reset` (Reset panel sizes, Reset toolbar), `refresh` (Reload theme), `image` (scenes), `arrow-left` and `arrow-right` (Previous and Next scene), `pencil` (Rename; Edit in the theme list), `trash` (Remove scene, Delete source, Delete in the theme list), `export` and `import` (Export in the theme list, Import themes), `transition` and `menu` (the RBS menu button), `rail-between` and `rail-below` (the Transition rail's position, drawn like the docking guides), and `window-minimize`, `window-maximize` and `window-restore` (the Windows window buttons, with `close`; ADR-0071), and for the Library shape buttons `circle`, `square`, `rectangle`, `rounded-rectangle`, `ellipse` and `triangle` (outline geometry; the arrow shape uses `arrow-right`, not the filled `stop`). The paths live in `rbs_ui::icon::ICONS`; the library's `IconName`, `Icon` and `Icons.named` are generated from it (`rbs-app/src/icons.rs`, a test fails when the copy is stale). Registry entries and panels name their icon by these names, and every registry entry has one (a test checks every entry and every menu and context menu layout), so no menu item is blank. **Menu icons.** Menus that take images (the menu bar, context menus) get each icon drawn from its path as an image in a neutral grey (`#8e8e93`) that reads on light and dark menus alike, because native menus follow the OS appearance, not the app theme: 36 px square (macOS shows 18 points), 16 px on Windows (which draws menu bitmaps at 16 x 16). A checked item shows its checkmark in the icon's place and no icon; macOS and Windows native menus show no icon on checkable items at all. Choices in a submenu show checkmarks only. An icon is decorative (no accessible role): the control that shows it carries the name, and state is never shown by the icon alone (U7). The converter checks every SVG it reads against the SHA-256 digests pinned in `tools/icons/tabler-3.26.0.sha256` and stops on a mismatch.

- `Button` takes an optional trailing `icon`; its ink follows the button's text colour, including disabled.
- `NumberField` takes a `label` (its accessible name; role spinbox with the value, increment and decrement actions), a `value`, a `step` and an `edited(float)` callback. Return or leaving the field commits text that differs from what it showed; the field then shows `value` again, so a refused edit never stays in it. Text that is not a number goes back to `value`. Up and Down step from what is typed (Shift: ten steps) and commit at once. A stepper column at the right edge (a divider, then `chevron-up` over `chevron-down`, `text.secondary` on the field, `surface.overlay` under the pointer) shows that the field steps: a press steps once as Up or Down does, holding it keeps stepping after 400 ms (every 80 ms); the buttons never take the focus, so a value being typed stays in the field. `typed(string)` reports each change of the typed text before it is confirmed, for a form whose Save button must see it (the theme editor). States: normal, focused (focus border), disabled (no background, disabled text, no stepping). It shows whole numbers. Drag to change is not there yet.
- `ColorPicker` is a swatch button (`label` is its accessible name, `value` the colour it shows) that opens a popover: a saturation and brightness area at the chosen hue, a hue bar, eight named preset colours (White, Black, Red, Orange, Yellow, Green, Blue, Purple) and the chosen colour as a swatch with its `#rrggbb` text. It reports a choice through `picked(string)` as `#rrggbb`, or `#rrggbbaa` when `value` is not opaque (the transparency is kept), and the choice stands only once the owner sets `value`. A drag on the area or the bar shows the colour in the popover and reports it on release, so one drag is one change; a preset, or an arrow key on the area (saturation left and right, brightness up and down, Shift: ten steps) or on the bar (hue, 1 degree, Shift: 10), reports at once. Return or Space opens it; Escape or a click outside closes it. The popover is a layer of the window (`Overlays.color-*`, drawn by `OverlayHost`, reported to the preview layer as a cover, ADR-0094); only the swatch that opened it takes its picks. The area and the bar are sliders with their values in words; each preset is a button named after its colour. The preset and wheel colours are content colours, not theme tokens.
- `Toggle` is an on/off switch for a setting that applies at once: a track two knobs wide, filled with `color.accent` and the knob at the right when on, `color.surface.sunken` with a `border.subtle` outline (`border` becomes `accent` under the pointer) and the knob at the left when off. The knob is `color.text.primary` when on and `color.text.secondary` when off, so it stays light on a dark theme and dark on a light one; its side shows the state as well as the fill (U7). `label` is the accessible name (role switch) when the row shows the name itself; `text` shows a label beside it. Click, Space or Return toggles it and reports `toggled(bool)`; the owner sets `checked`. States: off, on, hover (accent outline, hover fill when on), focused (focus ring), disabled (subtle outline, disabled knob, no input). The knob moves in `motion.fast`.
- `Select` is drawn as a field (mockup E's drop-downs): `color.surface.sunken` with a `border.subtle` outline (`border.strong` on hover and while open), the chosen option left-aligned and elided, and a `chevron-down` at the right; role combobox with "<label>: <option>" as its name. Click, Return, Space or Down opens a menu drawn with the theme under the field (`surface.raised`, `border.subtle`, `radius.md`), at least as wide as the field and `size.menu.sm` when the field is narrower. It scrolls after `size.select.list-h`. The highlighted row is a `surface.overlay` plate; the chosen option is bold with a check icon. Up and Down move, Return or Space chooses, Escape closes. With no option chosen it shows its `placeholder` (such as "Choose a kind") in `text.secondary`, which is also the accessible value.
- `SegmentedControl` is a sunken track (`color.surface.sunken`, `border.subtle`, `radius.md`) with the options side by side; the chosen one is a raised plate (`color.surface.overlay`, no extra outline), bold and checked for screen readers, the others in `color.text.secondary`. The track stretches to fill its row, as `Tabs` does, and the options share that width. Each option is a button reached by Tab.
- `SizeNest` picks one fixed picture size. The frames share the top-left corner of one well (`surface.sunken`, `radius.sm`, `size.menu.sm` wide, 16:9, or that wide side as the height when `portrait`). 4K fills the well, 1440p is two thirds, 1080p is half and 720p is one third, each a `surface.raised` plate with a `border.strong` outline. The largest is painted first, so a smaller frame sits on top and the pointer hits the ring around it. The well stays at the left. To its right, in the rest of the row: a `type.caption` line naming the hovered frame, or the chosen one when nothing is hovered ("1440p · 2560 × 1440"), then any size that is not one of the four as a dense checked `Button` ("This display", "Custom"), then the caller's fields (width and height, or a long side). No words are drawn inside a frame. Hover or keyboard focus fills that frame with `accent.subtle` and an `accent` outline. The chosen frame stays that way, and is checked (U7). States: rest, hover, focused (focus ring), disabled (`border.subtle`, `surface.sunken`, no input). Tab reaches each frame and each extra; Return or Space picks it. The fill moves in `motion.fast`.
- `IconButton` is the icon-only button (ghost, dense, square). Its `name` must be set and becomes the accessible name (Slint cannot enforce required properties; an accessibility-tree check is a follow-up).
- `SplitButton` is a command button with a ▾ part at its right edge, behind a `size.border` divider (`accent.hover` on primary, `border.subtle` on secondary), in one shape (`radius.sm`, `size.control.md` high). Kinds: primary and secondary, as Button. States: rest, hover (per part: `accent.hover` or `surface.overlay`; checked wins over hover, as in Button), keyboard focus (per part, the focus ring), checked (secondary: `accent.subtle`), disabled (the command part only, drawn on `surface.base` in `text.disabled`; the ▾ part keeps its fill and ink and stays usable). No pressed visual, as Button. The ▾ part has its own accessible name and tooltip (`menu-name`) and may show a short mark before the ▾ (`menu-text`, `type.caption` size, the button's text colour) with its meaning as the accessible description (`menu-description`); it is announced as expandable. Return or Space on the ▾ part opens the menu. First use: Go live and Record with a vertical canvas (ADR-0093 decision 6).

### Toast

The notice card for a one-off message (U18): an undo after closing a guarded panel or deleting a source, an automatic workspace switch, and the error bar. It sits centred, the error bar under the frame and the others along the bottom. It is one control tall (`size.control.md`, plus its padding and the outline) and at most `size.toast.max` wide; a longer message elides, and the card does not grow with the window. The fill is `color.toast.surface`, kept quiet, and the outline is `color.toast.edge` at `size.toast.border`, with a `size.toast.rail` mark of the same edge colour down the left. While it is counting down, the seconds left sit at the right end, after a gap past Dismiss, in a chip filled with `color.toast.edge`: a filled `hourglass` and the seconds, both in `color.toast.surface` ("8 s", and "8 seconds left" for the accessible name). A `warning` icon marks a failed action and an `info` icon a notice; an undo uses `undo`. The words are `text.primary`. The icon, the words, the buttons and the countdown chip are centred on the height of the card. Undo, when there is one, is a primary button with an `undo` icon; OK on the first-close notice is a primary button with a `check`; Dismiss is secondary with a `close` icon. Tab reaches the buttons; Return or Space activates the focused one. Colour is not the only signal: the icon, the words and the seconds say what it is.

It closes when Dismiss is pressed or when `delay.toast` has passed, whichever comes first. The seconds step every `delay.toast-tick`. A new notice, even with the same words, starts the time again. The first Close that leaves RBS running (ADR-0056) uses the same card without a countdown: OK and Dismiss hide the windows, so it waits for one of them. The card exists only while a notice is showing.

### LibraryRow

The Library panel (ADR-0075; applying a look and adding a sample are unchanged, the arrangement is this section). A `SegmentedControl` at the top switches Style and Add, and in Add a second one switches Background and Frame. The list follows Filling a row, so both tracks take the panel width and each option shares the track. The look row is a rectangle of that width: its Select stretches and Add stays at the trailing end. The list and the groups inside Style and Add use `size.section.gap`, so the tracks, the hint, the look row, the shape and the filters are not packed together. Filter rows use `size.field.gap`. Add copies the chosen look onto the selected source: a filter of the same kind is replaced, a shape look writes Shape and border. Under it, the source's filters use the same row as the Filters tab (`FilterRowView`: on or off, move up, move down, remove) plus a gear that opens Properties with that filter selected. When the item is not a plain rectangle, Shape and border sits above the filters, apart by `size.section.gap`, on `surface.sunken` with a `border.subtle` line: a caption Shape, the name, and a gear placed at the trailing end of the plate. The plate sets `width: 100%`, as a filter row does: without that, the plate paints the full width while `parent.width` stays the width of the words, and the gear sits beside them. It has no checkbox and no remove, so the picture cannot be flattened back to a rectangle from this list. Filter rows stay `size.control.lg` high and `size.field.gap` apart; the name stays on one line when it fits and wraps only when it does not, and their buttons stay on the right. A source with no picture cannot take a look. On Add, pictures and shapes are different categories, so `size.section.gap` separates them and Shapes starts with a `SectionTitle` (the same rule as a Properties section). Add starts with Choose a PNG file (an image source, fitted inside half the canvas and centred; PNG only, the image source's format). Background or Frame is a two-column grid of the sample pictures except `lower-third` (its words are part of the picture, so the panel does not offer it). Each cell is a button, the picture and one elided caption. The picture well is at most `size.library.thumb-w` wide and `size.library.thumb-h` tall, and never wider than its column. Shapes is a two-column grid of icon buttons (`size.field.gap` between cells). Circle, Square, Rectangle, Ellipse, Triangle and Arrow each share a cell with another short name: an outline icon and the name on one compact row, at least `size.control.lg` high, wrapping to about two control heights only when the name does not fit. Rounded rectangle takes the full width of the row under them. Each adds a colour source, centred, about 0.28 of the shorter canvas side (a rectangle, a rounded rectangle and an ellipse are 1.6 times as wide; an arrow is 1.8 times as wide and 0.9 times as tall), fill `#2f6fed`, and Properties opens on Shape and border. Square is a rectangle with no corner radius; Rounded rectangle uses radius 32. The triangle's tip is the top edge of the box; the arrow points at the right edge. A row or cell is a `surface.overlay` plate under the pointer, `radius.sm`. Its label is the whole accessible name. `frame-thin` and `frame-thick` are added as a transparent colour with a border, so the thickness is that source's border width.

### AudioMeter

The meter of rule U16, used alone and inside AudioStrip. Logic in `rbs_ui::meter` (toolkit-neutral, tested without a window).

- **Scale:** dBFS from -60 (floor; lower levels show an empty bar) to 0, linear in dB. Labelled marks at 0, -6, -12, -18, -24, -36 and -48 dBFS, drawn as static text and ticks.
- **Zones:** the lit bar is `color.meter.low` below -18 dBFS, `color.meter.mid` from -18 to -6 and `color.meter.high` above -6. The zone marks are on the labelled scale, so a zone is never shown by colour alone (U7).
- **Peak hold:** a 2 px line at the highest level of the last 1.5 s, then falling at 20 dB/s; never below the bar. It takes the colour of its zone.
- **Clip indicator:** a box at the end of the bar, outlined while not clipped and filled with `color.meter.clip` once a level reaches 0 dBFS. It stays lit until the operator resets it (click, or the strip's reset command); filled versus outlined is the non-colour cue.
- **Orientation:** vertical (grows upward) or horizontal (grows rightward).
- **Rates:** levels update at 30 Hz while the meter is visible and its audio is active, not at all otherwise (P13, `UpdateRate` of the panel).
- **Accessibility:** one element per meter with role progress indicator, the channel's name as its label and as its value the highest level since the last update in whole dBFS, updated at most once per second (screen readers do not need 30 updates per second). The level is rounded down, so it never reads higher than it was, and capped at +24 dBFS. Text: one Fluent message `meter-value` with variables `$db` (whole dBFS; absent below -60 dBFS) and `$clipped` (`yes` or `no`) and selectors on both, so each language orders the parts itself (English: "-12 dBFS", "silent", "-12 dBFS, clipped"). Messages are never concatenated. `rbs_ui::meter::Meter::take_report` gives the value, `AccessibleLevel::english` the English text until Fluent strings exist.
- **Rendering:** the toolkit draws the static parts (bar background, scale, labels, the clip indicator's outline) and owns the accessible element. The moving parts (lit zones, peak line, filled clip indicator) are drawn by a native compositor layer where one exists (macOS: `rbs_app::native::MeterBridgeLayer`, [ADR-0035](../adr/0035-meters-as-native-layers.md)), so meter updates do not make the toolkit redraw the window; elsewhere the toolkit draws them too. Both paths take their geometry from `rbs_ui::meter::MeterView::frames` and their colours from the theme's tokens. Toolkit content drawn over a meter bridge (menus, popovers, dialogs) hides the layer while it overlaps, as for the preview layer.

## Component standards

Every panel and window is built from these components with these shapes ([ADR-0076](../adr/0076-component-standards-and-panel-spacing.md)); a panel does not draw its own titles, tabs or action buttons. The owner's goal: a user can read a window and see its categories at once.

| Job | Component | Fixed shape |
| --- | --- | --- |
| Switch between views of one thing (Transform, Filters, Audio) | `Tabs` | One sunken pill filling the row (`color.surface.sunken`, `border.subtle`, `radius.md`, `size.control.md` high), inset in the panel. Each title shares the track. Chosen tab: a raised plate (`color.surface.overlay`, `radius.sm`), `text.primary`, `type.label` bold. Others: `text.secondary`, a `surface.raised` plate under the pointer. No underline. Text only (an icon only with a title). The row is one focus stop (Tab enters and leaves it); Left, Right, Home and End choose a tab and the focus ring follows it. Tabs are role tab in a tab list, the chosen one reported as checked. Arrow keys are fixed Left and Right (no right-to-left handling yet) and a tab cannot be disabled yet. |
| Pick one value of a few (Shape) | `SegmentedControl` | Sunken track; never used to switch views. |
| Pick a fixed picture size | `SizeNest` | One 16:9 well. 4K, 1440p, 1080p and 720p share its top-left corner at their pixel ratio. The line under the well names the hovered or chosen size. Anything else is a dense button. |
| Start a group of fields | `SectionHeader` | Title in sentence case, `type.label`, `text.primary` (ADR-0112 decision 5). No rule after the title. `size.section.gap` above (none for the first), `size.field.gap` below. Optional `chevron-down` (open) / `chevron-right` (closed): the whole row is a button with its expanded state and a `surface.overlay` plate under the pointer; a closed section draws nothing and takes no room. |
| A label with a field | Field / `NumberField` / `Toggle` rows | `size.field.gap` between rows and between the two columns of a grid; the label in `text.secondary` inside or above the field. |
| An explanation | Hint text | `type.caption`, `text.secondary`, word-wrapped, `size.field.gap` above, never touching the next section's header. |
| An action | `Button` | `primary` (filled `accent`, a hairline of `accent.hover` along the top while it rests, one per window or section), `secondary` (a `surface.sunken` fill and a `border.strong` outline at rest, so it reads as a button before the pointer reaches it; hover raises a `surface.overlay` plate; a checked one uses `accent.subtle`), `ghost` (no fill and no outline until the pointer raises a `surface.overlay` plate, unless `framed`, which keeps the `border.strong` outline at rest — the mixer mute), `danger` (ink and the `trash` icon in `color.state.error`, the same plate on hover, never a box and never bare coloured text), `live` (only to stop a live or recording output, filled with the fixed live colour and a `text.on-live` hairline). Colours are the button's; a caller never sets one. |

**Interaction patterns** ([ADR-0094](../adr/0094-ui-interaction-patterns-and-tabler-icon-set.md), components added by the migration steps listed there; until a component exists the rule applies to new and edited UI by the nearest existing component):

- `InfoHint`: an `info` icon button after a label (hit target at least 24 px); press opens an in-window overlay (not a `PopupWindow`) with the explanation and "Default ... · range ..."; Escape or an outside click closes it and focus returns to the button.
- `Tooltip`: one host per window, shown on hover after `delay.tooltip` and at once on keyboard focus, kept while the pointer is over its control or over it, dismissed by Escape; it is the name of an icon-only control and the reason a disabled control is disabled. Drawn on `surface.overlay` with a `border.subtle` hairline. Only the active window shows one. It closes when its window loses the activation (another window opens or takes the focus), on a press or a scroll anywhere in the window, when the pointer leaves the window, and when the pointer moves off its control and the tooltip, also when the control went away under the pointer or the move is onto a control without a tooltip (`rbs-app` `window_events`). Focus left by a click does not keep it, and focus that comes back with its window does not show it.
- `StatusLine`: icon, one line and an optional action; info, success, warning or error; space reserved or overlaid while live, never moving controls.
- `FeatureSection`: feature name flush left, then `InfoHint`, fold chevron and `Toggle` on the right; on expands the parameters (flush left, same edge as the name) and shows the chevron, off collapses them and hides the chevron; parameters are kept while off.
- Controls by option count, one menu system (`CommandMenu`), icons instead of buttons for universal actions, and the Tabler icon set: see the ADR, rules A to F.

Spacing: a panel's content has `size.panel.pad` on every side. Panels use `size.panel.pad`, `size.section.gap` and `size.field.gap`, not `space.*`, because these have floors (8, 12 and 6 px) no theme can go below; `space.*` stays for small parts inside a component. Section order in a panel puts the most used section first, and the destructive one (Delete source) last in its own section ("Remove"), so it is never beside a common action. A static title with no collapse (the Filters tab's) is the private `SectionTitle` in `studio.slint`, the same look as plain text for screen readers, until the library has a plain header. Slint has no heading role; headers are not exposed as headings yet. A `danger` Button always shows the `trash` icon and a caller cannot turn it off; its ink uses `color.state.error`, which has the contrast rules for error text on every surface (the same colour as `color.action.destructive`). The icon is the cue besides the colour.

**Filling a row.** A scrolling panel (`Flickable`) gives its list the panel width only when the list does not set `width` and the flickable does not set `content-width`. Properties is the pattern. `width: 100%` on that list is the preferred width of the contents: a short control stays short, and a long label looks full. A control that fills the row sets `horizontal-stretch: 1` and does not set `width` (a width binding turns stretch off). `Tabs` and `SegmentedControl` do this. The track's own layout then sets `width: parent.width`, because a layout inside a rectangle stays as wide as its labels until it is given the track. Do not set a field's `preferred-width` or `min-width` to `0px` to make it grow: with no extra space the field disappears. Give the row the panel width first, then `horizontal-stretch: 1` on the field.

Collapsible sections: a section's open or closed state is kept by section id while the app runs, shared by every window that shows the panel (saving it in the workspace file comes later); sections start open, and a panel may start a rarely used section closed when its spec says so.

The main window is a frame around a centre and three areas ([ADR-0049](../adr/0049-main-window-areas-panel-states-and-sizes.md)). The picture shows the built-in Edit workspace.

```
+--------------------------------------------------------------------------------+
| Menu bar: File Edit View Scene Source Output Tools Window Help                 | (macOS: system menu bar)
+--------------------------------------------------------------------------------+
| Toolbar (per workspace, customisable): mode | + Scene  Add source | Studio mode |
|   Transition | screenshot marker replay ~ search [L][B][R] Go live Record [live indicator] |
+--+------------+--------------------------------------------+---------------+--+
|e | Left area  |  Centre                                    | Right area    |e |
|d | Scenes     |  Preview (studio mode: Preview | Transition | Inspector     |d |
|g |------------|  rail | Program)                           |---------------|g |
|e | Sources    |                                            | Filters (coll.)|e |

|t +------------+--------------------------------------------+---------------+t |
|a | Bottom area: Mixer (collapsed: one-line meter strip)                    |a |

+--+-------------------------------------------------------------------------+--+
| Status bar: live/rec state + time, bitrate, dropped frames, CPU, GPU           |
+--------------------------------------------------------------------------------+
```

- **Frame.** Toolbar row, content, status bar. The menu bar exists only on macOS, in the system menu bar; Windows and Linux use the RBS menu (ADR-0069). On Windows the toolbar row is also the title bar (ADR-0071): the OS caption is removed and the row ends with the window buttons; macOS and Linux keep the OS title bar. The live indicator (U4, U21) is at the right end of the toolbar row's end group on every platform, before the window buttons on Windows. The toolbar can be hidden (View › Toolbar): its items go and its row stays as a slim strip that holds the live indicator, so the indicator never moves and never shares a row with the menu bar (a native Windows menu bar and Slint's drawn Linux menu bar cannot hold other elements). The menu bar cannot be hidden. The live indicator is compact: idle it is not shown at all (the status bar says "Not live · not recording", so the state is still in words, U4), and the toolbar's last item sits at the row's right end. While live or recording it is a small chip in `state.live` (`radius.sm`, `type.caption` in the label weight, `text.on.live`) with a `dot` and "REC", "LIVE" or "LIVE · REC". While RBS sends to the virtual camera (ADR-0066 decision 12; an app may be showing it to other people) the chip shows too, with "CAM" ("CAM" alone, or "LIVE · CAM", "REC · CAM", "LIVE · REC · CAM"); the camera has no duration, so it needs no tick. The duration and the outputs are in the status bar: a `dot` in `state.live`, then "Recording 0:00:07 · <file>", "Live 0:12:30 · not recording · <host>" or "Live and recording 0:12:30 · <host> · <file>", followed by " · virtual camera on" while it sends ("Virtual camera on · not live · not recording" when nothing else runs). The indicator's accessible name holds the whole text ("Live status: Recording 0:00:07 · <file>"). While the status bar cannot be hidden, the frame does not repeat the duration and outputs; a hidden status bar (U21) will need the indicator to show them again. Screenshots: `docs/ui/screenshots/live-indicator-{dark,light,high-contrast}.png` (not live, recording, live and recording; toolbar row and status bar).
- **Areas.** `left`, `right` and `bottom` hold panels around the `centre`. Each has a size in logical pixels (width, or height for `bottom`) and can be hidden and shown with its toolbar toggle or the View menu (no shortcut is bound by default, U21); hiding keeps its panels and size. Hide side panels (`ui.area.hide_all`) hides all three and Show side panels (`ui.area.show_all`) shows them again. An area that is visible but empty takes no space. The bottom area spans the full width under the other three. The centre always exists and takes the remaining space; with every area hidden and an empty centre it shows an empty state with Show areas and Reset layout (U10).
- **Edge tabs.** Auto-hidden panels show as tabs on the left, right or bottom window edge (outside the areas, inside the frame); there are no top edge tabs, so nothing sits between the toolbar and the content. An edge with no auto-hidden panel takes no space. Edge tabs stay visible when their area is hidden. Floating windows have no areas: their stacks can collapse but not auto-hide.
- **Look** (implemented, matching the owner's chosen mockup E): the content sits on `surface.base`. Each tab stack is a card: `surface.raised`, `radius.lg`, with a `border.subtle` line only while `Theme.panel-outline` is on (ADR-0112 decision 3: the panel colour is closer than 1.15:1 to the window ground, as in High contrast), with gaps of the layout's divider thickness (6 px) between cards and around them; a divider is invisible until hovered, dragged or keyboard-focused, then drawn in `accent`; releasing the pointer leaves it unfocused. A card's header is `size.control.lg` high and the same surface as the card, with no rule under the row. A collapsed stack draws only that title row, and an area whose stacks are all collapsed is only as tall or wide as those rows; it keeps its saved size for when a stack expands. One panel shows its name as plain text, with no underline. Two or more panels in the stack are tabs: text, the shown one underlined in `accent` for the width of its title (`size.tab.indicator`, no tab background), and on the right Auto-hide (`pin`), Collapse or Expand (`chevron-down` / `chevron-right`, reporting expanded or collapsed) and the panel menu (`more`, opening under the button); a right click on a tab opens that menu too, under the tab row's start. The centre's last expanded stack shows no Collapse and a centre of one stack no Auto-hide. Edge tabs are cards `size.control.md` wide with the panel's icon and its title turned along the edge; clicking one (or Enter or Space) slides its panel out over the dock area along that edge, `size` wide, as a card with Pin and Hide; Escape, Hide, the tab again, or a click on the dock outside the slid-out panel slides it back, and so does another command (a toolbar button, a menu item). Pinning, closing or adding an auto-hidden panel slides it back too. Opening a panel (`ui.panel.open`, including Properties from a source's menu) shows it: a hidden area is shown, a collapsed stack expands, and an auto-hidden panel slides out over the dock. The slid-out panel is reported to the preview layer like a toast (ADR-0054). Not yet: hover to open with its delay and grace period, and sliding animation. **Dragging a tab** (ADR-0049 decision 5, inside one window, not while the layout is locked) moves its panel: over a stack, its title row or middle drops the panel in as a tab, and the outer 30 % on each side puts it in a new stack on that side, sharing the stack's place half and half (one layout undo step); within 16 px of the dock area's edge it goes to that edge of the window (in the main window, that area's outer side). `rbs-ui` (`frame::drop_target`) decides the target; the shell shades the part the drop would fill in `accent.subtle` with an `accent` border, reported to the preview layer like a toast. Dropping a panel where nothing would change shows no guide. Tearing off to a new window and dropping into another window stay with the panel menu's Float and Dock for now. The toolbar row is `size.control.md` plus `space.1` above and below on `surface.base`: the Workspace picker as a bordered button reading "Workspace <name>", commands as ghost buttons with their icon before the title, area toggles as their icon alone (tinted `accent.subtle` while on, the title as accessible name), Go live as the one primary button and Record as a secondary button with a `dot` in the live colour. The status bar is `size.control.sm` plus two borders high on `surface.sunken`: live and recording state with duration in words, the stream's connection text, then on the right Output profile and Scene collection (each opens its menu, with New, Duplicate, Rename, Delete, Import and Export) and the canvas size and frame rate. It shows values the app already has and polls nothing (P13); bitrate, dropped frames, CPU and GPU come when a cheap source for them exists. Properties groups its fields under section captions (`type.caption`, uppercase, `text.secondary`): a header row with the source's icon, name and type, then Position and size, Crop and Shape and border; the number fields carry their label inside on the left in `text.secondary` (X, Y, W, H, Left, Right, Top, Bottom) with the value right-aligned. A Mixer row in the rows arrangement is two lines: the kind's icon, the name, the level, the clip box and the icon buttons on the first, then the meter and the fader across the row. A column puts the name on top, the meter and fader in the leftover height, and the readout with the icon buttons under the fader, leaving out any control it does not show. Text fields draw the caret 2 px wide in the selection colour (`accent`, selected text in `text.inverse`) so it shows on `surface.sunken` in every theme.- **Commands.** Every command is in the menu bar; the toolbar only holds a chosen subset (see Commands, menus and the toolbar).

## Studio panels (first version, ADR-0041)

The app runs the studio in its own process on a control thread (`rbs_app::studio_host`, ADR-0041 decision 7). The UI sends commands and receives updates; it never calls the studio. The studio runs one canvas from the scene collection; the Sources panel shows the scene being edited: the program scene, or the preview scene in studio mode (ADR-0061), while the Mixer always plays the program scene's sources.

- **Program and Preview.** Outside studio mode both panels show the scene on air: the picture goes to Program when that panel is open, otherwise to Preview, and the other panel says where the picture is. In studio mode (ADR-0061) Program shows the program scene and Preview the preview scene, each on its own picture (the studio's `scene_preview`); editing on the picture (below) and the selection marks belong to Preview only, so the scene on air is never edited by a stray drag. On Windows both pictures share the window's one DirectComposition target (gpu-compositor spec, several layers in one window). The picture is the studio's preview surfaces (1280 x 720 for a 16:9 canvas; the ring follows the canvas rate: 5 surfaces at 30 fps and 6 at 60 fps on macOS, 5 at both on Windows, and never more than 8) shown as a native layer over the panel's content: a Core Animation layer on macOS (ADR-0034) and a DirectComposition visual on Windows (ADR-0036). It is letterboxed, and a new frame changes only the layer. The picture never disappears behind something drawn inside the window (ADR-0054): every open Slint `PopupWindow` (read from Slint with the place Slint gave it, so a new popup needs no code of its own), the bottom toast and the error bar (they report their rectangles in `Shell.bottom-toast` and `Shell.top-toast`) are passed to the layer as covers before every redraw of the main window. A cover beside the picture changes nothing; one over it is cut out: the picture is shown as tiles around it (rectangular clips sharing the surface: Core Animation layers on macOS, DirectComposition visuals on Windows), and selection marks are drawn around it. The first-close notice of ADR-0056, in the error bar's place, is a cover too. The layer is also hidden while the panel is not in the main window. A panel that cannot show the picture says why in words: the studio is starting, the platform has no preview yet (Linux), the session cannot show the layer (for example remote desktop), the picture is in the main window, or the studio stopped. Accessible role: image, named after the panel. **Editing on the picture (ADR-0048):** a press on a source selects the topmost one under the pointer (outside every source clears the selection) and dragging moves it; the selected source shows a 1 px `color.accent` outline and eight 8 px handles (`color.accent` border, `surface.raised` inside; outline only when the box is smaller than three handles on screen). Corner handles resize keeping the aspect ratio, Shift (held at the press) resizes freely; edge handles change one side; a drag never makes a box smaller than 8 canvas pixels or turns it inside out. Moved edges and the box's centre snap to the canvas's edges and centre within 8 logical pixels unless Ctrl (Cmd on macOS) is held at the press. Alt (Option on macOS) held at the press on a handle crops instead of resizing (ADR-0058), once the source has shown a picture: each moved edge cuts or uncuts source pixels at the box's scale, corners move both of their edges, the crop never goes past the picture's edge and leaves at least one pixel, and all crops of one drag are one undo step ("Undo cropping …"); crops go to the studio with the same one-at-a-time numbering as boxes. With the panel focused, arrow keys move the selected source by 1 canvas pixel (Shift: 10) and Escape clears the selection. Delete or Backspace asks before removing the selected source from the scene, including when it was selected only to drag it: the Sources panel opens if it is closed and that source's row shows the same question as Delete on the row (a second Delete or Return there confirms, Escape cancels). The question is not drawn on the picture, because the live picture covers the panel. The marks move with the pointer at once; the studio gets at most one new box at a time (the newest per source waits, each box is numbered and the studio answers every one, even an unchanged or refused box), so the picture follows within a round trip and a refused box puts the marks back where the studio has the source. With a preview layer the layer draws the marks (they show over the live picture); where no layer shows the picture the toolkit draws them over the panel.
- **Sources.** The panel lists the scene's sources, top first, one row each (`size.control.md` high, `space.1` apart): the kind's icon (`monitor`, `window`, `camera`, `mic`, `speaker`), the name, and on the right the Show or Hide button (`eye` / `eye-off`, "Hide <name>" / "Show <name>", reporting checked while hidden). A hidden source stays in the scene but is not drawn; its icon and name use `text.disabled` and the accessible label adds "hidden"; showing or hiding is one undo step ("Undo showing or hiding …"). The type ("Screen capture", "Window capture", "Camera", "Audio input", "System audio", "Application audio") and the state in words ("Running"; "Not shown, closed" for a video source the user deactivated, or with no picture or recording to feed, which is not opened (P13); or "Not running: <reason>") are in the accessible label. Hiding a source does not deactivate it: the device stays open, so showing it again is immediate. Active in the source's menu (`source.active.toggle`, checked while the device stays open) is what releases it. a row whose source is not running shows "<type> · <reason>" in `state.error` under the name. The list order is the drawing order: a source is drawn over every source below it. Move up and Move down are in the row menu (`item.move`, protocol 1.32) and, on a focused row, Alt+Up and Alt+Down (video sources only; disabled when no source with a picture lies that way). Delete or Backspace asks first, for a source and for a scene: the row shows the question, a trash icon (Remove or Delete, named in its tooltip) and a close icon (Cancel), a second Delete or Return confirms, and Escape cancels. A move goes over or under the next source with a picture, skipping sound-only sources, which draw nothing; the button is disabled when there is none that way. A row of a video source can also be dragged onto another row of a video source: it takes that row's place (one undo step, "Undo the layer change of …"), and an `accent` line along the row it would go to shows where. Double-clicking a row opens the Source settings window when the source has one (screen, window or camera; the same as Source settings… in its menu); otherwise it only selects the row. Rename stays on F2, the row menu and the Properties name field. Clicking a row, or Return or Space on a focused row, selects it: a `surface.overlay` plate, an accent border of `size.border` and the name in the title weight (not colour alone: the border, the weight and the accessible selected state). The same plate, border and weight mark the scene being worked on, the selected filter, the Settings section in use and the selected theme. One selection is shared by every window; the source an Add source adds is selected, and a deleted one is no longer. Add source is the `plus` button in the Sources card's title row (the panel's own action, before Auto-hide); the empty state offers Add source too. Undo and Redo are not in the panel: they are app-wide, in the Edit menu and on the keys.
- **Add source (core flow, 3 interactions).** Add source opens a menu of the types (only types this system's adapters provide, ADR-0094 rule B1); a type opens the **picker**, a small searchable dialog over the window that lists what it captures (the OS's displays, windows, cameras or endpoints, the default marked "default") with a filter field that holds the focus. The source is added on top: a screen or window is as large as fits on the canvas with its own aspect ratio, centred (a 21:9 display gets bars above and below on a 16:9 canvas), at the canvas rate; a camera asks for 1280 x 720 at 30 fps and sits 4/15 of the canvas wide in the bottom-right corner; audio is placed in the scene only so that it plays. A name the collection already uses gets " 2", " 3" and so on. The picker has no live preview yet; the new source is selected, with handles on the picture.
- **Properties.** Shows the selected source: its name and, for a video source, X and Y (the box's top-left corner) and Width and Height, as NumberFields in canvas pixels, with a hint saying so. A value applies when confirmed with Return or by leaving the field; Up and Down arrows change it by 1 (Shift: 10) at once. Text that is not a number goes back to the current value; a size of 0 is refused with an error. The fields change the layout the canvas shows: the item's own layout for this canvas if it has one, else its default layout. Rotation is a Slider under the flip and fit buttons (0 to 360 degrees clockwise about the box centre, the number shown beside it; Left and Right change it by 1 degree, Shift by 10, one drag is one undo step, double-click returns it to 0). The 90 degree buttons stay above it. A refused change is said in plain words in the error bar. A sound-only source says it has no place on the canvas. A stream that fails (the server refuses, reconnecting gives up) leaves its recording running: it is the copy of what viewers missed, and from then on it is the user's to stop, as is a recording whose stream ended that way; stopping the recording while live never ends the stream. A recording that cannot start (the folder, no encoder) says why under Record and leaves the stream running. While the setting is on, a notice under it says what it costs: with the same encoder picked and the same video settings in Recording and Stream the two share one video encoder (ADR-0047 decision 3) and the extra load is small, otherwise every frame is encoded twice and the notice says so and how to share one; and the disk space the recording takes per hour of streaming at the Recording bitrate (video plus audio; not shown for constant quality, where it says only that the recording needs free space). Kept as `auto_record` in the output profile's `stream` section. Then the same encoder fields as the Recording section, with their own values and the stream's defaults (CBR 6000 kbit/s, keyframe every 2 s, which most services require, balanced preset, audio 160 kbit/s); constant quality is not offered, since services need a bitrate. The video bitrate row uses the same warning as the Recording section when the chosen rate is below the recommendation for this stream's output size. Changes apply to the next stream and are saved at once; while a stream runs they are disabled and say so. Kept in the `stream` section of the output profile in use (ADR-0051; a first start takes it from `stream.toml`) (`format_version = 1`, `server`, `key_saved`, `reconnect`, `auto_record` (absent: off), optional `srt_latency_ms`, and an `[encoding]` table with the Recording section's encoder fields and names); a section that cannot be used gives the defaults and a note in the section. Starting a stream without a server or saved key does not open anything and says what is missing; the note then follows the settings (it names what is still missing and goes once nothing is). Screenshots: `docs/ui/screenshots/settings-stream-{dark,light,high-contrast}.png`.
- **Settings window, Remote control section (U17, ADR-0044).** Lets other apps on this computer (Stream Deck, panels, scripts) control RBS through the control API. "Allow remote control" (a Toggle, off by default; while off nothing of the API exists). A status line under it: where apps connect (`ws://localhost:<port>`, "Other computers cannot connect"), or in the error colour why it is not running ("another app is using port 4456" with what to do, or that the studio did not start). Port (a TextField, 1024 to 65535, default 4456; confirmed with Return or by leaving the field; a refused value is put back with a note; a change disconnects connected apps, said in the hint). Access tokens: Name (TextField) and Access (SegmentedControl: View only, Control (the default, for panels), Full control, each explained in one line), and "Create access token". A new token is shown once in a bordered group with a read-only TextField, Copy (primary) and Done; it is gone after Done or when the Settings window closes. The list shows each token's name and access with "Revoke"; revoking disconnects the apps using it and shows "<name> was revoked" with Undo, which puts the same token back (until another token is made or the window closes). Name problems (empty, longer than 64 characters, taken) are shown under the button. Kept in `remote-control.toml` in the config directory (`format_version = 1`, `enabled`, `port`, `[[tokens]]` with `name`, `scopes`, `hash`: only SHA-256 hashes); on Unix the file is mode 0600, and a file other users can write is refused. An unreadable, invalid or refused file leaves remote control off, is moved to `remote-control.toml.refused`, and the section says why. Screenshots: `docs/ui/screenshots/settings-remote-control-{dark,light,high-contrast}.png`. **Network access (ADR-0046)**, under the port: "Allow access from other computers" (a Toggle, off by default, disabled while remote control is off), with a hint to turn it on only on trusted networks and that a refused firewall prompt blocks other computers without notice. While on: a status line (where other computers connect, `wss://<name>.local:<port>` or the computer's address, or in the error colour why they cannot, such as a missing key, with "New key" as the fix); "Key pin" (`sha256//...`) and "Certificate fingerprint (SHA-256)", each a read-only TextField with Copy, the fingerprint's hint saying where the certificate came from and when it was just renewed; "Allow remote admin" (a Toggle, off by default; a change restarts the server, said in the hint); "Certificate" (a SegmentedControl: Made by RBS, Your own; the hint says browser panels need the user's own certificate); for Your own, "Certificate file" and "Key file" (TextFields, full paths) and "Use these files", refused with a note when they cannot be read or do not match; for Made by RBS, "New key…", which asks first in a bordered group ("Make new key" primary, "Cancel"), since it cannot be undone. While other computers can connect, the frame bar shows "Reachable from other computers" in every workspace. Screenshots: `docs/ui/screenshots/settings-remote-control-network-{dark,light,high-contrast}.png`.
- **Errors.** The studio not starting or stopping (no usable GPU, a studio node failing for good) shows in the error bar and in the panels. The error bar is the notice card at the top of the window: it closes on its own after `delay.toast`, or sooner with Dismiss, and shows the seconds left. A hardware GPU is preferred; without one the app uses a software adapter.
- **Checks without devices.** A build with the `demo-sources` feature and `RBS_DEMO_SOURCES=1` adds the reference adapters (synthetic display, camera, microphones, loopback) for screenshots and UI checks. `crates/rbs-app/tests/studio_host.rs` covers the host on those adapters: add, unique names, delete and undo, moving a source up and down (past a sound-only source), setting its box (and refusing a zero size), undo and redo of every edit kind with a drag as one step, and shutdown. `crates/rbs-app/tests/studio_record.rs` covers recording through the host with fake encoders: the picked encoder only, automatic fallback, refusals (a running recording, an existing file, an unknown encoder) and a closed file after stop. `crates/rbs-app/tests/studio_stream.rs` covers streaming through the host with a fake RTMP transport: the key read from the store reaches the transport only, a missing key refuses before anything opens (a missing or invalid server is refused by the UI, `stream_profile` unit tests), connection changes reach the UI, one output at a time, and a clean end.

## Panels and workspaces (contract for U21)

Workspaces are client-side UI state. The desktop UI crate owns the panel model and the workspace format; the engine and `rbs-core` know nothing about them (P1).

### Where a feature's settings live

The inspector pattern (as in Figma, Blender, DaVinci Resolve and Visual Studio), so Properties stays short as features grow (owner question, 2026-11-06):

- **Properties is a compact inspector** of the selected item: the settings changed often, per item, at a glance (box, crop, shape and border). It is grouped in sections that collapse and remember their state; a search field comes once it has more than a handful of sections.
- **A feature that grows gets its own panel** (a dockable panel with an id, U21): the mixer, transitions, effects, a theme editor. Properties then shows only a one-line summary of it for the selected item and an Open button that shows that panel with the item selected; editing never happens in two places.
- **Exception: filter chains** (owner's design, mockup E; ADR-0062). They are edited only in the Filters tab of Properties, which stays short because one tab shows at a time; they move to an `rbs.filters` panel only if the tab needs more than one screen. **Mirrored live controls** (volume and mute) show the same single value in the Mixer row and the Audio tab, as on a hardware desk; that is not editing in two places.
- **Rare, complex or one-time work goes to a dialog or a Settings page** (U17): output, encoder and stream settings, import and export, first-time setup.
- Rule of thumb: touched often while live goes in a panel; touched rarely goes in a dialog or Settings. A Properties section that needs more than one screen at the default window size, or needs a large working area (a curve editor, a preview of its own), moves to its own panel.
- New features (crop, filters, themes and later ones) state in their spec where their settings live by these rules.

### Panel model

- A panel id is `<namespace>.<panel>` in lowercase ASCII letters, digits, `.`, `-` and `_`, at most 128 bytes, with optional parameters `?key=value&key=value` in the same characters. Each key appears once and parameters are stored sorted by key, so one panel has exactly one id.
- Every panel has a stable id (`rbs.scenes`, `rbs.sources`, `rbs.preview`, `rbs.program`, `rbs.properties`, `rbs.mixer`, `rbs.live-controls`, `rbs.transition`, `rbs.outputs`, `rbs.stats`, `rbs.library`, `rbs.status-bar`, plugin panels as `<plugin-id>.<panel>`), a title, an icon, a default dock position and an optional shortcut.
- Panels that can exist more than once take parameters in the id: `rbs.preview?canvas=vertical`, `rbs.program?canvas=horizontal`. Without a parameter they show the canvas being edited.
- A layout is a tree per window: splits (horizontal or vertical, with ratios) whose leaves are tab stacks of panels. Floating windows and projectors have their own tree or content plus their position.
- Each built-in panel declares how often it must redraw while visible: on change only (lists, properties, controls, `rbs.library`), at most N times per second (`rbs.mixer` 30 Hz, `rbs.stats` and `rbs.status-bar` 1 Hz), or at display rate (`rbs.preview`, `rbs.program`). `rbs.stats` shows each number as its own full-width row (the label, then the value) so a narrow panel never clips it; a group name is a title above its rows. The shell runs at most one redraw timer, at the fastest rate any visible panel or visible compact view needs, plus 1 Hz for the live indicator while live or recording, and no timer otherwise. Hidden tabs, closed panels, auto-hidden panels that are not out, panels in hidden areas, panels covered by a maximized panel and collapsed panels without a compact view never count.
- `rbs.program`, `rbs.live-controls` and `rbs.mixer` are guarded: closing them while live (directly or by closing their floating window) shows the undo toast of U21. Collapsing or auto-hiding them, hiding their area or covering them with a maximized panel shows no toast: one interaction brings them back.
- **Stack states** (ADR-0049). Panel commands (`ui.panel.collapse(id)` and the others) act on the stack that holds the panel. A tab stack in an area or the centre is:
  - `docked` (default);
  - `collapsed`: only its title row is shown, `size.control.lg` plus border high in a vertical split, a vertical strip as wide in a horizontal split. The strip shows the tabs' icons with their titles as tooltips (no rotated text) and has the accessible name of the stack's panels. The title row or strip has an expand button whose accessible state is collapsed or expanded. It keeps its ratio, used again on expand; the rest of its split takes the space. A split whose stacks are all collapsed shrinks to their title rows; an area whose stacks are all collapsed shrinks to their title rows and keeps its `size` as the size to restore. The centre keeps at least one stack that is not collapsed;
  - auto-hidden: it leaves the tree and becomes edge tabs: those of an area on that area's edge, those of the centre on the left, right or bottom edge nearest to its stack (ties: left, then right, then bottom). Several groups on one edge are drawn in file order. Hovering an edge tab for `motion.hover-open` slides the panel out without taking focus; a click, or Enter or Space on a focused edge tab, slides it out and moves focus into it. It stays out while the pointer is on the tab or the panel and for 300 ms after it leaves both, and slides back on Escape, when focus leaves it or when another edge tab opens; focus returns to the edge tab. A hover-opened panel has no focus: Escape goes to the focused widget first and closes the panel only if that widget does not use it. Edge tabs have the accessible role tab and report expanded or collapsed. Pinning docks the panel next to its anchor if the anchor is docked in the main window (collapsed counts as docked; an anchor in a floating window does not count), else at the outer side of the area of its edge (left, right or bottom), which is shown if it was hidden. The slid-out card's title drags like a tab, its menu is the panel menu, and Close closes the panel; Escape and a click on the dock slide it back without closing it. A dock drop accepts only a panel drag, so dropping a panel on a source row moves the panel.
  - **Maximize** (double-click a tab, Shift+Esc while a tab has focus, or the panel menu) shows one panel over the whole content until restored. It is not saved and is not a layout history step; neither is sliding an auto-hidden panel out or back. Covered panels count as hidden (U5).
- **Compact view** (amends U5, ADR-0049). A panel may declare a view drawn in its title row while collapsed, with its own update rate; it follows the same visibility rules as the full panel. `rbs.mixer`: one small meter and a mute button per audio source, meters at 30 Hz while audio is active. Panels without one show only their titles and do no rendering or polling.
- **Size limits.** Each panel declares `min`, `default` and `max` sizes on both axes in logical pixels; `max` may be a share of the window. Dividers move within the limits of the panels on both sides, double-click returns a divider to the default, and View › Reset panel sizes resets them all. Built-in limits (width x height where both matter):

  | Panel or area | Min | Default | Max |
  | --- | --- | --- | --- |
  | Left and right area | 200 px | 260 px | 40 % of the window |
  | Bottom area | 90 px | 200 px | 60 % of the window |
  | The Transition rail (ADR-0064) | 156 px between the pictures, 44 px below them | (fixed) | (fixed) |
  | `rbs.transition` elsewhere | 200 x 120 px | (fills) | (fills) |
  | `rbs.preview`, `rbs.program` | 320 x 180 px | (fills) | (fills) |
  | Auto-hide flyout | the panel's min | 320 px | 60 % of the window |

  - A tree's minimum is computed from its panels: the sum of its children's minimums along a split's axis and the largest across it. An area's minimum is the larger of its own (table) and its tree's; its maximum is the table's. The centre's minimum is its tree's (320 x 180 px; a studio split in studio mode puts its rail below the pictures when it is too narrow for the column, ADR-0064).
  - A split child may have a fixed `size` in logical pixels instead of a ratio share: it keeps that size when the window is resized and the other children share the rest by their ratios. Dragging its divider changes its `size`. When the fixed sizes do not fit, they shrink toward their minimums in step 2 of the conflict order below, together with the areas.
  - **Studio mode** is engine state: a canvas is in studio mode while it has a preview scene (scene model, `set_preview`), shared by every client. The registry toggle `canvas.studio_mode.toggle` (parameter `canvas`, default the canvas being edited) pairs `canvas.set_preview {canvas, scene}` (the program scene) and `canvas.set_preview {canvas, scene: null}`, methods of the control API from protocol 1.9 (ADR-0061). It is a live action and on no undo stack (ADR-0021). In studio mode a click on a scene in the Scenes panel previews it (the row is marked in `color.accent`; the scene on air keeps a neutral "Program" badge, and the red Live/REC badge shows only while streaming or recording), and `canvas.transition` (Ctrl/Cmd+Enter, the Scene menu, the rail) puts it on air. A transition keeps the preview scene in Preview unless Settings › General › "Swap scenes after a transition" is on (off by default; then the old program scene goes to Preview, ADR-0098). While the preview scene is the program scene (entering the mode, a click on the scene on air, or after a transition that kept it), the program is held as it was (ADR-0063): edits to the scene's items show in Preview only, and the transition puts them on air. The hold lasts while that scene is on air, also after another scene is previewed (ADR-0098), so previewing never puts edits on air. The held copy is never shown: no extra scene in the Scenes panel, the Sources panel or the saved collection; source settings (filters, volume, mute, sync offset) are shared and reach the program at once.
    - Studio mode never rearranges a workspace, and no workspace sets it ([ADR-0073](../adr/0073-pictures-area-and-studio-mode-switch.md)). A workspace may hold one **Pictures leaf** (panel id `rbs.pictures`) in the main window's centre tree: a fixed area, not a tab stack. It shows Preview alone outside studio mode; in studio mode Preview, the **Transition rail** and Program, the two pictures in equal halves. The leaf takes no tab (open, drop, move to a stack or edge find no stack in it; there is no drop guide over it), and cannot be collapsed, auto-hidden, floated or moved; closing Preview, Program or `rbs.pictures` removes it, and opening any of them (when neither is open as an ordinary panel) puts it back as a new first child of the centre. The rail is not a panel: between the pictures it is `rail_size` wide (48 to 240 px, default 88, plus a divider gap on each side), below them a 44 px row; when the leaf is too narrow for the column and two 160 px pictures, or shorter than 240 px, the rail is drawn below. `ui.layout.studio_rail {at}` (`between` or `below`) moves it: one layout history step, allowed on a locked workspace, refused with `conflict` when there is no leaf. A panel that is opened goes to the first tab stack of its default home area (Scenes and Sources left, Properties right, Mixer bottom), else the centre's first tab stack, never beside the pictures. Workspaces without a leaf show Preview and Program wherever they are docked as ordinary panels and have no rail. Both rail edges are drag handles, and up to 120 px the rail is icon-only (the Transition button shows its name and shortcut while pointed at or focused). `ui.layout.rail_size {px}` sets the rail's width (clamped to its limits; one layout history step; allowed on a locked workspace like `studio_rail`; refused with `conflict` when there is no leaf); it is in no menu. The **Studio mode switch** (a Toggle bound to `canvas.studio_mode.toggle`, so the same setting as the toolbar button, the Scene menu entry and the shortcut) sits in Preview's title row, left of its Maximize button, while the rail is not between the pictures: outside studio mode, and in studio mode with the rail below them. With the rail between the pictures it is a card of its own above the rail (the switch with its name under it), and the rail's controls are the card below it, so the pictures keep their full height. The toolbar keeps its Studio mode button (owner, 2026-11-08). Not yet built: the "No Pictures area in this workspace" hint on the Studio mode button in Minimal and Audio.
  - The rail holds, top to bottom (between) or left to right (below): the transition type as a `Select` ("Transition type"; Cut is the only entry until fades) and a primary "Transition" button (disabled while the studio is not running) with the `canvas.transition` shortcut as small `text.secondary` caption text under it between the pictures and not shown below them. **Glide** (ADR-0100) is not on the rail or the floating `rbs.transition` panel: collection defaults are **Settings › General › Scene changes**; a per-source slide override is **Properties** (Custom glide) when that source is selected. Apart from the type and button, behind a divider, the rail's position as a caption "Position" with two `IconButton`s: `rail-between` and `rail-below`; the current one is checked. Between the pictures they sit at the foot of the rail; below them at the right end, with type and Transition centred under the two pictures. First slice (ADR-0061): Auto, a T-bar and the picker's thumbnails come with fades. `rbs.transition` is no longer in the built-in workspaces or the Panels menu; an older workspace that still has it shows it as an ordinary panel with the same controls.
  - Dragging the bottom area below 90 px collapses its stacks, and dragging the left or right area below 200 px collapses its stacks to strips; dragging back out expands them.
- **When limits conflict** (small window, 200 % text): the centre's minimum (above) is kept first; then visible areas shrink in proportion down to their minimums; then the bottom area collapses its stacks; then the left and right areas are drawn as their edge tabs (not saved: they return when there is room). Nothing is cut off (U11). A property test covers window sizes from 1280 x 720 upwards and text scales up to 200 %.
- The live indicator is not a panel and cannot be removed (U4, U21). The workspace and Panels menus are in the menu bar (View › Workspace, View › Panels), part of the window frame, not panels.

### Workspace file

Workspaces are stored as versioned TOML in the user's config directory, one file per workspace, so they can be shared and kept in version control. A JSON Schema for the format is published with the UI crate and checked in CI.

Format 2 (ADR-0049; format 1 is read and migrated, see below):

```toml
format = 2
name = "Edit"
locked = false
toolbar = { style = "icons-text", items = [
  "ui.workspace.select", "|", "scene.create", "source.add", "|",
  "canvas.studio_mode.toggle", "transition.pick", "|", "program.screenshot", "marker.add",
  "~", "ui.app_menu.open", "ui.area.toggle?area=left", "ui.area.toggle?area=bottom",
  "ui.area.toggle?area=right", "|", "stream.toggle", "record.toggle",
] }
# rbs.library: the Library panel (ADR-0075), an edge tab on the left of Edit.

[[windows]]
kind = "main"
centre = { tabs = ["rbs.preview"] }
left = { size = 260, visible = true, layout = { split = "vertical", ratios = [0.4, 0.6], children = [
  { tabs = ["rbs.scenes"] },
  { tabs = ["rbs.sources"] },
] } }
right = { size = 290, visible = true, layout = { split = "vertical", ratios = [0.6, 0.25, 0.15], children = [
  { tabs = ["rbs.properties"] },
  { tabs = ["rbs.live-controls"] },
  { tabs = ["rbs.transition"], state = "collapsed" },
] } }
bottom = { size = 200, visible = true, layout = { tabs = ["rbs.mixer"] } }
auto_hide = [
  { edge = "left", tabs = ["rbs.library"], size = 320, anchor = "rbs.scenes" },
  { edge = "right", tabs = ["rbs.stats"], size = 320, anchor = "rbs.properties" },
]

[[windows]]
kind = "floating"
layout = { tabs = ["rbs.outputs"] }
placement = { display = "edid:DEL-41A3-7H2K9", connector = "DP-2", size = [2560, 1440], scale = 1.5, rect = [0, 0, 640, 420] }

[[windows]]
kind = "projector"
content = "program?canvas=vertical"
placement = { display = "edid:SAM-7012-HX55", connector = "HDMI-1", size = [1920, 1080], scale = 1.0, fullscreen = true }
```

Toolbar items are command registry ids ([ADR-0050](../adr/0050-command-registry-menus-and-toolbar.md)): control API method names, or `.toggle` ids that pair two of them (`stream.toggle` = `stream.start` / `stream.stop`). The ids above show the shape; the final list is fixed with the registry.

- **Main window (format 3).** `centre` is a layout tree (required). `left`, `right` and `bottom` are optional tables with `size` (integer logical pixels, 0 to 16384, clamped to the area limits when laid out), `visible` (default true) and `layout` (a tree; an absent area is empty). An area's `layout` has no empty tab stacks (an empty area has no `layout`). A split child may carry `size` (integer logical pixels, 0 to 16384) in place of its ratio share; the split's `ratios` then lists only the children without `size`, in order, and at least one child has no `size`. A node may be the Pictures leaf (format 3, ADR-0073): `{ pictures = true, rail = "between"|"below", rail_size = 88, canvas = "..." }` (`rail` required, `rail_size` clamped to 48 to 240, `canvas` optional); at most one in the workspace, in the main window's centre tree. Format 2 files (ADR-0064) have a split with `studio = "between"|"below"` over a Preview stack and a Program stack: it is read as the leaf in its place, keeping the rail and the canvas; the first save after that copies the old file to `<file>.format2.bak`, and older builds refuse format 3. `auto_hide` is a list of edge groups: `edge` (`left`, `right`, `bottom`), `tabs` (1 to 32 panel ids), `active` (index into `tabs`, default 0, must be smaller than its length), `size` (integer logical pixels, 0 to 16384, clamped to the flyout limits when shown) and optional `anchor` (a panel id that appears elsewhere in the workspace and not in this group; an anchor that does not resolve, or is not docked in the main window, is ignored and pinning docks at the outer side of the edge's area). At most 16 edge groups. A tab stack may carry `state = "collapsed"`; the centre's tree must keep at least one stack that is not collapsed. Only the main window has `centre`, areas and `auto_hide`; a floating window has `layout`.
- **Implementation status.** `rbs_ui::workspace` reads, validates, migrates and writes everything in this format except fixed-size split children (`size` on a child), which are refused as an unknown field. The Pictures leaf (ADR-0073) is implemented. The shell still draws only the centre.
- **Closed sections** (ADR-0078). `closed_sections` is an optional sorted list of section ids (1 to 64 characters from `a-z`, `0-9`, `.`, `_`, `-`; at most 256, each once) that the user closed in panels. Absent means all open; it is written only when not empty, and a build without the key refuses the file. Opening or closing a section is not a layout undo step.
- **Panel options** (ADR-0083, ADR-0101). `panel_options` is an optional table keyed by panel id, each value a table of simple keys; the Mixer (`rbs.mixer`) has `orientation` = `"auto"` (the default), `"rows"` or `"columns"` (and may keep a reserved `scene_share` float from earlier drafts; the columns layout packs clusters by preferred width and ignores it). Absent `orientation` means `auto`; an invalid value means `auto`. It is written only for non-default options, keeps unknown panels and keys, and a build without the key refuses the file. Changing it is not a layout undo step, is allowed on a locked workspace, and Reset workspace keeps it. `auto` draws columns when the panel is wider than 1.5 times its height, else rows; `rows` and `columns` never reflow by size. The Mixer's right-click menu, a strip's … menu and the panel's … menu each hold the `ui.mixer.orientation` picker as a submenu (Mixer layout: Automatic, Rows and Columns, the current one checked), and `ui.mixer.set_orientation {orientation}` is its client-scoped control API method.
- **Toolbar** (ADR-0050). `toolbar` is optional (absent: the workspace's built-in default, or the Edit default for user workspaces). `style` is `icons` or `icons-text`; `visible` defaults to true; `items` has at most 64 entries: command ids (the panel id grammar), `"|"` (separator) and at most one `"~"` (flexible space). A command id appears at most once; leading, trailing and repeated separators are removed on load. Unknown command ids are kept and shown as a disabled placeholder whose tooltip names what is missing (Fluent message `toolbar-unknown-command`). Only the id grammar is checked on load: a known id whose parameters its entry does not accept is kept and shown disabled with the reason too, so a registry change never makes a workspace file unreadable.
- **Migration from format 1.** The main window's `layout` becomes `centre`; the three areas start empty and visible; nothing is collapsed or auto-hidden; the toolbar is the default. Floating windows and projectors are unchanged. Migration happens in memory on load; the file is rewritten in format 2 only when the workspace is next saved, after which older builds refuse it (one-way, stated in the release notes). Before that first rewrite the format 1 file is copied to `<file>.format1.bak` next to it (once, never overwritten), so a user can go back to an older build by hand. A format 1 override of a built-in workspace migrates to everything in the centre; the app says so once and offers Restore default.
- `placement.display` is a stable fingerprint derived from the display's EDID (manufacturer, product code, serial). `connector`, `size` (physical pixels) and `scale` help when the fingerprint is ambiguous. `rect` is in logical pixels relative to that display.
- Matching order when a workspace is applied: (1) same fingerprint, (2) same connector with the same size, (3) any display with the same size and scale, (4) no match: the window docks into the main window and a projector is not opened. A rect that would fall outside the matched display is clamped to it.
- Export removes `placement` display details (fingerprint, connector) and keeps only size, scale and relative rect, so exported workspaces are portable and contain no hardware identifiers. Import then matches by step (3) or docks.
- `locked` blocks pointer moves, resizes and close buttons. Commands from the palette, shortcuts and the control API still apply.
- Unknown panel ids (for example from an uninstalled plugin) are kept in the file and shown as a placeholder that offers to install or remove them.
- The format is versioned; RBS reads older versions and migrates them. A file with a newer `format` is refused with a message, never rewritten.
- Validation: unknown keys are errors; there is exactly one `main` window and it is first; a panel id appears at most once in the whole workspace (areas, centre, edge groups and floating windows together); a split has at least two children, one positive ratio per child without a fixed `size`, ratios summing to 1 (within 0.01, then normalised) and at most 16 levels of nesting; a tab stack may carry `active` (index of the visible tab, default 0); only the main window's centre may be an empty stack (`{ tabs = [] }`, every panel closed; format 1: its root); a floating window holds at least one panel; a projector has `content` and no `layout`; names have 1 to 64 characters, no control characters, and are unique ignoring case (Unicode lowercase, not locale-specific).
- Files are named after a slug of the workspace name and written atomically (temporary file, then rename). Files that fail to parse are listed as problems and left untouched. Built-in workspaces need no file; saving a changed built-in writes an override file, and restoring its default removes it.

### Switching

- Client-scoped control API commands `ui.workspace.list` and `ui.workspace.switch(name)` ([control API](control-api.md#client-scoped-ui-commands)), available in the command palette and the workspace menu. Shortcuts are user-assigned; none is bound by default (U21).
- Optional `on_go_live` and `on_stream_end` workspace settings, stored in the UI settings, not in the scene collection or output profile.
- Switching only changes UI state; it never reconfigures sources or outputs.
- Layout changes and switches go into the UI's own layout undo history, not the engine command log. A history step is a whole-workspace snapshot; the moves of one splitter drag form one step; changes that leave the layout as it was record nothing; at least 100 steps are kept.
- Every layout change is a command (open, close, show tab, move to stack, move to edge, float, dock, close window, resize, lock, switch; and with ADR-0049: show or hide an area, collapse or expand a stack, auto-hide or pin a panel, maximize or restore, reset sizes, edit the toolbar, build the studio split). Pointer and keyboard both issue these commands. When `locked` is set, close, move to stack, move to edge, float, dock, close window, resize, auto-hide, pin, toolbar edits and building the studio split are refused if they come from the pointer (collapse, expand, area toggles, maximize and opening an auto-hidden panel stay allowed: they hide or show, they do not rearrange); open, show tab, lock or unlock and switch are always allowed, and every command from the palette, a shortcut or the control API applies.
- The result of every command is validated against the rules above; a command whose result would break one (for example splits nested deeper than 16 levels) is refused, so a workspace can always be saved and loaded again.
- A switch that leaves a guarded panel closed while live shows the same undo toast as closing it. An automatic switch (on go live or stream end) shows one toast naming the previous workspace with a one-click way back; that toast replaces the undo toast for any guarded panel the switch closed, because going back reopens it.
- Deleting a workspace asks for confirmation; deleting a built-in workspace is not possible, only restoring its default.

### Commands, menus and the toolbar

- Decided in [ADR-0050](../adr/0050-command-registry-menus-and-toolbar.md). One command registry in `rbs-ui`: id, title and tooltip (Fluent), icon, default shortcut, menu and group, kind (`action`; `toggle` pairing two control API commands, whose off half keeps its confirmation, so End stream still asks while live; or `picker`), and how to read its enabled state (with the reason when disabled, shown as a tooltip) and checked state. The menu bar, context menus, toolbar, command palette and shortcut map are all built from it (U20).
- Menus: File, Edit, View, Scene, Source, Output, Tools, Window, Help. Every command is in exactly one menu, except the few `NOT_IN_MENU` lists for shortcuts (`scene.position`). `MENU_LAYOUT` lists each menu's ids, `|` separators, `#Heading` section headings (ADR-0069: the RBS menu shows a heading's title, the menu bar draws it as a separator) and `{Title:icon` … `}` groups (one submenu of the commands inside, as in context menus). Commands that do not `CommandState::applies` stay out of the menu bar and the RBS menu (type-specific Source items: Transform for a picture, Mute for audio); with no selection they still apply so the entry can show disabled. Context menus repeat the commands that apply to their item (U3). Menus show shortcuts and checkmarks. **Icons:** every menu item and every picker choice has an icon from the set (`choice_icon` for a choice, else the entry's icon); while a checkable item or the current choice is checked, the icon is empty so the checkmark takes its place.
- The menu bar is Slint's `MenuBar` and context menus are Slint's `ContextMenuArea`. Every RBS window that can take focus (main, floating and Settings) declares the same menu bar, because the macOS system menu bar shows the focused window's menus; it is shown only on macOS (`Shell.native-menu-bar`). On Windows and Linux the RBS menu takes its place ([ADR-0069](../adr/0069-rbs-menu-and-command-search.md)).
- Kinds (the first bullet's list in full): `action` runs one command; `toggle` pairs two (`stream.toggle` = `stream.start` / `stream.stop`) and reads which applies from state; `picker` opens a list of choices, each of which runs an action with a parameter (`ui.workspace.select` lists workspaces and runs `ui.workspace.switch(name)`; `transition.pick` lists transitions). An id's parameters (`ui.area.toggle?area=left`) are the command's parameters as strings, converted by the types the registry entry declares. In command ids, parameter values are UTF-8 and percent-encoded outside the id characters and ASCII capitals, with capital hex digits (`ui.workspace.switch?name=Live%20show`), and the 128-byte limit counts the encoded form. Escapes are two hex digits; lower case ones are read and written in capitals. The canonical form (parameters sorted by key, values encoded this way) is what files and `ui.command.list` hold. (This settles ADR-0050's "outside the id characters": its own example keeps the capital L.) An entry declares its parameters with a type and whether each is required; an id with an unknown parameter, a value outside its type or a missing required parameter cannot run. A picker's id with its choice parameter (`ui.workspace.select?name=Live%20show`) runs that choice, which is how menus, the toolbar and `ui.command.run` run one; the bare picker id opens the list in the UI, and `ui.command.run` answers it with `invalid_params`.

  Pickers take their choice as an optional parameter (`name`, `id`); `ui.area.toggle` requires `area`. A type opens the **picker**, a reusable in-window overlay (`Overlays.picker-open`, `picker-title`, `picker-status`, `picker-rows`, `picker-current`; `picker-chosen(index)`, `picker-filtered(text)` and `picker-cancelled()`; reported to the preview layer as a cover like the name prompt): a title, a filter field that holds the focus, a status line while it says something ("Looking for devices...", "Nothing of this type was found.", "Nothing matches."), a list of rows (name, and a note such as "default"), Cancel. Filtering is done by the app (case-insensitive, the name contains the text). Enter chooses the highlighted row (the first match at first), Up and Down move it, Escape or a click outside cancels; the picker is above the name prompt and the hint, and Escape closes the topmost overlay only. A row keeps the index of the app's own listing, so filtering never changes what choosing it adds; the picker keeps its own listing (a Source tab or Global sources listing never replaces its rows) and takes the first answer for its kind. A closed picker has no timers, models or polling. The Appearance font list is to use the same overlay. **Panel menu** (ADR-0094 rule B1): the panel header's more button, a tab's right-click and its Menu key or Shift+F10 open the context `panel` (target `id`, the panel): Collapse or Expand, Maximize or Restore layout, Move to (a submenu: left, bottom, top and right edge, and the next tab stack when the window has two), Float in its own window or Dock back, Auto-hide to the edge, then Close. The commands are `ui.panel.collapse`, `ui.panel.maximize`, `ui.panel.move`, `ui.panel.float` and `ui.panel.close`/`ui.panel.auto_hide`; they are disabled with a reason, never hidden (Preview and Program in the studio split do not fold or hide; auto-hide needs a stack at the edge of the main window), and run in floating windows through the same menu.
- **Source transform commands and menu** (ADR-0084). Registry entries `item.flip` (id parameter `axis`, checkable; checked when the picture is mirrored and not turned, or turned by half a circle for vertical), `item.rotate` (submenu: 90° clockwise, 90° counter-clockwise; 180° is two 90° turns), `item.fit` (submenu: Fit, Fill, Stretch), `item.align` (submenu Center: Both, Horizontally, Vertically) and `item.reset_transform`. The source context menu (preview picture, Sources row) and the Source menu group them as **Transform**, then **Arrange** (`item.move` with `front` / `up` / `down` / `back`), **Visibility**, **Source** (`source.settings`, `ui.properties.show?tab=filters` as Filters…, Reload, `ui.properties.show?tab=source` as Choose another target…), Remove, and **Mixer**. A locked source greys out Transform, Arrange and the Properties position/size, arrange, crop and style fields; running those commands is refused. Type-irrelevant commands leave the menu (`applies`: no Transform for a mic, no Mute for a picture-only source). Properties' "Flip, rotate & fit" section is two icon-only rows (`flip-h`, `flip-v`, `rotate-ccw`, `rotate-cw`, `center`, then `fit`, `fill-canvas`, `stretch`, `reset`); section id `properties.arrange`. Center horizontally / vertically stay in the menus so Properties does not grow. Not yet: multi-selection.
  - Contexts: **Scene** (a Scenes row: Put on air or Show in preview, Rename, Add scene, Remove), **Scenes** (the panel outside its rows: Add scene), **Source** (a Sources row, or a source's picture in a picture panel: Visible, Locked, Muted, Rename, Properties, then Remove from this scene and Delete everywhere, ADR-0065), **Sources** (the panel outside its rows: the Add source submenu of types), **Preview** (the editable picture panel, Program or in studio mode Preview, outside any picture: Add source, Studio mode, Maximize this panel).
  - Opening: a right-click (secondary button down; on the Preview and Program pictures, secondary button up, so the system menu never takes a press whose release the picture would miss and the next click never drags a source), or the Menu key or Shift+F10 on a focused row, opens the menu at the pointer (or under the row). A right-click on a row selects it first, as a click would, except that it never puts a scene on air; on a picture it selects the topmost source there, locked ones included (so its menu offers Unlock), and with no picture there clears the selection and opens the panel's menu. Picking an item runs its id as the menu bar does, with the same confirmations; Escape or a click outside closes the menu.
  - Toolkit: one `CommandMenu` (`rbs-app` `ui/context_menu.slint`, Slint's `ContextMenuArea` with its own right-click handling off) per element that has a menu. Opening calls `ContextMenus.prepare(context, target)` first, which returns the items of the moment, so a menu never shows stale state and nothing is computed while menus are closed (P13). The menu declares 16 generated slots, each a command, separator or submenu by its item's kind (`context_menu.rs`; a test fails when the copy is stale). On macOS and Windows the menu is native (drawn by the OS above the window, so the preview layer needs no cover); elsewhere Slint draws it as an in-window popup, which the preview layer already treats as a cover (ADR-0054).
  - Not yet: menus for panel tabs and card headers (the hand-made panel menu stays until the panel and layout commands are registry entries), the toolbar (Customize toolbar), Mixer rows, edge tabs and the Program picture in studio mode; the reason a disabled item is disabled (ADR-0050 decision 4 wants it as a tooltip; menus have none); Duplicate; shortcuts shown in context menus.
- Control surfaces store registry ids and run them with the client-scoped `ui.command.run {id}` (control API), which runs the entry as the menu would, without the local confirmation (the caller is the one asking, as with `stream.stop`), and only with the caller's rights: every control API method the entry resolves to is checked against the calling session's scopes and remote limits (`scope_denied` otherwise). `ui.command.list` returns the registry with each entry's enabled and checked state and whether the caller may run it.
- Toolbar: the workspace's `toolbar.items` in order. Items that do not fit go into a » overflow menu at the end, last items first (U11). Customize toolbar (View menu, or the toolbar's context menu) adds commands from a searchable list, removes and reorders them by drag or keyboard, adds separators, picks the style and resets to the default. Every U1 core flow stays startable from a panel or a frame element that cannot be removed, never from the toolbar or a menu bar menu alone (U1); removing a toolbar item for one shows where the command still is. Each built-in workspace declares the U1 flows it serves (Edit and Live: all; Minimal: Go live and Record; Audio: Go live, Record and Mute), and a test checks each one with the toolbar hidden, with studio mode on and off, within the Core flows limits; opening an edge tab counts as one interaction.

## Core flows (contract for U1)

Interactions are counted as defined in the UI principles. "Max" is the limit for the whole flow with default choices. The table also holds two U21 flows (switch workspace, hide a panel), marked as such, held to the same counting.

| Flow | Steps | Max |
| --- | --- | --- |
| Add source | "+" on the Sources panel (or drop a file or window onto the preview: 1 drag, done) -> pick a type from large icons with search, recent first -> confirm in the picker, which shows a live preview -> the source is selected on the preview with handles | 3 |
| Add and adjust a filter | Select the source on the preview or list -> "+" in the Filters section of Properties -> pick from a searchable list with previews -> adjust in place; before/after toggle | 3 + adjustments |
| Choose a transition | The Transition rail (studio mode, ADR-0064) shows the current one -> pick another (duration inline) | 2 |
| Create a scene | "+" on Scenes -> type a name (optional template) and confirm | 3 |
| Switch workspace (U21) | Workspace selector in the toolbar (or View › Workspace), or a user-assigned shortcut | 2 (1 with a shortcut) |
| Hide a panel and get it back (U21) | Pin icon (or an area toggle) -> edge tab (or the same toggle) | 1 each way |
| Go live | Go live button (first time only: pick service, sign in or paste key, automatic checks for bandwidth and encoder) | 1 after setup |

## Actions that cannot be undone

End stream, stop recording, delete a scene collection, delete a recording file, sign out of a service. "Remove from scene" (undoable) and "Delete source" (removes it from every scene; undoable) are distinct commands. Volume, mute and sync offset are live controls, not undo steps (ADR-0059, ADR-0062; no confirmation). Everything else that edits scenes, sources, filters, transitions, audio or settings is undoable.

## Keyboard

Docking by keyboard (U21): Tab moves focus through the frame (menu bar where drawn in the window, toolbar), then each tab stack's tabs and their buttons, then the edge tabs, then the splitters. F10 focuses the menu bar on Windows; on Linux, where Slint's drawn menu bar has no keyboard support yet, F10 opens the same menus as a popup (ADR-0049, decision 8). On a focused tab the panel menu also offers collapse or expand, auto-hide or pin, and maximize or restore; Shift+Esc maximizes or restores the focused panel. Showing or hiding areas has no default shortcut (U21: Ctrl+Alt combinations clash with AltGr); users can assign one. An auto-hidden panel that slides out takes focus and gives it back when it closes. On a focused tab, Enter or Space shows it, the Menu key or Shift+F10 opens its panel menu (move to an edge, move to the next tab stack, float or dock back, close), and Delete closes it. A focused splitter moves by `step.nudge` per arrow key, `step.nudge-large` with Shift. A pointer drag does not focus a splitter. Menus open with the first item focused; Tab and Shift+Tab move between items, Enter or Space chooses one and closes the menu, Escape closes it. Delete or Backspace on a focused tab closes it.

Every menu command is found by the RBS menu's search field (Ctrl/Cmd+K, ADR-0069) with its shortcut; `NOT_IN_MENU` commands are reached by their shortcuts. Defaults include: switch to scene 1-9 (Ctrl/Cmd+1..9), transition preview to program (Ctrl/Cmd+Enter; Space also works while the preview or program has focus), undo/redo, nudge source (arrows, Shift for 10 px), duplicate, delete, toggle studio mode. All shortcuts are rebindable; global hotkeys are opt-in. Shortcuts are decided in [ADR-0060](../adr/0060-shortcuts-in-app-and-global.md) and specified in the [shortcuts spec](shortcuts.md): any command registry id (picker choices included) can be bound to a chord in app scope or globally (macOS and Windows), the user's changes are kept in `shortcuts.toml`, conflicts and unsafe chords are refused before they take effect, and Settings › Shortcuts (after Appearance) views, records, removes and resets them. Implemented today: Undo (Ctrl/Cmd+Z), Redo (Ctrl/Cmd+Shift+Z and Ctrl/Cmd+Y) and the scene position defaults once scene commands exist.

Focus and the pointer: one click always reaches the control under the pointer, whichever panel had the focus. A focus scope (`FocusScope`, `RingFocus`) with no child elements that is declared after another element sets `focus-on-click: false`, because Slint's focus-on-click accepts the first press while the scope has no focus and the control under it would need a second click; the control's own click handler takes the focus (`focus-pointer()`). `tests/ui_patterns.rs` checks every `.slint` file.

## Requirements on the UI toolkit

The native toolkit chosen under ADR-0016 (Slint, iced or Qt through `cxx-qt`; ADR-0022 proposes Slint) must satisfy:

1. Renders the engine's shared GPU surface for preview and program without CPU copies.
2. Supports the tokens and components above, including custom drawing for meters and the preview canvas at display refresh rate.
3. Accessibility APIs on Windows, macOS and Linux (screen readers, keyboard focus).
4. Fluent-based i18n and right-to-left layout.
5. Idle CPU near zero when nothing changes on screen.
6. A docking system with tabs, splits and floating windows across monitors (U21), or the ability to build one.
7. A licence compatible with ADR-0010.
8. Rich visualisations (meters, equalizer curves, spectrum, histogram, scopes): light graphics with the toolkit's vector primitives; dense or per-pixel graphics drawn on the GPU and shown as textures. Graphics that move at the meter rate or faster are native compositor layers where the platform has a layer backend (ADR-0034 for the preview, ADR-0035 for meters), because the toolkit redraws the whole window for any change.

The comparison prototype and its measurements are in [`prototypes/ui-toolkit`](../../prototypes/ui-toolkit/README.md); the choice is recorded in [ADR-0022](../adr/0022-native-ui-toolkit.md).
