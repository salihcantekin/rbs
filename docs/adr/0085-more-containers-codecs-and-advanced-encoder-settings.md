# ADR-0085: More containers and codecs, and advanced video and audio encoder settings

- Status: Proposed
- Date: 2026-11-09
- Deciders: Salih (owner)
- Builds on: [ADR-0007](0007-ffmpeg-as-optional-adapter.md), [ADR-0019](0019-encode-mux-transport-ports.md), [ADR-0047](0047-several-outputs-per-canvas.md), [ADR-0051](0051-user-data-profiles-and-scene-collections.md) (output profiles), [ADR-0055](0055-crash-resilience.md), [ADR-0076](0076-component-standards-and-panel-spacing.md), [ADR-0078](0078-saved-section-state-and-shared-section-components.md), [ADR-0082](0082-audio-filter-chains-on-sources.md) (`rbs-params`)
- Spec: [output-ports](../specs/output-ports.md), [recording](../specs/recording.md), [user-data](../specs/user-data.md) (output profile), [media-types](../specs/media-types.md)

## Context

Recording offers two formats today: MKV (`ContainerId::Matroska`) and MP4, which is fragmented MP4 (`ContainerId::Mp4Fragmented`, so a crash leaves a playable file). `ContainerId` has four values (fMP4, Matroska, MPEG-TS, FLV), `CodecId` has H.264, HEVC, AV1, VP9, AAC and Opus, and the recording adapters implement H.264 and HEVC video and AAC audio (the other ids are reserved). `VideoSettings` already carries rate control (CBR, padded CBR, VBR, constant quality), keyframe interval, B-frames, profile, preset and pixel format, and `AudioSettings` a bitrate. The owner (2026-11-09) wants more formats and codecs, and advanced options for video and for audio, because an editor needs different files than a streamer (an intermediate codec, lossless audio, a specific profile), and settings that change quality must be user settings (standing rule).

Forces: no vendor names in engine code, choice by capability (P3); every encoder and muxer is an adapter behind a port (P2); recordings must survive a crash (ADR-0055); each new encoder/OS pair adds hardware test work; encoder and muxer code is on the hot path (P15); the settings UI must stay simple for people who never open the advanced options (principles U1, U6, ADR-0078).

## Decision

1. **New containers (`ContainerId` is `non_exhaustive`, additions are minor).**
   - `Mov` (QuickTime): the same ISO BMFF writer family as fMP4 with the `qt  ` brand and the sample entries editors expect for ProRes and PCM; written fragmented while recording (crash-safe), so it shares the fMP4 muxer crate's fragment logic.
   - Audio-only containers for audio files (used by ISO audio, ADR-0086): `Wav` (RIFF, switching to RF64 past 4 GiB so a long recording is never truncated) and `Flac` (native FLAC stream). Both are written in place with a header patched at the end *and* a header that stays valid if the process dies (WAV/RF64 sizes are rewritten periodically off the real-time path; FLAC needs no patch).
   - MKV, fMP4, MPEG-TS and FLV are unchanged.
2. **Finalize on stop (optional, off by default).** For fMP4 and MOV, a recording can be *finalized*: after the stop, a background job writes a classic (non-fragmented, `moov` first) copy next to the file and replaces the original only after the copy is checked (duration, stream count, packet count); on any failure the fragmented original stays. It needs about twice the file size in free disk (checked first), replaces the original by an atomic rename under the same name (so paths in the manifest, markers and project, ADR-0086/0089, stay valid), and a crash mid-copy leaves the original. It runs at low priority off the real-time path, shows progress and can be cancelled. A crash or a power loss before it finishes leaves the playable fragmented file.
3. **New codecs (`CodecId` additions, all capability-gated).** Video: AV1 (id exists; `CodecId` is made `non_exhaustive` in the first PR, a one-time workspace-only break; an adapter is offered only where a hardware or software encoder probes it), ProRes (a new id; offered only where an adapter probes it: Apple's VideoToolbox on supported Macs; on Windows only through an optional FFmpeg adapter under ADR-0007, which is not part of the default install). Audio: Opus (id exists), FLAC and PCM (new ids; PCM 16-bit, 24-bit integer and 32-bit float). A codec with no probed adapter is not offered; it is never shown as available and then fail at start. Which hardware encodes AV1 is a probe result, not an assumption (for example, recent NVIDIA, AMD and Intel GPUs do; Apple's current chips decode AV1 in hardware but have no hardware AV1 encoder, so on a Mac AV1 appears only if a software adapter probes it).
4. **Which codec fits which container is data.** A muxer declares a capability `mux.codecs` (a set of `<container>.<codec>`, for example `mov.prores`, `mp4.av1`, `wav.pcm`) in the common capability style (backend-ports spec). The settings UI and `output.validate` use it: the container list is filtered by the chosen codec and the reason is shown for a hidden choice ("MP4 cannot hold PCM"). No table of "known good pairs" lives in the engine.
5. **Advanced options are declared by the adapter as a schema, not coded per vendor in the UI.** An encoder adapter gets a capability `codec.video.options` / `codec.audio.options` and a function returning its options as `&[Field]` from `rbs-params` (ADR-0082): key, label, one-line help, kind (number with range and unit, toggle, choice), default. Because `rbs_params::MAX_FIELDS` is 12 (a hot `Values` size, ADR-0082) and these lists are longer, encoder options do **not** reuse that type: the encoder port crate (`rbs-codec`) owns a small `OptionSpec` list type with its own value type, built on the same ideas (key, label, help, number/toggle/choice, default) and mapped to UI controls by `rbs-app`; no port crate gains a dependency on `rbs-params`. The option list is a method on the encoder factory (`options()`); only the *keys* an adapter supports are published as the capability. The new trait method is a port change and gets its own independent review. The UI renders the Advanced section from that schema with the library components only; the stored form is a table of `key = value` pairs in the output profile. Standard keys that several adapters may support, so profiles move between machines: video `level`, `lookahead` (frames), `aq` (off, spatial, temporal), `multipass` (off, quarter, full), `b_ref` (B-frame as reference), `vbv_ms` (buffer size), `min_qp`, `max_qp`, `refs`, `tune` (quality, low latency), `closed_gop`, `scene_cut`, `color_range` (limited, full) and `color` (primaries, transfer, matrix: Rec.709 default; Rec.2020 PQ/HLG only where the pipeline carries such pictures); audio `bitrate`, `sample_rate`, `channels` (mono, stereo), `bit_depth` (PCM, FLAC), `compression` (FLAC level), `application` (Opus: audio, voice), `vbr` (Opus). An adapter may add keys under its own namespace (`nvenc.spatial_aq_strength`); a key an adapter does not list is **refused at open with `Unsupported` and a reason** (never ignored, same rule as `cbr_padded`, output-ports spec), and the UI shows it disabled with the reason when the chosen encoder lacks it. Vendor names appear only inside adapters (P1, P3).
6. **User-visible settings and presets.** Settings › Recording gets a *Format* card (container, video codec, audio codec, each filtered by decision 4 and annotated with "hardware" or "software") and a collapsed *Advanced video* and *Advanced audio* section (`settings.recording.video-advanced`, `settings.recording.audio-advanced`, ADR-0078) generated from decision 5, with a "Reset to defaults" per section and a one-line effect text per option. Four built-in presets fill the card: *Safe* (fMP4 H.264 AAC, the current default), *Editing* (MKV or fMP4 by default, MOV with *Finalize on stop* recommended because some editors read fragmented QuickTime poorly (checked per editor before the preset is shipped), with ProRes or high-bitrate HEVC, PCM or FLAC audio, where probed), *Archive* (AV1 or HEVC constant quality, FLAC audio, where probed) and *Small* (HEVC or AV1 VBR, Opus). A preset not available on this machine is shown disabled with the reason. The presets are data in the output profile, not code.
7. **Profile storage.** The recording section of the output profile (ADR-0051) gains `container`, `video.codec`, `audio.codec` and the two option tables; its `format_version` is raised, older files load with defaults, newer ones are refused. Unknown option keys are kept on save (a profile from a newer build or another machine keeps its options and shows them as "not available here"). The Stream settings get the same Format and Advanced cards, gated by `mux.codecs` (FLV/RTMP offer no FLAC, PCM, AV1 or ProRes). Control API: `output.profiles` rows show container and codecs, `settings.get/set` carry the new keys; a method `output.options {codec, adapter?}` returns the option schema so remote clients render it too.
8. **Order of work (each a small PR with its own conformance and hardware tests):** (a) `mux.codecs` and the option-schema plumbing with the existing H.264/HEVC/AAC options (no new codec); (b) FLAC/PCM/Opus audio and `Wav`/`Flac` containers; (c) `Mov` with H.264/HEVC/AAC/PCM; (d) AV1 per probed adapter; (e) ProRes on macOS; (f) finalize on stop. Each muxer and encoder change is a hot-path change: before/after numbers, the `hot-path-review` checklist and Salih's sign-off (P15).
9. **Zero cost (P13).** An unused codec or container adds nothing: adapters are installed (registered, probed once) and only the chosen ones are opened. Finalize and the schema functions run off the real-time path. Conformance suites gain "options" rules (declared range respected, unsupported key refused).

## Consequences

- Editors get intermediate and lossless files; streamers keep the safe default; advanced users get real control, and the UI cannot offer a combination the machine cannot do.
- Every adapter that wants Advanced options writes its schema; an adapter without one still works with the standard keys it declares.
- More encoder/OS combinations to test; hardware runs are listed per adapter in its spec section as today. AV1 and ProRes will be absent on machines that do not probe them, by design. The Windows-testable slice (NVENC AV1 Main, 8-bit, into Matroska and fragmented MP4, offered in Recording when the probe lists `av1`) is specified in [output-ports](../specs/output-ports.md) and [recording](../specs/recording.md). Streaming stays H.264 until enhanced RTMP and MPEG-TS carry AV1. The rest of this ADR (other containers, audio codecs, advanced option schemas, presets) stays Proposed.
- Spec follow-ups in the PRs: `output-ports.md` (`mux.codecs`, options capabilities, new codec and container ids), `recording.md` (settings), `user-data.md` (profile format), `control-api.md` (`output.options`), `media-types.md` (ids), `ui-design-system.md` (Format card, Advanced sections).
- ISO audio files (ADR-0086) depend on the `Wav`/`Flac` containers and on PCM/FLAC.

## Alternatives considered

- **Everything through FFmpeg.** Broadest coverage in one adapter, but ADR-0007 keeps FFmpeg optional and out of the default install, and OS encoders are cheaper on CPU and GPU (rule 17).
- **Hard-code the advanced options in the UI.** Fast to build, but couples the UI to vendors and breaks as soon as a second adapter differs (P3).
- **A free-text "extra encoder arguments" box.** Maximum power, no validation, vendor-specific strings in profiles (P1); at most a later expert escape hatch inside one adapter.
- **Classic (non-fragmented) MP4 or MOV written live.** Smaller files and wider old-player support, but a crash loses the recording (ADR-0055); finalize on stop gives the result without the risk.
