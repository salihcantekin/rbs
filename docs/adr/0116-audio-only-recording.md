# ADR-0116: Audio recording, an output that writes the mix without a picture

- Status: Closed (2026-11-14, owner): audio-only recording shipped as WAV and FLAC recording formats instead of the separate output decided here; see Review
- Date: 2026-11-13

- Spec: [recording](../specs/recording.md), [control-api](../specs/control-api.md), [ui-design-system](../specs/ui-design-system.md), [shortcuts](../specs/shortcuts.md), [ui glossary](../ui/glossary.md)

## Context

The owner asked (2026-11-13) for a way to record only sound: a podcast, a voice-over, a music take, or a clean audio file beside a video recording. Today every output carries a picture:

- `OutputSettings::video` is a required `VideoSettings`; only `audio` is optional. `Studio::start_output` always adds an export (GPU readback, `YuvDownload`, ADR-0038) and a video encoder, and the code assumes a video chain throughout: `StartReport::video_encoder` is a required `Chosen`, the studio's per-output record holds a video slot and video stats that `end_output`, `output_tail_done`, the counters and failure attribution read, and the audio encoder is linked to the output's fixed pin `s1`.
- The rest of the pipeline already handles sound alone. All four muxers write audio-only outputs and test it (`audio_only_output_*` in `rbs-mux-matroska`, `rbs-mux-fmp4`, `rbs-mux-mpegts`, `rbs-mux-flv`). The output node's aligned start passes every packet of an output without video (io-nodes spec, rule 7). The mixer, its master meter and the AAC encoders (Media Foundation, AudioToolbox, FFmpeg) run whenever the studio has audio. An output's sink pulls only what links reach it, so an output fed by the mixer alone schedules no render work.
- Each canvas feeds at most two outputs and the studio four (ADR-0047, ADR-0093 decision 6); the partitions come in four slots of video encoder, audio encoder and output.
- Recording sound through a video recording costs a full composite, readback and encode per frame that nobody needs. The vision asks for lean resource use (rule 17), and the owner wants every output controllable from the API and Stream Deck.

## Decision

1. **A new output kind, the audio recording.** It writes the main canvas's mix (what the recording hears; monitor-only strips are left out as today) to a file, without a picture. It is its own output beside the canvas's recording and stream, with its own start, stop and settings. A video recording and an audio recording may run at the same time and read the same mix. A studio whose scenes have no audio source still has a mixer: the file is silence, which is allowed, and the UI says so beside the control. Terms: "Audio recording", verb "Record audio" (glossary).
2. **Engine contract (`rbs-record`, a breaking change of its public types).** `OutputSettings::video` and `RecordSettings::video` become `Option<VideoSettings>` (`None`: no picture); `new` and `packets` keep `Some(VideoSettings::default())`. `StartReport::video_encoder` becomes `Option<Chosen>`. The studio's per-output record keeps its video slot, export and encoder stats as `Option`s; failure attribution, counters and the tail read them only when present, so an audio-only output is never blamed for a video encoder's failure. Output pins are assigned in order: video (when present) `s0`, audio next. Video counters in `Progress` are 0 for an audio-only output. For an output with `video: None`:
   - `start_output` adds no export and no video encoder and schedules no video source for it; it adds the audio encoder (shared under ADR-0047's rule when the `AudioSettings` match a running one) and the output node, with one stream `s0`. It takes an audio encoder partition (unless shared) and an output partition from a free slot; the slot's video encoder partition stays without a worker.
   - Refusals before anything is chosen: `RecordError::NoStreams` when `video` and `audio` are both `None`; `RecordError::SizeWithoutVideo` when `size` is `Some` (a size that cannot apply is never ignored); `NotBound("mixer")` on a studio without audio. The app checks that an audio encoder exists before it builds the settings and reports "no audio encoder" itself, so `NoStreams` means a caller bug, not a missing encoder.
   - Tail (ADR-0045): `end_output` records the end time on the master clock. With an unshared audio encoder, `output_tail_done` is true at once and `stop_output`'s draining apply flushes the encoder. With a shared one, it is true once that encoder has emitted a packet whose pts is at or after the end, or `END_TAIL_LIMIT` after the end, so the file does not lose the codec delay.
   - `Recording::start` with `video: None` (the CLI) still needs the canvas's program scene, because the mix is that scene's audio; it instantiates only audio sources, starts no render partition worker and checks in strict mode only the sources it records.
   - `rbs-cli record` gains `--no-video` and refuses it together with `--no-audio`. Callers to change: `rbs-app` and `rbs-cli` read the optional `video_encoder`.
3. **Output limits (amends ADR-0047 and ADR-0093 decision 6).** An audio-only output counts toward `MAX_OUTPUTS` (4), not toward `MAX_OUTPUTS_PER_CANVAS`, which from now on counts outputs with a picture. The reason: the per-canvas limit bounds video encode and readback per canvas, and an audio-only output adds neither. Outputs take slots first come, first served; no running output is stopped to make room. When ADR-0111 starts the vertical outputs with the main ones and no slot is left, the vertical output that does not fit is refused as ADR-0111 reports any vertical output that cannot start; the audio recording keeps running. While four outputs run, "Record audio" is disabled with the reason.
4. **Zero cost when unused (P13).** Installed: nothing runs and nothing is allocated; there is no Standby state. Active: one output node, one file transport and, unless shared, one audio encoder. No compositor pass, export, readback or video encoder is added by it, and with no preview and no other output the render worker stays off. Hot paths: the output node, muxers and encoders do not change behaviour. The engine changes are on the control thread.
5. **Formats.** First step, with what is built now: AAC in Matroska written as `.mka`, and AAC in fragmented MP4 written as `.m4a`. An audio-only fragmented MP4 gets the major brand `M4A ` (compatible `iso6`, `isom`, `mp41`); this is a header change in `begin`, once per file, not per packet. `.m4a` becomes the default only after a hardware check shows the fragmented file opens in DaVinci Resolve, QuickTime/Music on macOS and the Windows media player; until then, or if one fails, the default is `.mka`. When ADR-0085 step (b) is accepted and built, the list grows by data: WAV and FLAC, and Opus in `.mka`. A format is offered only where its muxer and encoder are probed (ADR-0085 decision 4).
6. **Settings.** The output profile gains a section `recording-audio` (`format_version = 1`): `format` (`"m4a"` or `"mka"`, default per decision 5), `audio_kbps` (the AAC rates of the recording), optional `folder` (absent: the `recording` section's folder). A missing section gives the defaults; one saved by a newer RBS is not changed. Export removes `folder`, as it does for `recording`. Changes apply to the next audio recording and are disabled while one runs. A file is `RBS <local date> <time> audio.<ext>`; an existing file is never replaced.
7. **Control API (protocol 1.43; Stream Deck parity).** New methods `audio_record.start {profile}` and `audio_record.stop` (`control`, effect class `live`), `audio_record.start_to_file {profile, path}` (`admin`, `live`, refused if the file exists, location rules of `record.start_to_file`) and `audio_record.status` (`read`), and the topic `audio_record.state` with a new type `AudioRecordState`: `{state: "idle", last}` or `{state: "recording", profile, audio_encoder}`, where `last` is an `AudioRecordingSummary {failure, duration_ms, bytes, audio_drops}` (queue drops, packet drops and tail loss of the audio stream). `record.state` and `RecordState` do not change, so a 1.42 client never sees the audio recording as its recording. While an audio recording runs, the main mix counts as on air for the irreversible-actions check, and `profile.switch`, `collection.switch` and a canvas change are refused with `conflict` ("stop the audio recording before ..."), because a studio restart would cut the file; closing the app asks first, as for a recording. `settings.get/set` and `settings.changed` carry `audio_recording` per profile. A 1.42 server answers `method_not_found`. The command id is `audio_record.toggle` (toggle kind, Output group), used by shortcuts, menus and Stream Deck.
8. **User interface: placement only.** The visual design follows rule 16 (proposal, screenshots, owner approval before merge) and comes after ADR-0111 is on main.
   - **Record**: "Record audio" is an entry of the Record ▾ menu, which is then always shown, next to ADR-0111's vertical entries; the Output menu lists it too. While it runs, the ▾ part shows a short label (as "9:16" does) and the entry reads "Stop audio recording".
   - **Settings, Recording**: a foldable card "Audio recording" after Encoding (ADR-0078 feature section) with Format, Audio bitrate and Folder ("Same as recording" by default), and the silence note of decision 1 when the program scene has no audio source.
   - **Outputs panel**: one more line ("Audio recording · MKA · AAC 192 kbit/s · <folder>"), "live now" while it runs.
   - **Live indicator and Stats**: it counts as recording for the live indicator (U12); Stats shows its duration and bytes. The Mixer does not change: its master strip is what is recorded.
9. **Order of work**, each a small PR: (a) engine (decisions 2 to 4, the `M4A ` brand, tests); (b) app host, profile section, control API 1.43, command id, no visible UI; (c) hardware format check (decision 5) on Mac and SC-PC; (d) the UI after the owner approves its proposal; (e) more formats when ADR-0085 (b) lands.

## Consequences

- Recording sound costs an audio encode and a file write; when it shares a running recording's audio encoder, a file write only.
- A podcast workflow (video file plus a clean sound file) works without a second app or an editor step.
- `rbs-record`'s public types change (`OutputSettings`, `RecordSettings`, `StartReport`); `rbs-app`, `rbs-cli` and tests follow in the same PR.
- The per-canvas limit now counts only outputs with a picture; recording.md and the `MAX_OUTPUTS_PER_CANVAS` docs change with step (a).
- One more output state for the host, the live indicator and the API; a fifth simultaneous output is still refused.
- The Record button gains a permanent ▾, a visible change that needs the owner's approval and must fit ADR-0111 and the screen grammar (ADR-0114, Proposed).
- Tests (ADR-0032, `TestClock`, waits on packet counts and tick indices): one audio stream and no export or video encoder in the graph; the render worker stays off without a preview; sharing a running audio encoder; the shared-encoder tail reaches the end; `NoStreams` and `SizeWithoutVideo` leave the studio unchanged; a video encoder failure in another slot is not attributed to it; it does not count toward the per-canvas limit but does toward `MAX_OUTPUTS`; the `M4A ` brand; `rbs-cli --no-video`. App: the profile section round-trips, defaults and loses `folder` on export; the API methods, errors and `audio_record.state`; `record.state` unchanged for a 1.42 client while an audio recording runs; the conflicts of decision 7.

## Alternatives considered

- **An "audio only" switch on the existing recording** (`content = "audio"` in `recording`). Smaller, but a user could no longer record a video and a separate sound file at once, and Record would mean different things per profile. Rejected.
- **A separate "audio recorder" screen or mode.** More UI for the same engine output, duplicating the Mixer and the live controls. Rejected.
- **Record a video and strip the picture afterwards.** A full encode per frame and a post step. Rejected (rule 17).
- **Fold it into ISO recording (ADR-0086).** ISO writes per-source files beside a master recording; the audio recording is the master mix alone. They share formats (ADR-0085) but stay separate outputs.
- **Reuse `record.start` with a parameter.** It would change the meaning of `conflict` per canvas and of `record.state` for older clients. Separate methods keep 1.42 clients correct.
- **Count it toward the per-canvas limit.** Then main recording, stream and audio recording could never run together, the main podcast case. Rejected; the total limit still bounds partitions.
