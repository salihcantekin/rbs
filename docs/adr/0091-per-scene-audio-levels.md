# ADR-0091: Per-scene audio levels: a scene can remember its own volumes and mutes

- Status: Proposed
- Date: 2026-11-09
- Deciders: Salih (owner)
- Builds on: [ADR-0021](0021-scene-collection-model.md), [ADR-0059](0059-scenes-lock-and-source-audio-in-the-studio.md), [ADR-0061](0061-studio-mode-in-the-desktop-app.md), [ADR-0065](0065-global-sources-and-safe-source-removal.md), [ADR-0080](0080-hide-sources-in-the-mixer.md), [ADR-0081](0081-master-strip-in-the-mixer.md)
- Spec: [scene-model](../specs/scene-model.md), [audio-graph](../specs/audio-graph.md), [control-api](../specs/control-api.md), [user-data](../specs/user-data.md), [ui-design-system](../specs/ui-design-system.md)

## Context

A source's volume and mute are properties of the source (`Source.audio`, ADR-0059), the same in every scene that shows it. Streamers want the opposite for some scenes: music loud on "Starting soon" and low on "Talking", the game quiet on "Be right back", a microphone live on "Chat" and off on "Intermission". Today they move faders by hand at every switch, or build duplicate sources.

What exists: the studio applies volume and mute through `Studio::set_mix` (a light path, no rebind, ADR-0059) and the mixer ramps level changes over 10 ms, so a switch is click-free. A scene already carries per-item overrides of layout (`SceneItem.overrides`). Scene switches and transitions are live actions (ADR-0021, ADR-0061).

Constraints: existing collections must behave exactly as before; nothing per-frame may be added for people who do not use the feature (P13, rule 10); levels are user data and need a clear UI that shows which mode a scene is in.

## Decision

1. **Opt-in per scene, with explicit modes.** A scene is in one of two modes: **Shared levels** (the default; the sources' own levels apply, as today) or **Own levels** (the scene keeps its own volume and mute for the sources it chooses). A scene never changes mode by itself.
2. **Model.** `Scene.audio: Option<SceneAudio>`; `SceneAudio` is a map from `SourceId` to `{ volume: Option<f32>, muted: Option<bool> }` (same ranges as `SourceAudio`). Absent entry or absent field means "use the source's own value". `None` is Shared levels. Every key names an existing source (scene-model invariant 4): a document that breaks it is refused, like any other dangling reference. A canvas's global scene (ADR-0065) never has `audio`. Deleting a source removes its entries in the same undo record; undoing the deletion puts them back into the scenes that are still in Own levels and skips scenes that went back to Shared levels since. Live level edits use a dedicated record that expects and replaces only one entry, as ADR-0081 does for `master`; `scene.audio.own` and `scene.audio.shared` use a record that checks only the mode (Own or Shared) and keeps whatever entries are current, so live edits never cause `undo_conflict` with them. Every other scene record ignores `audio` (rename and scope check only name and scope; nothing else replaces a whole scene), except the removal of a scene, whose undo restores the scene with its levels. Duplicating a scene copies its levels. The scene document gets an optional `audio` table, present only for scenes in Own levels; a scene in Own levels with no entries is written as an empty table so the mode survives a save and reload. The app writes the new format only when some scene has the key, as for format 16; the number is raised at the next free value at merge time (numbers are allocated in merge order), and older builds refuse a file that uses it. Scene scope (`Canvas(id)` or `Shared`, U15) is unchanged. Only the program scene of the canvas that owns the mixer (the main canvas; a following canvas hears the main canvas's mix, ADR-0093 decision 5) sets levels; a scene shown on a following canvas, its fallback included, never does.
3. **Effective level.** The level the mixer gets for a source is `scene override ?? source value`, evaluated for the **program** scene (and the global scene of the canvas, ADR-0065, whose sources keep their own values unless the program scene has an override for them). In studio mode only the program scene's levels are heard; the preview scene's levels apply when it goes to program (its audio is not mixed in preview, as today). Nested scenes use the outermost program scene's overrides for their sources; a nested scene's own `audio` is ignored (the UI says so). Entries for sources that are not heard are kept and ignored. Scene levels are not held (ADR-0063, ADR-0098): while a program copy is held, the effective levels come from the real program scene, as source volume and mute do today.
4. **Applying on a switch.** The studio builds the levels it sends the mixer in one place (`mix_of`), used by start, `Studio::update` and `Studio::set_mix`. It takes the studio's canvas and applies that canvas's program scene's entries, so every path that sends levels sends the effective ones and no signature changes. A switch and a transition already go through `Studio::update`; this adds no rebind and no new node. The levels step (with the mixer's existing 10 ms ramp, so there is no click) when the program scene changes, at the start of a transition, while the picture glides (ADR-0100); a following canvas hears the main mix, so it gets them at the same moment. A switch to the same scene changes nothing; switching the collection rebuilds the mix. Hidden sources (ADR-0080) and sources not in the scene are unaffected by the scene's levels except through the rule of decision 3. When no scene is in Own levels there is no extra work at a switch beyond what it does today.
5. **Editing.** While a scene is in Own levels and on air, the Mixer's faders and mute buttons edit **that scene's** entry (the strip shows a small "scene" mark in this mode, and Properties > Sound shows which value is being edited); in Shared levels they edit the source, as today. Both are live changes like source volume today: sent at once, saved in the document, not on the undo stack (ADR-0059). Commands: `scene.audio.own` (turn Own levels on, **copying the levels the scene makes heard in Shared levels**, the sources' own, for every source the scene places, directly, through nested scenes or as a global source of its canvas, hidden items included, so nothing jumps; one undo step), `scene.audio.shared` (turn it off, discarding the overrides; one undo step, with the usual confirmation because it discards data), and `scene.audio.reset_source {source}` (remove one entry; one undo step whose record covers only that entry). In Own levels a fader or mute on any heard source writes the scene's entry, creating it when absent. Registry commands appear in the Mixer's scene header menu and the Scenes panel row menu (U3).
6. **Control API** (next free minor version): `scene.audio.get {scene}`, `scene.audio.set {scene, source, volume?, muted?}`, `scene.audio.own {scene}`, `scene.audio.shared {scene}` and `scene.audio.reset_source {scene, source}`, all class `control` (`get` is `read`). `scene.audio.set` turns the scene to Own levels if it is not (copying levels like `own`, one undo step, which the reply states with `turned_own: true`); the level edit itself is live, not undoable. Refusals: `invalid_params` when neither `volume` nor `muted` is given or the volume is outside `0..=1` or not finite; `not_found` for an unknown scene (the global scene included) or source. `scene.list` and `scene.changed` scene rows carry `own_audio: true` (absent when false). `source.list` and `source.changed` rows keep `volume` and `muted` as the source's own values and add `heard: {volume, muted}`, present only while the program scene has an entry for the source (its presence is the "overridden" mark), so remote panels show what is heard without a change of meaning. Events: `own`, `shared` and `reset_source` publish `scene.changed`; any level change that alters what the program scene makes heard publishes `source.changed`; a level edit on a scene that is not on air publishes nothing (a client reads `scene.audio.get`). `source.set_volume` on a source while the program scene overrides it changes the source's own value, and the row's `heard` shows that the scene's entry is still in force.
7. **Zero cost.** A scene without the field adds nothing. Computing effective levels runs on the control thread at a switch, over the scene's sources.
8. **Visual change.** The Mixer scene header menu, the "scene" mark on strips and the Properties note are visual and follow rules 15 and 16: proposal first, then screenshots in three themes.

## Consequences

- Scenes can have their own mix without duplicating sources, and the behaviour for everyone else is exactly the same.
- The mode is visible (mark, note), so a fader is never silently editing something other than the user thinks.
- A fader adjusted in Own levels does not change the source's level elsewhere, which is the point and also something the UI must say.
- Format and compatibility notes in `scene-model.md` and `user-data.md`; `audio-graph.md` documents the effective-level rule; `control-api.md` the methods; glossary: "Scene levels".
- Interactions: the ducker's key is taken before the fader and mute (ADR-0095), so a microphone muted by a scene still ducks the music, as a source mute does today; the monitor mix is after the fader (ADR-0097), so scene levels change what the headphones hear too; the leveler holds its gain over level steps at a switch (ADR-0092).
- Fade lengths longer than the 10 ms ramp (a slow fade of the music between scenes) need a mixer change (hot path, P15) and are not part of this decision; `fade_ms` per scene is a possible later field.

## Alternatives considered

- **Per-item volume (volume on the scene item, like layout).** The same source in two scenes can differ, but it multiplies fields per item and cannot reach global sources or sources inside nested scenes; per-scene entries are smaller and match how people think ("this scene's mix").
- **Always per-scene (no shared mode).** Breaks existing collections and makes a global change (one mic gain) a chore across scenes.
- **Snapshot/preset mixes recalled by command.** More general, but a mix that changes with the scene automatically is what the owner asked for; presets can be added on top.
- **Apply by switching which sources are Active.** Changes cost and startup latency, not just levels (P13 favours leaving sources as they are).
