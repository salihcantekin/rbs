# ADR-0037: Audio graph: block-cadence partitions on the shared executor, drift correction in input nodes, one graph format

- Status: Accepted
- Date: 2026-11-03
- Deciders: Salih (owner), independent AI review
- Supersedes in part: [ADR-0020](0020-node-contract-and-schedule-swap.md) (audio links refused by the executor; a separate audio executor), [ADR-0026](0026-partitions-and-queues.md) (audio cannot cross partitions; "audio has its own executor"), [ADR-0004](0004-single-master-clock.md) (a drift estimator per audio device; replaced by the steering loop of decision 5, which still corrects drift by small-ratio resampling against the master clock)

## Context

Audio inputs exist (`rbs-audio-io` port and the PipeWire, WASAPI and CoreAudio adapters, [ADR-0033](0033-audio-input-port.md)), audio encoders exist behind `rbs_codec::AudioEncoder` (AudioToolbox AAC; a Media Foundation AAC adapter is being written), and the engine runs partitions on worker threads ([ADR-0026](0026-partitions-and-queues.md), [ADR-0027](0027-engine-loop.md)). Missing is the audio graph between them: aligning each source to the master clock, correcting device drift, converting rates and channels, per-source gain and mute, level meters for the UI, and the hand-off to audio encoders. The executor refused audio links (`ApplyError::UnsupportedLink`), the lowering refused audio crossings, and ADR-0020 deferred an audio executor to `rbs-audio`.

Forces:

- **One master clock** (ADR-0004): every block carries master time; drift is corrected once, in the audio graph, by small-ratio resampling. Adapters already deliver master-clock timestamps per run (`EdgeClock`), so the graph sees drift as timestamps that move against the sample count.
- **Real time** (P6): the audio graph runs every 10 ms with no allocation, blocking or contended lock. OS callbacks run on adapter threads and only fill the sample ring; the graph pulls.
- **Every block counts.** Skipping a video frame shows the previous one; skipping an audio block is an audible gap and a shift in time.
- **Zero cost when unused** (P13, [ADR-0013](0013-zero-cost-when-unused.md)): no audio thread while no audio reaches an output; an input device is started only while its node is Active.
- **Live editing**: sources join and leave while streaming; gain changes must not click.
- **A/V sync** for hours across devices with their own clocks, with a per-source offset for device latency (a camera's video later than its microphone, a Bluetooth microphone later than video).
- **Layers** (P1): `rbs-graph` names no audio API; `rbs-engine` depends only on `rbs-core` and `rbs-graph`.

## Decision

1. **Audio runs on the existing executor and engine.** An audio partition is an ordinary partition paced at the block rate (`sample_rate / block_frames`, 100 Hz for 480 frames at 48 kHz) with the same `Node` trait, swap, restart and shutdown rules. Its pacing runs **every due tick in order** while at most `catch_up` ticks late (`Pacing::stream(cadence, catch_up)`, a new field of `Pacing::Cadence`; video keeps `catch_up` 0, newest tick only), so a late wake-up (timer granularity, preemption) costs latency, not audio. Further behind, the worker skips to the newest tick and counts the skipped ones as `late`; the lost blocks become silence downstream (decision 9). The worker asks the thread policy for `Periodic { period: 10 ms }` (ADR-0030); on Windows that is MMCSS "Games" today. A "Pro Audio" class is a new `ThreadClass` variant, a port change with its own review, not part of this decision.

2. **Audio values on links.** Every `Audio` output pin of a scheduled node gets one planar buffer in its value slot, allocated when the controller builds the schedule: `MAX_CHANNELS x block_frames` `f32` (`Controller::set_audio_block_frames`, default `DEFAULT_BLOCK_FRAMES`; set on every controller whose partition has audio pins, including an encoder partition's queue reader). Audio is an event per tick like packets: the slot is empty before its producer runs; the producer writes channels (`Outputs::audio`) and commits format, timestamp and length; consumers read an `rbs_core::media::AudioBlock` (`Inputs::audio`) and treat a missing block as silence. `ApplyError::UnsupportedLink` is removed (a breaking change of the pre-1.0 `rbs-graph`).

3. **One graph format per audio partition.** `AudioGraphConfig { format, block_frames, latency }` (default 48 kHz stereo, 480 frames, 50 ms). Every audio link in the partition carries blocks of exactly that format and length; input nodes convert rate and channels, so mixers, filters and encoders never resample. A mixer's inputs come from the same partition (they are named by producer id, decision 7).

4. **Block time.** Block `i` covers master time `[t_i - latency, t_i - latency + block)` and carries that timestamp; `t_i = cadence.time_of(i)` is computed from the index, so timestamps never drift and consecutive blocks are contiguous on the sample grid. Ticks earlier than `latency` after the clock origin produce no block (their time would repeat 0). `latency` is the graph's fixed delay behind real time, long enough for every input to have delivered the block's audio (largest OS packet plus scheduling slack); it is configured, not adapted while running (adapting would shift audio against video).

5. **Inputs align, correct drift and convert in one place: the input node** (`rbs_audio::InputNode`, one per `AudioInputStream`). Each block it:
   - reads everything the stream has into a pre-allocated FIFO in the source's rate and channels. A **time map** gives the master time of every FIFO frame (`head + k / source_rate`). A read within `MAP_TOLERANCE` (2 ms, the port's timestamp tolerance) of where the map expects it continues the map, and the map moves by a sixteenth of the block's mean timestamp error (filters jitter, follows drift). A read further off, or flagged as a discontinuity, is placed where its timestamp says: a gap is filled with silence, an overlap (older audio, such as late audio the node already played as silence) is dropped, and and a run further off than the FIFO can bridge restarts the map (a stray timestamp ahead restarts it twice, there and at the next correct run; one behind once, after which the position carries the head back);
   - steers one variable-ratio windowed-sinc resampler: the step per output frame is `source_rate / graph_rate x (1 - clamp(error x STEER_GAIN, ±MAX_CORRECTION))`, where `error` is the master time of the resampler's position minus the time the block wants (block start minus the source's sync offset). `STEER_GAIN` is 0.5 per second and `MAX_CORRECTION` 2000 ppm (devices drift by tens of ppm), so the steady-state error is drift divided by gain (0.2 ms at 100 ppm) and pitch never moves audibly. An error beyond `RESYNC_THRESHOLD` (5 ms) jumps instead, in either direction (counted, audible once); with the map's tolerance at 2 ms, that happens only after a restart of the map (counted when the position locks again), an offset change larger than 5 ms, or a worker that skipped more ticks than `catch_up`. At start the position is set to the wanted time;
   - for output frames whose audio has not arrived, writes silence and **keeps advancing**: sync is never traded for continuity. The late audio, once it arrives, is older than the position and is dropped as an overlap (counted as `late_frames` and `overlaps_dropped`), never mapped as continuous. The resampler needs `TAPS / 2` source frames after a position (32, about 0.7 ms at 48 kHz), so `latency` must cover the largest OS packet plus that look-ahead plus scheduling slack; audio inside the look-ahead at the block's end is silence for those frames. A source that is often late needs a longer graph latency;
   - maps channels to the graph layout with a fixed matrix (mono to the front pair; surround to stereo with centre and surrounds at -3 dB, LFE dropped, normalised to full scale; otherwise channel by channel);
   - is sized for `latency + max_offset + MAX_PACKET (100 ms) + 2 blocks + the resampler's window`; when the FIFO is full anyway it drops its oldest audio and counts it.
   The stream is started in `prepare` and stopped in `release`, so an input that is not Active holds no device. A read error is `NodeError::Backend`; `EndpointLost`, `FormatChanged` and `PermissionDenied` are `Permanent` (the stream cannot recover; the composition root opens a new one).

6. **Signed sync offset per source** (ADR-0023 channel): positive delays the source (its audio of time `t - offset` plays at `t`), negative advances it, within `-(latency - block - 5 ms) ..= max_offset` (clamped). Advancing further needs a longer latency. A change slews below 5 ms and jumps (one audible resync) above.

7. **Mixer** (`rbs_audio::MixerNode`, input pin `in` with many links, output pin `main`). Parameters (ADR-0023) are strips keyed by producer `NodeId` (gain in linear amplitude, mute, optional meter), a master gain and a ramp time. Gain and mute changes are targets reached linearly over the ramp time, evaluated against block time, so they never click. An input whose producer has no strip is **not heard** (parameters and schedule swaps are not applied together, so a source the scene wants muted must never be on air by default). An input that joins, or returns after a tick without a block, fades in over the ramp. An input block of the wrong format or length is skipped and counted; the rest of the mix continues. With no input the output is silence, so an on-air stream with muted microphones keeps streaming. Inputs that leave stop at once (a fade-out needs the producer's last block; open). More buses are more output pins, later.

8. **Meters are lock-free atomics read by the UI at its own rate.** `rbs_audio::LevelMeter` holds one `AtomicU32` per channel: the mixer stores the block's post-fader absolute peak with `fetch_max` on the `f32` bits (ordered like the values for non-negative floats); the UI takes and resets it (`swap`) at its redraw rate, so it sees the highest peak since its last read and never misses a clip. Without a meter nothing is stored.

9. **Audio crosses partitions through an audio queue** (`rbs_graph::runtime::queue::audio`): a fixed set of pre-allocated block buffers (default 50, 500 ms) moving between a free and a full `sync_channel`. The writer copies the block into a free buffer, sends it and rings the consumer's doorbell; without a free buffer the block is lost and counted (`overflows`); with the reader gone it keeps the buffer instead of freeing it on the audio thread. The reader passes one block per tick, rings its own doorbell while blocks are queued (a count of queued blocks, so a released reader does not ring forever), and **fills lost blocks with silence at their times** (up to 1 s), so the encoder's timeline has no gap: output-ports rule 8 treats a gap shorter than one codec frame as continuous, which would shift later audio early.

10. **Audio encoder node** (`rbs_audio::EncoderNode`, audio in, packets out), generic over the runtime, wrapping a `Box<dyn AudioEncoder>`: submits the block, drains packets into vectors reserved at construction, passes `PER_TICK_EVENTS` per tick and keeps the rest for the next tick. It runs in an encoder partition paced by the audio queue's doorbell, because encoders allocate packet payloads, which the audio thread must not do. Any adapter of the port works (AudioToolbox today, Media Foundation AAC next).

11. **A/V sync and its remaining skew.** Audio blocks carry the master time of their content; video frames carry their capture time, and a composited frame the time of the render tick, whose content is the newest frame at or before it. The remaining skew is at most one video frame plus the difference in device latency, which the sync offset corrects. Audio packets reach the muxers about `latency` plus one codec frame later than video packets of the same time; muxers interleave by timestamp, so a muxer's `max_buffered` (output ports, muxer rule 2: `fragment_duration`, or 1 s when unset) must be at least that, which the defaults satisfy.

12. **Crate.** `rbs-audio` (engine layer) holds the configuration, input node, resampler, channel matrix, mixer, meters and encoder node; it depends on `rbs-core`, `rbs-graph`, `rbs-audio-io` and `rbs-codec`, on no adapter. The composition root opens streams and encoders through the registry and adopts the nodes. Its test builds are optimised (`[profile.dev.package.rbs-audio] opt-level = 2`) so drift tests over simulated minutes run in milliseconds.

## Consequences

- One real-time worker runs all audio of a graph on the executor the render and encoder workers already use; restart, bypass (a failing input is silence) and shutdown order come with it.
- A/V sync holds by construction plus the per-source offset. Drift correction is one function tested with scripted devices (drift up to ±1000 ppm, timestamp jitter, gaps, late delivery, offsets, 44.1 kHz) and the reference adapter, all on `TestClock`.
- Audio is `latency` (default 50 ms) behind real time. That adds to the stream delay, not to the skew. Monitoring through headphones (audio output, not in the port yet) would hear it; a low-latency monitor path is a later decision.
- `rbs-graph` changes on its hot path (value slots, a new queue kind) and `rbs-engine`'s worker loop gains one comparison in the late branch: measured with the executor, cross-thread and new audio benches; `hot-path-review`; human sign-off (P15).
- The resampler is written here (64 taps, 256 phases, Kaiser window; 1 kHz within 0.1 dB, 18 kHz within 0.5 dB, aliasing tones at least 60 dB down), about 27 to 35 µs per block per source with the rest of the node on the reference VM. A bypass for sources already at the graph rate with negligible correction is a possible optimisation.
- Inputs start in `prepare`, serially on the control thread; with several devices an `apply` can take up to 500 ms per device. Starting them in parallel is a follow-up.
- Not decided here: buses beyond `main`, audio filters, audio output and monitoring, the scene model's audio items and the binder that creates these nodes, mux and transport nodes in the graph (also missing for video), adaptive latency, a reopen path for a stream that ended with `FormatChanged`.

## Alternatives considered

- **A separate audio engine in `rbs-audio`** with its own thread and schedule: duplicates the executor, swap, restart and shutdown that ADR-0020 to ADR-0030 settled. Rejected.
- **Mixing in the OS callback of one "master" device:** ties the graph to one device's clock (ADR-0004 rejected the audio clock as master) and breaks when that device is removed.
- **Encoding in the audio partition:** saves a queue, but encoders allocate packet payloads (P6).
- **A resampler crate (`rubato`):** good quality, but its API changed in each recent minor version and drift steering needs control of the ratio per block. Revisit if quality or cost falls short.
- **`DriftEstimator` per device plus a fixed ratio:** needs the device's raw clock, which the port does not expose (timestamps are already master time), and still needs a phase loop to remove the accumulated offset.
- **Keeping the position on late audio (silence that does not advance):** keeps every sample but leaves the source late until steering catches up, seconds at 2000 ppm. Sync matters more.
- **Adaptive graph latency:** lower delay on fast devices, but changing latency while live shifts audio against video. Deferred.
