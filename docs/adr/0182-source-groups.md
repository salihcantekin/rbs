# ADR-0182: Sources can be grouped, and a group moves, resizes and hides as one

- Status: Accepted
- Date: 2026-11-24
- Deciders: Salih (owner)
- Spec: [scene-model](../specs/scene-model.md), [ui-design-system](../specs/ui-design-system.md) (Sources panel), [control-api](../specs/control-api.md)
- Builds on: [ADR-0173](0173-companion-sound-nested-under-its-picture.md) (`ListRow` disclosure arrow and `size.list.indent`), [ADR-0131](0131-obs-import.md) (OBS groups are flattened today), [ADR-0084](0084-source-transform-commands-and-source-context-menu.md) (item commands)

## Context

The owner asked (2026-11-24) for grouping: several sources used as one, moving and resizing together, with Group and Ungroup in the Arrange menu and an open/close row in the Sources list like the companion sound row. Selecting several rows in the list and moving or scaling them together already exists (multi-selection, `rbs_ui::group_transform`, one undo step through a shared gesture), but it lasts only while selected. A nested scene already composes transforms, but it is a separate scene with its own list entry, an extra concept for the user, and ADR-0131 rejected groups as nested scenes for that reason.

## Decision

1. **A group is a tag on items, not a layer type.** A scene stores `groups: Vec<Group { id: GroupId, name }>` and each `SceneItem` has `group: Option<GroupId>`. Flattening, compositor and binder do not change; members stay ordinary layers, so a group costs nothing per frame (P13). `GroupId` is a new counter in `IdCounters` (stored in the document, never reused, as every id). Scene-header records (`ReplaceSceneHeader` and the `set_scene_*` edits) carry and expect `groups`. The counter is always stored in the document, with or without groups, so ids are never reused after a reload. `duplicate_scene` and `duplicate_source` issue fresh `GroupId`s.
2. **Shape.** A group has two or more members, all items of one scene (source or nested-scene items; a global scene is a scene, so its items group among themselves). A group never spans two scenes. One level: a group cannot contain a group. Names are non-blank and unique in the scene.
3. **Invariants** (checked on every edit, each with a `SceneError` variant and a test): every `item.group` names a group of the same scene and every group member points back (`UnknownGroup`); at least two members (`GroupTooSmall`); members are contiguous in layer order (`GroupNotContiguous`); members all in the group's own scene (`GroupScope`); names (`DuplicateName`).
4. **Existing edits keep the block.** Moving a member within the block is allowed; moving it out of the block is refused (`GroupNotContiguous`; Ungroup first). A group moves in layer order as a unit: dragging the group row in the Sources list and Arrange Bring forward / Send backward on a group are a Batch of `MoveItem`s for its members (UI only; the API has no group move). `add_item` at an index inside a block, paste and `duplicate_source` place the new item directly above the block; a copy never carries the source item's `group` tag (the model clears it in `duplicate_source`, paste and copies; the host clears it for attribute pastes), and a copy of a member is placed directly above the block. A companion sound follows its picture's tag: when the picture is grouped, its companion joins the same group and stays next to it; when the picture is ungrouped or leaves, so does the companion. A non-member that sits between members is lifted out of the block's way by Group (decision 5), never left inside. Removing, deleting or removing-from-scene a member leaves the group; a group left with one member is dissolved in the same step. Nesting a scene updates nothing else.
5. **Group and Ungroup.** Group (and `group.create`, which behaves the same: lifts non-contiguous items, merges any groups among them, names the group "Group N" with the next free N when no name is given) takes the selected items (and the members of any selected group; groups merge into one) and moves them next to the topmost one, keeping their order. This lifts them over non-members that sat between them; the user sees that in the picture and Undo restores the exact order (accepted, not prevented). Ungroup removes the tag and keeps the order.
6. **Undo.** A new `Op::SetGroups { scene, expect, set }` for one scene's group list, used inside `Op::Batch` with `ReplaceItems`, so a group edit and the member edits of one gesture are one undo step. A dissolve caused by a removal (`RemoveItem`, `RemoveSource`, `RemoveScene`, `SetSceneItems`, in every affected scene) is recorded by the edit as a `Batch` it builds up front: the removal, then a `SetGroups` and the member's cleared `group` tag, so the inverse restores the survivor's tag and the list. Validation runs at the end of a Batch, so a Batch of `MoveItem`s may pass through split blocks.
7. **Group edits are batches of member edits.** Move, nudge, proportional resize, flip, show/hide, lock and remove apply to every member as one undo step on the edited canvas: each member gets a per-canvas override as a multi-selection edit does today, starting from its default layout. There is no stored group transform; the group box is the box covering the members on the edited canvas, so it can differ between canvases when members have different overrides (accepted); a member with no override there is read from its default layout in that canvas's space (ADR-0110) and gets an override when edited. Scroll, style lengths and crop follow a resize as in multi-selection. Group rotation is not offered; resizing members that are rotated is as approximate as OBS import (ADR-0131). Locked members stay where they are while the others move. Group opacity, clipping and filters are not offered (they need render-to-texture; scene-model spec).
8. **Mixed state.** The group row's eye shows hidden only when every member is hidden; a click hides all when any is visible, else shows all. Lock works the same. `show_for_ms` and cues stay per item and are untouched. Delete or Backspace on a group row asks to remove all its items from the scene (one step, the ADR-0142 remove question); Ungroup is a separate command.
9. **Selection and Sources list.** Clicking a member in the list or on the picture selects the whole group; Ctrl/Cmd+click selects that member alone to edit it, and it keeps its group. A group is one row with the disclosure arrow, combined Show/Hide and Lock, closed by default, open state in memory only. Members sit under it at `size.list.indent`; a companion sound is nested under its picture inside the group (one more indent) and is a member of the group (decision 4), and `sound_nest.rs` orders within each group block. The group row shows no member marks.
10. **Commands and API.** Registry entries `item.group` and `item.ungroup` in Arrange (enabled for two or more items, or a group). Control API (minor protocol bump 1.104): `group.create {scene, items, name?}` -> `{group, name}`, `group.remove {scene, group}` (ungroup), `group.rename {scene, group, name}`, `group.list {scene}` -> `{scene, groups: [{id, name, items}]}`; `scene.sources` rows gain `group`. Errors: `not_found` for unknown ids, `invalid_params` for items of two scenes, fewer than two items or a blank name, `conflict` for a name another group of the scene has. All are undoable like `item.*`; existing `item.*` methods act on the one item named (group behaviour is the UI's batch), and an `item.move` that would leave a block is refused. The existing scene-change events cover them.
11. **Words.** "Group" is the user-facing word for this feature; the Sources list's "Global" and "This scene" headers (ADR-0065, ADR-0173) are called section headers in specs, and `docs/ui/glossary.md` gets "Group" and "Ungroup". Struct-expression callers of `IdCounters` and `Scene` (`rbs-import-obs/build.rs`, `rbs-user-data/scenes.rs`) are updated with the format change.
12. **Format.** The document format is bumped by one (the next free number when implemented). It is written only when a scene has a group, so older builds still load other files (as formats 15/16 did); an older reader refuses a file with groups. User-data spec: item key `group`, scene table `[[groups]]`. In the `AttributeGroup` split, `group` belongs to none (never copied, pasted or reset with attributes).
13. **OBS import.** A group becomes a group; its transform is still composed into the children, so the picture is unchanged. This partly supersedes only the `group` row of ADR-0131's mapping table (the hide rule maps to per-item `visible`; crop on a group item stays approximate). ADR-0131 gets a note pointing here when this is accepted.
14. **Plugin-ready, zero cost.** Groups know nothing about source kinds; plugin sources group like any other; no closed list grows; nothing runs per frame.
15. **Tests.** The property test (random edits, undo to start, redo) and the out-of-order record test gain group edits and `Op::SetGroups`; invariants in `crates/rbs-scene/tests`; a list-ordering test; an OBS import golden; geometry reuses `group_transform`.

## Consequences

- OBS-style groups with proportional resize and one undo step; copying a group to another scene is a later change.
- A group's picture equals its members' pictures: overlapping semi-transparent members still show through each other until render-to-texture exists.
- Public contracts change (scene format, control API, Sources panel, menus): independent review (ADR-0014) and owner approval first; implementation after.
- Specs updated in the same change: scene-model (groups, invariants, errors), user-data, control-api, ui-design-system (Sources panel, Arrange), obs-import, and ADR-0131's note.
- Align and distribute (geometry exists) stay a separate, smaller change on any selection.

## Alternatives considered

- **Group as a nested scene.** Reuses the composition math, but adds an invisible scene to the collection and list and an extra composite per group (ADR-0131 rejected it); crop and style are refused on nested scenes.
- **A group item with its own stored transform.** Allows group opacity later, but every member's box would be relative to the group, so ungrouping and cross-scene copies need conversions, and every layout read changes.
- **Keep only the temporary multi-selection.** Cheapest, but it cannot hide, lock or reorder a set, and the owner asked for the open/close row.
