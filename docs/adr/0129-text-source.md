# ADR-0129: A text source drawn on the CPU once per change, through a text rendering port, updated in place

- Status: Proposed
- Date: 2026-11-16
- Deciders: Salih (owner)
- Builds on: [ADR-0013](0013-zero-cost-when-unused.md), [ADR-0039](0039-scene-source-types.md), [ADR-0053](0053-item-style-and-video-filter-chains.md), [ADR-0062](0062-built-in-video-filters-and-properties-tabs.md), [ADR-0074](0074-still-image-and-colour-sources.md), [ADR-0077](0077-source-health-retarget-and-settings-window.md), [ADR-0107](0107-temporal-sources-sleep-when-hidden.md)

## Context

There is no text source. Titles, names, lower thirds, a "be right back" line, a now-playing line written by another program and a ticker all need a picture made elsewhere today. OBS has a text source on every platform, so this is a parity gap the owner ranked fourth (OBS gap list, 2026-11-16).

Forces:

- **P1 and P2.** Laying out and drawing text needs a shaping library and the system's fonts. Enumerating system fonts calls OS APIs (CoreText, DirectWrite, fontconfig). The engine crates (`rbs-sources`, `rbs-nodes`, `rbs-scene`) must not call them directly, and a different renderer (for example DirectWrite, for exact Windows metrics) must be possible later without a scene change.
- **P6 and P13.** Text that does not change must cost nothing per frame, like a still (ADR-0074). Text that changes (typing in Properties, a file another program rewrites, a control API call) must not rebuild the node: a rebuild is break-before-make and shows a gap on air. A changed picture must not be drawn or allocated in `Node::process`.
- **The binder rebuilds a source on every settings edit** (`rbs-scene` binder, "Sources whose settings changed get a new node"). Filters already have the other path: `changed_filters` keeps the node and the host sends new values (ADR-0062 decision 3). Sources have no such path.
- **Owner rules.** The default font is the system font (owner, 2026-11-16). UI uses theme tokens only, stays compact, and a visual change is approved with dark and light screenshots before merge. Beyond-OBS ideas are welcome in every area (vision, rule 17).
- **Licences.** GPL-3.0-or-later. `parley`, `fontique`, `harfrust`, `swash` and `skrifa` are MIT or Apache-2.0 and already in `Cargo.lock` through Slint 1.18, at the versions this ADR uses.

## Decision

1. **Scene type `org.rbs.source.text`, node type `org.rbs.text`.** One text block per source. The node is kind `Source`, one "video" output, render partition, like `org.rbs.still`. `SourceInstance` gains `Text { node, stats }` and `SourceClass` gains `Text`. A text source is not temporal (ADR-0107 decision 7 is unchanged): its node stays scheduled while placed, as a still does. Under ADR-0117 decision 2 a text source is still only when `kind` is `text` and `fields` is off (its picture then changes only when its settings or its file change); every other kind is not still, so `video_as: auto` gives it a video file.

2. **Drawing text is a port.** A new port crate `rbs-text` (layer Core in `check-layers`, depends on `rbs-core` only) owns the contract: `TextBlock` (the validated settings below), `TextPicture` (straight-alpha sRGB `Rgba8`, width, height), `TextError`, all `#[non_exhaustive]`, and the trait

   ```rust
   pub trait TextRenderer: Send + Sync {
       fn id(&self) -> &str;
       fn capabilities(&self) -> &Capabilities;          // e.g. text.color_glyphs, text.tabular_figures
       /// Lays out and draws `block` into a picture of exactly `block.box_size()`.
       /// Off the render thread only; may block, read fonts and allocate.
       fn render(&self, block: &TextBlock) -> Result<TextPicture, TextError>;
       /// Installed font families, for pickers.
       fn families(&self) -> Result<Vec<String>, TextError>;
       /// Drops font caches and the system collection (called when no text source is left).
       fn trim(&self) {}
   }
   ```

   The first adapter, `rbs-text-parley` (layer Adapter), uses `parley` (layout, line breaking, bidi, fallback through `fontique`) and `swash` (outlines and colour glyphs). It builds its font collection and contexts lazily on the first `render` or `families` and drops them in `trim`, so a registered renderer with no text source holds no font memory (Installed state, P13). `rbs-text-test` is a deterministic fake that draws each glyph as a box from fixed metrics. `rbs-sources` and `rbs-nodes` may depend on `rbs-text`, never on an adapter. Composition roots register renderers (`SourceTypes::register_text`); the type is installed only when one is registered. The document never names a renderer: the host takes the first registered renderer that has the capabilities the block asks for (colour glyphs when the text has emoji), else the first registered. New `TextBlock` fields are added with defaults (minor version of the port); a new required capability is a major one.

3. **Settings** (the scene sources spec holds the table; all optional except the box, which the host writes when it adds the source):
   - Kind and content: `kind` (decision 11), `text` (`\n` breaks a line, at most 10 000 characters), `file` (decision 6), `file_lines` (Int ≥ 0; 0 = whole file, N = last N lines).
   - Font: `font` (family; absent is the system UI font), `size` (Float px, 1 to 1024, default 72), `weight` (Int 100 to 900, default 400), `italic` (Bool).
   - Fill: `color` (default `#ffffff`), optional `color2` and `angle` for a linear gradient, as the colour source.
   - Box: `width` and `height` (Int px, 1 to 4096 each, at most 32 MiB of pixels). **The picture is always exactly the box** (decision 4). `align` (`left`, `center`, `right`; default `center`), `valign` (`top`, `middle`, `bottom`; default `middle`), `wrap` (Bool, default true), `overflow` (`fit` (default: shrink the font until it fits, down to 25 %), `clip`, `ellipsis`), `line_spacing` (Float 0.5 to 3, default 1), `letter_spacing` (Float px, -50 to 200).
   - Outline: `outline_width` (Float px, 0 to 64; 0 = none), `outline_color` (default `#000000`).
   - Shadow: `shadow_color` (absent = none), `shadow_x`, `shadow_y` (Float px, -256 to 256), `shadow_blur` (Float px, 0 to 64).
   - Background: `background` (a colour; absent = transparent) and `padding` (Float px, 0 to 1024). Rounded corners and a border are the item's Shape and border (ADR-0053).

   Every check is static (on the values, before the edit is committed): a value outside its range is `InvalidSetting` from the app and the API, and is clamped with `SourceSettingsAdjusted` when read from a document (ADR-0062 decision 8). Because the picture size is the box, no edit can be accepted and then fail a size cap at render time. A family that is not installed falls back to the system UI font with a `FontMissing { family }` note, never a failure. Keys of the kinds not chosen are kept (switching back restores them) and checked like the others. The settings use the value kinds documents already store, so the scene format does not change.

4. **Sizing: a fixed box, drawn one picture pixel per box pixel.** A text item's picture never changes size because of its content: typing, a file change, a clock or a `{scene}` field re-renders inside the same `width` x `height`, aligned by `align` and `valign`, with `overflow` deciding what happens to text that does not fit. Only an edit of `width` or `height` (from the user, decision 12, or the API) changes the picture size. Adding a text source measures the initial text, sets the box to fit it with `padding`, and sets the item's box to the same size (1:1 on the canvas it was added on). Properties offers **Fit box to text**, one undo step that sets `width`, `height` and the item's box together. Outline and shadow are drawn inside the box (the layout area is the box less `padding` and the outline and shadow extents), so the compositor sees one plain picture and crop, filters and Shape and border keep working.

5. **Edits update the node in place, through the existing parameter channel.**
   - **Binder.** `rbs_scene::NodeTypes` gains `fn live_settings(&self, type_id: &NodeTypeId) -> bool { false }` (a default method: additive, no break for closures and other implementers). `rbs-sources` answers true for `org.rbs.source.text` only. For such a source the binder keeps the node when its settings change, updates `bound.settings`, and reports `(source, node)` in a new `BindReport::changed_sources`. Every other source is rebuilt as today.
   - **Host.** For each changed source the host sends the new settings to the text worker (decision 7). If the source has no instance or a failed one (for example the renderer failed), the host instantiates it again instead, so fixing a setting recovers it.
   - **Node.** The node holds a `ParamReceiver<TextPicture>` (`rbs_graph::runtime::param`, ADR-0023); the worker owns the only `ParamSender`. With nothing new, `process` is the receiver's one atomic load. With a new picture, `process` uploads it with `SourceUpload` into the next of **two textures of the box size, prepared with `prepare_for` in `warm`**, publishes it, and stamps it with the tick's time and a new generation (ADR-0117 decision 4), so a filter downstream never sees the same `(texture, timestamp)` pair twice and always redraws (FilterNode step 2a). The replaced picture goes back through the channel's return slot and is dropped on the worker. A box size change makes the worker ask the host to replace the node (break-before-make, as any rebuild), so `process` never acquires a texture of a new size.
   - **Upload budget.** One upload of at most 32 MiB per change, at most one per tick (the channel keeps only the newest picture). At 1920 x 1080 that is the same 8 MiB a capture source uploads every frame. The text node's `process` and its upload are a hot path: phase (b) needs `hot-path-review`, before and after measurements, and the owner's sign-off (P15).
   - **Undo.** An edit is one undo step and is saved. Consecutive edits of `text` on the same source coalesce into one step until the field loses focus or 1 second passes without typing, the same rule a slider drag follows (ADR-0062 decision 3).

6. **Files.** `file` is a local file. Before **every** read the worker canonicalises the path and refuses anything but a local regular file (ADR-0108 decision 9). Encodings: UTF-8 with or without BOM, UTF-16 LE or BE with BOM; invalid bytes keep the last picture and show the problem "The file is not readable text". At most 1 MiB is read: the whole file when it is smaller, else (and always when `file_lines` > 0) the last 1 MiB, read from the end, and then the last N lines. Change detection: the worker compares size and the modification time at full precision; it also re-reads, and compares the content hash, while the modification time is within 2 seconds of now, so a same-size rewrite on a coarse file system is still seen. A changed file is accepted only when two consecutive polls agree, so a half-written file is not put on air; an empty result keeps the last picture until the next agreeing poll. A missing file shows an empty picture and the problem "File not found" on the source, and the worker keeps watching, so a file another program creates later appears. The control API may not set `file` (decision 8); only the desktop app's file dialog sets it.

7. **One text worker, driven from the control side.** All renders (edits, files, live kinds) run on one worker thread in `rbs-sources`, so pictures are made in order. Each request carries the source's settings generation; a result older than the newest generation for that source is discarded. The host starts the worker when the first text source is instantiated and joins it when the last one is released, on the control path (never in `warm`, `cool` or `process`, and never while a render is running: join waits for the current render). It also calls `trim` on the renderer then. **Polling and live updates run only for sources drawn by a shown scene** (the same union of program and preview scenes ADR-0107 decision 6 computes): the host gives the worker that set whenever the plan changes. A file text or a clock in a scene that is not shown is not polled or re-rendered; it keeps its last picture and is brought up to date when it becomes shown. With no shown live or file text the worker only waits on its queue. Every renderer call is inside `catch_unwind`; a panic or error becomes a problem on that source, keeps its last picture, and never stops the host. `overflow: fit` is a binary search of at most 8 layouts. `families()` is cached on the worker after the first call and served from the cache.

8. **Control API.** `SourceKind::Text`; `source.add` with kind `text` and `text`; the source settings commands read and write the keys above with strict checks, **except `file`, which the API refuses** (`forbidden`) until token scopes exist: a text path would put any readable file (keys, `.env`) on air, a larger gap than the PNG path ADR-0074 decision 9 accepted. `source.set_text {source, text}` replaces only `text` (coalesced like typing). `text.fonts` returns the cached families. `text.timer {source, action: start | pause | reset}` (decision 11). Error texts never include a path or file contents. The numbers go to the next free protocol minor at merge.

9. **Scrolling is decided separately.** A ticker needs a moving picture every tick. Two designs compete: a per-layer UV offset with repeat addressing in the compositor (no extra pass or texture, every source) and an animated video filter (a second pass, but no compositor change). Either must keep the phase in f64 on the CPU, integrate speed x dt and write only the wrapped offset (no f32 time drift on 24/7 streams, no jump on a speed change), draw nothing for an off-air item, make the chain not still (ADR-0117), and handle a line longer than the 4096 px box (several texture strips or a rendered window that advances). The choice needs measurements of both, so it is its own ADR and its own hot-path sign-off. Until then the Text tab has no Scroll row.

10. **Phases.** Each phase is its own pull request: (a) the port, the fake and the parley adapter with conformance tests; (b) the node, the type, `live_settings` and `changed_sources`, the worker and files (hot-path gate, decision 5); (c) the control API; (d) live kinds (decision 11); (e) crisp resizing (decision 12); (f) the desktop UI (decision 13), after the owner approves the proposal and the screenshots. Phases (a) to (e) are not reachable from the desktop UI until (f).

11. **Live kinds** (owner, 2026-11-16). `kind` (Text, default `text`): `text` (the `text` or `file` content), `clock` (local time and date), `countdown` (to a time of day, `target` `HH:mm[:ss]`, or for `duration_ms`, started by the user), `stopwatch` (counts up, started by the user), `recording_time` and `stream_time` (how long the **main canvas's** main recording or stream has run; separate files and vertical outputs do not count; `end_text`, default empty, while stopped). `format` (Text) is a pattern with `HH`, `H`, `mm`, `ss`, `dd`, `MM`, `yyyy`, `ddd` (weekday name) and literal text in quotes; defaults `HH:mm:ss` for a clock and `mm:ss` (with `H:` from one hour) for timers. Weekday names follow the app's UI language from a table in `rbs-sources` (English and Turkish now), with no locale crate. `countdown` has `end_text` (shown at zero, default `00:00`). In `text`, `fields` (Bool, default false) turns on `{time}`, `{date}`, `{time:FORMAT}`, `{scene}` (the main canvas's program scene), `{recording_time}` and `{stream_time}`; with `fields` off braces are plain text.
   - **Clocks.** The worker gets two injected clocks: `TextClock` (local wall time, the real one from `chrono::Local` in the composition root, already in `Cargo.lock`) for `clock`, `{time}`, `{date}` and a countdown to a time of day; and the master clock (`rbs-core`) for `countdown` by duration, `stopwatch` and the elapsed times, so those do not drift from the recording. The next update is the soonest whole second of whichever clock each shown live source uses. A countdown to a time of day counts to the next occurrence of that local time (tomorrow when it has passed today), recomputed from `TextClock` at every update, so a DST or time-zone change moves it with the wall clock. Tabular figures are used when the font has them (`tnum`), so digits do not shimmer.
   - **Run state is live state, not the document.** `text.timer` (API, global shortcuts, Stream Deck) starts, pauses and resets a countdown or stopwatch. It is a live action, like a scene switch (ADR-0059): not on the undo stack and not in the scene collection. The host keeps it in a user-data file, `text-timers.toml` (source id, state, value at the last stop), so a restart shows the stopped value, and never a running timer. The scene format does not change.
   - **Scene names.** On a program switch the host sends `{scene}` texts to the worker when the switch is requested, so the new name normally lands before the transition's first frames; at most two ticks of the old name are accepted.
   - A kind the build does not know is shown as its `text` with `SourceSettingsAdjusted`, so an older build keeps the document.

12. **Crisp at any size** (owner, 2026-11-16). When the user resizes a text item on the preview or in Transform, the source is placed once in the whole collection, and the item has no per-canvas layout override (ADR-0110), the host turns the resize into a box change: the new `width` and `height` are the item's new box in the layout space; `size`, `outline_width`, `shadow_*`, `padding` and `letter_spacing` scale by the vertical factor (the smaller factor when the aspect ratio is kept); the crop scales by each axis's factor; the item's box is set to the new box. If a cap would be passed (box side 4096, `size` 1024), the box stops at the cap and the rest of the resize stays as ordinary stretching. Settings and layout change in one undo step through a new collection record, `SceneCollection::resize_text(item, settings, layout) -> Undo` (record `ResizeText`), which checks both parts as the existing settings and layout records do. A source placed more than once, or an item with per-canvas overrides, scales as a bitmap as today; Properties says why in its (i) help. During a drag the item is stretched and the worker renders once on release.

13. **Desktop UI** (proposal; binding only after the owner's approval of screenshots). Add source lists Text, which adds "Text" in the system font, centred, and opens Properties on a new first tab, Text: a multi-line text field, then compact rows: Kind (Text, Clock, Countdown, Stopwatch, Recording time, Stream time) and the kind's own fields, Font (family picker in the picker overlay, system font first), Size, Bold and Italic, Colour, Alignment (`SegmentedControl`), and Read from file (a file row with Lines). Outline, Shadow and Background are collapsed groups whose header `Toggle` turns them on. Fit box to text is a command button. The Source settings window (ADR-0077) of a text source starts with Kind (owner, 2026-11-16). Every size and colour comes from tokens; help sits behind (i).

## Beyond parity (rule 17)

OBS draws text with GDI+ on Windows and FreeType elsewhere, so features differ by platform (gradients, vertical text and the chat-log mode only on Windows), complex scripts are not shaped on macOS and Linux, a scaled text item is a stretched bitmap, and a clock or countdown needs a script.

This decision gives the same shaping, fallback fonts, colour emoji, gradient, outline, shadow and last-N-lines mode on every platform; edits, files and clocks update in place without a rebuild; a clock, a countdown, a stopwatch and the recording or stream time are built in and follow the master clock; text stays sharp when it is enlarged; and a file or clock in a scene that is not shown is neither polled nor re-rendered.

Left for later decisions: scrolling (decision 9) and **lines to step through** (a list of lines with a hotkey, for lower-third names in an interview).

## Consequences

- A plain title costs one render and one upload, then nothing per frame. Typing updates the picture on the next tick without a gap.
- New crates: `rbs-text` (Core), `rbs-text-parley` and `rbs-text-test` (Adapter); `check-layers` lists them. They add no crate that is not already in `Cargo.lock`. Because Cargo shares one version of `parley` with Slint, the text adapter moves with Slint's updates: when Slint moves to another `parley` version, the adapter either follows in the same change or pins its own (a second copy compiled); text output changes are checked by golden pictures then.
- `rbs-scene` gains `NodeTypes::live_settings`, `BindReport::changed_sources` and the `ResizeText` record (scene-model spec). Binder tests: a live-settings source keeps its node and is reported; other sources are rebuilt; a failed instance is instantiated again.
- Spec updates in the phase that implements each part: a new `text-port.md`; `scene-sources.md`; `scene-model.md`; `control-api.md`; `user-data.md` (`text-timers.toml`); `hot-paths.md` (the text node's `process`); `ui-design-system.md` and the glossary with phase (f).
- Tests (ADR-0032): the port's conformance suite on the fake, and on the parley adapter with a font bundled under `tests/fonts` (an SIL OFL font with its licence file, loaded explicitly; system-font tests are `#[ignore = "slow: ..."]`); the node on `TestClock`: no allocation in `process`, one upload per change, a filter after the text redraws after an edit, the old picture dropped off the render thread; the worker through a `FileProbe` trait (metadata and read) and `poll_once(now)` driven by `TestClock` and a test `TextClock`, with no sleeps: same-size rewrites, half-written files, a missing file that appears, tail reads, a countdown across midnight and DST, nothing polled for a source that is not shown; `trim` after the last text source.
- Negative: the CPU copy of the latest picture stays for the life of the node, as for a still, and so does the box-sized texture pair (a full-canvas 1920 x 1080 box is about 8 MiB of CPU memory and two 8 MiB textures). A box that is too small makes `fit` shrink the text; the user resizes it or uses Fit box to text. Font fallback depends on the computer's fonts, so the same document can look different elsewhere (as in OBS). The API cannot set `file` until token scopes exist.

## Alternatives considered

- **Render text with Slint's renderer.** A UI dependency in the engine (P1).
- **`parley` directly in `rbs-sources`, as `png` is (ADR-0074).** Puts OS font enumeration into an engine crate and leaves no way to plug in a native renderer.
- **Draw glyphs on the GPU every frame.** Sharper when scaled, but per-frame cost for text that does not change and a new compositor pipeline.
- **A picture that follows the content's size.** Needs the item to follow its source's size (a scene-model change: an anchor and a scale), and makes every content change a texture size change on the render thread. A fixed box keeps sizes stable; Fit box to text covers the "auto size" case as an explicit step.
- **Rebuild the node on every edit, as other sources do.** Each keystroke and each file change would be a break-before-make gap on air.
- **A new lock-free mailbox.** Needs `unsafe` in an engine crate or a new dependency; `ParamSender`/`ParamReceiver` already give newest-wins with a return slot.
- **Watch files with OS notifications (`notify`).** A new dependency with platform back-ends and misses on network drives; a bounded metadata check of shown sources is cheap and testable.
- **Let the API set `file`.** Simpler, but turns any API client into a reader of local secrets on air.

## Review

Reviewer: independent AI session (round 1)
Date: 2026-11-16
Verdict: changes requested
Concerns:
1. A picture that changes size is stretched by the item's fixed box; crisp resizing was undefined against layouts. -> Decision 4 (fixed box, one picture pixel per box pixel, Fit box to text) and decision 12 rewritten (single placement and no per-canvas override, factors per axis, caps, crop, `ResizeText` record).
2. Upload claims did not match `SourceUpload`; filter step 2a; render-thread allocations; no P15 gate for phase (b). -> Decision 5: two box-sized textures prepared in `warm`, fresh timestamp per picture, size change rebuilds the node, upload budget, hot-path gate for phase (b), filter-redraw test.
3. Two writers on one slot; a new primitive. -> Decision 5 and 7: `ParamSender`/`ParamReceiver`, one worker makes every picture, generation tags.
4. Binder hook in the wrong layer; failed instances; render-time caps; undo per keystroke. -> `NodeTypes::live_settings` default method, re-instantiate failed entries, static checks only (the box is the picture size), coalesced text edits.
5. Updater lifecycle in `warm`/`cool`; not zero cost off-air; renderer memory while Installed. -> Decision 7: started and joined on the control path, polls and live renders only for sources drawn by a shown scene, lazy renderer with `trim`; parity text corrected.
6. Animated filter: off-air cost, f32 time, ADR-0117, ticker recipe, missing compositor alternative. -> Scrolling moved to its own ADR (decision 9) with these requirements stated.
7. Live kinds vs format, still class, transitions, clocks, DST, locale, canvas. -> Decision 1 (still only for static text), decision 11 (two injected clocks, run state in `text-timers.toml`, next-occurrence rule, UI-language weekday table, main canvas, scene names sent at switch request).
8. File following misses same-size rewrites, half writes, large logs, late files; encoding; re-canonicalisation. -> Decision 6.
9. `file` is a larger security gap than PNG. -> Decision 8: the API refuses `file` until token scopes exist; no paths or contents in errors.
10. Renderer failures not contained; unbounded fit; slow `families()`. -> Decision 7: `catch_unwind`, 8-step fit search, cached families.
11. Updater and adapter tests not deterministic. -> Consequences: `FileProbe`, `poll_once(now)`, bundled OFL font.
12. Wording, `#[non_exhaustive]`, renderer choice, Slint version coupling, kind keys. -> Fixed in decisions 2, 3, 10 and Consequences.
