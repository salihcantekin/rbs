# ADR-0092: Loudness: BS.1770 metering first, then a slow leveler, and gain advice for editing

- Status: Proposed
- Date: 2026-11-09
- Deciders: Salih (owner)
- Builds on: [ADR-0037](0037-audio-graph.md), [ADR-0081](0081-master-strip-in-the-mixer.md), [ADR-0082](0082-audio-filter-chains-on-sources.md), [ADR-0086](0086-recording-sources-separately-iso.md), [ADR-0089](0089-recording-markers-and-editor-project-export.md), [ADR-0091](0091-per-scene-audio-levels.md)
- Spec: [audio-graph](../specs/audio-graph.md), [audio-filters](../specs/audio-filters.md) (from ADR-0082), [control-api](../specs/control-api.md), [ui-design-system](../specs/ui-design-system.md)

## Context

Peak meters (dBFS) show clipping, not how loud a programme sounds. Platforms and broadcasters judge loudness in LUFS (ITU-R BS.1770, EBU R 128): YouTube and many streaming services reference about -14 LUFS, podcasts about -16, European broadcast -23. A live creator whose voice is quiet in one scene and loud in another is heard as inconsistent, and a recording that must be corrected later costs editing time. The owner approved scene-aware audio profiles and loudness normalization as ideas to pursue. Live normalization has a hard limit: the future of a live signal is unknown, so any real-time gain ride must be slow, bounded and gated, and a limiter that never clips needs look-ahead, which the graph cannot yet report (ADR-0082: filters add no latency today).

Facts: the master volume and mute are the last stage of the mix (ADR-0081); filters exist only on sources (ADR-0082); recorded files get a manifest (ADR-0086, ADR-0089); audio nodes are a hot path (P15).

## Decision

1. **Three stages, each useful alone.**
   - **Stage 1: Loudness meter.** Momentary (400 ms), short-term (3 s) and integrated loudness (LUFS), loudness range (LU) and true peak (dBTP), as defined by BS.1770-4 and EBU R 128 (K-weighting, gating at -70 LUFS absolute and -10 LU relative for integrated loudness, -20 LU relative for loudness range, 4x oversampled true peak at 48 kHz and a rate-appropriate factor at other graph rates; K-weighting coefficients are derived for the graph's rate). Shown on the master strip as readouts and a target mark; available per output tap.
   - **Stage 2 (cannot ship before ADR-0086 and ADR-0089): Loudness advice in the manifest and editor project.** True peak is measured before encoding; overs after a lossy encode can differ. When recording, a meter instance per recorded file (master, and each separate audio file, ADR-0086) accumulates integrated loudness, range and true peak; the manifest stores them per file; the editor project export (ADR-0089) can write a clip gain that brings each file to the user's target, so the correction is exact, non-destructive and made in the edit where the future is known.
   - **Stage 3: Leveler (live gain ride).** A slow automatic gain on the master bus that moves the short-term loudness toward a target, then a ceiling (decision 6).
2. **Placement: a master chain.** Audio filters so far exist on sources (ADR-0082). The master needs the same: an ordered filter chain between the mixer's output (after the master volume and mute, ADR-0081) and its consumers (the audio encoder and the master meter). The binder inserts processing filters into it like a source chain, which is **new binder work** for the master (the master volume is a mixer parameter today, ADR-0081, and each output's audio route is wired in `Studio`, ADR-0047); the ADR's implementation PR specifies how the chain interacts with encoder sharing (one chain per canvas, before the fan-out) and is a contract and hot-path change. The loudness **meter is not a chain filter but a parallel tap** on the mixer output (a sink node, no change of the chain tail), so *Show loudness* during a stream causes no dip; adding or removing a processing filter such as the leveler on the master does cause the 10 to 20 ms dip of ADR-0082 decision 6, and the UI says so. It uses the same `AudioFilterType`/`AudioDsp` traits and nodes (ADR-0082). The chain is after the master volume and mute: with the master muted the leveler holds (it sees silence), and a lowered master fader is counteracted within *Max boost*, which the help text says; on a scene switch (ADR-0091 changes levels in steps) the leveler holds its gain for its settle time and then resumes. A canvas with an empty master chain has no node between the mixer and its consumers (P13). Separate audio files (ADR-0086) tap *before* this chain, so the master's processing never changes them; their own meters measure them.
3. **Filter types** (in `rbs-audio-filters`, ADR-0082): `org.rbs.audio-filter.loudness-meter` (no audio change, publishes a meter struct of atomics read by the UI and recorder), `org.rbs.audio-filter.leveler`. Both are fields-from-schema (ADR-0082 `rbs-params`), so the controls come from the same generated editor. Metering is an opt-in: **off by default**; the Mixer's master menu has *Show loudness*, which adds the meter to the chain, and recording loudness measurement is a profile setting (*Measure loudness of recordings*, default off, with a note that it costs CPU on the audio thread, measured and stated in the PR). Nothing runs unless enabled (P13, rule 10).
4. **Meter algorithm contract (testable).** K-weighting (the two-stage biquad cascade, coefficients computed for the graph's sample rate in `make`), mean square per channel with the standard channel weights (surround weights for future 5.1; stereo and mono now), 400 ms blocks with 75 % overlap for gating, 3 s window for short-term, true peak by 4x polyphase oversampling. All state is sized in `make`, nothing allocates in `process`. Conformance: the EBU Tech 3341 and 3342 test signals (public) must read within +-0.1 LU (integrated, momentary, short-term) and the stated tolerance for true peak; a known sine at known level reads the known LUFS; silence reads below -70 and does not move the integrated value (gated).
5. **Settings (user-visible, saved; targets are not hard-coded).** Settings › Audio › Loudness: *Target* (presets -14 streaming, -16 podcast, -23 broadcast EBU R 128, -24 ATSC A/85, or a custom value in LUFS), *Measure on* (master, per recording), and for the leveler: *Leveler* on/off, *Max boost* (default 0 dB until a limiter exists; the user may raise it), *Max reduction* (default -12 dB), *Speed* (slow, medium, fast: the time constant of the gain ride, default slow, 10 s), *Gate* (below which short-term loudness the leveler holds its gain instead of raising it: default -50 LUFS, so silence and room noise are not pumped up), *Ceiling* (true-peak ceiling, default -1 dBTP; see decision 6). Each control has a one-line help and a reset. Per scene (ADR-0091) a target override may be added later with the same ramp rules; not in this decision.
6. **Leveler behaviour, honestly.** The leveler is a gain ride, not a compressor: it changes gain by at most a configured rate (dB per second from *Speed*), never above *Max boost*, holds when the gate says "no programme", and moves with a smooth law (no steps, no clicks). It does **not** guarantee that peaks stay under the ceiling. A true-peak limiter needs look-ahead, therefore latency, which the node contract cannot report today (ADR-0082). The leveler is therefore delivered in two parts: first without a limiter (the UI says the ceiling is *monitored*, with a warning indicator when the true peak passes it), then, once a separate decision adds latency reporting to nodes, a look-ahead limiter filter that makes the ceiling a guarantee. Until then the meter and the manifest report overs, and a gain filter (ADR-0082) is the manual trim.
7. **Live indicator on the master strip** (visual: proposal and screenshots first, rules 15 and 16): short-term LUFS as a number next to the peak meter, a target mark on a small loudness bar, a gain-reduction/boost readout when the leveler is on, and a true-peak "over" lamp. Colours and sizes are tokens.
8. **Control API** (next free minor version): `loudness.status` (momentary, short-term, integrated, range, true peak, target, leveler gain), `loudness.reset` (restart the integrated measurement), `loudness.set_target`; events on the `audio.levels` topic at its existing rate carry the short-term value only when the meter is on. The recording report and manifest carry per-file `loudness` objects.
9. **Hot-path review.** The meter and leveler are new audio nodes in the audio partition. They need benchmarks (a target in microseconds per 10 ms block is set in the first PR from measurements), the allocation guard test, the `hot-path-review` checklist and Salih's sign-off (P15). The master-chain binder change is the same review as ADR-0082's.
10. **Order of work.** (1) meter filter on sources and on a master chain (needs the master-chain binder step); (2) per-file measurement and manifest fields, then editor clip gain (ADR-0089); (3) leveler; (4) look-ahead limiter after the latency decision. Windows and macOS only.

## Consequences

- Creators see loudness the way platforms judge it, can aim at a target, and get exact correction data for the edit; live gain ride is available but honest about its limits.
- The master chain adds a binder feature that other master effects (compressor, limiter, EQ) will also use.
- No cost unless the user enables a meter or the leveler.
- A guarantee against clipping needs a separate, later decision (latency reporting); this ADR does not pretend otherwise.
- Spec follow-ups: `audio-filters.md`, `audio-graph.md` (master chain), `control-api.md`, `user-data.md`, `ui-design-system.md`, glossary ("Loudness", "LUFS", "Target").

## Alternatives considered

- **Peak normalization only.** Simple, but peak level says little about perceived loudness.
- **A fast compressor/limiter as "normalization".** Changes the sound character and pumps; a slow leveler plus clip gain in the edit respects the material.
- **Normalize only after recording (offline).** Most accurate, and decision 1 stage 2 provides the data; live streaming has no "after", so the live stages remain.
- **Write the loudness meter into the mixer.** Touches the mixer hot path for everyone; a filter in the chain costs nothing when absent.
- **Look-ahead limiter now.** Needs node latency reporting; deciding that inside this ADR would change the node contract without its own review.
