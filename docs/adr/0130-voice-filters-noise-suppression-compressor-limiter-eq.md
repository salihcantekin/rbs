# ADR-0130: Voice filters: noise suppression, compressor, limiter and equaliser, with filter latency

- Status: Proposed
- Date: 2026-11-16
- Deciders: Salih (owner)
- Builds on: [ADR-0082](0082-audio-filter-chains-on-sources.md) (audio filter chains), [ADR-0095](0095-audio-ducker-and-key-tap.md) (key input), [ADR-0126](0126-measured-sync-offset-and-device-memory.md) (sync offset; amended by decision 4), [ADR-0091](0091-per-scene-audio-levels.md), [ADR-0092](0092-loudness-metering-and-leveling.md) (loudness)
- Spec: [audio-filters](../specs/audio-filters.md), [audio-graph](../specs/audio-graph.md) ("Offset"), [control-api](../specs/control-api.md)

## Context

Sources have audio filter chains (ADR-0082) with three types: Gain, Noise gate and Ducker. A microphone in a live production usually needs four more: noise suppression (fans, keyboard, room hum that a gate cannot remove while the person talks), a compressor (even voice level), a limiter (no overs after gain or compression) and an equaliser (low cut, presence). OBS offers RNNoise and Speex suppression, a compressor, a limiter without look-ahead and a 3-band EQ with fixed bands. ADR-0082 named a compressor, limiter and equaliser as later work and kept filters latency-free; ADR-0092 decision 6 defers a look-ahead limiter until nodes can report latency.

Facts that shape this decision:

- The graph runs at 48 kHz stereo with 480-frame blocks by default (`AudioGraphConfig`); rate and block size are configurable (1 to 8192 frames).
- `AudioDsp::set` runs inside `AudioFilterNode::process` when values change (`node.rs`), so it is on the audio thread and must be real-time safe (P6). With no input block, `process` returns early and the DSP sees nothing.
- `Values` holds at most 12 fields (`rbs_params::MAX_FIELDS`); `ParamError` is `#[non_exhaustive]`.
- An input node applies a per-source offset (`InputParams`): a delay up to `max_offset`, or an advance up to `latency - period - 5 ms` (35 ms with the default 50 ms graph latency), by reading its FIFO earlier (`effective_offset_ns`). An offset step larger than the node's slew limit makes it resynchronise.
- `Studio::set_audio_offset` stores the user's offset (`settings.audio_offsets`), feeds the sync measurement and, in the app, the device memory of ADR-0126. ADR-0126 suggests `effective - r` from a measured residual `r`, with `effective = effective_offset_ns(stored)`, and states that filter delay is included because the program hears it.
- If `make` fails, the studio runs a pass-through node and reports `FILTER_UNAVAILABLE` (ADR-0082 decision 8).
- RNNoise (Xiph, BSD-3-Clause) is the established light neural denoiser: 48 kHz mono, 480-sample frames, a model of about 88 KB, roughly 1 % of one core. Its overlap-add synthesis outputs the previous frame, so it delays by 480 samples. Its pure Rust port `nnnoiseless` 0.5 (BSD-3-Clause) reaches its FFT through `easyfft`, which plans lazily in a thread-local cache (`generic_singleton`): the first call on a thread allocates and plans, and every call does a map lookup; it also contains `assert!` and `unwrap()` on its frame path and expects samples in the i16 range.

## Decision

1. **Four new built-in types, in this order:** Noise suppression, Compressor, Limiter, Equaliser. Each is an `AudioFilterType` in the catalogue (ADR-0082 decision 3) with schema, DSP, conformance run, benchmark and allocation guard. No scene format change. VST and other plugin hosting is out of scope and needs its own ADR.

2. **Latency is a property of the built DSP.** `AudioDsp` gains `fn latency_frames(&self) -> u32 { 0 }`, fixed when the DSP is made: it must not change on `set`, so a value edit never changes a chain's latency. `PassThrough` reports 0, so a filter whose `make` failed counts nothing. `AudioFilterType` gains `fn latency_frames(&self, setup: DspSetup) -> u32 { 0 }` for display only (API, help text); it must equal what `make` would build for that setup and be 0 when `make` would refuse (conformance test). The chain latency `L` of a source is the sum of the instance latencies of its **enabled, scheduled** filters, kept by the studio next to its filter instances. Both methods are default trait methods; `AudioFilterType` is not part of `rbs-plugin-sdk` yet, so this is additive with no semver impact, and the SDK inherits it.

3. **A latent DSP starts clean after a gap.** `reset` fills delay lines and FIFOs with silence (no allocation). `AudioFilterNode` keeps one `bool`, "missed a block", set when `process` sees no input block; on the next block it calls `reset` before processing, so stale audio never plays after a gap. This is one branch per block in the filter node only, not in any other node.

4. **Compensation by input advance; never by delaying other sources.** For a source bound to an input node the studio sends `a = clamp(stored - L)` (the existing clamp) through a new internal path, `Studio::apply_input_offset(source)`, called when a filter instance is created, enabled, disabled or removed and when the stored offset changes. It never writes `settings.audio_offsets`, never feeds `sync_measure_offset_set` and never touches the device memory: the stored offset stays a property of the device (test: enabling a denoiser changes neither the stored offset nor `device-sync.toml`). What the program hears as the source's alignment is `h = a + L`; when the clamp does not bite, `h = stored`.
   **Amendment of ADR-0126** (Accepted; recorded here as ADR-0092 amended ADR-0081): decision 4's suggested offset becomes `h - r` (equal to `stored - r` while compensation is complete), and the `effective_offset_ms` reported in `sync.measure.changed` and in source rows is `h`. Decision 5's sentence "delay added by the source's filters is correctly included" becomes "compensated, and any uncompensated rest is included, since the program hears it". A test with a latent test DSP where the clamp bites checks the formula and that the stored offset is not polluted by the uncompensated rest.
   The advance spends the input's jitter headroom: each latent millisecond moves the read point closer to the device's arrival time (a denoiser plus a limiter use 12 of the 35 ms default budget). When the clamp cuts the advance, `uncompensated_ms = L - (stored - a)` is reported (decision 9). Sources without an input node (media, browser audio) are late by `L` and report it; giving decoding sources an advance through their own timestamp offset is a follow-up.
   **Ordering on enable and disable.** The offset reaches the input through its `ParamSender` on its next block, while a new chain tail joins one tick late (ADR-0020); the two can land one block apart, and a 10 ms offset step makes the input resynchronise. The combined disturbance must stay inside the dip that ADR-0082 decision 6 accepts (two blocks plus the 10 ms fade-in); a test enables and disables a denoiser on a sine and checks the mixer output against that envelope. A value edit never moves the offset.
   **Master chain.** The master chain of ADR-0092 has no input node, so this compensation does not apply to it. A look-ahead limiter on the master still needs its own decision (advance every input by the master latency, or delay the video); this ADR gives it only the latency contract.

5. **Noise suppression** (`org.rbs.audio-filter.noise-suppression`, "Noise suppression").
   - RNNoise, as a **vendored, minimally patched copy of `nnnoiseless` 0.5** in a new crate `rbs-denoise` (pure Rust DSP, no OS, no GPU, no device). The patches are limited and listed in the crate's README so the copy stays diffable against upstream: `easyfft` replaced by `realfft`/`rustfft` plans and scratch buffers owned by the state and made in `new`; every `assert!`, `unwrap()` and index panic on the frame path replaced by checked code (rule 8); training and C API code removed. Samples are scaled by 32768 on the way in and back. The model is compiled in (`include_bytes!`, about 88 KB, no file I/O). The BSD-3-Clause notice is kept in `LICENSE-RNNOISE` and in the source headers. `rustfft` and `realfft` (MIT or Apache-2.0, already on the `deny.toml` allow list, widely used, no unsafe beyond their own audited SIMD) are the only new dependencies.
   - `rbs-audio-filters` depends on `rbs-denoise`; the layering test keeps both free of `rbs-gpu`, `wgpu` and OS crates. `rbs-denoise` joins `hot-paths.md` and CODEOWNERS.
   - Only at 48 kHz: at another rate `make` returns the new `ParamError::Unsupported(&'static str)` and the studio's pass-through fallback reports `FILTER_UNAVAILABLE`; latency 0 (decision 2). A resampling wrapper is a later change.
   - Latency for a block of `B` frames: `480` when `B` is a multiple of 480, else `960 - gcd(B, 480)` (an internal 480-frame FIFO in front of the frame processor; 928 for 256-frame blocks). Blocks that are not a multiple of 480 make the cost uneven (0 or more frames per block); the budget below is per frame processed, and the worst block is `ceil(B / 480)` frames.
   - Fields (4): `max_reduction` (6..80 dB, default 30: the floor for RNNoise's per-band gains, so speech is not over-suppressed and the residual noise stays natural; OBS has no strength control); `mode` (choice `mono` "One pass for all channels", the default, since a microphone is one voice: L+R are denoised once and written to every channel; or `separate` "Each channel"); `voice_gate` (toggle, off: lowers by `max_reduction` while the voice probability stays under `voice_threshold` for 200 ms, a gate keyed on speech, not level); `voice_threshold` (0..100 %, 60). `make` builds one RNNoise state per channel of the graph format (two for stereo), so switching `mode` in `set` allocates nothing; `mono` uses the first.
   - Meter: `FilterMeter` (input peak, reduction) gains a third relaxed atomic, `voice` (probability 0..1), read only by this filter's editor. This is a change of the spec's `FilterMeter` contract (additive).

6. **Compressor** (`org.rbs.audio-filter.compressor`, "Compressor"). Zero latency. Fields (9): `key_source` (`FieldKind::Source`, none), `threshold` (-60..0 dB, -18), `ratio` (1..20, log, 4), `knee` (0..24 dB, 6; quadratic soft knee), `attack` (0.1..200 ms, log, 5), `release` (10..2000 ms, log, 120), `detector` (choice `rms` (10 ms) default, or `peak`), `makeup` (0..24 dB, 0), `mix` (0..100 %, 100; parallel compression, which OBS lacks). The detector is linked over all channels. `key_input()` is true: with no key source it detects on its own input; with a key source it detects on the key, and a key with no block is silence (no reduction), the ducker's rule. A key taken from a source whose own chain is latent arrives `L` later than that source's dry signal; the help text says a sidechain follows the key source's processed sound. At `mix` 0 or with no reduction and `makeup` 0 the block is bit-exact. Meter: input peak and gain reduction.

7. **Limiter** (`org.rbs.audio-filter.limiter`, "Limiter"). Look-ahead `W` = 2 ms rounded to whole frames (96 at 48 kHz); latency `W`. Construction, chosen because it is provably safe: per sample the required gain `g = min(1, ceiling / max_ch |x|)`; a release stage that only limits how fast the gain may *rise* (`g' = min(g, previous + rise)`, with `rise` from `release` 1..1000 ms, log, 60) and never raises it above `g`; a sliding minimum of `g'` over `W` samples (monotonic queue sized in `make`); then a moving average of length `W` of that minimum. Every term of the average is a minimum over a window that contains the delayed sample, so the applied gain never exceeds the gain that sample needs: no output sample of the limiter exceeds `ceiling` (-30..0 dBFS, default -1). A final clamp stays as a guard; a counter records if it ever acts, and the tests require zero on their signals. The guarantee is for the limiter's output only: filters after it, the fader and the mix can still pass the ceiling. Sample peak, not true peak (a 4x true-peak detector is a later field). Meter: input peak and gain reduction.

8. **Equaliser** (`org.rbs.audio-filter.equaliser`, "Equaliser"). Zero latency, RBJ biquads in transposed direct form II per channel. Exactly 12 fields: `low_cut` (toggle, off), `low_cut_freq` (20..400 Hz, log, 80; 12 dB/oct, Q 0.707), `low_shelf_freq` (20..1000 Hz, log, 120), `low_shelf_gain` (-18..18 dB, 0), `band1_freq` (40..16000 Hz, log, 400), `band1_gain` (0), `band1_q` (0.1..10, log, 1), `band2_freq` (40..16000, log, 3000), `band2_gain` (0), `band2_q` (1), `high_shelf_freq` (1000..20000 Hz, log, 8000), `high_shelf_gain` (0). Frequencies above 0.45 × the rate are clamped. A band at 0 dB (or an off low cut) is skipped, so the defaults are bit-exact. `set` only stores targets; the parameters glide with a 20 ms constant and coefficients are recomputed every 32 frames, so a sweep makes no zipper noise or step.

9. **Control API** (one minor version, numbered at merge; next free today 1.68). `filter.types` entries gain `latency_ms` at the running graph's setup (decision 2). Source rows (`source.list`) gain `filter_latency_ms`, `effective_offset_ms` (`h`, decision 4) and, when not zero, `uncompensated_ms`, plus the input's existing late and resync counters as `input_late_frames` and `input_resyncs`, so spent headroom is visible. New filter type ids appear only for `domain` `"audio"` or `"all"`, so older clients see no change.

10. **UI.** Editors are generated from the schemas (ADR-0082 decision 10); the compressor and limiter reuse the gate's level bar for gain reduction. A latent filter shows its delay in its help line ("Adds 10 ms, compensated" or "Adds 10 ms; 4 ms could not be compensated"). Every visible change is proposed to the owner with dark and light screenshots before merge (CLAUDE.md rules 15, 16, 18). A one-click "Voice chain" preset and an EQ response curve are later visual proposals.

11. **Zero cost and hot path.** A source with none of these filters runs as before: no node, no `rbs-denoise` state, and `L = 0` gives the same offset as today. A disabled filter is Standby and counts zero latency. Budgets at 48 kHz stereo, measured with `cargo bench -p rbs-audio-filters` and recorded in each PR: compressor, limiter and equaliser at most 5 µs per 480-frame block; noise suppression at most 250 µs per 480-frame RNNoise frame in `mono` mode (2.5 % of real time), `separate` mode times the channel count. Each PR has the allocation guard, the `hot-path-review` checklist and Salih's sign-off (P15).

## Consequences

- Microphones get the four filters a voice chain needs, with controls OBS lacks: a reduction limit and a speech gate for noise suppression, parallel compression, a limiter that cannot overshoot, a parametric EQ with Q, and compensated latency.
- Latency becomes a declared, tested property of a built DSP. Master-chain compensation for ADR-0092 remains a separate decision.
- `rbs-denoise` is vendored code the project maintains; keeping the patch small and listed keeps upstream fixes portable. Its output is compared with `nnnoiseless` (dev-dependency) on the same input: difference below -90 dBFS (FFT libraries differ, so not bit-exact).
- Noise suppression works only at 48 kHz in this version.
- Latent filters spend input advance headroom; a source whose offset already uses it gets partial compensation, reported.
- ADR-0126 decisions 4 and 5 are amended (decision 4 above).
- Specs: `audio-filters.md` (`AudioDsp::latency_frames`, `AudioFilterType::latency_frames`, reset after a gap, `FilterMeter::voice`, the four types), `audio-graph.md` (effective offset `a`, heard alignment `h`), `sync-measure` text in the spec that holds ADR-0126, `control-api.md`, `hot-paths.md`, `docs/architecture/overview.md` (`rbs-denoise`), `rbs-params` (`ParamError::Unsupported`), CODEOWNERS.

## Implementation order

1. Latency contract, reset after a gap, `apply_input_offset` and the ADR-0126 amendment, tested with a latent test DSP; API fields.
2. `rbs-denoise` and Noise suppression. 3. Compressor. 4. Limiter. 5. Equaliser.
6. UI proposal with screenshots; merges one at a time after Salih's approval.

## Tests

- **Contract:** instance latency fixed across `set`; type latency equals instance latency and is 0 where `make` refuses; the pass-through fallback counts 0 and causes no advance; `L` sums enabled filters only; `apply_input_offset` sends `clamp(stored - L)`, changes only on create, enable, disable, remove or a stored-offset change, and never writes the stored offset or device memory; `uncompensated_ms` at the clamp boundary; a non-input source reports its latency; a latent DSP is reset after a missing block.
- **Alignment:** an impulse through noise suppression and a limiter reaches the mixer at the same graph time as without them; at the clamp boundary the residual equals `uncompensated_ms`; the sync measurement suggestion is `h - r`.
- **Enable and disable:** mixer output within the ADR-0082 dip envelope.
- **Noise suppression:** agreement with `nnnoiseless` below -90 dBFS; measured impulse delay equals the reported latency for 480-, 256- and 1024-frame blocks; white noise reduced by at least 20 dB and by no more than `max_reduction`; voice gate behaviour; `make` refuses 44.1 kHz; no allocation including the first call and a `mode` switch; no panic on NaN, infinity and full-scale input.
- **Compressor:** static curve within 0.1 dB on steady sines; attack and release in blocks; bit-exact cases; key silence gives no reduction.
- **Limiter:** no sample above the ceiling for full-scale squares, impulse trains with rising peaks inside one window, and noise at +12 dB; the guard clamp count stays 0; measured delay equals `W`; release time.
- **Equaliser:** defaults bit-exact; magnitude at band centres within 0.1 dB of the RBJ formulas; a frequency sweep during a sine has no step above a bound; stable at every field extreme.
- The ADR-0082 conformance suite and allocation guards for all four.

## Alternatives considered

- **`nnnoiseless` as a dependency, warming its planner in `prepare`.** `prepare` is not guaranteed to run on the thread that later calls `process`, the audio thread is recreated on a device restart (planning again on it), and every frame still pays a thread-local map lookup. Rejected.
- **A full rewrite of RNNoise.** Larger diff from upstream and higher maintenance than a vendored copy with a short patch list. Rejected.
- **Speex preprocessor denoiser.** C library (FFI in a filter crate) and weaker on non-stationary noise. Rejected.
- **DeepFilterNet or another larger model.** Better quality, but tens of MB and a neural runtime at about ten times the CPU; against the lean rule (CLAUDE.md rule 17) as a default. A later optional type, ideally through the plugin SDK.
- **Delay every other source and the video by the largest chain latency.** Adds delay to the whole programme for one filter. Rejected; input advance costs nothing where it applies.
- **Ignore latency (as OBS does).** Silently shifts sync and makes ADR-0126's measurement depend on which filters were on. Rejected.
- **Value-dependent latency (adjustable look-ahead).** A slider would move the offset and make edits audible. Rejected.
- **Raise `MAX_FIELDS` for a larger EQ.** `Values` is copied on every value update of every filter; 12 fields give a usable parametric EQ. A graphic EQ is a later type.
- **A limiter without look-ahead (OBS).** Overshoots on transients. Rejected.

## Review

Independent review per ADR-0014.

Round 1 (independent AI session, 2026-11-16): changes requested. Blocking: (1) compensation contradicted ADR-0126's measurement formula and could write the uncompensated rest into device memory (resolved: decision 4 defines `a` and `h`, amends ADR-0126 decisions 4 and 5, adds a clamp-boundary test); (2) latency taken from the type would advance a source whose filter fell back to pass-through (resolved: decision 2, latency belongs to the built DSP, the type method is display-only and 0 when `make` refuses). Should-fix, all adopted: a separate `apply_input_offset` path that never touches stored offsets or device memory; ordering of the offset step and the tail change bounded by the ADR-0082 dip envelope with a test; reset of latent DSPs after a missing block (decision 3); ADR-0092's master limiter still needs its own compensation decision; headroom cost stated and the input's late and resync counters exposed; a provably safe limiter construction and the scope of its guarantee; per-channel states made in `make`, no panics in the port, the i16 scale, a consistent -90 dBFS comparison; the exact latency formula for other block sizes and a per-frame budget; `FilterMeter::voice` as a spec change, 9 compressor fields, dependency licences and semver impact, the keyed compressor's key latency; `nnnoiseless` alternatives weighed (warm-up, rewrite vs vendored patch); sources without an input node recorded as a known limit with a follow-up.
