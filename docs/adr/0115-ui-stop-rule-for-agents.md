# ADR-0115: A stop rule for UI changes by AI agents, with counted checks and an exceptions register

- Status: Accepted
- Date: 2026-11-13
- Deciders: Salih (owner)
- Amends: `CLAUDE.md` rule 16 and the Migration paragraph of [ADR-0094](0094-ui-interaction-patterns-and-tabler-icon-set.md) (which themes are shown for approval)
- Spec: [ui-design-system](../specs/ui-design-system.md), [testing-strategy](../specs/testing-strategy.md)

## Context

The owner works with two kinds of AI agents, Claude Code and Cursor, and asked (2026-11-13) that a change which breaks a UI rule stops and asks him, with exceptions possible only by his approval.

Today two tests of `rbs-app` guard the UI: `no_hard_coded_visual_values` and `every_drawn_pair_has_a_contrast_rule`; and `tests/ui_patterns.rs` holds two checks (no new `PopupWindow`, focus scopes). The other checks ADR-0094 planned were not built. The accepted rules have drifted (see the Context of ADR-0114). The repository has no `AGENTS.md`, no `.cursor` folder, no `.claude/settings.json` and no git hooks; an agent that does not read `CLAUDE.md` meets no UI rule. `.github/CODEOWNERS` does not cover `crates/rbs-app/ui/`, `docs/ui/`, `CLAUDE.md` or the agent folders. GitHub CI triggers are off; tests run locally before a merge, and only the owner merges.

## Decision

1. **The rule.** An AI agent whose change would break a rule of `docs/ui/principles.md`, the design system spec or an accepted UI ADR must stop and ask the owner in writing before making the change. It must not add an exception, raise a count or mark a literal to get past a check.
2. **Counted checks.** A new command `cargo xtask check-ui` reads the `.slint` files under `crates/rbs-app/ui` as text (no UI build, well under a second). It tracks statements and braces as `tests/ui_patterns.rs` does, so a property that runs over several lines is one statement. The library is the list of files named in `docs/ui/baseline.toml` (today `components.slint`). It counts, over all other files together:
   - `touch`: `TouchArea {` elements and components that `inherits TouchArea`. A raw `TouchArea` is what a home-made control is built from; exporting the component or moving it does not change the count.
   - `duplicate`: component declarations, exported or not, whose name is declared in more than one file, a library file included. Today `Hint` (3), `Problem` (2) and `Field` (2) give 7; the goal is zero.
   - `help`: `help:` statements that contain a string literal longer than 90 characters, one per statement whatever the number of branches (ADR-0094: long help belongs in an `InfoHint`).

   What goes into a library file is not counted; it is reviewed with the `ui-review` skill and covered by `CODEOWNERS`. A helper component without a raw `TouchArea` costs nothing.
3. **Baseline.** `docs/ui/baseline.toml` holds one allowed number per check for the whole tree, written once at acceptance. `check-ui` fails when a count differs from its baseline plus the register, above or below, as `ui_patterns.rs` does, so a lowered count must be written down and cannot drift back up. `cargo xtask check-ui --lower` rewrites the baseline with the current counts where they are lower and refuses to raise any. When a count has fallen below what the register allows, `--lower` first reduces or removes the register entries of that check (oldest first, printed), then the baseline, which never goes below zero. Totals mean that moving, splitting or renaming a file changes nothing.
4. **Exceptions register.** `docs/ui/exceptions.toml` lists each approved increase or broken rule: check or rule id, count, file, reason, date, and the owner's approval (a link to his message, or its date and his words where there is no link). After the owner approves in writing, the agent adds the entry with `cargo xtask check-ui --except`, which appends it and prints it. The register is the only way a count can rise.
5. **The same rules for both agents.** `CLAUDE.md` and the `ui-review` skill; `AGENTS.md` at the root and `.cursor/rules/ui.mdc` scoped to `crates/rbs-app/ui/**`, `crates/rbs-ui/tokens.toml` and `docs/ui/**`, with a Cursor command that carries the `ui-review` checklist. All four state decision 1 in the same words and point to the same spec.
6. **Hooks, as early warning.** A Claude Code hook runs `check-ui` after an edit to a `.slint` or token file and refuses a direct edit to `docs/ui/baseline.toml` or `docs/ui/exceptions.toml`, pointing to the two commands. The same is set up for Cursor where its hook events allow it; if they do not, the other decisions still hold. Hooks are not the gate: a shell write goes round them.
7. **The gate** has two parts. A unit test in `xtask` (a workspace member, so part of `cargo test --workspace`) asserts that every count equals its baseline plus the register; it reads only the tree. The pre-merge run adds `cargo xtask check-ui --against <base>`, which reads both files at the base commit, fails when a baseline number is higher than there or when the library list grew without a register entry of rule id `library`, and prints every register entry added since. The owner runs this one command before he merges, or starts the dispatched workflow that runs it; an agent's report of its output is not the gate. The pull request template has a line "UI exceptions added: none | list". `CODEOWNERS` gains `/crates/rbs-app/ui/`, `/crates/rbs-app-ui/`, `/crates/rbs-app/src/look.rs`, `/crates/rbs-app/src/look/`, `/crates/rbs-app/tests/ui_patterns.rs`, `/crates/rbs-ui/tokens.toml`, `/crates/rbs-ui/src/tokens.rs`, `/crates/rbs-ui/src/tokens/`, `/docs/ui/`, `/CLAUDE.md`, `/AGENTS.md`, `/.claude/`, `/.cursor/`, `/.github/` and `/xtask/`. Only the owner merges.
8. **Screenshots for approval** (rule 16) are dark and light. High contrast is added when the change touches a surface or border token, an outline, or a branch on the high-contrast theme.

## Consequences

- A migration lowers counts with one command and never edits a guarded file by hand, so the guard does not block the work it exists to protect.
- A new raw `TouchArea` outside the library needs the owner's approval once, through the register. That is the intended stop. Factoring a panel into helper components is free.
- The checks count text and see only what they name. Long help passed as `hint:` or `detail:` or set from Rust, a `Checkbox` used as a setting, and window buttons drawn without `DialogActions` are not counted; they stay review rules in the `ui-review` skill. The checks catch drift, not intent.
- Two branches that both lower a count conflict in one line of `baseline.toml`; the fix is to run `--lower` again after the merge.
- Nothing proves that the owner approved a register entry. The entry is printed by the pre-merge run, shown in the pull request line, and the owner merges.
- Cursor's hook events must be read from its current documentation before decision 6 is promised there.
- Follow-up in the implementing change: `xtask` command and test, baseline and register files, `CLAUDE.md` rules 13, 15 and 16, `AGENTS.md`, the Cursor rule and command, hooks, `CODEOWNERS`, pull request template, `ui-review` skill, testing-strategy spec.
- Order: this ADR depends on no other. Its checks encode accepted rules (ADR-0094's library components and `InfoHint`), not ADR-0114.
- Reversal: delete the command, the two files and the hooks; no product code depends on them.

## Alternatives considered

- **Gate only, no hooks or rule files:** the agent learns of a violation at the end of its work instead of at the edit.
- **Hooks that refuse edits to the baseline and rule files with no command:** every migration must change the baseline, so agents could never finish one.
- **Counts per file** (round 2 text): a pure move or split needs a register entry, and a file without an entry is undefined.
- **Counting private components, `Checkbox` in a `SettingRow`, shadowed exports and `Cancel` texts** (round 2 text): two of them are zero today and cannot see the drift, one punishes ordinary helper components and is passed by writing `export`, and one counts confirmations that are correct.
- **More checks in `tests/ui_patterns.rs`:** that test builds the whole Slint UI; a text check should not wait for it.
- **Comparing with the merge base inside `cargo test`:** needs git history and its print is swallowed in a passing test (ADR-0032).
- **Warnings instead of a stop:** the audit shows accepted rules drift when nothing stops a change.
- **Semantic checks through the Slint compiler's syntax tree:** more exact, more work; possible later behind the same command and files.
