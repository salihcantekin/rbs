# ADR-0195: Inactive scenes and filters for the Scenes and Sources lists

- Status: Proposed
- Date: 2026-11-26
- Deciders: Salih (owner)
- Builds on: [ADR-0059](0059-scenes-lock-and-source-audio-in-the-studio.md), [ADR-0163](0163-one-command-path-for-the-window-and-the-api.md)

## Context

A source can be hidden, but a scene cannot be taken out of play or out of the list. A show with many scenes needs both: scenes that are prepared but not for tonight must not be reached by a hotkey or an automation by mistake, and the Scenes list should be able to hide them. The Sources list also grows long and mixes kinds; users want to see only text, only windows, and so on, and to show or hide the hidden sources. The Scenes panel is narrow (owner, 2026-11-26), so the control must fit the panel header.

## Decision

1. **Scene state.** A scene is **Active** (default) or **Inactive**. `Scene` gains `active: bool`; `SceneCollection::set_scene_active(scene, active) -> Undo` is one undo step. The document stores `active = false` on the scene only when it is inactive, and the format version rises as ADR-0059 did for `locked`, so an older build refuses the file untouched.
2. **What Inactive means.** Today scene navigation is the command catalog: `scene.next`, `scene.previous` (`StudioUi::scene_step`, wrapping) and `scene.position?n=` (`scene_at`), resolved in `menu_bar.rs` for menus, shortcuts, automations and AI tools alike; `scene.select` and the control API's `scene.switch` take an id. This ADR changes only the first group:
   - `scene.next` and `scene.previous` step through the **active** scenes in list order, wrapping, from the program scene (from the preview scene in studio mode, as today). When the anchor scene is itself inactive (it was put on air on purpose), they go to the nearest active scene after (or before) it in list order.
   - `scene.position?n=` keeps meaning the n-th scene of the full list, so a slot number never moves when a scene is made inactive; it is refused ("The scene is inactive") when that scene is inactive. The control API gains `scene.position {n}` as well: the host resolves the slot, checks activity and selects in one control-path call, and `scene.position?n=` becomes a `Command::Api` call of it, so a concurrent deactivation cannot be bypassed.
   - `scene.select`, `scene.switch` and a click in the Scenes list work on any scene, active or not: naming a scene by id is a deliberate act, and the flag exists to keep a scene out of *cycling* (next, previous, a mistyped slot), not to lock it. This is the policy for existing automations and API clients too: an id they hold keeps working, and `scene.switch` answers `{scene, active}` so a client can see it went to an inactive scene. The filter never changes what these commands resolve: it hides rows only.
   - Navigation resolves on the host, atomically with the switch. The control API gains `scene.step {step: 1 | -1}` (`edit`, with the on-air check). Its effect depends on the mode, like today's navigation: in studio mode it selects the target as the preview scene (no program change); otherwise it switches the program scene, with the same refusal as `scene.switch`, which calls `SceneCollection::next_active` and switches in one control-path call; `scene.next` and `scene.previous` become `studio_host::Command::Api` calls of it, so no client resolves from a stale snapshot. `StudioUi::scene_step` is removed.
   - Candidates are `showable_scenes(canvas)` of the studio canvas: not the globals scene and not scenes of other canvases. The anchor is the program scene; in studio mode it is the preview scene, which is a change from today, where `scene_step` anchors on the program in both modes.
   - With no active scene other than the anchor, next and previous are refused with "No other active scene."
   `next_active` is the only place that holds this rule.
3. **Making a scene inactive.** `scene.set_active {scene, active}` (control API, `edit`, protocol minor bump; `scene.list` rows carry `active`, absent means true). `scene.changed` is published after every successful flag change, by edit, undo or redo, even when the scene is not on the studio canvas, because the list row changed. Going inactive is refused (`SceneOnAir`) for any scene that is *effectively shown*: the program or preview of a canvas as the host resolves it (a following canvas's fallback or retained scene counts, not only the stored `program`), either endpoint of a running transition, and a scene of a held switch. The same check runs before an **undo or redo of either direction** commits (undoing an activation also makes a scene inactive); a refused undo or redo leaves the history untouched and says why. Going active is never refused. Undo and redo never switch program or preview. Duplicating a scene copies `active`; a scene added is active; an old document loads as all active; a build older than the format refuses the file. Nested scene items are not supported yet (ADR-0188), so this ADR defines nothing for them. Window operations go through `studio_host::Command::Api` (ADR-0163); no window-only command.
4. **Scenes panel.** The header gets a **filter button** (funnel icon) before the existing header buttons, with one switch, "Show inactive scenes" (default on). A dot on the button says the filter differs from the default. Each row gets a **power button** (a new `power` icon) on the right: it shows on hover and on inactive rows, its tooltip and accessible name say "Make {scene} inactive" or "Make {scene} active", and an inactive row is dimmed. The row menu has the same command (U3). The eye is not used, because it already means show or hide a source.
5. **Sources panel.** The header gets the same filter button. Its menu lists one checkbox per **source category**, "All" and "None" shortcuts, and a separate switch "Show hidden sources" (default on). A category is declared by the source type through its registry entry (a category id and a display-name key), not by a closed list in the engine or the host (rule 19, P16). The type registry of ADR-0162 does not exist yet (`SourceClass` and `rbs_api::SourceKind` are still closed). Until it does, a single function `source_category(type id) -> Category` in `rbs-sources` maps each existing built-in type id; it is the only place that lists them, it is replaced by the registry entry when the registry lands, and an unknown or plugin type id is "Other". The category ids are stable strings, so a saved filter survives that change. The filter changes only the list. A filtered-out source stays on air as it was, and a filtered-out source that is selected stays listed until the selection changes.
   Filtered-out rows and the Scenes panel: the program scene, the preview scene and the selected scene stay listed even when the filter would hide them, shown as in the list today with the dimmed inactive style, so the user always sees what is on air. Keyboard focus never lands on a hidden row, and reordering works on the visible rows without changing the order of the hidden ones.
6. **Persistence.** The filters are view state, not part of the scene document and not part of a workspace (workspaces hold layout only, `docs/ui/principles.md`). They are stored in the user data, per scene collection, in a separate per-collection view-state file next to the collection's user-data entry (the entry is the scene document, so `panel_filters` is not a section of it), keyed by the collection id, written when a filter changes and deleted when the collection is deleted; the user-data spec gets the exact key and format. A collection without an entry shows everything. A filter change rebinds nothing and adds no per-frame work.
7. **Names and accessibility.** The glossary gains "Active scene / Inactive scene", with a note that it is not the source Active state of the scene-model spec (a source that runs); the UI says "inactive scene" only for the flag. An inactive row is dimmed with a token that keeps the contrast the principles require, and its state is also in its accessible description ("inactive"), not only its colour (U7). The power button is keyboard reachable and its pressed state is exposed. The ui-design-system spec is checked for an existing power icon before the new one is added. A group row filters with its members: it is listed while any member is.

## Consequences

- Scene model, user-data document, control API, scene-switch callers (menu bar, shortcuts, automations, AI tools) and the Scenes and Sources panels change; one crate per change where possible. Tests cover: next and previous skipping inactive scenes (wrapping, inactive anchor, studio-mode preview anchor, no other active scene, globals and other-canvas scenes excluded), `scene.step` racing a deactivation, the position command, the refusals (program, preview, follower fallback, transition endpoints, held switch) for the edit and for undo and redo in both directions, `scene.changed` after each, duplication, the document round trip and old-document default, and that a filter change does no binding work.
- Specs updated in the same change: scene-model (flag, edit, invariants), control-api (`scene.set_active`, `active` field, protocol minor), user-data (document key and format, `panel_filters`), ui-design-system, glossary.
- ADR-0059's removal rule (the program switches away first) is unchanged; this ADR refuses instead of switching, because an inactive flag change has no reason to move the program.
- The ui-design-system spec gains the filter button, the power button and the dimmed row; the glossary gains Active/Inactive.
- Needs a source-type category in the type registry; until a type declares one it is "Other". Types that exist today are classified in the same change.
- Visual change: dark and light screenshots go to the owner before merge (rule 16).

## Alternatives considered

- **Eye button for scenes.** Same look as Sources, but the eye already means "show a source"; the same icon with two meanings was rejected by the owner.
- **Only a row menu command.** No extra row width, but not discoverable and slower than one click.
- **Hidden as a second scene state.** More flexible, but two flags are too much for a narrow panel; the list filter covers hiding.
- **A fixed category enum for sources.** Simpler, but it is a new closed list in the engine (rule 19).
- **Saving the filters in the scene document.** They would travel with a shared collection and enter undo; they are view state.
