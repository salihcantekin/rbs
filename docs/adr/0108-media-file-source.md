# ADR-0108: A local media-file source for video and animated pictures

- Status: Proposed
- Date: 2026-11-12
- Deciders: Salih (owner)
- Builds on: [ADR-0007](0007-ffmpeg-as-optional-adapter.md), [ADR-0052](0052-ai-agent-control-through-mcp.md), [ADR-0074](0074-still-image-and-colour-sources.md), [ADR-0106](0106-picture-and-sound-on-one-source.md), [ADR-0107](0107-temporal-sources-sleep-when-hidden.md)

## Context

ADR-0074 covers pictures that do not change: a PNG or a generated colour. GIF, APNG, animated WebP, and video files need a source that produces frames over time. The capture port leaves media files to a separate node type. ADR-0007 already allows FFmpeg inside a media-file source adapter, dynamically linked, LGPL, and forbids it in mux, transport, audio processing, and compositing.

People use one file as a looping bug, a stinger that plays once, or a silent animation. Those are one kind of source. A slideshow is a list of stills and is not this type. A network URL is not a local file; an agent that can set a path must not be able to open a host (ADR-0052).

Sound needs ADR-0106. Sleeping while no shown scene draws the item needs ADR-0107. Neither is accepted yet. This ADR must not be implemented as a silent picture that later grows an audio pin.

## Decision

1. **Scene type `org.rbs.source.media`, node type `org.rbs.media`.** The scene type plays one local file that changes over time: video, GIF, APNG, or animated WebP. There must not be a separate GIF type. A slideshow must not use this type. The graph node type id must be the single fixed id `org.rbs.media`, with one descriptor in the node crate (`rbs-nodes`). That descriptor must declare one video output and one audio output. Every instance must use that descriptor, so the instance descriptor equals the one entry in `node_types()` (scene-sources invariant 2). The pin set must stay that pair for the life of the node, including Standby and a failed decode. It must not grow or shrink because of the container or a probe. `SourceInstance` must gain a `Media` variant and `SourceClass` must gain `Media` when this ADR is implemented (Consequences). This record does not edit that code.

2. **The audio pin is always present.** A file with no audio stream must still expose the audio pin and must emit silence on it. The ADR-0106 partition-queue reader of that pin must be the mixer-strip producer from the first build that binds the node, including a test double whose pin emits only silence. A later build must not add the pin or replace that producer. Once ADR-0106 is in force, the binder must not report this type as `AudioOnVideoSource`. The source must not ship until ADR-0106 and ADR-0107 are accepted. Parallel implementation is allowed.

3. **A probe must not choose pins.** A control-thread probe of `path` may run only at instantiate and when a path replace builds the new node. The probe must not retain a file handle or a decoder after it returns. The pin set must not depend on the probe.

4. **Demux and decode are a port.** They must go through a trait and a capability set owned by the port crate `rbs-media-decode`. The trait `MediaDecoder` must open a path the host has already accepted, seek to a media-time cursor, and return picture frames, interleaved PCM, and container timestamps. It must not own the master clock, `loop`, `restart_when_shown`, the cursor, sleep, or the queues. Those belong to the `org.rbs.media` node. FFmpeg, dynamically linked and LGPL as ADR-0007 requires, must implement the trait in the adapter crate `rbs-media-ffmpeg`. A later hardware decoder must be another adapter on the same trait. The composition roots (`rbs-app`, `rbs-cli`, and `rbs-mcp`) must register adapters. `rbs-sources` must gain a register entry for `MediaDecoder` factories. `rbs-core`, `rbs-graph`, `rbs-scene`, `rbs-engine`, `rbs-nodes`, `rbs-sources`, `rbs-gpu`, and `rbs-audio` must not depend on an adapter crate. `rbs-nodes` and `rbs-sources` may depend on `rbs-media-decode`. The scene type id must stay `org.rbs.source.media` and must not name a decoder. The document may store an adapter id as text in the existing `adapter` setting. Saving a source must not write an adapter id the user did not set. When `adapter` is absent, the host must choose by capability order: `media.decode.pixel` = `zero-copy` before `cpu-upload`, then registration order, among adapters that can open the file. When `adapter` is set, the host must use only that id. The conformance suite must run on a fake adapter (`rbs-media-decode-test`) and must not require FFmpeg.

5. **Two queues, and `process` only dequeues.** The node must keep two lock-free queues, a video lookahead and audio blocks, only while its worker is running. The worker must run only while the source is Active and has not entered the end hold in decision 7. Standby and that end hold must hold no queue. The video queue must hold at most 8 frames and at most 128 MiB of payload, whichever bound is reached first (the same 128 MiB ceiling a still uses for one decoder buffer). The audio queue must hold at most four blocks of `AudioGraphConfig`'s `block_frames` at that config's format, which caps its bytes. The node must not reserve those caps while Standby. `process` must only dequeue. It must not allocate, block, upload, resample, or read the file. An empty video queue must repeat the last published texture, or publish nothing before the first frame, and must not wait. Video may drop or repeat so the published frame matches the master clock. When the video bound would be exceeded, the worker must drop the oldest queued frame or skip a frame that is already late. Audio must stay continuous on the master clock. The worker must resample PCM to `AudioGraphConfig.format` before enqueue. On underrun the pin must emit silence for that block and must not wait. When the audio bound would be exceeded, the worker may block on that queue. It must not drop samples, and `process` must not block. Container timestamps must be mapped onto the master clock on the worker, before enqueue. The node must not schedule pictures by frame index over a nominal frame rate. A missing timestamp must continue from the previous mapped stamp by the container's frame duration. A container that states neither a timestamp nor a frame duration must fail open with `Media` (decision 9).

6. **Pixel and audio handoff.** An 8-bit 4:2:0 frame must be NV12, and a 10-bit 4:2:0 frame must be P010. Both must use the compositor's existing `YuvDecoder` (`check_color` for range and matrix). A `cpu-upload` adapter must upload on the worker, through the existing `SourceUpload`, before enqueue. A `zero-copy` adapter must enqueue a GPU handle the same decoder can sample. The node must not add a second YUV decoder. GIF, APNG, animated WebP, and any other picture brought to this path as a full frame must be straight-alpha sRGB `Rgba8`, the same pixel rule as a still. 4:2:2, 4:4:4, I420, and every other layout must be converted by the adapter into NV12, P010, or straight-alpha sRGB `Rgba8` before enqueue, or open must fail with `Media`. A colour space `check_color` rejects must be converted to one it accepts, or open must fail with `Media`. The node must use the first audio stream and must ignore any further audio stream. A side over 8192 pixels, or one frame over 128 MiB, must be refused with `InvalidSetting` before either queue is allocated. The node must count uploads, dropped video frames, repeated video frames, and audio underruns. The upload and the decode-to-writer path must take `hot-path-review` when they land.

7. **Cursor, loop, and restart survive with no decoder.** The node must store the media cursor, `loop` (default true), and `restart_when_shown` (default true) while it holds no decoder, no file handle, and no queue. On wake, `restart_when_shown` true must set the cursor to 0; false must seek to the stored cursor. Playback must follow the master clock. The node must not keep its own clock and must not write `visible`. A change to `loop` or `restart_when_shown` must not replace the node. Each change is one undo step. A live `loop` change while the worker is playing must be stored at once and must take effect at the next loop boundary, when the cursor reaches the end. While the worker is not playing, the stored value is already in force: Standby only updates the stored flag, and an end hold whose `loop` becomes true must start a worker from cursor 0 on the control path. `restart_when_shown` must be read on the next wake only. At end of file with `loop` false, the node must release the worker, keep the last texture published, and emit silence. The worker must be joined on the control path only.

8. **Changing `path` replaces the node.** The replacement must follow an image path (break-before-make, filters kept). The new node must use the same `org.rbs.media` descriptor. Decision 3 allows a probe on that new node.

9. **Local files and named errors.** The setting is `path`. Before any read of file contents, the host must canonicalize `path` and must refuse the open unless the canonical target is a local regular file. A URL, a UNC path, a device path, a directory, a pipe, and a symlink, junction, or substituted-drive target that does not resolve to a local regular file must be `InvalidSetting` on `path`. `InvalidSetting` is also the error for a wrong setting type, a file with no picture stream, a side over 8192, a frame over 128 MiB, and a layout the adapter refuses rather than converts. A missing file, an unreadable file, an unsupported codec, or any other open or decode failure that prevents a picture must be `SourceError::Media(String)`, the same role `Image(String)` has for a still. A fault after playback has started must mark this source Unavailable, release the worker on the control path, keep the last published texture, emit silence, and restart with ADR-0024 back-off. Other sources and the show must keep running.

10. **Conformance is named.** Tests must use `rbs-media-decode-test` and `TestClock`. The suite must cover these checks: local-only refusal before any content read, including a symlink, junction, or substituted drive; the audio pin present and silent when the file has no audio stream; video drop and repeat on `TestClock`; hold-last texture and silence at end of file with `loop` false and the worker released; no allocation in `process`; no queue and no file handle while Standby. FFmpeg must not be required for this suite. The with-and-without FFmpeg CI build (ADR-0007) stays separate and must not stand in for these checks.

## Consequences

- One source covers a looping animation and a one-shot clip. End of file does not hide the item; hiding stays `visible` or a later timed-show cue. With `loop` false the worker is released and the last texture stays published.
- The pin pair is fixed, so a file with no audio stream and a test double that emits silence share the ADR-0106 producer from the first build. The source must not ship until ADR-0106 and ADR-0107 are accepted. Implementation may proceed in parallel.
- The first adapter (`rbs-media-ffmpeg`) uploads on the worker through the existing upload path. A hardware adapter can take `media.decode.pixel` = `zero-copy` without a scene-type change. The document stores an adapter id only when the user sets `adapter`.
- When this ADR is implemented, `SourceInstance` gains `Media { node, stats, adapter }`, `SourceClass` gains `Media`, and `SourceError` gains `Media(String)`. Those enum edits are a follow-up of this decision. They are not part of this text change.
- Spec follow-ups at implementation, at the next free scene-format and protocol minor: a `rbs-media-decode` port spec (trait, `media.decode.pixel`, conformance on `rbs-media-decode-test`); scene sources (type id `org.rbs.source.media`, node id `org.rbs.media`, settings, local-only, the `Media` instance); scene model (temporal scheduling, ADR-0107); user-data; control API (`source.add` and settings for this type); glossary; and the UI design system (Add source, Source settings). The capture-port line that media files are not capture stays true.
- Tests must include the six checks in decision 10, on the fake adapter and `TestClock`. The FFmpeg adapter is not required for that suite. CI that already builds with and without FFmpeg (ADR-0007) covers the real adapter separately and must not replace those checks.
- The upload counters and the decode-to-writer path need `hot-path-review` and a human maintainer's approval when they land (P15, ADR-0106 decision 8).
- Negative: a playing file still needs a worker and two capped queues. Sleep, and an ended clip with `loop` false, release that cost. The first frame after show waits on open.
- ADR-0074's "animated pictures are decided separately" points here. Text and SVG stay undecided.

## Reference tools (CLAUDE.md rule 17)

- **OBS Studio** has a Media Source (FFmpeg: local files and URLs, looping, restart, close file when inactive) and plays GIF either there or as an image. Network URLs and a visible source that keeps reading while hidden are both common. Hardware decode is a property of that source, tied to the FFmpeg build.
- **Where this falls short of that set:** no network URL, no slideshow, no hardware decode in the first adapter, and end-of-file does not hide the item.
- **What RBS does by this decision:** one type id for every animated file; the document does not name the decoder; a hidden file holds no reader (ADR-0107); sound uses the same mixer producer as any other picture-and-sound source (ADR-0106); an agent cannot turn the path into a URL (ADR-0052).

## Alternatives considered

- **A GIF type and a video type.** Two documents for one playback rule. Rejected.
- **Decode inside `rbs-sources` with the `png` crate extended to GIF.** Pulls demux into an engine crate and cannot play video. Rejected (P1, ADR-0007).
- **Expand a short GIF into a frame atlas in CPU memory.** A long animation would hold every frame. The worker queue is the one path.
- **Write `visible` false when the file ends.** That is a scene edit, and it fights a user who left the item shown on the last frame. Holding the frame keeps the document stable.

Reviewer: independent AI session
Date: 2026-11-12
Verdict: changes requested
Concerns:

1. **Audio topology, the static descriptor, and sleep cannot all be true.** Scene-sources invariant 2 requires every instance descriptor to equal the single descriptor in `node_types()`, and graph nodes carry a node-crate type id, not the scene source type id. `SourceClass` and `SourceInstance` only cover capture, audio, and still. Decision 1 names only `org.rbs.source.media`. Decision 6 gives the node an audio pin when the container has an audio stream, and no pin otherwise, and forbids reporting that case as `AudioOnVideoSource`. The pin set is known only after opening the file. Decision 7 and ADR-0107 release the file handle and decoder while the source is Standby and leave it unlinked. ADR-0106 decision 4 forbids a picture that later gains a different strip producer. A probe therefore has to finish before the first bind, the pin set has to stay fixed for the life of that node (including Standby and a failed later decode), and one table descriptor cannot equal both shapes. Path replace may probe again, because decision 8 already replaces the node and ADR-0106 rebuilds strips on `replaced_sources`. A simpler rule that keeps one descriptor: the node always has an audio output, a file with no audio stream emits silence, and the partition-queue reader is the producer from the first build. -> **open** (name the scene type id, the node-crate type id, and the `SourceInstance` shape; pick non-retaining control-thread probe with a pin set frozen until `path` replaces the node, including an explicit exception to invariant 2, or the always-on audio pin with silence).

2. **Demux and decode have no port, so a second adapter is not swappable (P1, P2, P3).** Decision 3 puts demux and decode in an adapter, keeps FFmpeg out of engine, scene, and core crates, and puts a later hardware decoder behind the same type id. Consequences depend on a fake decoder adapter. P2 requires a trait, a capability description, and a conformance suite; P3 selects by capability. The ADR does not say which crate owns master-clock alignment, `loop`, sleep, and the queues, what the adapter returns (frames, audio, timestamps), or how the host chooses among adapters. The existing `adapter` setting is how every current source pins a choice, but decision 3 also says the scene document must not name FFmpeg, so a stored adapter id and a forbidden name are both plausible. "Must not link FFmpeg" is also narrower than P1: engine, scene, and core crates must not depend on the media adapter; only the composition root wires it. Without the split, each hardware adapter reimplements playback or the trait appears only in code. -> **open** (define the port and the node/adapter split; capabilities cover pixel path and zero-copy; selection is capability order, and a stored adapter id is allowed while the type id stays decoder-neutral; conformance runs on the fake adapter).

3. **The frame and audio handoff can break the render thread, the mix, or memory (P4, P5, P6, P10, P15).** Decision 4 allows one upload per frame, sends 4:2:0 through the compositor's existing YUV decode, and treats 8-bit sRGB pictures as the still source does. Decision 5 drops or repeats frames to the master clock. Decision 7 uses one bounded worker queue and forbids allocate, block, and file I/O in `process`. A side over 8192 is refused before that queue exists. Those sentences still leave incompatible implementations. Video may drop or repeat; audio on this path uses ADR-0106 master-clock time, and a dropped audio block is a silent strip, so the same drop policy applied to samples glitches the mix. File timestamps have to be converted onto the master clock at the edge (P5); frame-index over nominal fps breaks variable frame rate, and the ADR does not choose. One queue does not keep a short video lookahead separate from audio blocks. Resample and upload have no thread: either inside `process` can allocate or block (P6). Empty queues have no wait rule. Layout, range, and matrix of the YUV path are unnamed; 10-bit, 4:2:2, 4:4:4, straight alpha for GIF, APNG, and animated WebP, the audio stream index, and a file with no picture are unnamed, so the fake adapter and FFmpeg can disagree. Stills also cap a decoder buffer at 128 MiB and upload once; a queue of 8192-square frames has no byte cap. The accepted upload is a hot path (ADR-0106 already flags decode-to-writer) and has no metric and no `hot-path-review`. -> **open** (lock-free video lookahead and audio block queue, both only while Active, with a byte cap; `process` only dequeues; video drops or repeats and never waits; audio is continuous master-clock time, resampled on the worker, silence on underrun; container timestamps mapped at the edge; name the YUV and straight-alpha sRGB handoff and refuse or convert every other layout, including audio-only; metrics plus hot-path review for the upload).

4. **`restart_when_shown` and a live `loop` edit have nothing to talk to after sleep.** Decision 5 reads `restart_when_shown` when the source becomes Active and pushes `loop` to the running decoder without replacing the node. Decision 7 releases the file handle and the decoder while the source sleeps, which is what ADR-0107 requires. After that release there is no decoder to resume and no running decoder to accept `loop`, so `restart_when_shown: false` behaves as true unless the node keeps a media-time cursor with no reader, and a `loop` edit made while Standby is dropped. End of file with `loop` false holds the last frame and emits silence, but the worker is not required to stop, so a finished clip stays at the Active cost this ADR accepts only for a playing file. A live `loop` change has no take-effect point (immediately, or at the next loop point). Joining that worker on the render thread would make sleep itself block `process`. -> **open** (store the cursor, `loop`, and `restart_when_shown` on the node with no decoder; seek on wake when restart is false; define when a live `loop` change applies; at end of file release the worker and repeat the last texture; join the worker on the control path).

5. **Failure and the local-only boundary are not yet a contract, and the ship gate is one ADR short.** P7 keeps a failed node's last good frame or silence, restarts with back-off, and notifies the user. ADR-0107 uses ADR-0024 and Unavailable for a failed wake. This ADR gives no error for a missing file, a bad `path`, an oversized frame, an unsupported codec, or a fault after playback has started. Stills use `InvalidSetting` and `Image`. Local-only refuses a URL, a UNC path, or a device path so an agent cannot open a host (ADR-0052). A check of the raw string still opens a host or a pipe when a symlink, junction, or substituted drive resolves there, and a pipe open on the control thread stalls the host. The check has to run on the canonical path, and non-regular files have to be refused, before any read. Tests correctly use a fake decoder and `TestClock`, with FFmpeg left to the existing with/without build, but that build does not assert playback and no assertion list locks the choices above. Decision 6 blocks shipping until ADR-0106 is accepted. Decision 7 is false under today's `wanted_sources` / `warm_sources` until ADR-0107 is accepted; the context already says neither is accepted. Parallel implementation matches the owner line; shipping has to wait on both. -> **open** (name the errors; contain a mid-play fault to this node with last frame and silence; canonicalize and refuse non-files; conformance for local-only, the pin rule, TestClock drop/repeat, hold-last and silence, no allocation in `process`, and no queue or handle while Standby; do not ship until ADR-0106 and ADR-0107 are accepted).

Resolutions (author, 2026-11-12), written into decisions 1–10. Concerns 1–5 are closed:

1. Scene type `org.rbs.source.media`, node type `org.rbs.media`, one descriptor with video and audio outputs for every instance (invariant 2, no pin-set exception). A file with no audio stream keeps the pin and emits silence. The ADR-0106 reader is the producer from the first build. A control-thread probe may run only at instantiate and path replace, retains nothing, and must not change the pin set. `SourceInstance::Media` and `SourceClass::Media` are the follow-up in Consequences.
2. Port crate `rbs-media-decode` (`MediaDecoder`, capability `media.decode.pixel` of `zero-copy` or `cpu-upload`). FFmpeg lives in `rbs-media-ffmpeg`; later hardware adapters use the same trait. Composition roots register. The node owns clock, loop, cursor, sleep, and queues. `adapter` may store an id; otherwise selection is capability order. The type id stays decoder-neutral. Conformance runs on `rbs-media-decode-test`. Engine, scene, and core crates must not depend on an adapter crate.
3. Two lock-free queues while the worker runs (video at most 8 frames and 128 MiB, audio at most four graph blocks). `process` only dequeues. Video may drop or repeat and must not wait. Audio stays on the master clock, resampled on the worker, silence on underrun. Container timestamps are mapped on the worker. NV12 and P010 use the existing `YuvDecoder`; animated pictures are straight-alpha sRGB `Rgba8`; every other layout is converted or refused; a file with no picture is `InvalidSetting`. Upload counts and `hot-path-review` are required when that path lands.
4. The node stores the cursor, `loop`, and `restart_when_shown` with no decoder while Standby. Wake sets the cursor to 0 when `restart_when_shown` is true, and seeks otherwise. A live `loop` change applies at the next loop boundary while playing, and immediately when stored otherwise. End of file with `loop` false releases the worker, keeps the last texture, emits silence, and joins the worker on the control path only.
5. Errors are `InvalidSetting`, `SourceError::Media(String)` in the role of `Image`, and Unavailable with the last frame, silence, and ADR-0024 back-off. The host must canonicalize `path` and refuse anything that is not a local regular file before any content read. The source must not ship until ADR-0106 and ADR-0107 are accepted. The six conformance checks are decision 10.
