# ADR-0108: A local media-file source for video and animated pictures

- Status: Accepted
- Date: 2026-11-12
- Deciders: Salih (owner)
- Builds on: [ADR-0007](0007-ffmpeg-as-optional-adapter.md), [ADR-0052](0052-ai-agent-control-through-mcp.md), [ADR-0074](0074-still-image-and-colour-sources.md), [ADR-0106](0106-picture-and-sound-on-one-source.md), [ADR-0107](0107-temporal-sources-sleep-when-hidden.md)

## Context

ADR-0074 covers pictures that do not change: a PNG or a generated colour. GIF, APNG, animated WebP, and video files need a source that produces frames over time. The capture port leaves media files to a separate node type. ADR-0007 already allows FFmpeg inside a media-file source adapter, dynamically linked, LGPL, and forbids it in mux, transport, audio processing, and compositing.

People use one file as a looping bug, a stinger that plays once, or a silent animation. Those are one kind of source. A slideshow is a list of stills and is not this type. A network URL is not a local file; an agent that can set a path must not be able to open a host (ADR-0052).

Sound needs ADR-0106. Sleeping while no shown scene draws the item needs ADR-0107. Neither is accepted yet. This ADR must not be implemented as a silent picture that later grows an audio pin.

## Decision

1. **Scene type `org.rbs.source.media`, two fixed node types.** The scene type plays one local file that changes over time: video, GIF, APNG, or animated WebP. There must not be a separate GIF type. A slideshow must not use this type. Following ADR-0106, one source is two nodes fed by one decode worker: the picture node `org.rbs.media` (render partition, one video output) and the sound node `org.rbs.media.sound` (audio partition, one audio output). Both descriptors live in `rbs-nodes`, both are in `node_types()`, and every instance uses them (scene-sources invariant 2). Whenever the binder has an audio partition, the pair is fixed for the life of the source, including Standby, a failed decode, and a file with no audio stream, whose sound node writes silence. `SourceInstance` gains `Media { picture, sound, control, stats, adapter }`, where `sound` is absent when the binder has no audio partition (ADR-0106 decision 2), and `SourceClass` gains `Media`.

2. **Ship gate.** The source must not ship until ADR-0106 and ADR-0107 are accepted. Parallel implementation is allowed.

3. **The probe picks the adapter and reads the duration; it never chooses pins.** A probe of `path` runs on a worker thread, not the control thread, at instantiate and when a `path` or `adapter` change builds a new source. It reads the container header only. Until it finishes the adapter and the duration are unknown, the source publishes nothing, and the duration is `None`. The probe sends its result (adapter, duration, audio flag) on a channel and wakes the control loop, which reads it at once. A wake while the probe still runs does not probe again: the worker waits for that result on its own thread. It tries adapters in the order of decision 4 and keeps the first that opens the file. The source keeps that adapter until `path` or `adapter` changes; a wake does not try every adapter again, except that `Unsupported` from the kept adapter at wake (the file at that path was replaced) runs the probe once more. The probe stores the adapter id (not in the document unless the user set `adapter`), the stated duration, and whether there is an audio stream on the instance, then drops the decoder and the file handle. When every adapter refuses, the reported error is the most specific one: `InvalidSetting` before `Unsupported` (a named missing codec) before `Failed`.

4. **Demux and decode are the `rbs-media-decode` port.** The trait `MediaDecoder` opens a path the host has already accepted, seeks to a media-time position, and reads each stream separately: the next picture of the picture stream and the next interleaved PCM of the first audio stream, each with container timestamps (both platform readers read per stream). An adapter whose demuxer reads in container order keeps its own bounded skew buffer of compressed packets, at most 1 s and at most 8 MiB, off the rings, and fails with a counted `Failed` beyond it. It does not own the master clock, `loop`, `restart_when_shown`, the cursor, sleep, or the rings; the source does. A picture's payload is an `rbs_core::media::VideoFrame`: system memory (NV12, P010, or straight-alpha sRGB `Rgba8`) or a native surface the render partition already imports for capture (`IoSurface` on macOS, `D3dSharedHandle` on Windows). Capability `media.decode.pixel` is a set of `zero-copy` and `cpu-upload`. `duration()` returns `Option<Duration>` with a default of `None`. The port's public enums are `#[non_exhaustive]`, and a new trait method must have a default, so adding a payload or a method is not a breaking change. A frame duration of 0, or of 10 ms or less in an animated picture, must be read as 100 ms (the browser rule), and a video frame of zero duration continues by the stream's nominal frame duration; the adapter applies this before returning the sample.

   The first adapters are the platform decoders (owner's choice, 2026-11-16), plus one pure-Rust adapter. `rbs-media-mf` (Windows, Media Foundation source reader with DXVA hardware decode) and `rbs-media-avf` (macOS, `AVAssetReader`, VideoToolbox) must target `zero-copy`, through the same import paths the capture adapters use (`rbs-capture-wgc`, `rbs-capture-avf`). A native payload follows the capture port's native surface rules unchanged (lease returned only after the importer's GPU work is retired, a handed-out handle kept open at least 10 s after its last reference, also after the worker stops, the LUID encoding), and a source holds at most the surface budget of decision 5 (at most 18), recorded in the port spec against the importer's shared `MAX_SURFACES` of 64. When an import fails at that limit the picture node repeats its last texture and counts it. On Windows the adapter copies the decoder's texture-array slice into a shared texture on the GPU and counts that copy. Each may also offer `cpu-upload`, but only as a measured fallback (P4): CPU, bus bandwidth, and frame time at 1080p60 and 4K60 recorded in its PR, its copies counted in the source's metrics, and an exit criterion in the adapter's spec. `rbs-media-anim` (every platform) decodes GIF, APNG, and animated WebP to `Rgba8` in system memory. FFmpeg, dynamically linked and LGPL as ADR-0007 requires, may later be `rbs-media-ffmpeg` for other formats and for Linux video. Selection: when `adapter` is set, only that id; otherwise `zero-copy` before `cpu-upload`, then registration order. A codec the platform lacks (for example HEVC or AV1 without the Store extension, or a Windows N edition without Media Foundation) must be `DecodeError::Unsupported` naming the codec, so the host can try the next adapter and the user is told what is missing. A hardware session limit is handled inside the adapter (its own software path) or is `Failed`; it must not change the adapter's stated capability. Composition roots (`rbs-app`, `rbs-cli`, `rbs-mcp`) register adapters; `rbs-core`, `rbs-graph`, `rbs-scene`, `rbs-engine`, `rbs-nodes`, `rbs-sources`, `rbs-gpu`, and `rbs-audio` must not depend on an adapter crate. The scene type id must not name a decoder.

5. **One worker, source-owned rings, and nodes that only dequeue.** The decode worker runs only while the source is Active, not paused or cued past the release time of decision 10, and not in the end hold of decision 7, except that the control path may start it to decode one picture in those states (decision 10), after which it is released again. It owns the decoder. The rings belong to the source for its Active life, not to a worker. They are fixed-bound slot arrays that hold small item records (a stamp, the epoch, the generation, and a buffer or surface reference), not pixels: at most 16 picture slots, and sound slots for the lead plus `AudioGraphConfig.latency` plus 2 blocks, all known on the control path without opening the file. They are allocated on the control path at the Active transition and freed at Standby through the engine's background drop, never on a real-time thread. The worker allocates pixel and sample buffers on its own thread after open and gets them back on the return rings. A worker release (pause release, end hold, fault) frees only that worker's buffers, on the worker's or the reaper's thread after the nodes have returned them; the slot arrays stay while the nodes are scheduled. Successive workers reuse the slot arrays. A graph latency change takes effect at the next Active transition; until then the worker paces sound so that it never needs more slots than exist, and counts what it drops. Each worker has an epoch; every item and every write it makes to the control handle carries that epoch, and the nodes and the handle ignore an older epoch, so a stale worker that unblocks late changes nothing. The rings are lock-free SPSC: a picture ring, a sound ring, and one return ring per node for system buffers.

   *Pacing.* The worker paces each stream by master time only and never waits on a ring. The lead `L` is 150 ms. After open the worker sets how many picture slots it fills: the pictures within `L` plus 2, at the stream's nominal frame rate (for a variable rate or an animated picture, the shortest of its first 8 frame durations after the 100 ms rule), bounded by the 16 slots, by 128 MiB of system memory, and by the surface budget; when a bound allows fewer, `L` shrinks to that span. The surface budget of decision 4 is the filled picture slots plus 2 (a decoder's working surfaces); when the decoder would need more, the worker drops the new picture and counts it. "Full" means the fill count is reached: a burst above it uses a free slot only while the buffer or surface stays within the budget, and is dropped and counted otherwise. Each return ring holds its forward ring's slot count plus one, so a return from a real-time thread never finds it full. While paused or cued (including a seek while paused) the worker queues only the one picture it was asked for and no sound, so the pause release can free every buffer. The sound ring holds `L` plus `AudioGraphConfig.latency` plus 2 blocks, read when the rings are allocated, because the sound node reads at `block_time` (tick time minus that latency). The worker decodes a stream ahead only until its next stamp is `L` ahead of now. When a ring is full anyway (its node is not running, or its thread stalls), the worker drops the new item and counts it. So a render stall or an unscheduled compositor never stops the sound, and an unscheduled sound node never stops the picture (ADR-0106 decisions 1 and 3). Only the consuming node skips late items; the worker never removes a queued one. The port reads each stream separately (decision 4), so the worker paces pictures and sound independently whatever the file's interleave.

   *Time.* Every item carries its master-time stamp, the worker epoch, and the generation of decision 10. The worker anchors the cursor to master time once it holds the first picture (and, when the source has a sound node and the file has audio, the first sound block) for that cursor, at now plus `L`. The first sound block is padded with leading silence up to the anchor so the first sample is at the anchor. The play latency is the open or seek, the decode to that first picture, and `L`. The worker maps container timestamps onto the master clock with that anchor, keeps mapping forward across a loop boundary (the next pass starts where the range's length ends), resamples PCM to `AudioGraphConfig.format`, remaps channels, cuts blocks on the `block_time` grid (ADR-0106 decision 3), and cuts sound to the sample at the play range's ends. A missing timestamp continues from the previous stamp by the frame duration; a container that states neither fails open with `Media`.

   *Nodes.* The picture node's `process` dequeues the picture due at the tick, imports a native surface or uploads a system frame the way the capture node does (the render partition's pool, an existing hot path), publishes it, and returns a system item on its return ring (a native item goes back by its lease after the importer retires it). An empty ring repeats the last texture and never waits. The sound node's `process` drops every block older than the tick's block (a loop bounded by the ring size), copies the due block into its pin, or writes silence, and returns the blocks. Neither `process` allocates, frees, blocks, resamples, or reads the file. A file with no audio stream writes silence that is not counted as an underrun. The source counts uploads, imports, copies (`cpu-upload`), pictures and blocks the worker dropped, pictures the node skipped or repeated, and sound underruns.

6. **Pixel rules.** An 8-bit 4:2:0 picture is NV12, a 10-bit one P010, both through the compositor's existing `YuvDecoder` (`check_color`); the source must not add a second YUV decoder. GIF, APNG, and animated WebP are straight-alpha sRGB `Rgba8`, the still rule. Every other layout or colour space `check_color` rejects is converted by the adapter or open fails with `Media`. The first audio stream is used; others are ignored. A side over 8192 pixels or a frame over 128 MiB is `InvalidSetting` before any buffer is allocated.

7. **Cursor, loop, and restart survive with no decoder.** The source stores the cursor, `loop` (default true), and `restart_when_shown` (default true) while it holds no decoder, file handle, or ring. On wake, `restart_when_shown` true sets the cursor to the start of the play range; false seeks to the stored cursor. Playback follows the master clock; the source keeps no clock of its own and never writes `visible`. With `loop` true, reaching the end of the range seeks to its start. A loop must not leave a timestamp gap. When the seek back takes longer than the lead (a `start_ms` inside a long group of pictures, a slow disk) the picture repeats and the sound has underruns, both counted. With `loop` false, the end of the range is the end hold: the worker is released on the control path, the last texture stays published, and the sound is silence. Releasing a worker signals it to stop and hands the join to a reaper thread off the control thread, so a worker stuck in an open or a seek never blocks an apply; the thread is counted until it exits, and a new wake does not wait for it. The reaper exists only while it holds a worker or a lingering native surface and exits when it holds none (P13). It also holds a stopped worker's native surfaces for the 10 s the capture rules require, counted from each surface's last reference (the picture node keeps its last texture's reference while it shows it, so in the end hold that surface lives until it is replaced), so a source reaches ADR-0107's "no thread, no timer" at most 10 s after sleep. Lingering surfaces count against the source's budget until released, so rapid show and hide does not stack budgets against `MAX_SURFACES`. A worker stuck in an open (for example a cloud placeholder file) is shown as a live thread in the source's metrics.

8. **Changing `path` replaces the source.** Break-before-make, filters kept, a new probe (decision 3).

9. **Local files and named errors.** Before any read of file contents, the host canonicalizes `path` and refuses the open unless the canonical target is a local regular file. A URL, a UNC path, a device path, a directory, a pipe, and a symlink, junction, or substituted-drive target that does not resolve to a local regular file are `InvalidSetting` on `path`. So are a wrong setting type, a file with no picture stream, a side over 8192, a frame over 128 MiB, and a layout the adapter refuses. A missing or unreadable file, an unsupported codec, and any other failure that prevents a picture are `SourceError::Media(String)`. A fault after playback has started marks the source Unavailable, releases the worker on the control path, keeps the last texture, writes silence, and restarts with ADR-0024 back-off. Other sources and the show keep running. Wake follows ADR-0107 decision 5: the Active transition starts the worker and returns, and the first picture arrives later.

10. **Playback controls go through a control handle, not through `process`.** The source instance gives the host a control handle (as the browser source does) made of atomics and a generation counter, readable and writable without locks. The host offers play, pause, restart, and seek for one source. They are live actions: they do not write the document, are not undo steps, and do not replace the source (the `set_program` rule, ADR-0021). The control thread writes the handle; the worker reads it; the nodes only compare the generation on each item. A seek or restart bumps the generation, the worker seeks and decodes forward to the first picture at or after the position (dropping its own older items), and the nodes skip and return items of an older generation. Every command writes a record to the handle: a new generation, its instant, and a `paused` flag. The handle keeps the last 4 records in a small array under a sequence counter. At a tick or block time `t` the record that applies is the latest one whose instant is at or before `t`; silence before a new anchor is not an underrun. More than 4 commands within one graph latency end the oldest generation's sound early, counted and never doubled, and the control path merges consecutive seeks of a scrub into one record per render period. A real-time reader never retries: on a torn read it keeps the records it read last tick and reads again next tick, which is in time for the sound node because the instant is ahead; the picture node may then act one picture late, which is counted. The instant is the current master time plus the longest render period among the partitions that hold the picture node, rounded up to the audio block grid, so no node has already passed it. An item of generation `h` plays only when it is stamped before the instant of the record that ended `h` (the record of generation `h + 1`); an item whose generation has left the array is skipped and returned; items of the newest generation follow their own stamps and the `paused` flag. So two commands within one graph latency never let sound the first one cut play later. Pause writes a record with `paused` set: from its instant the picture node repeats its last texture and the sound node writes silence that is not counted as underrun, so picture and sound stop at the same media time. The cursor is the media time at that instant, and the worker stops pulling. A seek while paused writes a record with `paused` still set; the worker decodes forward to the first picture at or after the position, and the picture node publishes that one picture and holds it. Play writes a record with `paused` clear; the worker seeks to the cursor and anchors again (decision 5). Restart and seek while playing use the same rule. Each transition in the table below writes the handle as the matching command: playing to `cued` is a pause (plus a seek to the range start when `restart_when_shown` is true), and `cued` or `paused` to `playing` is a play, or a restart when the table starts at the range start (`restart_when_shown` true). A seek while paused publishes the picture at the new position. Play maps the stored cursor to the current master time, so no picture before the cursor is shown and no sample is skipped or doubled. Restart is a seek to the range start followed by play; play from the end hold is restart, and the control path starts the worker. After 30 seconds paused or cued (and in the end hold, which holds no worker except for a one-picture decode) (the default of the `pause_release_s` app setting, which the user can change) the control path releases the worker, the decoder, and the worker's buffers (decision 5; the slot arrays stay), keeping the texture, the cursor, and the state; the next play opens the file again. A seek after that release is stored, and the control path starts the worker to publish the picture at the new position, which the release timer then releases again. The handle publishes the play state (`playing`, `paused`, `cued`, `ended`, `standby`, `unavailable`), the cursor, and the stored duration. A source asleep with a stored `paused` or `ended` publishes that stored state, not `standby`. In Standby the picture node holds no texture (P13), so the texture kept by ADR-0107 decision 5 is only that of a node that was not cooled; when it wakes into `paused` or `ended` from Standby, the control path starts the worker for one picture, as for a seek after the pause release: the picture at the cursor, or for `ended` the last picture of the range, which costs a seek near the end. A source has one playback: controls act on every canvas and on preview and program together, and the UI marks a source that is on program before a control changes what is on air. A media file never plays in the studio-mode preview unless a program or hold scene on some canvas also draws it (owner, 2026-11-16; the source has one playback). A source that only a preview scene draws is `cued` (ADR-0107 decision 6). Its transitions, driven by the binder's on-air set in the same apply:

   | From | Event | To |
   | --- | --- | --- |
   | Standby | a preview scene draws it | `cued`: the picture at the range start (or at the stored cursor with `restart_when_shown` false), silence, no advance |
   | Standby or `cued` | a program or hold scene draws it | `playing`: the cued picture is on air from the first program frame (from Standby nothing is published until the first picture, ADR-0107 decision 5); motion and sound start one lead later, plus the open when the worker had been released (`restart_when_shown` true starts at the range start) |
   | `playing` | only a preview scene draws it (a take swapped it out) | `cued`: with `restart_when_shown` true the cursor moves to the range start, otherwise it stays where it stopped |
   | `playing` | no shown scene draws it | Standby, cursor stored |
   | `paused` or `ended` | only a preview scene draws it, or none | stays `paused` or `ended` (in preview it shows its picture), cursor kept; in Standby the stored state stays `paused` or `ended` |
   | `paused` or `ended`, also stored in Standby | a program or hold scene draws it again (a stored `paused` or `ended` wins over every Standby row) | with `restart_when_shown` false: stays `paused` or `ended`; with true: `playing` from the range start |
   | `cued` | no shown scene draws it | Standby, cursor and state stored |

   The source's own playback is the on-air one. A private audition player in the source's settings window (owner, 2026-11-16) is not part of this ADR: its sound path needs a monitor-only input that ADR-0097 does not have, and its picture path and clock need their own design. A later ADR decides it. The control API carries these commands and a state read at the next free protocol minor; a source of another type refuses them with a typed error.

11. **A play range trims the file without re-encoding.** Settings `start_ms` (default 0) and `end_ms` (absent means the end of the file). `start_ms` must be less than `end_ms` when both are set, or the setting is `InvalidSetting`; a live edit that breaks this is refused at the command, before the document write, and a slider never sends an intermediate invalid pair. Values past the end of the file are clamped at open. A range that is empty after clamping, or shorter than one frame, shows one picture and goes to the end hold (or, with `loop`, holds that picture without seeking again). Looping and the end hold of decision 7 use the range.

12. **Live settings are not a replacement.** `loop`, `restart_when_shown`, `start_ms`, and `end_ms` are the type's live keys. They are declared on the scene-type side: `rbs-scene`'s `NodeTypes` trait gains a method with a default of no keys, which `rbs-sources` implements; `NodeDescriptor` and the plugin SDK do not change. When only live keys differ, the binder updates its bound settings, does not replace the source, and lists the source and the changed keys in a new `BindReport::live_changed`; the host forwards them to the control handle. A live `loop` change takes effect at the next loop boundary while playing, and at once otherwise (an end hold whose `loop` becomes true starts the worker from the range start on the control path). A range change moves a cursor outside the new range to its start. The document write is one undo step per committed edit; a slider drag commits once, on release.

13. **Conformance.** Tests use `rbs-media-decode-test` and `TestClock` and do not require a platform decoder or FFmpeg. They cover: local-only refusal before any content read (symlink, junction, substituted drive); a file with no audio stream giving a silent sound node; picture drop and repeat; lip sync of a stamped picture and its sound (ADR-0106 decision 4); hold-last and silence at the end hold with the worker released; no allocation and no free in either `process`; no ring, worker, or file handle while Standby; no worker, decoder, file handle, or picture or sound buffer after the pause release (the slot arrays stay); the Active transition returning before the first picture; a non-48 kHz file playing at the right speed; a loop boundary with no timestamp gap; a zero-duration GIF frame; pause and play (no picture before the cursor, no sample skipped or doubled); seek while paused publishing the new picture; a stale-generation item skipped; restart from the end hold; an empty range; `cued` in preview starting on the take; live-key edits that do not replace the source and appear in `live_changed`; a duration of `None` and of `Some`; a 60 fps file with sound showing every picture with no drop; the picture playing on while the sound node is unscheduled; the first picture of a clip on time after the anchor; a take, then a take back, of a playing, a paused, and an ended clip, following the table of decision 10; pause stopping picture and sound at the same media time; play within one graph latency of pause, two seeks within one graph latency while playing, and pause then seek within one graph latency, each with no sample of the old position after the first instant and none doubled; a 1 s interleaved fixture paced without drops; a stale worker epoch ignored; a wake into `paused` and into `ended`; an import failure at the `MAX_SURFACES` limit repeating the last texture; the probe off the control thread and one re-probe on `Unsupported`; a release that does not wait for a stuck worker; and a native item returned only by its lease. Each real adapter also has a per-platform conformance test with small fixture files (as `rbs-capture-avf/tests/conformance.rs` does), run on that platform; a codec the machine lacks is a skip with a reason, not a failure.

## Consequences

- One source covers a looping animation, a trimmed clip, and a one-shot stinger. End of file does not hide the item; it holds the last picture.
- The source is two nodes with one worker (ADR-0106), so its sound runs on the audio cadence and its picture on the render cadence, both on the master clock.
- On standard editions of Windows and on macOS, common H.264 and AAC files play with nothing to install, decoded in hardware and passed to the compositor without a CPU copy. HEVC and AV1 on Windows can need a Store extension, and Windows N editions need the Media Feature Pack; the user is told which. Linux plays GIF, APNG, and animated WebP only, until an FFmpeg adapter lands.
- Spec follow-ups at implementation, at the next free scene-format and protocol minor: the `rbs-media-decode` port spec (trait, payload, `media.decode.pixel`, frame-duration rule, conformance), scene sources (the two node ids, live keys, `SourceInstance::Media`), scene model (live keys in the binder, `cued`), audio graph (the sound node), control API (playback commands and state), user data (`pause_release_s`), glossary, and the UI design system (Add source, Properties, the playback bar). The UI is a visual change and follows the UI approval rule.
- The picture node's import or upload, the worker-to-ring path, and the sound node's `process` take `hot-path-review` and a human maintainer's approval when they land (P15). The `cpu-upload` fallback needs its numbers.
- Negative: a playing file costs a worker, a decoder, and the rings. Sleep, the end hold, and a long pause release them. The first picture after show waits on open, without blocking the scene switch.
- ADR-0074's "animated pictures are decided separately" points here. Text and SVG stay undecided.

## Reference tools (CLAUDE.md rule 17)

- **OBS Studio** has a Media Source (FFmpeg: local files and URLs, looping, restart when shown, hardware decode as a checkbox, show nothing when ended, close file when inactive, speed, colour range) and media controls under the preview while the source is selected. It ships FFmpeg. Unless "close file when inactive" is set, a hidden source keeps its decoder.
- **Where this falls short of that set:** no network URL, no slideshow, no speed control yet, no "show nothing when ended" yet, and on Linux no video until an FFmpeg adapter.
- **What RBS does by this decision:** hardware decode with no CPU copy on Windows and macOS, and nothing to install for common files;  one type id for every animated file; a play range that trims without re-encoding; sound and picture locked to the master clock with a tested lip-sync bound; a preview-only clip that waits for the take instead of playing out in preview; a hidden file holds no reader (ADR-0107); controls through the control API as well as the UI; an agent cannot turn the path into a URL (ADR-0052).

## Alternatives considered

- **A GIF type and a video type.** Two documents for one playback rule. Rejected.
- **Decode inside `rbs-sources` with the `png` crate extended to GIF.** Pulls demux into an engine crate and cannot play video. Rejected (P1, ADR-0007).
- **Expand a short GIF into a frame atlas in CPU memory.** A long animation would hold every frame. The worker queue is the one path.
- **One node with both pins, sound crossing on a partition queue.** This ADR's first text. Replaced by two nodes after review round 2 (ADR-0106).
- **Write `visible` false when the file ends.** That is a scene edit, and it fights a user who left the item shown on the last frame. Holding the frame keeps the document stable.

Reviewer: independent AI session
Date: 2026-11-12
Verdict: changes requested
Concerns:

1. **Audio topology, the static descriptor, and sleep cannot all be true.** Scene-sources invariant 2 requires every instance descriptor to equal the single descriptor in `node_types()`, and graph nodes carry a node-crate type id, not the scene source type id. `SourceClass` and `SourceInstance` only cover capture, audio, and still. Decision 1 names only `org.rbs.source.media`. Decision 6 gives the node an audio pin when the container has an audio stream, and no pin otherwise, and forbids reporting that case as `AudioOnVideoSource`. The pin set is known only after opening the file. Decision 7 and ADR-0107 release the file handle and decoder while the source is Standby and leave it unlinked. ADR-0106 decision 4 forbids a picture that later gains a different strip producer. A probe therefore has to finish before the first bind, the pin set has to stay fixed for the life of that node (including Standby and a failed later decode), and one table descriptor cannot equal both shapes. Path replace may probe again, because decision 8 already replaces the node and ADR-0106 rebuilds strips on `replaced_sources`. A simpler rule that keeps one descriptor: the node always has an audio output, a file with no audio stream emits silence, and the partition-queue reader is the producer from the first build. -> **open** (name the scene type id, the node-crate type id, and the `SourceInstance` shape; pick non-retaining control-thread probe with a pin set frozen until `path` replaces the node, including an explicit exception to invariant 2, or the always-on audio pin with silence).

2. **Demux and decode have no port, so a second adapter is not swappable (P1, P2, P3).** Decision 3 puts demux and decode in an adapter, keeps FFmpeg out of engine, scene, and core crates, and puts a later hardware decoder behind the same type id. Consequences depend on a fake decoder adapter. P2 requires a trait, a capability description, and a conformance suite; P3 selects by capability. The ADR does not say which crate owns master-clock alignment, `loop`, sleep, and the queues, what the adapter returns (frames, audio, timestamps), or how the host chooses among adapters. The existing `adapter` setting is how every current source pins a choice, but decision 3 also says the scene document must not name FFmpeg, so a stored adapter id and a forbidden name are both plausible. "Must not link FFmpeg" is also narrower than P1: engine, scene, and core crates must not depend on the media adapter; only the composition root wires it. Without the split, each hardware adapter reimplements playback or the trait appears only in code. -> **open** (define the port and the node/adapter split; capabilities cover pixel path and zero-copy; selection is capability order, and a stored adapter id is allowed while the type id stays decoder-neutral; conformance runs on the fake adapter).

3. **The frame and audio handoff can break the render thread, the mix, or memory (P4, P5, P6, P10, P15).** Decision 4 allows one upload per frame, sends 4:2:0 through the compositor's existing YUV decode, and treats 8-bit sRGB pictures as the still source does. Decision 5 drops or repeats frames to the master clock. Decision 7 uses one bounded worker queue and forbids allocate, block, and file I/O in `process`. A side over 8192 is refused before that queue exists. Those sentences still leave incompatible implementations. Video may drop or repeat; audio on this path uses ADR-0106 master-clock time, and a dropped audio block is a silent strip, so the same drop policy applied to samples glitches the mix. File timestamps have to be converted onto the master clock at the edge (P5); frame-index over nominal fps breaks variable frame rate, and the ADR does not choose. One queue does not keep a short video lookahead separate from audio blocks. Resample and upload have no thread: either inside `process` can allocate or block (P6). Empty queues have no wait rule. Layout, range, and matrix of the YUV path are unnamed; 10-bit, 4:2:2, 4:4:4, straight alpha for GIF, APNG, and animated WebP, the audio stream index, and a file with no picture are unnamed, so the fake adapter and FFmpeg can disagree. Stills also cap a decoder buffer at 128 MiB and upload once; a queue of 8192-square frames has no byte cap. The accepted upload is a hot path (ADR-0106 already flags decode-to-writer) and has no metric and no `hot-path-review`. -> **open** (lock-free video lookahead and audio block queue, both only while Active, with a byte cap; `process` only dequeues; video drops or repeats and never waits; audio is continuous master-clock time, resampled on the worker, silence on underrun; container timestamps mapped at the edge; name the YUV and straight-alpha sRGB handoff and refuse or convert every other layout, including audio-only; metrics plus hot-path review for the upload).

4. **`restart_when_shown` and a live `loop` edit have nothing to talk to after sleep.** Decision 5 reads `restart_when_shown` when the source becomes Active and pushes `loop` to the running decoder without replacing the node. Decision 7 releases the file handle and the decoder while the source sleeps, which is what ADR-0107 requires. After that release there is no decoder to resume and no running decoder to accept `loop`, so `restart_when_shown: false` behaves as true unless the node keeps a media-time cursor with no reader, and a `loop` edit made while Standby is dropped. End of file with `loop` false holds the last frame and emits silence, but the worker is not required to stop, so a finished clip stays at the Active cost this ADR accepts only for a playing file. A live `loop` change has no take-effect point (immediately, or at the next loop point). Joining that worker on the render thread would make sleep itself block `process`. -> **open** (store the cursor, `loop`, and `restart_when_shown` on the node with no decoder; seek on wake when restart is false; define when a live `loop` change applies; at end of file release the worker and repeat the last texture; join the worker on the control path).

5. **Failure and the local-only boundary are not yet a contract, and the ship gate is one ADR short.** P7 keeps a failed node's last good frame or silence, restarts with back-off, and notifies the user. ADR-0107 uses ADR-0024 and Unavailable for a failed wake. This ADR gives no error for a missing file, a bad `path`, an oversized frame, an unsupported codec, or a fault after playback has started. Stills use `InvalidSetting` and `Image`. Local-only refuses a URL, a UNC path, or a device path so an agent cannot open a host (ADR-0052). A check of the raw string still opens a host or a pipe when a symlink, junction, or substituted drive resolves there, and a pipe open on the control thread stalls the host. The check has to run on the canonical path, and non-regular files have to be refused, before any read. Tests correctly use a fake decoder and `TestClock`, with FFmpeg left to the existing with/without build, but that build does not assert playback and no assertion list locks the choices above. Decision 6 blocks shipping until ADR-0106 is accepted. Decision 7 is false under today's `wanted_sources` / `warm_sources` until ADR-0107 is accepted; the context already says neither is accepted. Parallel implementation matches the owner line; shipping has to wait on both. -> **open** (name the errors; contain a mid-play fault to this node with last frame and silence; canonicalize and refuse non-files; conformance for local-only, the pin rule, TestClock drop/repeat, hold-last and silence, no allocation in `process`, and no queue or handle while Standby; do not ship until ADR-0106 and ADR-0107 are accepted).
