# ADR-0073: The Pictures area, a resizable rail and Studio mode as one switch

- Status: Proposed
- Date: 2026-11-08
- Deciders: Salih (owner)
- Builds on: ADR-0061 (studio mode), ADR-0064 (Transition rail), ADR-0049 (docking, areas), ADR-0054 (the picture never disappears), ADR-0050 (command registry)
- Supersedes in part: ADR-0064 decisions 1, 2 (rail size), 4 and 5 (the studio split as two tab stacks, dissolving), ADR-0049 decision 2's guarded-panel list (Live controls) and decision 3's studio text, ADR-0061's picture-goes-to-Preview rule when no leaf is shown; the UI design system and control API specs change with it

## Context

The owner tested the Live workspace on the Mac (2026-11-08) and found four problems.

1. Opening Properties put it as a tab next to Preview. Cause: `Workspace::open` adds a closed panel to stack 0 of the centre, and in a studio split stack 0 is Preview's stack. ADR-0064 protected moving, closing and collapsing, not opening, and the tab stacks stay reachable by every other route (drops, `move_to_stack`). A rule that each new path must remember is the reason it came back.
2. The Transition rail is 156 px wide between the pictures and cannot be resized. Its "Transition" button takes much room.
3. "Live" (a workspace: which panels are where) and "Studio mode" (a canvas state: Preview and Program apart, transition on air) look like one thing, because the studio split lives inside the workspace files and Edit and Live both carry it.
4. The Live controls panel repeats Go live and Record from the toolbar; its only unique content is the status text.

The owner chose (2026-11-08): Studio mode is one switch that works in every workspace; a workspace is only a layout.

## Decision

1. **The Pictures leaf.** A layout tree may hold one leaf `pictures` in the main window's centre tree, anywhere a stack could be. It is a node, not a tab stack. It shows the canvas it names (`canvas`, optional, default the canvas being edited): Preview alone outside studio mode; Preview, the Transition rail and Program in studio mode. It has no tabs and accepts no tab: open, drop, `move_to_stack` and `move_to_edge` find no stack in it, no drop guide shows over it (edge guides around it still work), and it cannot be collapsed, auto-hidden or floated (`float` and `move_to_stack` into a floating window are refused with `conflict` and the reason). It moves only as a whole. Preview and Program of another canvas (`rbs.preview?canvas=...`) and Program in a floating or projector window stay ordinary panels, unchanged.
2. **Addressing.** The leaf is the panel id `rbs.pictures`: it is in the Panels menu and is opened and closed like a panel. The ids `rbs.preview` and `rbs.program` (no canvas parameter, or the leaf's canvas) are aliases of it: `open` of either shows the leaf, or opens the leaf if it was closed, and never creates a stack. `ui.panel.maximize?id=rbs.program` maximizes the leaf; the picture context menus (Preview, Source) are unchanged and apply to the picture clicked. Entering studio mode no longer opens Preview (U21 line in the spec is dropped): a workspace without the leaf shows no pictures, and the studio switch stays enabled in the toolbar and Scene menu with the hint "This workspace has no Pictures area." Closing `rbs.pictures` is a guarded close like closing Program was (ADR-0054: the undo toast); when it leaves the centre empty, the centre shows the empty-workspace hint with "Open Pictures". Reopening puts the leaf as a new first child of the centre's outermost split (ratio 0.5) or as the whole centre when it was empty.
3. **Studio mode is one switch.** Engine state is as ADR-0061 and ADR-0063. `canvas.studio_mode.toggle` keeps its toolbar button, Scene menu entry and shortcut; the leaf has a header strip with a Toggle "Studio mode" bound to the same command. No workspace sets, forces or clears studio mode, and switching workspaces never changes it.
4. **Panel placement on open.** `Workspace::open` adds a closed panel to the first ordinary tab stack (depth first; the leaf is never one) of the area that is the panel's default home in the built-in Edit layout (Scenes and Sources left, Properties right, Mixer bottom, Stats and Outputs as in Edit); if that area has none, the first ordinary stack of the centre; else a new stack in the right area. It never adds a stack to the centre next to the pictures.
5. **Rail size and form.** In `between` the rail's width is `rail_size` (integer logical pixels, 48 to 240, default 88, clamped on load), changed by dragging either edge of the rail; the pictures share the rest by equal halves. Up to 120 px the rail shows icons only; every icon control has an accessible name and a tooltip with its name and shortcut. The "Transition" text button becomes an icon button, "Transition" with the shortcut as tooltip and accessible name. In `below` the rail stays 44 px high. The rail is still not a panel and keeps the narrow and short fallback of ADR-0064 decision 4. Sizes are `size.transition.*` tokens; `rail_size` is user data, tokens give default and limits. View > Reset panel sizes and a double-click on the rail's edge reset it. Dragging the edge is a pointer resize, so a locked workspace refuses it from the pointer; the command applies.
6. **File format 3.** Workspace format becomes 3. The leaf is `{ pictures = true, rail = "between"|"below", rail_size = 88, canvas = "..." }` (`rail` required, the rest optional); the `studio` key on splits is gone. Validation: at most one leaf, only in the main window's centre tree, none in a floating window, `rail_size` clamped. Format 2 is migrated in memory on load (and in the layout history), as 1 to 2 was in ADR-0049 decision 6: a studio-shaped split becomes the leaf in the same place, keeping `rail`, the canvas of `rbs.preview?canvas=...`, and dropping the ratio between the pictures (the leaf's pictures are always equal halves, the `below` divider no longer moves; the one-time loss is stated in the release notes). A split with a broken `studio` shape loses the key. Loose Preview and Program tabs stay ordinary panels, and the file shows no rail. The first save after migration copies the old file to `<file>.format2.bak`; older builds refuse format 3 with the usual "made by a newer RBS" error (ADR-0017), a one-way upgrade. Stack indices (`ui.layout.*`, history) are computed on the migrated model: the two stacks of the old split become none, later stacks shift down by two. The Reset workspace command restores the built-in layout.
7. **Built-in workspaces.** Edit and Live place the leaf where the studio split was. Minimal and Audio keep a single Program stack and no leaf; the studio switch shows its "no Pictures area" hint there.
8. **Live controls leaves the layouts; Go live and Record become frame.** The toolbar's Go live and Record buttons (with the live indicator and Settings) move out of the customisable toolbar into the main window frame's fixed right group, which cannot be removed, hidden with the toolbar, or reordered; this group is the "non-removable frame element" of U1 and ADR-0049 review 1 (the spec's U1 test runs with the toolbar hidden and checks the group). Hence `rbs.live-controls` leaves every built-in layout, including Minimal and Audio (the spec table is amended), and the Panels menu; a saved file that holds it still loads and shows it. Its status text moves to the status bar, owned by the client: after an output ends it shows the last outcome ("Saved <path>", "The stream ended after <duration>", dropped frames, or why it could not start) with a "Show in folder" action for a recording (registry command `output.show_recording`, local clients only), until the next output starts or the user dismisses it; "Virtual camera on: ..." while sending. Texts come from the engine events the panel already used; long paths are elided in the middle. ADR-0049's guarded-panel list drops Live controls.
9. **Commands and the control API.** `ui.layout.studio_rail {at}` stays (refused with `conflict` without a leaf). New `ui.layout.rail_size {px}`: one layout history step, `conflict` without a leaf or in `below`. `ui.layout.studio_split` is replaced by opening `rbs.pictures`. `ui.layout.get` returns the leaf node and no `studio` key; the control API spec records the new node and a minor protocol version, as do the command table and error list.
10. **Zero cost.** The leaf is one rectangle; the rail is laid out only in studio mode and draws no picture; the status bar message has no timer.
11. **Tests.** For a workspace with no loose `rbs.preview` or `rbs.program`, no sequence of open, close, move, drop, collapse, auto-hide and float commands (including open of those ids and of `rbs.pictures`) leaves them in a stack, and the leaf is removed only by closing it. Layout tests: both rail positions, `rail_size` limits, locked pointer refusal, narrow fallback, leaf in a floating window refused. Migration tests: ADR-0064 files, a saved Live with loose Preview and Program, a canvas parameter, index shifts. `ui.layout.get` shape; a view test that Properties opened from the menu lands in the right area in Edit and Live; the U1 flows test with the toolbar hidden; status bar states.
12. **UI rules.** The header strip, the rail and the frame group are visible changes: rules 15 and 16 apply (tokens only; proposal, screenshots in dark, light and high contrast, owner approval before CI and merge).

## Consequences

- Preview and Program can no longer be turned into tabs of other panels by any command.
- Edit, Live and any custom layout all get studio mode with no setup; workspaces differ only in their arrangement.
- A saved Edit or Live that is already broken (loose Preview or Program) stays so until reset, as in ADR-0064; Reset workspace repairs it.
- Programmatic clients that read `ui.layout.get` see a `pictures` node where they saw a split with `studio`; the workspace format is 3 and one-way.
- The Pictures leaf has no ratio drag between the two pictures.
- The Live controls panel's text moves to the status bar, which gets one more state to lay out and test (long paths are elided in the middle).

## Alternatives considered

- **Keep tabs, forbid drops and opens into the studio stacks.** Smaller, but every new route into a stack (a plugin, a restore, a new command) must remember the exception; this bug appeared because one route forgot it.
- **A separate Studio workspace** that turns studio mode on. Simple to explain, but keeps the two concepts tied and leaves Edit unable to use studio mode.
- **Studio mode as a Live-only setting.** Same coupling, and Edit is where scenes are prepared.
- **Repurpose Live controls as an output status panel.** Overlaps Stats and Outputs.
- **A fixed rail width.** The owner asked to widen and narrow it.

Round 2, 2026-11-08, second fresh AI session: approve with changes, 8 findings, resolved here (they refine decisions 2, 6 and 8 and are binding):

1. Frame group. ADR-0050 decisions 3, 5 and 6 and the Live, Minimal and Audio toolbar rows of the spec are amended: `stream.toggle` and `record.toggle` leave the default toolbars; Customize toolbar no longer offers them (they are in the frame group; the commands stay in menus and shortcuts). The group sits at the right end of the toolbar row, never goes into the » overflow (U11) and has a minimum width the window minimum respects; End stream keeps its in-place confirmation (U4).
2. The virtual camera button lived in Live controls: it becomes registry and Output menu only (it was already not in the default toolbar), and its state text goes to the status bar as in decision 8.
3. If a workspace has both the leaf and a loose `rbs.program` for the same canvas, the leaf wins as the alias target and the loose panel stays an ordinary panel by its own tab. `collapse`, `auto_hide` and `float` of `id=rbs.pictures` (or an alias that resolves to it) return `conflict`. Maximize shows both pictures. The guarded-close rule and its undo toast use `rbs.pictures`.
4. The format 2 reader loses its tolerance for `studio` as a known key only through migration; format 1 files migrate 1 to 2 to 3 in memory. An existing `.format1.bak` is never overwritten; `.format2.bak` is written once. A stack index that pointed into the old studio stacks fails with `NoTarget`.
5. `ui.layout.rail_size` counts as a resize for the spec's lock list (pointer refused when locked, command applies); `studio_rail` stays allowed when locked; "building the studio split" leaves the list.
6. Reopening the leaf is refused with `conflict` when the tree depth limit would be exceeded.
7. Spec edits in the implementing change: the picture-goes-to-Preview text, the U21 "studio mode opens Preview" line, the studio split paragraphs, the format 3 section, the built-in table, the guarded-panel list, the lock list, Core flows.
8. Minimal and Audio do not serve the "Choose a transition" flow (they declare it so in the spec).
