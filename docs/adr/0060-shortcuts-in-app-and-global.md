# ADR-0060: Shortcuts bind registry commands to key chords, in the app or globally; Settings › Shortcuts edits them

- Status: Proposed
- Date: 2026-11-07
- Deciders: Salih (owner)
- Builds on: ADR-0050 (command registry), ADR-0051 (user data documents), ADR-0013 (zero cost when unused), ADR-0056 (keep running after the main window closes), ADR-0057 (Settings › Appearance), ADR-0059 (scenes in the studio)
- Spec: [shortcuts](../specs/shortcuts.md)

## Context

The owner wants shortcuts that work both inside RBS and while it is in the background (for example switching scenes while recording a game that has the focus), an engine that runs them, and a Settings page to edit them.

What exists:

- The command registry (ADR-0050) lists every UI command once, with ids that may carry parameters (`ui.area.toggle?area=left`, picker choices such as `ui.workspace.select?name=Live`). Each entry has an optional default shortcut text (`Ctrl+Z` for Undo, `Ctrl+Shift+Z` for Redo), which nothing reads yet. `App::run_command(id)` runs any registry id from the menu bar, with the menu's enabled check and confirmations.
- The main and floating windows hard-code Cmd/Ctrl+Z, Shift+Z and Y (scene undo and redo) and Cmd+W (close on macOS) as Slint `KeyBinding`s in a root `FocusScope`. In Slint 1.18.1 a `KeyBinding` accepts its keys even when its handler does nothing, so Ctrl+W is swallowed on Windows too. Text fields take their keys first, so their own undo keeps working.
- U7 asks for "a complete, rebindable shortcut map"; the design system spec says "All shortcuts are rebindable; global hotkeys are opt-in" and that Ctrl+Alt combinations must not be bound by default (AltGr). The glossary names the term: "Shortcut", and "global shortcut" when it works outside RBS.
- Slint 1.18.1 gives key events as text plus modifiers (Command reported as `control` and Control as `meta` on macOS) with a `repeat` flag. The text is the key's character on the active layout: AZERTY's top row reports `&é"'…` without Shift; on macOS Option changes the character (Option+A is `å`, some are dead keys that never arrive) unless Command or Control is held. Its `MenuItem.shortcut` installs a real menu accelerator on macOS and Windows, which would take Cmd+Z from a focused text field.
- The multi-scene work (ADR-0059) adds scenes to the studio: `SwitchScene(SceneId)`, `scene.switch` in the control API, scene ids stable and never reused *within a scene collection* (the counter is stored in the collection document). It does not add registry entries: scene commands are added here.
- No Linux work for now (owner, 2026-11-04).

## Decision

1. **A shortcut binds a registry command id to a key chord, in one of two scopes.** A binding is `(command id with parameters, chord, scope)`. *App* scope works while an RBS window that runs commands has the focus (main and floating windows; not the Settings window, dialogs or projectors). *Global* scope works whatever app has the focus, also while RBS has no window shown (ADR-0056), on macOS and Windows. Any registry id can be bound, so every picker choice is a command of its own (`scene.select?collection=…&id=7`, `ui.workspace.select?name=Live`). A command may have several bindings (at most 4); a chord has at most one binding in force across both scopes.

2. **Chords are text with a fixed grammar.** Modifiers in the order `Ctrl`, `Alt`, `Shift`, `Meta`, then one key, joined by `+` (`Ctrl+Shift+F5`). `Ctrl` is Command on macOS and Control elsewhere (the primary modifier, as Slint and the registry already use it); `Meta` is Control on macOS and the Windows key on Windows; `Alt` is Option. Keys are `A`–`Z`, `0`–`9`, `F1`–`F24`, `Space`, `Enter`, `Escape`, `Tab`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, `Up`, `Down`, `Left`, `Right` and the punctuation keys `Minus`, `Equal`, `BracketLeft`, `BracketRight`, `Backslash`, `Semicolon`, `Quote`, `Comma`, `Period`, `Slash`, `Backquote`. A chord is stored canonically, so one chord has one text. Refused, each with the reason shown: modifiers alone; letters outside ASCII A–Z (they exist on some layouts only, and ASCII-only mapping keeps `ı` and `i` from both becoming I); `Shift` with a digit or a punctuation key (what Shift does with them depends on the layout); numpad keys as separate keys (the toolkit does not tell them apart).
   **Reading a key press.** A digit or known punctuation character makes the chord with Shift dropped, so on AZERTY Ctrl+Shift+`&` (which types `1`) is Ctrl+1, as Slint's own `@keys` treats these keys. Any other character (a shifted symbol such as `!`, a letter outside A–Z) is not a chord and reads as "This key cannot be used". On macOS, Alt (Option) without Ctrl or Meta is refused in app scope ("Option with this key types a character"); such chords may be bound globally, where Carbon sees key codes, not characters.
   **Layouts in global scope.** Windows registers letters by the active layout's virtual keys, digits and punctuation by their US virtual keys (on AZERTY, global Ctrl+1 is the `&` key without Shift, the same key app scope reads as Ctrl+1). macOS registers every key by its position on a US keyboard (Carbon key codes). So letters match app scope on QWERTY-like layouts, with one known exception: on Turkish Q the global I is the `ı` key on both platforms, while app scope reads I from the `i` key. Mapping through the active layout is a follow-up; the Settings page states the rule.

3. **Defaults come from the registry and are opt-out.** An entry's `shortcut` is its default app binding; other defaults come from a `DEFAULT_SHORTCUTS` table in `rbs_ui::shortcut`: `edit.redo` Ctrl+Y, and Ctrl+1…9 select the scene at position 1…9 (`scene.position?n=1`…`9`). No default is global, and no default uses Ctrl+Alt (AltGr). Defaults are part of each release, not of the user's file, so later defaults reach users who did not change them.

4. **The user's changes are a document.** `shortcuts.toml` (`kind = "shortcuts"`, format 1) in the config directory, read and written through `rbs-user-data` like `appearance.toml` (ADR-0051 writer and lock), holds only differences from the defaults: `[[binding]]` entries the user added (`command`, `keys`, `scope = "app" | "global"`) and `[[removed]]` default bindings (`command`, `keys`). The *keymap* in force is: defaults, minus removed ones, minus defaults whose chord a user binding takes, plus user bindings. Limits: at most 512 entries (`binding` plus `removed`) and 64 KiB; a file over a limit, with an unknown key or with a chord that does not parse fails as a whole. A file that cannot be read means the defaults, with a note in the error bar; the file is kept and never overwritten until the user changes a shortcut. Unknown commands (a missing plugin) are kept and listed as unavailable, as the toolbar does (ADR-0050 decision 5).

5. **Conflicts and unsafe chords are found before they take effect.** The model checks all of these for any platform (the platform is a parameter, not a `cfg`), so every platform's rules are tested everywhere.
   - *Same chord twice:* the editor never saves two bindings with one chord; recording a chord in use shows "Ctrl+2 is used by Scene: Game" with Replace (moves it) and Cancel. A hand-edited file with a repeated chord keeps the first in file order; the others are listed as conflicts and do nothing. A fifth binding of one command is listed as "at most 4".
   - *Reserved chords* are refused in every scope, per platform (the spec has the list): on macOS Cmd+Q, W, H, M, Comma, Tab, Space, Backquote, Cmd+Alt+Escape, Cmd+Control+Q, Control+Space and Control+arrows; on Windows every chord with the Windows key, Alt+F4, Alt+Tab, Alt+Space, Ctrl+Escape, Ctrl+Shift+Escape, F10 and Shift+F10 (menu focus). Text editing keys (Ctrl+C, V, X, A, Z) are not reserved in app scope: a focused text field takes them first (decision 6).
   - *Global chords must not swallow typing, per platform:* macOS needs Cmd or Control (Option-only chords type characters, `@` is Option+Q on a Turkish Q Mac); Windows needs Ctrl without Alt, or Alt with Shift and without Ctrl (Ctrl+Alt is AltGr: global Ctrl+Alt+7 would take `{` from every app on Turkish Q and German layouts); F13–F20 alone are allowed on both (F21–F24 exist on Windows only). A global chord that other apps commonly use (Ctrl or Cmd with C, V, X, Z, A, S, F, N, O, P, T, W) is allowed with a warning: "Other apps use this shortcut; while it is global they will not get it."
   - *Another app owns it:* when the OS refuses to register a global chord (Windows `RegisterHotKey` fails with "already registered"), the binding is listed as "Another app uses this shortcut" and is inactive; other refusals are listed with their own reason. Nothing else is affected. macOS does not report chords that system shortcuts or apps using an event tap take, and Secure Input (a password field in any app) blocks global shortcuts while it is on; the page says both.

6. **App scope runs through the window's key handling.** Each main and floating window has one root `FocusScope` with the focus whenever no control has it (the window forwards focus to it when it opens and after popups close); keys that a focused control does not take (text fields keep their own editing keys, U7) reach it, and the shell looks the chord up in a table built when the keymap changes. A match runs `run_command` exactly as the menu item does: the same enabled check, and the same confirmations (End stream asks while live). Repeated key events (a key held down) do not run commands again. A chord bound globally is not looked up in app scope: the OS delivers it once. The root scope has no `KeyBinding`s any more: undo and redo become the defaults `edit.undo` Ctrl+Z, `edit.redo` Ctrl+Shift+Z and Ctrl+Y, and the dispatcher handles Cmd+W (close the main window) on macOS only, where it is reserved; on Windows Ctrl+W is free.

7. **Global scope uses the OS hotkey APIs through `global-hotkey`, only while used.** macOS: Carbon `RegisterEventHotKey` on the application event target (the main run loop; no Accessibility or Input Monitoring permission; no media keys, which would need an event tap). Windows: `RegisterHotKey` with `MOD_NOREPEAT` on a hidden window of the thread that creates the manager, which RBS does on the UI thread, whose event loop Slint already runs. The modifier mapping is explicit: RBS `Ctrl` is the crate's `SUPER` (Command) on macOS and `CONTROL` on Windows; `Meta` is the reverse; chords are registered one at a time so one refusal does not stop the others.
   The `global-hotkey` crate (tauri-apps, MIT or Apache-2.0, from the same project as `muda` and `tray-icon`, which RBS already builds) is a dependency of `rbs-app` only, for macOS and Windows targets only, behind a small `GlobalKeys` trait so tests use a fake. Its event handler is process-global and set once: RBS sets it before the first manager exists, and it only hands each event to the UI thread (`slint::invoke_from_event_loop`). Pressed runs the command; a second Pressed of the same chord before its Released is ignored (so a held key runs once on both platforms).
   **Cost (P13).** With no global bindings there is no manager, no hidden window and no registered key; the handler that is set does nothing. With global bindings, nothing runs until a bound chord is pressed. On Windows the crate then starts a short-lived thread for that press that checks the key every 50 ms until it is released, to report Released; that is the cost of a press of a key the user bound, not a standing cost. The manager is dropped (after unregistering every chord) when the last global binding goes. While Settings › Shortcuts records a chord, global chords are unregistered and registered again afterwards, so a chord bound globally can be recorded again.
   **A global shortcut acts like a control surface**: it runs the command through the same path as `ui.command.run` (ADR-0050 decision 2), as a local caller named "global shortcut" with the user's full rights, with the same enabled check but without the local confirmation, because the user pressed a key they bound for exactly that and the window may be hidden. A toggle bound globally runs whichever half applies: Go live while off, End stream while live. The editor says so beside every global binding of `stream.toggle` and `record.toggle` ("Starts or ends the stream without asking." / "Starts or stops the recording without asking."), and no default is global.

8. **Settings › Shortcuts.** A Settings section after Appearance, in the same visual language (the Appearance page, and key chips drawn with the library's KeyboardShortcutHint component, as in the mockup):
   - A hint about scopes, the layout rule of decision 2, and on macOS that system shortcuts and Secure Input win.
   - A search field that matches command titles and chord text, and Reset all (asks first: "Reset every shortcut to its default?").
   - Commands grouped by menu (File, Edit, View, Scene, Output, Window), one row per command and per picker choice ("Scene: Game"), each with its chords as key chips; a global binding's chip carries a "Global" tag. Per row: Add, a remove button per chip, and Reset when the row differs from its defaults.
   - Add opens an inline recorder (accessible role group, name "New shortcut for <command>"; focus moves into it and back to Add when it closes): pressing keys fills a key picker and four modifier checkboxes, which can also be set by hand (so chords the toolkit cannot read, such as Option chords on macOS, can still be bound globally); a "Works when RBS is in the background" checkbox for global scope; the chord is checked at once (decision 5) and the reason or warning is shown beside it; Add, or Replace and Cancel for a chord in use.
   - Rows show problems in the error style: conflicts, unavailable commands, chords another app uses, reserved chords from a hand-edited file.
   - Every change is saved at once (one write) and applied at once; there is no Save button, as in General.

9. **Layers.** The chord, the keymap, defaults, conflicts, reserved lists and the document body are toolkit-free in `rbs_ui::shortcut` (`rbs-ui` keeps depending only on `serde` and `toml`). `rbs-user-data` implements `Document` for the shortcuts document and `UserData::shortcuts()` / `set_shortcuts()`. `rbs-app` maps Slint key events to chords, runs commands, owns the global hotkey adapter and the page. No core or port crate changes. Public contract added: the chord grammar, the shortcuts document and the scene commands below (command ids are already public, ADR-0050 decision 2).

10. **Scene commands join the registry** (Scene menu). They act on the canvas the main window shows (one canvas today; a `canvas` parameter, defaulting to that one, comes with several canvases) and switch the program scene, as a click in the Scenes panel does; with studio mode they will set the preview, as the panel will.
    - `scene.select` (picker over the canvas's scenes in panel order) with parameters `collection` (the scene collection's id) and `id` (the scene id). Scene ids are only unique within a collection, so a choice names both; while another collection is in use the binding stays and is listed "In another scene collection", and runs nothing.
    - `scene.position` with `n` from 1: the scene at that position in the current collection (for the position defaults).
    - `scene.next` and `scene.previous`: around the program scene, wrapping.
    A scene that is deleted leaves its binding listed as "Scene not found" until the user removes it.

## Consequences

- Every command, including each scene, workspace, profile and panel choice, can get a key in the app or globally; Stream Deck-like setups work without extra software.
- A global shortcut on a toggle can start or end a stream without asking. That is the explicit, documented price of hotkeys that work while a game has the focus; the editor shows it on each such binding, and no default is global.
- `rbs-app` gains `global-hotkey` 0.9 and, through it, `keyboard-types` 0.8 (a second copy next to 0.7, which winit and muda use), `crossbeam-channel`, `once_cell` and `thiserror` 2 on macOS and Windows. Its `unsafe` code is the crate's own; RBS adds none.
- Menus do not show shortcuts yet: Slint's `MenuItem.shortcut` is a real accelerator that would take Cmd+Z from a focused text field. Showing them needs a display-only menu text or a toolkit change; that is a follow-up.
- New work: `rbs_ui::shortcut` with unit and property-style tests (canonical text round trip; keymap resolution; conflicts; reserved lists and global rules for every platform), the document with conformance tests, the shell's key mapping and dispatch tests (including a fresh main and floating window), the global adapter with a fake in tests (debounce, one refusal not stopping the others, error kinds), the page with light, dark and high-contrast screenshots and the `ui-review` skill. Hardware checks on macOS and Windows: a global chord while another app has the focus and while the main window is hidden.
- Follow-ups: shortcuts through the control API and MCP (`ui.shortcut.list/set`); a command palette showing chords; global layout mapping on macOS and Turkish I; Linux global shortcuts (portal `GlobalShortcuts`) when a Linux machine is available; hold-to-act bindings (push-to-talk) that need key release; a `canvas` parameter on scene commands.

## Alternatives considered

- **Own FFI for `RegisterHotKey` and Carbon**: about 200 lines of `unsafe` in RBS for what a maintained crate from a project RBS already depends on does, and it would avoid the per-press thread on Windows only.
- **A CGEventTap on macOS** (sees every key, push-to-talk possible): needs the Input Monitoring permission and runs on every key press system-wide; against P13 for a feature most users never turn on.
- **Store the full keymap in the file**: simple, but new defaults would never reach existing users and every release would need a migration.
- **Physical key codes instead of characters**: would make chords layout-independent on every platform, but Slint 1.18 reports text, not key codes, so app scope cannot see them.
- **Scene bindings in the scene collection document**: they would follow the collection, but a shortcut is a per-user setting (a shared collection should not bring keys), and two places to edit shortcuts confuse; a `collection` parameter on the choice keeps one place.
- **Bind only the explicit halves (`stream.start`, `stream.stop`) globally**: safer, but needs registry entries that are not menu items, against ADR-0050 decision 1; a visible note on each global toggle is the chosen trade.
- **Confirm global End stream by bringing the window to the front**: would pull a hidden RBS over a game at the worst moment; a clear note on the binding is the lesser cost.
- **Slint `MenuItem.shortcut` as the app scope engine**: native accelerators fire before text fields and exist only for menu items, so per-choice bindings (scenes) and text field undo would break.

## Review

- 2026-11-07, independent AI session (given only the proposal, specs, principles, the code and the `global-hotkey` and Slint sources). Verdict: changes requested, 14 concerns (6 blocking); all addressed in this revision:
  1. Blocking: scene ids are per collection; canvas and studio mode were undefined. `scene.select` takes `collection` and `id`; canvas and studio mode stated (decision 10).
  2. Blocking: the global modifier rule let Option-only (macOS) and Ctrl+Alt (Windows, AltGr) chords swallow typing. Per-platform rules and a warning for chords other apps use (decision 5).
  3. Blocking: a global toggle also starts a stream; repeats on macOS. Notes cover both halves; a second Pressed before Released is ignored (decision 7).
  4. Blocking: `global-hotkey` on Windows sends Released from a per-press thread that polls while the key is held, and its handler is process-global. Threading and cost text corrected; handler set once and only forwards to the UI thread (decision 7).
  5. Blocking: the root `KeyBinding` for Cmd+W swallowed Ctrl+W on Windows. Root `KeyBinding`s removed; Cmd+W handled by the dispatcher on macOS only (decision 6).
  6. Blocking: AZERTY digits, Turkish `ı`, macOS Option characters. Shift dropped for digit and punctuation characters, ASCII-only letters, Option-only app chords refused on macOS, the Turkish I exception stated (decision 2).
  7. OS errors mapped to their kind, one registration at a time, explicit unregistering, the modifier mapping stated, F21–F24 not global on macOS (decisions 5 and 7).
  8. Reserved list extended (decision 5, spec).
  9. Limits made consistent: 512 entries, over the limit fails the file (decision 4).
  10. Focus: the root scope gets the focus when the window opens; a dispatch test on fresh windows (decision 6).
  11. KeyboardShortcutHint named; recorder role, name and focus order; Settings › Shortcuts added to the design system spec (decision 8).
  12. The caller context is named "global shortcut", local, full rights, enabled check kept (decision 7).
  13. The second `keyboard-types` copy is stated (Consequences).
  14. Secure Input stated (decision 5).
