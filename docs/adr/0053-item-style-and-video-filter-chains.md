# ADR-0053: Item shape, border and shadow drawn by the compositor; video filters as a per-source chain of GPU nodes

- Status: Accepted
- Date: 2026-11-06
- Deciders: Salih (owner)
- Builds on: ADR-0005 (GPU compositing with wgpu), ADR-0013 (zero cost when unused), ADR-0020 (node contract and schedule swap), ADR-0021 (scene collection model), ADR-0023 (parameter channels), ADR-0044 (control API), ADR-0051 (user data documents)

## Context

The owner asked that common looks need no plugin, no downloaded file and no workaround: a camera as a circle, a screen capture with rounded corners and a frame around it, colour correction, chroma key, blur, a LUT, later background removal. In OBS these take third-party plugins, image masks or nested scenes.

What exists today (checked in the code, not assumed):

- `rbs_gpu::compositor::Compositor::render` draws every layer of a canvas in one render pass, one draw call (six vertices, one instance) per layer, from a per-layer storage buffer record (`LayerGpu`: affine, canvas size, crop, opacity and flags, 64 bytes). The fragment shader samples the source, decodes sRGB if needed and multiplies by opacity. It is on the render hot path (`docs/architecture/hot-paths.md`).
- A layer's placement comes from the scene item's `Layout` (position, size, rotation, crop, opacity; per-canvas overrides, U15), through `SceneCollection::flatten` (`FlatLayer`), the binder (`BoundLayer`), `rbs_sources::layers::node_layers` (`NodeLayer`) and the compositor node, which turns it into `Layer` each tick without allocating.
- The scene model already has per-source, ordered `filters` (`Filter`: node type id, `enabled`, `Settings`), saved in the scene collection document. The binder already chains a source's enabled filter nodes (kind `VideoFilter`) between the source node and the compositor, and keeps disabled filters Standby and out of the schedule. No filter node type exists yet, and there is no edit to change a filter's settings.
- Layout edits are undoable (one step per user action, a drag is one step), saved in the scene collection, and the desktop app edits position and size in the Properties panel. The control API has no method to place or style a source yet.

Forces: P4 (no CPU readback), P6 (no allocation on the render path), P13 (an unused feature costs nothing; no per-iteration "is it enabled" checks in hot loops), P15 (hot path changes need numbers and the owner's sign-off), U4 (undo), the API parity rule of ADR-0052 (pending), and ADR-0051 decision 6 (a document change that older builds cannot read needs a new format).

Two different kinds of effect are asked for:

1. **Shape of the placed picture** (rounded corners, circle, ellipse, a border, a drop shadow). These depend on the item's box on the canvas, not on the source's pixels, and differ per placement: the same camera can be a circle in one scene and a rectangle in another.
2. **Changes to the pixels** (colour, keying, blur, LUT, masks from images, background removal). These belong to the source and are the same wherever it is placed; OBS calls them filters, and our model and glossary already do.

## Decision

1. **Item style is part of the layout.** `Layout` gains `style: ItemStyle` with `shape: Shape` (`Rectangle { radius }`, `Circle`, `Ellipse`), `border: Option<Border { width, color }>` and `shadow: Option<Shadow { offset, blur, color }>`. Lengths are in the item's own box units, the units of `Layout::size` (canvas pixels for an item placed directly on the canvas); colours are sRGB with straight alpha, `[u8; 4]`. Because it is part of `Layout`, per-canvas overrides (U15), undo and saving work as for position and size. The shape follows the cropped box: changing the crop changes what is inside the shape, not where the shape is. `Circle` is the largest circle centred in the box, so a 16:9 camera becomes a centred circle without changing its box or crop; `Ellipse` fills the box; a `Rectangle` radius larger than half the shorter side is drawn as half the shorter side. The border lies inside the shape's edge, so the box, hit testing and selection handles do not change. A style is valid when every length is finite and not negative and a border's width is above 0 (`ItemStyle::is_valid`, checked with the layout); only source items may have a style other than the default (`SceneError::StyleOnScene`, like crop), because a nested scene is not drawn as one picture. The default style (rectangle, radius 0, no border, no shadow) draws exactly as today.
2. **Shape is evaluated in the item's local frame, so it transforms with the pixels.** The compositor gets the item's local box size (`|Layout::size|`, before nesting) per styled layer and evaluates an analytic signed distance on `unit × size`, where `unit` is the position in the cropped box (0..1). Any affine the scene produces (rotation, flips, the non-uniform scale and shear of nested scenes) then moves the shape exactly as it moves the picture: inside a squashed nested scene a circle is squashed like the camera around it, as in the nested scene's own preview. Antialiasing converts the distance to canvas pixels along the edge's normal: with `J` the screen-space derivatives of the local position (taken before any branch, WGSL uniformity) and `n` the unit gradient of the distance (by central differences of the same function), one pixel spans `w = length(Jᵀ n)` box units, and coverage is `clamp(0.5 - d / w, 0, 1)`; the border's inner edge uses the same rule. This stays one pixel wide on every edge under non-uniform scale and shear. To keep the outer half of that ramp, the quad of a styled layer is grown by one canvas pixel on every side in the vertex shader and the texture coordinate is clamped to the crop. A layer whose box has no area (`Layout::size` 0 on an axis), or whose whole transform is singular (a nested scene of zero size), is drawn by the plain pipeline, which draws nothing for it, so no division by a zero size happens.
3. **Styled layers use their own pipeline; unstyled layers do not change.** There is already one draw call per layer. Styled layers are drawn with a second pipeline (same pipeline layout and blend state; group 0 gains a second read-only storage binding for the style array, which both pipelines share and the plain shader never reads, entry points `vs_styled` and `fs_styled`) bound only for them, and read their style from a second storage array (`StyleGpu`: kind, radius, border width, local size, border colour, 48 bytes) indexed by the layer record's `params.w`, unused today. Both arrays are filled in one loop over the drawn layers, after skipped layers are left out, so the instance index and the style index stay in step. Unstyled layers keep today's shader and the 64-byte record byte for byte, so a scene without styles does no extra work per fragment or per layer (rule 10, P13). `render` switches pipelines only where consecutive layers differ. Both arrays are sized by `reserve_layers`; `render` allocates nothing. The styled pipeline and the style array are created with the compositor (in `prepare`, not per frame) also when no layer is styled; that is accepted: they hold no device handle beyond memory and do no work until used. `rbs-gpu` keeps its own style type (`LayerStyle`, border colour linear and premultiplied), converted from the scene's `ItemStyle` in `rbs-sources` as the transform is, so `rbs-gpu` does not depend on `rbs-scene`.
4. **Composition.** For a styled layer the source is sampled and decoded as for any layer (XRGB alpha forced to 1, sRGB decoded to linear, premultiplied). With `outer` the shape's coverage, `inner` the coverage of the border's inner edge (`inner = outer` without a border) and `t = (outer - inner) / outer` (0 where `outer` is 0), the colour is `(border * t + content * (1 - border.a * t)) * outer * opacity`, with `border` linear and premultiplied: the border is drawn over the picture inside the shape, so a half-transparent border shows the picture beneath it, and nothing is drawn outside the shape.
5. **Shadows (later step) in the same draw call.** The vertex shader grows the quad of a layer with a shadow by its blur and offset; the fragment shader adds an analytic Gaussian falloff of the shape's distance under the content. No extra pass. Until that step, `shadow` is part of the model, validated and saved, and not drawn. Shapes that are not analytic (an image mask, a star, text) are filters (decision 6), not layer properties.
6. **Video filters are a per-source chain of GPU nodes.** The existing model and binder rules stay: a source's enabled filters run in order between the source and every compositor that draws it; disabled ones are Standby and out of the schedule (P13). Built-in filters must be `Node<GpuRuntime>` of kind `VideoFilter` in a new engine crate `rbs-filters` (depends on `rbs-gpu`, `rbs-graph`, `rbs-core`; never on adapters), type ids `org.rbs.filter.<name>`, specified in `docs/specs/video-filters.md` before any code. Each filter renders into a pooled texture of its input's size in the render partition: pipelines in `prepare`, textures warmed in `warm`, nothing allocated in `process` (P6), no readback (P4). When the input's size changes (a camera switching format), `process` must not allocate and must never output the unfiltered input (a chroma key or blur would reveal what it hides): it keeps publishing its last filtered frame, or nothing (the compositor then skips the layer, P7), and flags the node; the control thread re-warms it for the new size. The filter spec defines the mechanism and tests it. First catalogue: colour correction (brightness, contrast, saturation, gamma, hue), chroma key and colour key, blur (separable Gaussian over a downsampled chain), sharpen, LUT (`.cube`), image mask. Background removal needs a segmentation model and an OS or ML runtime; it gets its own port and ADR (adapters such as Apple Vision person segmentation or ONNX Runtime with DirectML), so the filter crate stays free of vendor SDKs.
7. **Filter settings change without rebuilding the node.** The scene model gains `set_filter_settings` (undoable). The binder keeps the filter's node when only its settings change and reports it (`BindReport::changed_filters`); the application passes the new values through the node's parameter channel (ADR-0023, latest value wins), so a slider drag never swaps the schedule. Resources (a LUT's 3D texture, a mask image) are loaded and uploaded on the control thread and sent through the same channel as a shared handle; the node never reads files. Until the plugin SDK's settings schema exists, each built-in filter type validates its settings in code, and an edit with values the type cannot use is refused, never discovered in `process`.
8. **Per-pixel filters may be fused later, only with numbers.** Each filter is one full-frame pass (blur two or more). Fusing adjacent per-pixel filters into one pass is a later optimisation decided on measurements (P15).
9. **Presets ("looks") are user data.** A look is a document (ADR-0051, `kind = "look"`, library `looks/<id>.toml`) holding an optional item style and a filter list (types and settings, no ids). Applying a look copies it onto an item and its source as one undo step; it does not link them. Built-in looks ship read-only (for example "Circle camera", "Rounded with frame"). Looks are what a `.rbspack` shares once the pack format exists.
10. **Control API (API parity).** Protocol 1.3: `source.list` returns, for each video source, its program-scene `item` id and the `layout` the studio's canvas shows (`position`, `size`, `rotation`, `crop`, `opacity`, `style`). `item.set_style {item, style}` replaces the whole style of that item's layout on the studio's canvas (its override for that canvas when it has one, else the default layout), exactly as the desktop app's Properties panel does. Refusals: `not_found` for an unknown item, `invalid_params` for a style that is not valid or an item that places a scene. Each call is one undo step on the shared stack. Coalescing a client's slider drag into one step (a `gesture` number) is a later minor addition and must be scoped to the calling session and the item, ended by any other edit on the stack, so two clients can never merge their steps. `source.changed` carries the same `item` and `layout` fields as `source.list`, so a style edit is published. Adding a `canvas` parameter for several canvases is a later minor version. Filter methods (`filter.add`, `filter.remove`, `filter.move`, `filter.set_enabled`, `filter.set_settings`) and `look.*` join with those changes.
11. **Scene collection document format 2.** The `layout` table gains an optional `style` table with the whole schema, shadow included: `shape = "rectangle" | "circle" | "ellipse"`, `radius`, `border = { width, color = "#rrggbbaa" }`, `shadow = { offset = [x, y], blur, color }`. Format 1 documents upgrade to 2 unchanged. A build that knows only format 1 refuses format 2 files and never overwrites them (ADR-0051 decision 2); since the app writes the current format, a collection becomes unreadable to such builds after its first save by a newer one, also when it uses no style. Reserving the shadow now avoids a format 3 for the shadow step.
12. **Rescaling.** When the canvas size changes, the app scales an item's style lengths by the factor its box actually changed by (`rescale_layout` scales a box uniformly in both of its branches, fitted or kept in its corner; the factor is `sqrt(|new w·h| / |old w·h|)`), so a rounded camera keeps its look. Both branches are tested.
13. **Rollout.** Step 1: decisions 1 to 4, 10 (`source.list` layout, `item.set_style`), 11 and 12, the Properties panel's shape and border fields in the desktop app, and spec updates in the same change: `gpu-compositor.md` (style record, second pipeline, shader contract, golden tests), `scene-model.md` (`ItemStyle`, `StyleOnScene`, flattening), `user-data.md` (format 2) and `control-api.md` (1.3). Then shadows (5), `rbs-filters` with colour correction, chroma key and blur (6, 7), LUT and image mask, looks (9), background removal (own ADR).

## Consequences

- The most asked-for looks need one click and no plugin; they are saved with the scene, undoable and scriptable through the control API.
- Scenes without styles render exactly as before. Styled layers cost a pipeline switch and a few ALU instructions per fragment. The render hot path changes, so the step 1 PR carries before and after numbers from `benches/compositor.rs` (unstyled and styled scenes) and needs the owner's P15 sign-off.
- `Layout` grows, so every place that builds or compares layouts (document, rescaling, preview edit) carries the style. The scene collection document becomes format 2.
- Semver: `rbs_gpu::compositor::Layer`, `rbs_gpu::node::NodeLayer`, `rbs_scene::FlatLayer`, `BoundLayer` and `Layout` gain fields; `Layout`, `FlatLayer` and `BoundLayer` are `#[non_exhaustive]`, `Layer` and `NodeLayer` are not, so their struct literals in other crates must add the field. The crates are not published; the public contracts that change are the scene document (format 2) and the control API (1.3, additive).
- Golden-image tests on any adapter check a rounded rectangle, a circle and an ellipse, a border with alpha, a rotated and a flipped styled layer, a circle in a 4:1 squashed (nested) transform, a crop, and that an unstyled layer next to styled ones draws as before.
- Shapes are analytic: arbitrary masks are the image mask filter.
- Group effects (a border around a nested scene, group opacity) still need render-to-texture for nested scenes, a later decision (scene model spec).
- Follow-ups: shadow step, `docs/specs/video-filters.md` and `rbs-filters`, `set_filter_settings` and `changed_filters`, the look document kind, the segmentation port ADR, the Filters panel in the UI.

## Alternatives considered

- **A per-fragment branch in the one existing pipeline** (the first draft of this ADR). Simplest, but every unstyled layer would read a larger record and test a flag per fragment, which rule 10 rules out; one draw call per layer already exists, so a second pipeline costs only a bind where styles change.
- **A mask pass per styled layer** (render the shape into a mask texture, then composite). General, but a pass and a texture per styled layer and frame; the analytic distance costs a few instructions in the pass that already runs.
- **Shape and border as filters on the source.** Needs a render target per source, makes the shape the same in every scene, and a border drawn into the source's pixels would be cropped and scaled with the picture.
- **Shape evaluated in canvas pixels with a geometric-mean scale for nested scenes** (first draft). Breaks under the shear that rotated items in non-uniformly scaled nested scenes produce, and draws a circle where the nested scene's preview shows an ellipse.
- **Style on the scene item outside `Layout`.** A per-canvas override (a vertical canvas with a circle camera) would need a second override mechanism.
- **Image masks only, as OBS's image mask filter.** Needs a file for every shape and size, the friction the owner wants gone.

## Review

Reviewer: independent AI session (round 1)
Date: 2026-11-06
Verdict: changes requested
Concerns:
1. The antialiasing band is clipped by a quad that covers exactly the box. -> Resolved: styled quads grow by one canvas pixel, texture coordinates clamp to the crop (decision 2); golden test of a rotated styled layer.
2. Derivatives inside a branch that WGSL does not treat as uniform. -> Resolved: derivatives are taken before any branch (decision 2), and styled layers have their own pipeline (decision 3).
3. Canvas-pixel distance with a geometric-mean scale is wrong under shear and differs from the nested scene's preview. -> Resolved: the distance is evaluated in the item's local frame (decision 2); the geometric mean was dropped.
4. Crop and texture-coordinate space unspecified. -> Resolved: a unit-square varying; the shape follows the cropped box (decisions 1, 2).
5. A per-fragment style branch on every layer conflicts with rule 10. -> Resolved: a second pipeline and a separate style array; unstyled layers unchanged byte for byte (decision 3), benchmark numbers for unstyled and styled scenes in the PR.
6. Premultiplied composition order and border alpha unspecified. -> Resolved: decision 4 gives the formula.
7. A later shadow key would force format 3; older builds lose access after the first save. -> Resolved: the whole style schema, shadow included, is format 2; the consequence is stated (decision 11).
8. Control API addressing, replace or patch, refusals and undo coalescing. -> Resolved: `item.set_style` by item id, whole style, refusal kinds, `gesture` coalescing (decision 10).
9. Rescaling of style lengths. -> Resolved: decision 12, with a test.
10. Filter crate: spec first, input size changes, resource uploads, settings schema. -> Resolved: decisions 6 and 7.
11. Specs in sync and CI-checkable tests. -> Resolved: decision 13 lists the spec changes of step 1; golden tests in Consequences.

Reviewer: independent AI session (round 2)
Date: 2026-11-06
Verdict: changes requested
Concerns:
1. The antialiasing width `sqrt(|det J|)` is still a mean, wrong by about 2x under a 4:1 squash. -> Resolved: width measured along the edge normal, `length(Jᵀ n)` (decision 2); golden test of a circle under a 4:1 squash.
2. A filter passing its input through on a size change leaks what it hides. -> Resolved: it keeps its last filtered frame or publishes nothing, never the input (decision 6).
3. Boxes with no area divide by zero. -> Resolved: drawn by the plain pipeline (decision 2), tested.
4. `gesture` coalescing could merge steps of two clients. -> Resolved: not in step 1; when added, scoped to session and item and ended by any other edit (decision 10).
5. Rescaling factor misstated. -> Resolved: the factor the box changed by, both branches tested (decision 12).
Non-blocking, taken: pipeline created with the compositor stated as accepted (decision 3); semver impact stated (Consequences); `rbs-gpu` keeps its own style type (decision 3); style index in `params.w`, in step with instances (decision 3); `source.changed` carries the layout (decision 10); `StyleOnScene` checks per-canvas overrides too (decision 1, test); `inner = outer` without a border (decision 4). Not taken: writing format 1 while no style is used; one rule (always the current format) is simpler, and ADR-0051 already refuses newer formats safely.
