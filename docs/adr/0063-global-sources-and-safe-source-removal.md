# ADR-0063: Global sources as a global scene per canvas, and safe source removal

- Status: Accepted
- Date: 2026-11-07
- Deciders: Salih (owner)
- Builds on: ADR-0021 (scene collection model), ADR-0037 (audio graph: one mixer per canvas), ADR-0039 (scene source types and the binder), ADR-0044 and ADR-0052 (control API and API parity), ADR-0051 (scene collection document), ADR-0053 (item style), ADR-0059 (scenes in the studio, "Existing source"), ADR-0061 (studio mode), ADR-0013 (zero cost when unused)

## Context

The owner asked (2026-11-07) for two things known from OBS:

1. **Global sources.** A microphone added once should be heard in every scene without adding it to each one. The same for a camera or a display: "Global sources" should be a section of Settings where the user picks a kind (Microphone, Camera, Display, ...) and then a source, and adds it. A source should also be markable as global from where it is edited.
2. **Source references.** The same webcam used in several scenes without the device being closed and opened again, and, per scene, a different look (round in one scene, square in another).

An audit of the engine on 2026-11-07 found:

- **References already exist.** The scene model keeps a `Source` (type, settings, filters, sound) apart from the `SceneItem` that places it. "Existing source" in Add source (ADR-0059) and `item.add` place one source in more scenes. The binder makes **one node per source**, however many scenes place it, and keeps its node id while the source exists and its settings are unchanged (scene model spec, Binding), so a scene switch or a cut keeps the camera open.
- **Per-scene look already exists.** Position, size, rotation, crop, opacity and the item style (shape, border; ADR-0053) are part of the item's `Layout`, so a camera can be a circle in one scene and a rectangle in another today. Device settings, filters (ADR-0062), volume, mute and the sync offset belong to the source, so they are the same wherever it is placed. That split is kept: filters run once on the one picture the source makes; a per-scene filter chain would mean a second chain on the same picture and is left to a later decision (see Alternatives).
- **No global sources.** The binder mixes the audio-only sources visible in a canvas's **program** scene, and a compositor draws the shown scene only. A microphone not placed in the program scene is not heard.
- **Removal is unsafe with references.** The Sources panel's delete button and the Delete key call `delete_source`, which removes the source from **every** scene. With references in use, removing a camera from one scene silently takes it out of all of them (undo brings it back, but the user may not notice). The glossary already separates "Remove from scene" (this scene only) and "Delete source" (every scene); the app has only the second.

## Decision

1. **A canvas may have a global scene.** `Canvas` gains `globals: Option<SceneId>`: a scene whose items are drawn and heard in **every** scene the canvas shows, as program and as preview. It is an ordinary scene in the collection (name, items, layouts, styles, crops, lock, visibility, per-canvas overrides), so every item edit, its undo record, the document format of items and the app's item editing work for global sources unchanged. Invariants, checked after every edit like the others (scene model spec):
   - the global scene of canvas C is scoped `Canvas(C)` (so it is the global scene of one canvas only, and its layouts are in that canvas's pixels);
   - it is not the program or the preview scene of any canvas;
   - no item nests it, and it nests no scene (its items are sources only; nesting would make "every scene" recursive and is not needed for the request).
   - a scene the canvas may show, together with the global scene, flattens to at most `MAX_LAYERS` layers (each within the limit alone is not enough, since they are drawn together);
   - the global scene's name is not checked against the other scenes' names, since it is never listed (a user can still name a scene "Global sources").
   Breaking one is refused with a new `SceneError::GlobalScene(SceneId)` (`TooManyLayers` for the layer count).
   New edit: `set_globals(canvas, Option<SceneId>)` (a canvas replacement, so its undo is the existing `ReplaceCanvas` record). `remove_scene` of a global scene clears the canvas's `globals` and its undo puts it back (the `RemoveScene` record remembers which canvases had it, as it does for program and preview), refused with `UndoConflict` when the canvas has another global scene by then. `remove_canvas` removes the canvas's global scene with it in the same record (the user cannot see it, so it must not block the removal), and its undo restores both. New accessors: `globals_of(canvas) -> Option<SceneId>`, `is_global_scene(scene)`, and `showable_scenes(canvas)`: the scenes the canvas may show without its global scene. Every scene list, switch, program fallback and "last scene" rule uses `showable_scenes`; `scenes_for` stays for code that must reach every item of the canvas (a canvas rescale).
2. **Global items are drawn above the shown scene and heard with it.** `flatten(canvas, scene)` returns the scene's layers and then the layers of the canvas's global scene, so global sources are on top of every scene (a camera corner, a microphone's meter-only item). Their `FlatLayer::path` starts with the global item's id, so hit testing and selection tell them apart. `visible_sources(canvas, scene)` includes the visible sources of the global scene. Through those two functions everything else follows without new code paths: `wanted_sources` keeps visible global sources Active (a hidden global item is Standby, as any hidden item), the binder links them to every compositor of the canvas (Program, and Preview in studio mode), and the canvas's mixer hears the audio-only ones because they are visible in the program scene. A cut (ADR-0061) keeps them on air and unchanged, since they are in both scenes. When `scene` is the global scene itself (a caller flattening it on its own) it is drawn once. A canvas without a global scene flattens exactly as before.
3. **Document format 5.** A canvas table gains `globals?` (a scene id). Format 4 documents load unchanged (no global scene). Loading checks the new invariants like every other (`from_parts`).
4. **The app makes the global scene on demand.** The studio host creates the canvas's global scene, named "Global sources" (a unique name, as other names), with the first global source, in the same undo step, and leaves it in place when the last global source goes (an empty global scene costs nothing: it adds no layers and no sources). The Scenes panel, `scene.list`, the program choice at start-up, the scene switch shortcuts and every program fallback use `showable_scenes`, so they never see the global scene. Control API methods that take a scene id (`scene.switch`, `scene.rename`, `scene.remove`, `scene.sources`, `canvas.set_preview`, the `scene` of `source.add` and `item.add`) answer `not_found` for the global scene's id, as for any scene they do not list.
5. **Making a source global moves it.** "Global" means "in every scene", so making a source global on canvas C (from Settings, from Properties or through the API) adds one item for it to C's global scene and removes its items from the scenes C may show, in one undo step. When one of those scenes is shown by another canvas (it is, or is nested in, another canvas's program or preview scene), the change is refused (`conflict`, "<name> is on air on <canvas>"), so no other canvas loses a source silently; with one canvas, as the desktop app runs today, it is never refused. The new global item's default layout is `layout_on(C)` of the source's item in the edited scene, else of its first placement on C, else the layout a new source of its kind gets; it has no per-canvas overrides (the global scene is scoped to C). Moving it back into a scene uses the same layout as that item's default layout. Taking a source out of the global sources ("Show in every scene" off in Properties) moves its global item into the edited scene with its layout, in one undo step, so it does not vanish. "Remove" in Settings › Global sources removes the global item; the rule of decision 7 then applies. "Existing source" lists global sources disabled, with "Already in every scene", and `item.add` of a global source into a scene of its canvas is refused (`conflict`), so a source is not drawn twice on one canvas by these paths. The model does not forbid it (a document, or a nested scene that holds the source, can still do it); then the Sources panel shows both rows, each with its own item, and the "Show in every scene" Toggle reflects the selected row (on for the global row).
6. **Settings › Global sources.** A new Settings section "Global sources" (icon `globe`, new in the icon set) in the Output group after Video, with the section id `global_sources` for `ui.settings.open`. Two cards, using only the Settings window's parts (`SettingsCard`, `SettingRow`, `SettingBlock`, `Select`, Buttons):
   - **Global sources**: one row per global source of the studio's canvas, top first: its kind icon, name and kind ("Microphone", "Camera", ...), and a "Remove" button (accessible name "Remove <name> from global sources"). Empty: "No global sources yet. A global source is heard and shown in every scene."
   - **Add a global source**: "Kind" (a Select: the kinds this computer has: Microphone, Desktop audio, Application audio, Camera, Screen, Window), "Source" (a Select of that kind's devices, as Add source lists them, followed by the collection's sources of that kind that are not global, marked "(in scenes)"), and "Add" (primary). Adding a device makes a new source and makes it global; adding an existing source makes it global (decision 5), and the hint under the Source field says that it then leaves the scenes that have it. A new picture source gets the layout Add source gives its kind (a camera in a corner, a screen fitted to the canvas), so it never hides the scenes by surprise; the user moves it on the picture like any item.
   The kinds are those Add source offers today; image, text, media and browser sources join both lists when they exist. Every row is level `simple` (U2). Every change is one undo step on the main window's undo stack, as other source edits. Changes apply at once; nothing is disabled while recording or streaming (they are edits to the program, U4: the section shows the on-air mark while the studio is on air).
7. **Remove from scene and Delete source are separate (safe removal).**
   - The Sources panel's delete button and the Delete and Backspace keys **remove the item from this scene** (accessible name "Remove <name> from this scene"). When that was the source's last placement anywhere (no other item in any scene, global scenes included), the source is deleted in the same undo step, so removing items never leaves sources placed nowhere (removing a whole scene still can, as today; they stay in "Existing source"); when other placements remain, only the item goes. The undo toast says "<name> removed from this scene" with Undo.
   - Properties gets **Delete source** (a danger ghost Button under the header): it removes the source from every scene and the global sources. When the source has more than one placement it asks in place first, in a callout: "<name> is in N scenes. Delete it from all of them?" (N counts every item, the global one counted as "every scene": "<name> is in every scene and 2 more. Delete it from all of them?"; plural forms through the localisation layer, U8) with "Delete source" (danger) and "Cancel"; with one placement it deletes at once. Undo restores every placement.
   - The Sources panel's row menu (U3: the context menu repeats the commands of its item) has Remove from scene, Delete source and Show in every scene.
   - The Sources panel marks a source that is placed more than once with a link mark and the tooltip and accessible description "Also in <other scene names>", so a reference is visible before it is edited.
8. **Sources panel and Mixer.** The Sources panel shows the global sources of the canvas above the edited scene's rows (they draw above it), under a small "Global" group header, each with the `globe` mark. They select, show and hide, lock, change layer order among themselves, and open Properties exactly as scene rows do; their edits act on the global item. Properties gets a "Show in every scene" Toggle under the header for every source item (on for global ones): on makes it global (decision 5), off moves it into the edited scene. The Mixer lists the global sources' sound with the program scene's, since both are heard. Picture handles (ADR-0048) work on global items like any item. In studio mode the Sources panel edits the preview scene, but global items are on air in both: while the canvas is on air (streaming or recording) the "Global" group header carries the on-air mark and so do the handles of a selected global item (U4), and the hint of "Show in every scene" says that turning it off takes the source off air until the next transition.
9. **Control API 1.10** (additive: no existing answer, row or event changes shape or meaning, because `session.hello` cannot tell a 1.9 client from a 1.10 one). `source.list`, `source.changed` and `scene.sources` keep their rows: items of the program (or named) scene only. `scene.list`'s and `scene.changed`'s `sources` rows (every source of the collection) gain `global: true` (absent when false). New methods, the changing ones each one undo step on the shared stack, publishing `scene.changed` and, when the program scene's rows change, `source.changed`:
   - `global.list` (`read`): `{sources}`, one row per global source of the studio's canvas, top first, in the `source.list` row form (with its `item`).
   - `item.remove {item}` (`control`): Remove from scene (decision 7); answers `{source_deleted}` (true when it was the source's last placement). `source.delete` keeps its meaning: Delete source, from every scene.
   - `global.add {source}` (`control`): makes an existing source global (decision 5); answers `{item}`. `source.add` gains an optional `global: true`, which adds the new source as a global source in one undo step, as Settings does (API parity, ADR-0052).
   - `global.remove {source, keep?}` (`control`): without `keep` (or `false`) removes the global item (decision 7's last-placement rule applies) and answers `{source_deleted}`; with `keep: true` moves it into the program scene (in studio mode the preview scene) and answers `{item}`.
   Refusals: `not_found` for an unknown source or item, and for the global scene's id where a scene id is taken; `conflict` for `global.add` of a source that is already global or on air on another canvas (decision 5), and for `item.add` of a global source into a scene of its canvas; `invalid_params` for `global.remove` of a source that is not global, and unknown keys. A model refusal `GlobalScene` that reaches the API is `conflict`. The planned MCP server (ADR-0052) exposes the methods like the others, from the same method table. Effects (ADR-0052 decision 4, when effects join the schema): all three `edit` with the on-air check (global items are always on air while the canvas has a program; `item.remove` when the item is reachable from the program scene). A 1.9 server answers `method_not_found`.
10. **Zero cost when unused (P13).** A canvas without a global scene flattens, binds and mixes exactly as today; the new work is one `Option` read per `flatten` and `visible_sources` call, on the control thread when the collection changes, never per frame or per audio block. A global source runs only while it is visible (as any item in the program scene). The compositor, the mixer and every node are unchanged, and nothing on a [hot path](../architecture/hot-paths.md) changes.

## Consequences

- One source can be in every scene with one device open, its look editable on the picture, and its sound always in the mix.
- Global sources reuse the item machinery, so styles, crop, lock, visibility, undo, handles and per-canvas overrides need no new code; the cost is the global-scene invariants and keeping that scene out of every scene list.
- Global sources are drawn above every scene. A global source drawn below the scenes (a background) is not offered; it can come later as a second global scene ("globals below") without changing this model.
- Public contracts that change: `Canvas` gains a field (built by `Canvas::new` in documents), `SceneError` (non-exhaustive) gains `GlobalScene`, scene document format 5, control API 1.10 (additive), the `ui.settings.open` section list, the icon set (`globe` is new; `link` is reused as the mark of a source placed more than once). Spec updates in the same change: `scene-model.md`, `user-data.md`, `control-api.md`, `ui-design-system.md`; glossary entry "Global source".
- Tests: the new invariants and their refusals; `flatten`, `visible_sources` and `wanted_sources` with a global scene (on top, path, hidden global item Standby, scene equals globals drawn once); `remove_scene` of a global scene and its undo; the random-edit binder test gains global scenes, so mixer inputs and compositor links are checked against expectations that include them; document format 5 round trip and format 4 loading; host tests for make global and back (one undo step each), Remove from scene with and without other placements, Delete source; API tests for `item.remove`, `global.*` and the new row field.

## Alternatives considered

- **A `global` flag on the source.** Sound is easy (always mixed), but a global picture needs a place, size, crop and style per canvas, which is exactly an item; storing them on the source would duplicate the item machinery.
- **Copying the source into every scene automatically.** Every new scene, scene removal and undo would have to keep the copies in step, and the user would see N rows to keep consistent; one global item is one place to edit.
- **Global audio only, as in OBS's Settings › Audio.** Simpler, but the owner asked for cameras and displays too.
- **A shared overlay scene nested by hand in each scene.** Works with today's model, but the user must remember to add it to every new scene; it stays possible for those who want it.
- **Per-scene filters on a referenced source.** Possible (one capture, one filter chain per distinct look, each a GPU pass), but it changes the binder's one-chain-per-source rule and the Filters tab's meaning; left to its own decision if the need appears. The per-scene look the owner asked for (shape, border, crop, size) is already per item.

## Review

- 2026-11-07, independent AI session (ADR-0014; given only this proposal, the specs and the code). Verdict: changes requested, 14 findings. All resolved in this ADR, the specs and the code:
  1. (Blocker) The hidden global scene, scoped to its canvas, blocked `remove_canvas` (`CanvasHasScenes`). Resolved: `remove_canvas` removes it in the same record and undo restores it (decision 1; test).
  2. `scenes_for` still returned the global scene, so start-up and program fallbacks could pick it. Resolved: `showable_scenes(canvas)` (decision 1), used by every list, switch and fallback (decision 4).
  3. Making a source global also stripped shared scenes other canvases show. Resolved: refused with `conflict` when a scene it would leave is shown by another canvas (decision 5).
  4. Adding global rows to `source.list` / `source.changed` / `scene.sources` would mislead 1.9 clients. Resolved: those rows are unchanged; `global.list` and a `global` mark on `scene.list`'s source rows instead (decision 9).
  5. In studio mode global edits go on air at once. Resolved: on-air mark on the Global group and on global handles, and a hint on the toggle (decision 8).
  6. A copied layout with overrides for other canvases would be refused by the global scene's scope. Resolved: the default layout is `layout_on(C)`, no overrides (decision 5).
  7. A scene and the global scene could together exceed `MAX_LAYERS`. Resolved: invariant counting both (decision 1; test).
  8. The undo restoring a removed global scene could overwrite a newer one. Resolved: `UndoConflict` (decision 1).
  9. "Never drawn twice" is not a model invariant. Resolved: stated as a property of the app paths only, with the panel and toggle behaviour when it happens (decision 5).
  10. The last-placement rule's reason was overstated. Resolved: reworded (decision 7).
  11. API and UI differed for adding a device as global. Resolved: `source.add {global: true}` (decision 9).
  12. control-api.md gaps (method table, `scene.list` mark, scene-id errors, `GlobalScene` mapping, MCP). Resolved in the spec and decision 9.
  13. ui-design-system.md gaps ("Existing source", Settings icon list, row menu, U2 level, plurals, kinds). Resolved in the spec and decisions 6 to 8.
  14. The hidden scene's name could clash with a user's scene; format 5 is always written. Resolved: global scenes are left out of the scene-name check (decision 1). Writing format 4 when no canvas has a global scene was considered and not taken: `Document::FORMAT` is one constant per kind, and every earlier format bump (ADR-0053, ADR-0059, ADR-0062) had the same effect on older builds, which refuse the file without touching it.
- 2026-11-07, Salih (owner): asked for global sources with a Settings › Global sources section (pick a kind, then a source) and for the safe-removal fix, after the analysis that led to this ADR. Accepted.
