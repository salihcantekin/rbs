# ADR-0131: Import OBS scene collections, profiles and settings

- Status: Proposed
- Date: 2026-11-16
- Deciders: Salih (owner)

## Context

People who try RBS already have their show in OBS Studio: scenes, sources, filters, audio settings, an output profile (stream service and key, recording format, encoder, canvas size) and hotkeys. Rebuilding that by hand is the largest switching cost. The roadmap names an OBS scene collection importer for phase 2 ([roadmap](../roadmap.md)), the vision promises importers instead of loading libobs plugins ([vision](../vision.md)), and the first-run page offers "the OBS import ... when it exists" ([ADR-0113](0113-experience-level-and-first-run.md) decision 5). On 2026-11-16 the owner asked for scenes, profiles and settings to be imported, starting with what RBS can already map.

Forces:

- OBS keeps a scene collection as one JSON file (`basic/scenes/<file>.json`, display name in its `name` key) and a profile as a folder (`basic/profiles/<name>/` with `basic.ini`, `service.json`, `streamEncoder.json`, `recordEncoder.json`). The canvas size and frame rate are only in the profile (`[Video]`). Hotkeys live in both: scene and source hotkeys in each source's `hotkeys` object in the collection, frontend actions in `basic.ini` `[Hotkeys]`. Global audio devices (`DesktopAudioDevice1`, `AuxAudioDevice1`, ...) are top-level objects of the collection. The format has no overall version; keys change between OBS releases (OBS 31 adds canvas-relative transform keys).
- RBS covers part of OBS's source and filter types today. Text, media file, browser, transitions and more microphone filters are being built in parallel threads, so the mapping must grow one type at a time.
- OBS item transforms (position at an alignment anchor, scale, rotation about that anchor, bounds types, crop) differ from RBS's `Layout` (a box rotated about its centre, [scene model](../specs/scene-model.md)). A box size needs the source's native picture size, which OBS does not store.
- Device and window targets are machine-specific. RBS already re-finds a lost device or window by name through `Source.hints` (`target_title`, `target_app`, [ADR-0077](0077-source-health-retarget-and-settings-window.md) decision 4).
- Stream keys and other credentials are secrets; RBS never writes them to a file ([ADR-0051](0051-user-data-profiles-and-scene-collections.md)). Browser URLs in OBS often carry widget tokens.
- An import must never change OBS's files, should change as little RBS data as possible, and must say plainly what did not come across (owner request).
- Layering (P1): `rbs-app` owns the app's settings types; the source and filter registries (`rbs-sources`, `rbs-filters`) are engine crates that pull in the GPU and capture stacks.
- Zero cost when unused (P13).

## Decision

1. **A new crate `rbs-import-obs`** (new layer class `Import`, used only by composition roots) reads OBS files and returns an in-memory **import plan**; it writes nothing. Allowed dependencies: `rbs-core`, `rbs-graph`, `rbs-scene`, `rbs-params`, `rbs-ui` (`shortcut::Chord`), `serde`, `serde_json`. It must not depend on an engine crate, `rbs-app`, `rbs-user-data`, an adapter or a toolkit. RBS type ids are written in each mapper as strings; a test in `rbs-app` (which links everything) checks that every mapper's target type and field keys exist in `rbs-sources` and the filter catalogues, so a renamed type fails the build's tests. `basic.ini` is read by a small INI reader inside the crate (UTF-8, optional BOM; no new dependency). `cargo xtask check-layers` learns the class.

2. **Inputs.** (a) The collection JSON; (b) optionally the profile files; (c) a `Catalogue` the caller implements: `has(type_id)` and `fields(type_id) -> Option<&[rbs_params::Field]>` for sources, video filters, audio filters and (later) transitions; (d) a `Lookup` the caller implements: `picture_size(path)` (PNG header), `file_exists(path)`, `targets(type_id)` returning target, name, application and size (asked at most once per type per import, on the control thread). OBS files are opened read-only; a file over 32 MiB is refused.

3. **Discovery.** `default_config_dirs()` returns the OBS folders that exist: macOS `~/Library/Application Support/obs-studio`, Windows `%APPDATA%\obs-studio`, Linux `~/.config/obs-studio` and `~/.var/app/com.obsproject.Studio/config/obs-studio`. OBS portable mode is not detected; the user picks the file. `scan(dir)` lists collections by the JSON's `name` key (file name when absent), skipping `*.bak` and `*.json.bak`, and profiles by `[General] Name` in `basic.ini` (folder name when absent).

4. **Output.** `ImportPlan { name, collection: SceneCollection, profile: Option<ObsProfileFacts>, secrets: ImportedSecrets, shortcuts: Vec<ImportedShortcut>, report: ImportReport }`.
   - The collection is built with `SceneCollection::from_parts`. Before that the importer enforces every invariant its validation checks and degrades one object at a time, with a report entry, never a failed import: a name clash takes "Name 2"; an empty or blank name takes the OBS type's readable name plus a number; an item past `MAX_LAYERS` or past `MAX_NESTING_DEPTH`, or that closes a nesting cycle, is left out; a crop or style on a nested scene item (`CropOnScene`, `StyleOnScene`) is dropped and the item kept (approximate); a layout or audio value out of range (`InvalidLayout`, `InvalidVolume`, `InvalidSyncOffset`) is clamped (approximate); a canvas side over `MAX_CANVAS_SIDE` or 0, or a frame rate that is 0, over the maximum or with `FPSDen` 0, falls back to 1920×1080 at 30 (Profile entry). User scenes are always shared and the global scene, scoped to its canvas, is made only by the importer, so `ScopeViolation` and `GlobalScene` cannot arise. The spec lists every `SceneError` variant with its action, and a test fails when a new variant is added without one. `from_parts` failing anyway is a bug, `ImportError::Internal`. No scene format change: format stays 18.
   - **Canvas**: size and `layout_size` from `[Video] BaseCX`/`BaseCY`, frame rate from `FPSType` (0 `FPSCommon`, 1 `FPSInt`, 2 `FPSNum`/`FPSDen`). Without a profile: 1920×1080 at 30, one Profile report entry, and every item marked approximate.
   - `ObsProfileFacts` is a neutral record of the profile, read per output mode: `[Output] Mode=Simple` takes `[SimpleOutput]` (`FilePath`, `RecFormat2` or before OBS 30 `RecFormat`, `VBitrate`, `ABitrate`, `StreamEncoder`, `RecEncoder`, `RecQuality` where `Stream` means the stream's settings, `RecRB`, `RecRBTime`); `Advanced` takes `[AdvOut]` (`RecFilePath`, `RecFormat2`/`RecFormat`, `Encoder`, `RecEncoder` where `none` means the stream encoder, `RecRB`, `RecRBTime`) and the encoder JSON files (`rate_control`, `bitrate`, `max_bitrate`, `crf`/`cqp`, `keyint_sec`, `preset`, `bf`). `[AdvOut] RecType=1` (custom FFmpeg output) is reported. The encoder table covers both id sets: simple-mode names (`x264`, `nvenc`, `qsv`, `amd`, `apple_h264`, ...) and advanced encoder ids. Output size `[Video] OutputCX`/`OutputCY`; `[Audio] SampleRate`, `MonitoringDeviceName`. OBS encoder ids map, as a data table in the importer, to a codec (H.264, HEVC, AV1) and a hardware-or-software preference, never to an RBS adapter by vendor (P3). `service.json`: `rtmp_custom` `settings.server`; `rtmp_common` `settings.service` and `settings.server`. A concrete server URL is kept only if it passes the app's server check (`parse_server`, the same check a typed server gets); otherwise (`auto`, RTMPS, an SRT URL with `streamid` or `passphrase` in its query, anything else refused) the server is left empty and reported by its scheme only, never written to a file or shown in the report, because a query part may be a secret (ADR-0051). Stream service presets are other work. `rbs-app` maps the facts onto `RecordProfile`, `StreamProfile`, replay and audio settings.

5. **Secrets.** `ImportedSecrets` holds only the stream key, `service.json` `settings.key`, in an own newtype whose `Debug` prints `<redacted>`, with no `Serialize` and no `Display`; no new dependency. It goes only to the OS credential store as `stream-key/<new profile id>` (ADR-0051), and only while the user keeps "Bring the stream key" on (on by default). Credentials RBS has no field for (`settings.username`, `settings.password`, `settings.use_auth`, `settings.bearer_token`) are never read into the plan; the report names them, never their values. `service.json` `type` `whip_custom` (WHIP) is reported.

6. **Mapping is a registry of mappers.** `trait SourceMapper { fn obs_id(&self) -> &'static str; fn rbs_types(&self) -> &'static [&'static str]; fn map(&self, src: &ObsSource, ctx: &mut MapContext) -> SourceOutcome; }`, with `FilterMapper` and `TransitionMapper` of the same shape. **One mapper per OBS id**; modes inside one id (`screen_capture` display, window or application) are handled inside that mapper. `Mappers::builtin()` holds the mappers of this ADR; at plan time a mapper whose `rbs_types` are not all in the `Catalogue` is not used, and its objects are reported as "not available in this build". A new RBS type adds one mapper file and one fixture test. Mapping runs in two passes: first every source is mapped and named, then references by OBS name (nested scenes, the compressor's `sidechain_source`, hotkey targets) are resolved; a reference to a skipped object is reported on the referring object.

8. **Transforms and crops.** Keys: the absolute keys `pos`, `scale`, `bounds` are read. OBS 31 also writes relative keys (`pos_rel`, `scale_ref`, `bounds_rel`); an item that has only relative keys is reported, until their conversion is written into the spec and checked against a file saved by a real OBS 31 (step 1 needs one such file from the owner's machine). `bounds_crop` (30.1+) crops to the bounds box. OBS places an item at `pos` with the anchor `align` (left 1, right 2, top 4, bottom 8; none is centre), size native × `scale` or the bounds box (`bounds_type` 1 stretch, 2 scale inner, 3 scale outer, 4 to width, 5 to height, 6 max only) aligned by `bounds_align`, rotated by `rot` degrees about `pos`, after `crop_*`. The converter computes the four corners of the OBS item and returns the RBS box with the same corners in texture order (top-left of the picture to top-left, and so on) within 0.01 px, so a flip never becomes a 180° turn; a negative scale is a negative size. Native size comes from the `Lookup` or the source's settings; when unknown, the canvas size is used and the item is approximate. A `crop_filter` (relative insets) becomes `Source.region`; because OBS adds the item crop to the filter crop while RBS takes the larger inset of region and item crop (ADR-0103 decision 2), the item's `Crop` is written as region + item crop per edge, and the native size used for the box is the size after the region. OBS applies a crop filter at its place in the chain and RBS applies the region after all filters (ADR-0103 decision 3): a crop filter that is not first is approximate. An absolute crop filter (`relative` false) needs the native size; without it the filter is reported.

9. **What is written.** `rbs-app` writes the plan only after it is complete. In order: the new scene collection, the new output profile, the credentials, the shortcuts. Collection and profile take the requested name, or the first free "Name 2", "Name 3", ... (a free-name helper in `rbs-user-data`, the rule `Library::import` uses today, spec change in the same PR). If the profile, credential or shortcut step fails, the earlier steps stay and the report says which step failed and what to redo; the collection on its own is usable. The import does not switch to the new collection while recording or streaming. **The one existing file the import changes is `shortcuts.toml`**, and only while the user keeps "Add the hotkeys" on: imported bindings are added; a chord for which `Keymap::check` returns `Taken` (a user binding or a default) is not added (reported), so an import never displaces a default or a user binding. OBS's files are never written.

10. **Hotkeys.** Frontend entries in `[Hotkeys]` are JSON objects (`{"bindings":[...]}`; the replay entry is `ReplayBuffer={"ReplayBuffer.Save":[...]}`); scene and source entries are in each object's `hotkeys`. OBS key names (`OBS_KEY_*`) and modifiers convert to `Chord` by the platform the file came from, read from the paths in the file (drive letters, `/Users/`, `/home/`) and otherwise this machine's: on macOS-made files `command` is RBS `Ctrl` (Command) and `control` is RBS `Meta` (Control); on others `control` is `Ctrl` and `command` (the Windows or Super key) is `Meta`. A chord that `Chord::app_problem` refuses (for example macOS Option with a typed key) is reported with the reserved ones. A reserved chord, a mouse button, or an action without an RBS command is reported. Where OBS has a pair and RBS a toggle (`PauseRecording`/`UnpauseRecording`), the first maps to the toggle and the second is reported, so no binding changes meaning silently. Source hotkeys are reported: `source.*` commands take no `collection=`, so a source id from the new collection would act on another source while a different collection is in use. `scene.select` gets `scene=` from the new collection's scene id and `collection=` from a placeholder that `rbs-app` replaces with the id the collection is written under (decision 9). Bindings beyond the shortcut limits (`MAX_ENTRIES`, `MAX_PER_COMMAND`) are reported. When `shortcuts.toml` cannot be read, the shortcut step is skipped and reported, so the import never moves the user's file aside. Every imported binding takes the app scope; a global binding for going live is the user's own choice in Settings › Shortcuts (reported as a hint).

11. **The report.** `ImportReport { exact: Counts, entries: Vec<ReportEntry> }`, `ReportEntry { outcome: Approximated | Skipped, area: Scene | Source | Filter | Item | Transition | Hotkey | Profile | Setting, obs_name, obs_type, scenes, reason, hint }`. Reasons are one plain sentence ("Text sources are not in RBS yet."). `rbs-app` saves it as `imports/<collection id>.report.toml` (`kind = "obs-import-report"`, format 1), deleted with its collection and never exported with it. With each skipped object it keeps an **allow-listed** copy of its OBS data for a later "add what is supported now": only the keys that object's future mapping needs, defined per OBS type in the spec; URLs lose their query and fragment; every key whose name contains `token`, `key`, `password`, `secret`, `auth` or `cookie` is dropped; paths keep only the file name; opaque plugin state (`chunk_data` and the like) is never kept. A type with no allow-list keeps only `obs_type` and `obs_name`. The report and kept data never contain a credential or a full path.

12. **Entry points.**
    - `rbs-cli obs-import check <collection.json> [--profile <dir>]` prints the report; `rbs-cli obs-import run ...` writes as in decision 9. These come first.
    - The desktop app: *Import from OBS...* in the RBS menu's scene collection submenu and on the first-run page: detected collections and profiles, a file picker, the report before anything is written, then Import. Its layout is proposed to the owner with screenshots before it is built (rule 16, ADR-0115).
    - Control API: `import.obs.scan`, `import.obs.check`, `import.obs.run` (next free protocol version at merge). Over the API: collections and profiles are named only by what `scan` found, returned as names, never paths; resolved paths are canonicalised and must stay inside the OBS folder (symlinks leaving it are refused); `run` needs the permission that edits output profiles and the stream key, not only scene edits.

13. **Testing.** Fixtures are hand-written OBS-shaped files made for this repository. Golden tests compare the plan (collection document and report) with checked-in TOML: each mapper; groups; nested scenes and cycles; global audio; Windows, macOS and Linux ids and window strings; a simple-mode and an advanced-mode profile; OBS 29, 30 and 31 transform keys; crop filter plus item crop; degrading at `MAX_LAYERS` and on name clashes; a browser URL with a token and every credential field (absent from the report, the kept data and `Debug`); hotkeys per platform. Property test: OBS and RBS corners agree within 0.01 px over random positions, scales, rotations, alignments and bounds types. `rbs-app` tests: catalogue agreement (decision 1), free names, path refusal over the API. Pure tests, fixture reads only, no sleeps (ADR-0032).

## Consequences

- A user brings an OBS setup across in one step and sees exactly what did not come across, also across operating systems (a Windows collection on a Mac finds cameras and windows by name), which OBS does not do.
- Each parallel feature thread (text, media, browser, transitions, microphone filters) adds an OBS mapper and fixture with its type; the coordinator tells those threads.
- Approximate mappings can surprise; they are always in the report.
- Mapper type ids are strings checked by an `rbs-app` test rather than shared constants: the price of keeping the importer out of the engine layer.
- No cost while unused: no threads, polling or resources until an import runs; discovery touches the disk only when asked.
- Follow-up: spec [`obs-import.md`](../specs/obs-import.md); `user-data.md` (free-name helper, `imports/` folder); `overview.md` layer row; `status.md` row; control-api spec with the API step; the first-run page with the UI step.

Implementation steps, each its own PR: (1) crate, collection mapping, report, `rbs-cli obs-import`; (2) profile, credentials and hotkeys, `rbs-app` mapping; (3) desktop dialog and first-run entry (visual approval first); (4) control API.

## Alternatives considered

- **Load OBS's own code (libobs).** Rejected: a C dependency with its own graphics stack, against P1 and the vision.
- **Importer inside `rbs-app`.** Rejected: not testable without the app, and `rbs-cli` could not share it.
- **Depend on `rbs-sources` and the filter crates for type ids.** Rejected: it pulls the GPU and capture stacks into a file reader; a catalogue trait and an `rbs-app` test keep the ids honest.
- **Produce `RecordProfile`/`StreamProfile` in the importer.** Rejected: those types belong to the composition root.
- **Groups as nested scenes.** Rejected for now: scenes the user never saw in their list and an extra composite pass per group; flattening draws the same picture.
- **Keep the skipped objects' full JSON.** Rejected after review: browser URLs carry tokens and plugin state is opaque. An allow-list keeps what a later mapping needs.
- **Import into the current collection.** Rejected: it mixes two shows; a new collection is undone by deleting it.
- **Placeholder sources for unsupported types.** Rejected: a source without a node type breaks binding; the report and kept data serve the purpose.

## Review

Round 1: independent AI session, 2026-11-16, changes requested. Main concerns and resolutions: (1) kept JSON could leak tokens and paths → allow-list and redaction (decision 11); (2) OBS adds item crop to filter crop, RBS takes the larger inset → region + item crop, size after region, non-first crop filter approximate (decision 8); (3) no LUT filter type, `is_installed` covers sources only, `Library::create` does not number names → LUT removed, `Catalogue` gating for every mapper kind, free-name helper (decisions 2, 6, 9); (4) canvas size only in the profile → `[Video]` keys, 1920×1080 fallback reported (decision 4); (5) engine dependencies → string ids checked by an `rbs-app` test (decision 1); (6) other credentials and the secret type → `ImportedSecrets` newtype (decision 5); (7) simple vs advanced output mode, frame rate keys, `auto` server → decision 4; (8) toggle pairs, scene hotkey location, collection id placeholder, modifiers per platform, global go-live bindings → decision 10; (9) `shortcuts.toml` change and partial failure → decision 9; (10) `from_parts` failures abort → invariants enforced first, degrade per object (decision 4); (11) `screen_capture` claimed twice, window strings per OS → one mapper per id, string table (decisions 6, 7); (12) API permission, paths, symlinks → decision 12; (13) OBS 31 relative keys, `bounds_crop` → decision 8; (14) ducker key by name, gate ramps, chroma presets, colour formulas → decisions 6, 7; (15)-(17) report file in user data, scan naming, missing tests → decisions 3, 11, 13.

Round 2: independent AI session, 2026-11-16, changes requested. Resolutions: (1) source mute hotkeys would hit another collection's source → reported until `source.*` takes `collection=` (decision 10); (2) every `SceneError` variant gets a degrade action, test for new variants (decision 4); (3) gamma direction and contrast scale corrected (decision 7); (4) only the stream key is kept, other credentials named and dropped, `settings.*` and `whip_custom` (decision 5); (5) shortcut limits and an unreadable `shortcuts.toml` (decision 10); (6) gate and ducker clamps (decision 7); (7) `[Hotkeys]` JSON and `ReplayBuffer`, simple-mode encoder names, `RecFormat`, `RecQuality=Stream`, `RecType=1` (decisions 4, 10); (8) OBS 31 relative-only items reported until checked against a real file (decision 8); (9)-(12) spec numbers, group crop, texture-order corners, shortcut placeholder.

Round 3: independent AI session, 2026-11-16, changes requested (small). Resolutions: (1) a server URL is kept only if it passes `parse_server`, never written or shown otherwise, as its query may be a secret (decision 4); (2) spec transform sentence aligned with decision 8; (3) the spec table covers every `SceneError` variant, an empty name gets an action, the global scene's own scope noted (decision 4); (4) modifiers to `Ctrl`/`Meta` per platform, `app_problem` chords reported (decision 10); (5) "bound" is `Keymap::check` `Taken`, defaults never displaced (decision 9); (6) concrete `rtmp_common` server kept when it passes the check.

Round 4: independent AI session, 2026-11-16, approve with nits. Resolved: the spec's `Unknown*` row now says references are resolved in pass two and dangling ones are left out and reported; the spec says a refused server is reported by scheme only and the check's error text is never shown.

Owner approval: pending.
