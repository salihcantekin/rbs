# Code quality plan, November 2026

- Date: 2026-11-17
- Source: [code quality audit 2026-11](audit-2026-11.md) (finding IDs QS, QT, QN, QR, QD) and the [performance audit 2026-11](../perf/audit-2026-11.md) (IDs R, C, E, A, U, G, D)
- Rules: [ADR-0144](../adr/0144-code-quality-rules-and-their-enforcement.md) (Proposed)
- Status: plan only. Each work package below becomes its own project thread **only after the owner approves that package** (owner, 2026-11-17).

## How to read this plan

- A **work package** (WP) is one thread and, where possible, one PR. Large packages say how they split into PRs.
- **Wave** says when it fits next to the performance waves. A later wave does not start before the packages it depends on are merged.
- **Approvals** lists what is needed besides the usual merge OK: an ADR with independent review (ADR-0014), the owner's written OK for a new `check-ui` count (ADR-0115), screenshots for a visible change (none of these packages changes what the user sees).
- **Collides with** names files that other threads edit often. Such a package is merged when no other open PR touches those files (one merge slot from the coordinator).
- Tests: each thread runs only the affected crates (`cargo xtask affected test`); a package that changes a root build file (`Cargo.toml`, `clippy.toml`, `rust-toolchain.toml`) selects the whole workspace, so its full run happens once, on the owner's machine or as the batch run.

## CI

CI runs by hand only for now; it becomes automatic again later (owner, 2026-11-17). The plan is written so that nothing has to be redesigned then:

- WP-03 makes `cargo xtask verify` the single gate. Agents run it before a push; CI runs the same command when it is automatic again, so local and CI results match.
- WP-08 writes the test tiers (T0 while editing, T1 before a push, T2 after a batch of merges, T3 nightly, T4 before a release) and the matching CI triggers, ready to switch on.
- Switching the triggers back on is the owner's decision and is not part of any package.

## Wave Q0: guard rails

Before performance wave 1. Tooling and docs only; no product behaviour changes.

### WP-01 Pin the toolchain, test allowances in clippy.toml
- Scope: `rust-toolchain.toml` to an exact version (1.97.0 at the time of writing); decide `rust-version` (test the MSRV in T3 or set it to the pinned version); fix the lints the pinned version reports (recorded: `rbs-cli` `interrupt.rs:89`, `rbs-app` `thumbnail.rs:109` on Windows). Add `clippy.toml` with `allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests`; remove the per-module allows that become unnecessary (about 370).
- Done when: clippy is clean with `-D warnings` on the pinned version on Linux, macOS and Windows; the allow count is in the PR.
- Collides with: every test file (the allow removal). Merge it alone, or split the removal into a second PR per crate group.
- Note: root build files select the whole workspace; run clippy for all crates once, tests only for crates whose code changed.

### WP-02 check-docs and the drift it finds
- Scope: `cargo xtask check-docs`: relative links, conflict markers anywhere in the tree, ADR index against headers, layer table against workspace crates, CODEOWNERS against `hot-paths.md`, Proposed ADRs named as built. Fix what it finds today: 3 broken links, ADR-0076 missing from the index, the layer table (16 crates missing, `rbs-transport-whip` absent), CLAUDE.md `rbs-mcp` "planned", ADR-0090 named Proposed in `status.md`.
- Done when: `cargo xtask check-docs` passes on main and has its own tests in `xtask`.
- Collides with: `docs/adr/README.md`, `docs/status.md` (small edits).

### WP-03 cargo xtask verify, size ratchet, hot-path note
- Scope: `cargo xtask verify` (fmt, `check-layers`, `check-ui`, `check-size`, `check-docs`, affected clippy, test and doc, `cargo deny` when `Cargo.lock` changed) with one result line (commit hash, selected crates, pass or fail); `cargo xtask check-size` with `docs/quality/size-baseline.toml` (files over 2,000 lines: 11; functions over 200 lines: 41; generated and `sys/` code excluded; `--lower` like `check-ui`); `affected` and `verify` name changed hot-path files. CLAUDE.md "Commands" and the PR template point to `verify`. An opt-in `.githooks/pre-push`.
- Done when: `verify` passes on main; the PR body of WP-03 carries its own result line.
- Note: when CI becomes automatic again, its jobs call `cargo xtask verify` (prepared in WP-08).

### WP-04 Owner decisions
- Not a code thread: three questions for the owner, answered on decision cards, then one small docs PR.
  1. ADR-0103, ADR-0104, ADR-0105 are Proposed but built: record reviews and accept, or mark the built parts experimental?
  2. `rbs-mux-flv`: register FLV recording or remove the crate? `rbs-plugin-host`: keep as "not wired"? `prototypes/`: keep with a README or remove?
  3. Replace the test decoder in the app with an "unsupported file" decoder (QS-09)?

## Wave Q1: test support and lints

Next to performance waves 1 and 2, which add tests: those tests use the shared helpers from the start.

### WP-05 Shared test support crate
- Scope: dev-only crate `rbs-test-support` (layer class Tool): `gpu_or_skip()` with the `RBS_REQUIRE_GPU` rule, `require_env!` for the other `RBS_REQUIRE_*` switches, update-waiting helpers with hang guards (ADR-0032), a skip counter printed at the end. Migrate the 20+ copies of `gpu()`. `cargo xtask affected test` sets `RBS_REQUIRE_GPU=1` where an adapter is known (cloud with lavapipe, owner machines).
- Done when: no test file defines its own GPU helper; a run without a GPU reports how many tests skipped.
- Collides with: GPU test files in `rbs-app`, `rbs-nodes`, `rbs-gpu`, `rbs-record` (mechanical edits).

### WP-06 Screenshot tools out of tests; fewer rbs-app UI test binaries
- Scope: the 9 `*_shots` ignored tests become `cargo xtask shots <set>` (one binary); the remaining `rbs-app` UI test files grouped into a few binaries. Studio host tests are grouped in WP-13. Coordinate with the devloop work for performance finding D-14.
- Done when: `rbs-app` has no ignored "tool" tests; the number of `rbs-app` test binaries and the link time before and after are in the PR.

### WP-07 Lints
- Scope: `unsafe_code = "forbid"` for the 46 crates without unsafe (a per-crate `[lints]` override or `#![forbid(unsafe_code)]`); `clippy::allow_attributes_without_reason`; move `#[allow]` to `#[expect(..., reason)]` where the lint fires; `dbg_macro`, `todo`, `print_stdout`, `print_stderr` in library crates (the 13 `eprintln!` stay with an `expect` until WP-21).
- Done when: clippy is clean; the PR lists the counts.

### WP-08 Test tiers, CI triggers ready, skills
- Scope: `docs/specs/testing-strategy.md` gets tiers T0 to T4 with time budgets and what each runs (T3: slow tier, interop, Miri, benchmarks compile and run; T4: soak). A prepared CI change (separate file or commented block) that runs `cargo xtask verify` on pull requests, T2 on pushes to main and T3 on a schedule, not switched on. Skills `add-api-method`, `add-setting`, `add-source-type`.
- Done when: the spec and skills are merged; the CI change is ready for the owner to switch on.

### WP-09 One platform adapter list
- Scope: an ADR (or an addendum ADR) for a shared composition crate `rbs-platform` used by `rbs-app` and `rbs-cli` (and later `rbs-mcp`), with explicit options for what differs; independent review; then the crate and the two roots using it.
- Done when: the adapter list exists once; `rbs-cli` and `rbs-app` register the same adapters except listed differences.
- Collides with: `rbs-app/src/platform.rs`, `rbs-cli/src/platform.rs` (rarely edited).

### WP-10 Typed errors in rbs-user-data and rbs-ui
- Scope: `DocumentError` and friends in `rbs-user-data` (`document.rs` trait and helpers, 34 places), typed errors in `rbs-ui` (17); callers in `rbs-app` map them.
- Done when: no `Result<_, String>` in those two crates.

### WP-11 check-ui count for unmarked literals
- Scope: needs the owner's written OK first (ADR-0115). A sixth count, `literal`: a px, phx or hex colour literal in `crates/rbs-app/ui` outside token files without a `// literal:` comment on its line. Baseline from today (a handful); the existing unmarked ones get a comment or a token.
- Done when: `check-ui` counts it and passes.

## Wave Q2: structural moves

After performance wave 2 and before performance wave 3, which rewrites the control plane, the UI sync and output planning. Doing the moves first means those changes are written once, in the new layout. The small control-plane fixes of performance wave 1 (G-03, G-05, U-06) land before the moves.

### WP-12 ADR: the studio host in its own crate
- Scope: a new ADR for a toolkit-free crate holding the studio host and its settings files (working name `rbs-studio-host`), its layer class, what stays in `rbs-app`, the public boundary between them, and layer metadata in `Cargo.toml` (QN-07). Independent review (ADR-0014), owner approval.
- Done when: the ADR is Accepted.

### WP-13 Move the studio host
- Scope: a pure move: `studio_host.rs`, `studio_host/`, the 18 settings-file modules and the 13 `studio_*` tests into the new crate; tests grouped into one or two binaries. No behaviour change, no renames beyond paths.
- Done when: all moved tests pass in the new crate; `rbs-app` builds against it; the PR reports test binary sizes and link time before and after.
- Collides with: almost every `rbs-app` PR. Needs a merge slot with no other open PR in `rbs-app`; announce it ahead.

### WP-14 Split the studio host by concern
- Scope: per-concern modules (`recording`, `stream`, `scenes`, `sources`, `outputs`, `projector`, `api`) with their own state inside `Host` and handler functions the dispatchers call. Several PRs, one concern each.
- Done when: no file in the host crate over 2,000 lines and no function over 200 (`check-size` lowered).
- Collides with: performance packages G-02, G-04, G-08 (do them right after, in the new modules).

### WP-15 Split main.rs and studio_ui.rs with targeted UI updates
- Scope: modules from `main.rs` into the library; `install_studio` and `sync` into per-window or per-panel bindings; `studio_ui.rs` into one module per update kind. Done together with performance U-04 (targeted updates) and U-05 (model reuse) in one thread, since they rewrite the same code. Not visible to the user; no screenshots needed unless something changes on screen.
- Done when: `check-size` lowered for both files; U-04 and U-05 measurements from the performance plan recorded.

### WP-16 Split rbs-record's Studio with shared producers
- Scope: `reconcile` per output kind, separate state types for outputs, encoders and canvases, as the first step of performance R-01 = E-04 (one conversion and readback per output shape) and E-01 (replay buffer reuses the encoder). Hot path: P15 numbers, `hot-path-review` and the owner's sign-off for the parts that touch the render tick.
- Done when: `check-size` lowered; the performance items' measurements recorded.

### WP-17 Adapter tests next to their adapters
- Scope: tests in `rbs-nodes`, `rbs-sources` and `rbs-record` that need an adapter (Media Foundation, WGC, WASAPI, AMF, NVENC, file transport, Matroska) move to the adapter crate or to one integration crate that only the batch run builds; the engine crates lose those dev-dependencies.
- Done when: no engine crate has an OS or vendor adapter as a dev-dependency; `affected list` for an adapter change shown before and after.

### WP-18 Split the large specs; implementation lines; short status
- Scope: the control API spec split by namespace, the UI design system spec by component group; an `Implementation:` line in every ADR header; an "Implementation status" section in every spec; `status.md` rows at most two lines that link to them. `check-docs` (WP-02) keeps links and lines valid.
- Done when: no spec file over about 60 KB; `status.md` under about 8 KB; `check-docs` passes.
- Collides with: every PR that edits these specs. Split one spec per PR, each in a quiet merge slot.

### WP-19 Numbers assigned at merge
- Scope: change fragments (`docs/changes/api/`, `docs/changes/scene-format/`) and `cargo xtask bump` that assigns the next protocol or format number, writes the constant and appends the spec section. CLAUDE.md and the merge procedure updated.
- Done when: a feature branch no longer edits `PROTOCOL_VERSION` or the scene format number.

## Wave Q3: contracts and depth

Next to performance wave 4, which also needs ADRs and reviews.

### WP-20 One command path for the window and the API
- Scope: an ADR (window operations go through `rbs_api::Command`; window-only commands listed with reasons; the U20 parity test), designed together with performance G-02 (the layers-only edit path for drags). Review, then implementation in steps by namespace.
- Done when: the U20 test is in the fast tier and passes; `studio_host::Command` holds only listed window-only commands.

### WP-21 Diagnostics log
- Scope: an ADR for a small diagnostics facility (levels, a ring in memory, a rotating file in the user data folder, zero cost when a level is off, nothing on real-time threads), then the facility and the existing `eprintln!` moved to it.
- Done when: the ADR is Accepted and the app's messages appear in the log file.

### WP-22 Property tests
- Scope: `proptest` as a dev-dependency with a fixed seed and small case counts, for scene collection operations with undo, time and rate arithmetic, bitstream conversion, muxer round trips, user-data format upgrades and layout.
- Done when: each listed area has property tests that run in milliseconds.

### WP-23 Miri and loom for lock-free code
- Scope: tier T3 runs Miri on `rbs-vcam`, `rbs-vcam-ring` and the pure parts of `rbs-core`; loom models for the vcam mailbox and the capture hand-off ring.
- Done when: the T3 job definition includes them and they pass.

### WP-24 Layer metadata and quality report
- Scope: `[package.metadata.rbs] layer` in each `Cargo.toml`, read by `check-layers` and compared with the overview by `check-docs`; `cargo xtask quality-report` printing the audit's numbers.
- Done when: the layer `match` in `xtask` is gone; the report reproduces the audit's table.

### WP-25 Typed errors in the studio host
- Scope: refusals with kinds that map to `ApiError` kinds instead of `String` (about 60 places in the host and `user_session`).
- Done when: no `Result<_, String>` in the host crate except at the UI edge.
